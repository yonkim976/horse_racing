# API78 출전카드 장구 표기의 의미와 시점

조사일: 2026-10-01. 범위: API78 `equipCrs` 파서·저장 코드, API24/API156 장구 필드 매핑, 기존 읽기 전용 저장 감사, 한국마사회 공식 설명. DB 쓰기·신규 API 대량수집은 하지 않았다.

## 확인된 의미

한국마사회 서울 경마의 공식 출전상세정보는 표의 `장구현황` 열에서 `+`는 **신규장구**, `-`는 **해지장구**라고 명시한다 ([공식 출전상세정보 예시](https://race.kra.co.kr/chulmainfo/chulmaDetailInfoChulmapyo.do?Act=02&Sub=1&meet=1&rcDate=20190504&rcNo=3), 페이지의 장구현황 주석). 따라서 `계란형큰+,망사눈`은 카드에 나열된 장구 가운데 계란형큰이 신규로 표시되고 망사눈은 부호 없이 표시된 형태다. `망사눈+,계란형큰-`은 망사눈 신규와 계란형큰 해지를 표시한다.

`+/-`는 장구 이름의 부분이 아니라 카드의 변경 상태 표식이다. 하지만 부호 없는 토큰을 모든 시점에서 실제 착용된 장구라고 단정해서는 안 된다. 가장 좁고 근거가 강한 해석은 **해당 카드 관측이 표시한 장구현황 및 그중 명시적으로 신규/해지된 항목**이다. 카드가 생성·게시된 시각과 사용자의 수집시각은 별도다.

한국마사회 서울 경마의 운영기준은 지정장구를 승인장구와 자유사용장구로 구분하고, 승인장구에는 사전 심판위원 승인 절차가 있다고 설명한다. 또 출전준비소부터 경주 종료까지 임의 교체·탈착을 금지하되, 원활한 입장을 위한 장구는 심판위원 승인으로 출발 전까지 사용할 수 있다고 규정한다 ([공식 장구 운영기준](https://race.kra.co.kr/raceguide/RaceManagementStandardService.do?Act=06&Sub=4&meet=1)). 신청 시각 안내는 출전신청일 12시까지이며 사정에 따라 이후 신청 허가가 가능하다고 적혀 있다 ([공식 사용·해지 신청 안내](https://race.kra.co.kr/raceguide/RaceUseApproveService.do?Act=06&Sub=4&meet=1)). 이 규칙들은 출전카드 표시가 장구 승인·출전신청 맥락에 놓인다는 점을 뒷받침하지만, 특정 API 응답이 정확히 언제 게시되었는지나 매 말의 경주 중 물리적 착용 여부를 단독으로 입증하지 않는다.

## API별 값과 시간 축

| 원천 | 확인된 필드·저장 방식 | 이 조사에서 가능한 해석 |
|---|---|---|
| API78 출전카드 | `equipCrs` 원문을 `equipment_card_raw`에 저장. 마지막 수집시각과 `+/-` 분해 결과도 저장 | 카드별 장구현황 원문과 명시 신규/해지 표시. 카드 관측시각은 수집시각이며, 당시 이용 가능했던 사전 예측 입력 시각과 같다고 자동 간주할 수 없음 |
| API24 보조 자료 | 파서에서 `toolName`과 `bleedingCnt`, `bleedingDate`, `illName`을 받음. 서비스는 별도 `entry_equipment`에 저장하고 비어 있지 않은 `toolName`만 공용 출전행 `equipment`에도 복사 | 원천 필드 구조가 장구와 진료 정보를 함께 다루는 보조 자료임. 공식 설명서에서 `toolName`의 사건 기준·게시 시점을 확인하지 못했으므로 이를 곧 경주 중 실착 목록으로 부르지 않음 |
| API156 상세성적 | 파서가 `pthrEquip`을 `equipment`로 매핑. 상세성적 수집기가 해당 값을 공용 출전행 `equipment`에 매번 대입하며 `None`도 대입 | 경기 후 상세성적 원천의 장구 내역으로 별도 보존해야 함. 공용 열에는 출처/관측시각이 없고 API24와 API156이 서로 덮어쓸 수 있어, 현 값만으로 provenance를 정할 수 없음 |

공공데이터포털의 공식 상세성적 API 설명은 시행된 경주의 상세성적표를 제공하며 응답 항목에 `hrTool`(장구내역)을 명시한다 ([한국마사회 경주별상세성적표](https://www.data.go.kr/data/15089492/openapi.do)). 프로젝트의 API156 응답 키는 `pthrEquip`이며 이 필드-항목명 대응은 프로젝트 파서에서 확인한 것이다. 공식 카탈로그 `hrTool`과 API156의 `pthrEquip`을 문서 근거 없이 완전히 동일한 계약이라고 간주하면 안 된다.

기존 운영 감사에 따르면 API78 원문은 운영 출전의 2017-01-06~2026-09-20 구간에 저장되어 있고, 과거 경주 API78 응답의 수집시각은 2026년 소급 조회 시각이다. 그러므로 과거 경주의 API78 원문은 후향적 공식 카드 관측으로 보존할 수 있지만, 당시 경주 전 정보였다고 모델에 공급해서는 안 된다. API78 서비스는 페이지별 `SourceDocument`에 개별 `retrieved_at_ms`를 기록하면서 출전행 표에는 한 배치의 최대 수집시각을 모든 응답행에 넣는다. 최신 표의 관측시각은 행·페이지별 최초 게시시각이 아니다.

## 카드와 성적의 값 차이 해석

이번 검토의 공식 KRA 공개 카드·성적표와 로컬 원문 감사에는 아래 두 사례가 있다 ([원문 출처 감사](../raw_examples/source_document_audit.json), [공개 카드·성적표 캡처와 해시](../public_examples/evidence.json)).

| 출전 | API78 카드 (`equipCrs`)와 API156 상세성적 (`pthrEquip`) | API24 `toolName` 관측 |
|---|---|---|
| 2026-09-18 부산경남 R4-9 플라잉스카이 | 카드 9/16, 9/17, 9/18 관측이 모두 `계란형큰,망사,승인편자,양털코,혀끈-`; API156도 9/18 22:55 관측에 같은 원문 | 9/17, 9/18, 9/23 관측 모두 `망사가면,양털코굴레,쿠션편자(Cushion)` |
| 2026-09-20 영천 R3-6 아처하트 | 카드 9/16, 9/17, 9/18 관측이 모두 `망사+,반가지큰+,양털코,혀끈+,Triabit -`; API156도 9/23 22:22 관측에 같은 원문 | 9/17, 9/18, 9/23 관측 모두 `망사가면,반가지큰고리재갈,혀보정끈` |

따라서 **이 두 샘플의 API24 대 API78/API156 문자열 차이는 전/당일 시간 차이로 설명되지 않는다.** 카드 값은 경기 전 여러 번과 경기 후에도 유지되며 API156 상세성적과 일치했다. API24 값도 앞뒤 관측에서 유지되었다. 이 결과는 두 샘플에 한정되며, API24 `toolName`의 공식 사건·게시 시점 정의나 항목별 약칭 대응은 확인되지 않았다. 다른 말에서 카드와 결과가 언제나 같다는 보장도 아니다.

## 코드 근거

- `src/horse_racing/parsers/gate_entry_sheet.py`: API78 `equipCrs` 원문 필드와 끝의 `+/-`만 인식하는 `parse_equipment_changes`.
- `src/horse_racing/services/gate_entry_sheet.py`: raw 카드 저장, 최신 관측 시각으로 현재 raw/변경행 갱신, 원문 source document 보존.
- `src/horse_racing/parsers/race_supplemental.py`: API24 `toolName` 및 진료·출혈 필드.
- `src/horse_racing/services/race_supplemental.py`: API24 항목을 혼합 보조 테이블에 저장하고 비공백 장구 문자열만 공용 출전행에 반영.
- `src/horse_racing/parsers/race_day.py`, `src/horse_racing/services/race_day.py`: API156 `pthrEquip` 매핑 및 공용 출전행 `equipment` 대입.
- `thoroughbred/research/20261001_equipment_storage_audit_v1/README.md`, `operational/README.md`: 과거 소급 관측·혼합 원천·결측 분류 감사.

## 새 연구 DB 적재 시 권장 보존 단위

1. API78 원문 `equipCrs`, 사건 키, 응답 수집시각·페이지 출처·해시를 관측 스냅샷으로 보존한다. 저장한 `retrieved_at`을 게시 시각으로 쓰지 않는다.
2. 토큰을 파싱할 때 원문 순번을 유지하고 `unmarked`, `new (+)`, `terminated (-)`를 다른 상태로 저장한다. 부호 없는 항목을 변경 이벤트로 만들지 않는다.
3. API156의 장구 내역과 API24의 `toolName`을 별도 원천·시점 자료로 보존한다. API78에서 전·후 카드 상태를 비교한 파생 결과와 KRA가 명시한 `+/-`를 같은 종류의 변경 이벤트로 합치지 않는다.
4. 결측 관측, 명시적 공백 카드, 파싱 불가 원문, 변경표시 없음은 각각 구분한다.

이 조사는 `equipCrs`의 표식 의미는 공식 KRA 페이지 주석으로 확인했지만, API24 `toolName`의 공식 시점 정의와 과거 API78 카드의 최초 게시시각은 확인하지 못했다.
