# 출전표 장구 목록·신규·해제 적재 가능성 검토

검토일: 2026-10-01 (Asia/Seoul). 서울·부산경남·영천 대상. 연구 코어와 운영 DB는 읽기 전용으로 확인했으며 장구를 적재하거나 DB를 변경하지 않았다. 서브에이전트는 사용자 지정 `gpt-6-luna xhigh`를 사용했다.

## 결론

**API78 출전표의 장구 원문과 각 항목의 신규 `+`·해제 `-` 표시를 연구 DB에 보존하는 것은 가능하고, 적재의 우선 원천으로 적절하다.** 자료의 의미는 ‘해당 출전표에 표시된 장구현황’으로 정의한다. 최초 출전표 발표 당시 값, 경주 전 모든 시점의 동일 값, 실제 경주 중 착용한 모든 장구의 전수 목록까지 자동 확정하지 않는다.

이번에 확인한 세 말은 **API78와 API156 상세성적의 장구 문자열이 같고 API24 상세목록은 달랐다.** 두 말은 현재 공식 홈페이지 출전표와 성적표도 같았다. 따라서 운영 DB `equipment`와 출전표의 차이를 경기 전→당일 장구 변경이라고 단정할 수 없다. 운영 공용 `equipment` 열에는 API24와 API156이 서로 다른 형식으로 쓰므로, 새 연구 DB에서는 이 열을 단독 기준으로 가져오지 않는다.

## 공식 표시의 의미

마사회 [출전표](https://race.kra.co.kr/chulmainfo/chulmaDetailInfoChulmapyo.do?Act=02&Sub=1&meet=3&rcDate=20260918&rcNo=4)는 `+`를 신규장구, `-`를 해지장구라고 설명한다. [성적표](https://race.kra.co.kr/raceScore/ScoretableDetailList.do?Act=04&Sub=1&meet=3&realRcDate=20260918&realRcNo=4)에도 같은 주석이 있고, 성적표의 이 표시 제공 시작은 2016년 2월이라고 안내한다. 이 날짜는 모든 API78 과거 원문의 제공 시작이나 완전한 커버리지를 증명하는 날짜는 아니다.

예시 원문 `계란형큰,망사눈+,혀끈-`은 아래처럼 보존한다.

| 원문 항목 | 장구명 원문 | 상태 | 출전표 기준 사용목록 포함 |
|---|---|---|---|
| 계란형큰 | 계란형큰 | 부호 없음 / 변경 표시 없음 | 포함 |
| 망사눈+ | 망사눈 | 신규 장착 표시 | 포함 |
| 혀끈- | 혀끈 | 해제 표시 | 제외, 해제 사건은 보존 |

여기서 ‘포함’은 카드에서 파생한 사용목록이며 실착 검증 플래그와 다르다. 부호 없는 항목을 별도 근거 없이 직전 경주부터의 지속 사용이나 평생 변경 없음으로 확정하지 않는다. `+` 역시 해당 경주의 공식 신규 표시로 저장하며 평생 최초 착용 여부까지 확정하지 않는다.

## 원문·성적표 대조 사례

### 보존된 API156 결과 전체와 현재 API78 관측 대조

보존 API156 문서는 539개이며 사건 범위는 **2025-01-03~2026-09-20**였다. 그중 대상 경주장 1·3·4의 날짜/경주장별 최신 수집 완료 배치 **345개**를 선택했다. 모두 단일 페이지이고 원문 응답의 총 건수와 실제 항목 수가 일치했으며 SHA-256도 일치했다. API156의 정상 착순을 가진 항목을 코어와 사건 키·공식 말 ID로 연결한 **32,491행**은 현재 운영 API78 관측과 모두 연결됐다.

| 대조 결과 | 행 수 |
|---|---:|
| 장구 문자열이 비공백이고 API78 = API156 (원문 그대로 일치) | **31,107** |
| API78는 관측된 공백, API156은 장구명 없이 단독 `-` | **1,384** |
| 위 공백/단독 `-` 차이 외의 장구 내용 불일치 | **0** |

이 대조는 현재 보존된 **2025년 이후 API156 자료**의 검증이다. 2017~2024년이나 2010년 이후 전체의 결과 원문 전수 대조라고 확대하지 않는다. 현재 운영 API78 값과 최신 보존 API156의 조회 시각도 다르므로, 최초 게시 카드와 당일 변화를 전수 관측했다는 뜻은 아니다. 원천값이 존재하는 이 범위에서는 출전표 장구를 기본 자료로 적재하는 근거가 된다. [원문별 선택 목록·대조 근거](raw_examples/broad_comparison.json), [재현 스크립트](raw_examples/broad_comparison.py), [주 에이전트 독립 집계](root_broad_comparison.json). 주 에이전트와 서브에이전트의 9개 독립 검증 항목은 모두 일치했으며 1,384행의 사건 키·공식 말 ID 집합도 정확히 같았다.

**장구명 뒤의 `-`와 단독 `-`는 구분한다.** `혀끈-`는 특정 장구의 해제 표시지만 `-`만 있는 필드는 해제할 장구명이 없다. 원문 자체는 남기고 ‘단독 기호 / 항목 없음’으로 구분하며 장구 해제 사건을 생성하지 않는다. 공백과 단독 `-`의 표현이 달랐다는 사실도 원장에 유지한다.

### 원천별 상세 예

| 출전 | API78 출전표 = API156 상세성적 | API24 `toolName` |
|---|---|---|
| 2026-09-18 부산경남 4R 9번 플라잉스카이 (`0053545`) | 계란형큰,망사,승인편자,양털코,혀끈- | 망사가면,양털코굴레,쿠션편자(Cushion) |
| 2026-09-20 영천 3R 6번 아처하트 (`0060852`) | 망사+,반가지큰+,양털코,혀끈+,Triabit - | 망사가면,반가지큰고리재갈,혀보정끈 |
| 2026-09-18 부산경남 9R 1번 오늘이순간 (`0047505`) | 망사,반가지큰,승인편자+,승인편자- | 반가지큰고리재갈,망사가면,쿠션편자(Cushion) |

플라잉스카이는 출전표의 부호 없는 `계란형큰`이 API24에는 없고, 아처하트는 부호 없는 `양털코`가 없다. **해제 항목을 제거하고 약칭을 풀어 쓰는 것만으로 모든 차이를 설명할 수 없다.** 그러나 각 원천의 복수 관측에서는 그 값이 유지됐다. API24에도 경주 전 조회가 있어 API24를 자동으로 ‘경주 후 실착 목록’이라고 부를 수 없다.

원문 API78는 이 세 말의 경주 전 관측을 포함해 세 차례씩 같은 값을 반환했다. API24 역시 세 차례씩 동일한 상세목록을 반환했고, 정상 착순 2·3·6착이 기록된 API156은 API78와 같은 `+/-` 포함 문자열이었다. API78 원문에는 말 ID가 없으므로 날짜·경주장·경주번호·마번·마명을 검증하고 API24/API156의 공식 말 ID로 교차 확인했다.

주 에이전트는 **14개 고유 원문 파일·21개 대상/원천 연결**의 해시와 원문 항목을 다시 검증했고 모두 일치했다. 두 사례의 공식 홈페이지 출전표·성적표 **4개 페이지**도 직접 받아 비교했다. HTTP 200만으로 검증을 끝내지 않았고 CP949로 해석하여 날짜·말·장구 행을 확인했다. [원문 근거](raw_examples/source_document_audit.json), [공식 화면 근거](public_examples/evidence.json), [주 에이전트 검증](root_verification.json).

## 신규와 해제가 같은 약칭에 같이 있을 수 있음

오늘이순간의 `승인편자+`와 `승인편자-`는 서로 지우거나 하나로 합치지 않는다. 약칭이 같아도 원천은 서로 다른 두 표시를 제공한다. 세부 편자의 교체일 가능성이 있지만 정확한 구·신 편자 종류는 이 표시만으로 확정하지 않는다.

2025년 이후 코어와 공식 말 ID까지 연결된 카드 **33,019행**에서 같은 장구 약칭이 사용 표시/신규와 해제에 동시에 나오는 행은 **115행**이었다. 순번과 토큰별 상태를 함께 저장해야 한다. [해당 목록](same_label_active_and_removed.csv).

## 최근 운영 자료의 진단 대조

2025-01-01~2026-09-29 서울·부산경남·영천 운영 API78 관측 33,031행 중 코어와 키·공식 말 ID가 일치하는 33,019행을 비교했다. 카드와 혼합 `entry_equipment` 원문이 모두 비공백인 31,564행에서 진단용 약칭 대응과 편자·좌우 구분의 단순화를 적용했을 때, 카드의 사용 후보 장구군이 모두 보조 원문에 나오는 것은 27,334행이고 일부가 없는 것은 **4,230행**이었다.

이는 **시점 변경 건수·공식 장구 오류 확정 건수·API24 전수 원문 검증 건수가 아니다.** 기존 혼합 테이블과 진단용 대응표에 대한 불일치 후보다. 약칭 대응표는 정식 장구 사전으로 승인하지 않았다. 같은 항목의 추가·해제가 공존할 때는 개별 토큰을 먼저 처리했고 해제 집합을 전체 목록에서 일괄 빼지 않았다. [재현 코드](compare_recent.py), [진단 집계](comparison.json), [후보 원장](diagnostic_active_absent.csv).

## 경기 전과 경기 당일의 시점

마사회 [장구 운영기준](https://race.kra.co.kr/raceguide/RaceManagementStandardService.do?Act=06&Sub=4&meet=1)은 사전 사용 승인을 설명하며 출전준비소부터 경주 종료까지 임의 교체·탈착을 금지한다. 출발 전 입장을 돕는 승인 장구 등 예외도 있다. 따라서 경기 전·당일 변경 가능성을 전부 배제하지 않되, 원천 문자열의 차이만으로 변경을 확정하지 않는다.

아울러 현재 홈페이지에서 조회한 과거 출전표는 조회 시점에 제공되는 공식 표다. **오늘 과거 자료를 가져왔다고 당시 최초 게시 상태가 보존되는 것은 아니다.** 보존된 경기 전 스냅샷이 있는 사례에서는 그 관측을 별도로 활용할 수 있고, 소급 조회 자료는 소급 수집 표시를 유지한다. 모델의 예측 기준시점 이전 이용 가능성은 별도 상태로 관리한다. 기존 연구의 1,828행 공식 성적표 대조 및 1,526행 반복관측 결과는 [기존 검증 문서](../../../docs/API78_EQUIPMENT_HISTORY_INDEPENDENT_VALIDATION_2026-09-30.md)에 있으며, 이번 전수 신규 웹 검증 수치로 사용하지 않았다.

## 권장 적재 설계와 범위

1. **카드 관측 원장:** 원문, 사건 키, 수집시각, 원문 파일·해시·페이지 출처를 보존한다. 운영의 최신 문자열뿐 아니라 이용 가능한 API78 원문 스냅샷을 우선 사용한다.
2. **항목별 표시:** 원문 순번, 장구 약칭, `부호없음 / 신규 / 해제`를 저장한다. 해제도 행으로 보존한다. 장구명 없이 단독 `-`인 값은 해제 사건으로 생성하지 않는다. 기존 운영 파서는 `+/-`만 분리하므로, 부호 없는 장구 목록도 새 구조에 포함해야 한다.
3. **출전표 기준 사용목록:** 부호 없는 항목과 신규 항목에서 파생하고, 해제 항목은 사용 목록에서 제외한다. 약칭 중복과 신규·해제 동시 표시는 원장으로 되돌아갈 수 있게 유지한다.
4. **원천별 보조 값:** API24 상세목록과 API156 결과 표시는 원천별로 별도 보존한다. 덮어써서 하나의 ‘진짜 실착값’을 만들지 않는다. 진료 혼합 과거 원문도 카드 값으로 대체·위장하지 않는다.
5. **결측과 연결:** 미관측, 관측된 공백, 토큰 해석 실패, 말 연결 미확정을 구분한다. 출전취소 등 코어 출전행에 바로 연결되지 않는 카드 원문을 버리거나 새로운 완주 경주로 생성하지 않는다.

운영에서 이미 저장된 카드의 사건 범위는 2017-01-06~2026-09-20이다. 이전 저장 감사에서는 2017년 이후 연결 출전 중 미관측 104행을 확인했다. **이 보유량을 그대로 가져오는 것과 2010년 이후 출전표 전수 확보 완료는 다른 작업**이다. 2010~2016 제공 범위와 `+/-` 제공 이전 기간은 별도로 확인해야 하며 부호 없는 과거 자료에 임의의 신규·해제 표시를 만들지 않는다. 상세성적표나 다른 공식 원천으로 보완하면 출처를 구별한다.

상세 공식 의미·코드 검토는 [의미 검토](semantics/README.md), 기존 저장 현황은 [저장 상태 감사](../20261001_equipment_storage_audit_v1/README.md)에 있다. 이 검토의 판정은 **출전표 기반 장구 표시 적재 가능**이며, 실제 적재·과거 전 기간 수집·전체 행의 실착 검증은 수행하지 않았다.
