# 더러브렛 데이터셋 v1

2026-10-04 정리 안내: 이 문서는 당시 구축 근거를 보존한다. 입력이었던 공유 구간 원본·검증·판정 DB 3개는 사용자 승인으로 삭제했고, 생성된 `thoroughbred/data/dataset_20260929_v1/thoroughbred.duckdb`의 `section`·`section_point`와 Parquet는 유지했다. 아래 과거 빌드 명령은 삭제된 입력 때문에 그대로 재실행할 수 없다. 새 연구의 기본 원천은 `thoroughbred/data/core_api_2010_20260929_v1/thoroughbred_core.duckdb`다. 상세 경로·해시·보존 검증은 [삭제 기록](../../../reports/data_deletion_audit_20261004/section_db_deletion_receipt.json)을 따른다.

## 목적과 범위

서울·부산의 경주 이력을 2010년부터 보존하고, 2017년부터는 학습·시간순 평가 대상으로 쓸 수 있도록 새 데이터 스냅샷을 만든다. 영천은 경주 시작 후 확보된 자료를 포함하며, 초기 경주마의 과거 부산 이력은 같은 말 ID로 이어서 조회할 수 있게 했다. 기존 데이터베이스나 원천 파일은 수정하거나 삭제하지 않았다.

스냅샷은 `data/dataset_20260929_v1/`에 생성된다. 기본 조회용 DuckDB와 테이블별 Parquet, 검증 요약, 출처·해시 목록이 들어 있다. 대용량 결과물은 Git에서 제외한다.

## 이력 피처

`performance_history_features`는 각 대상 경주일보다 앞선 확정 경주만 집계한다. 전체 선행 출전 수·우승·Top3, 직전 휴식일, 직전 경마장, 최근 1·3·5회 착순 요약과 우승·Top3 비율, 그보다 오래된 6회 이상 이력을 제공한다. `history_contract`는 적용한 시점 계약을 기록한다. 최근 5회와 과거 이력의 효용은 후보 피처 가설이며, 시간순 평가를 마친 뒤 채택해야 한다.

`prediction_frame_2017_onward`는 라벨이 붙은 학습 프레임이다. 실제 입력 피처를 만들 때 `target_*` 열을 설명변수로 사용하지 않는다. 정답은 별도 `race_label_2017_onward`에서 가져와 시점 누출을 막는다. 이 스냅샷에 있던 오류 경주 56개와 출전결과 581행을 제거한 뒤 과거 이력 피처를 재계산했다. 2017년 이후 프레임은 182,062행이다.

## 테이블

- `venue_dimension`: 서울·부산·영천 코드
- `race`, `entry_result`: 경주, 출전마·결과
- `section`: 보존된 원천 구간 레코드
- `section_point`: adjudicated 출처에서 가져온 표준 S1F/G3F/G1F
- `trial_entry`, `training_event`, `medical_event`, `weight_event`, `equipment_event`: 과거 이벤트 자료
- `identity_issue`, `unresolved_identity_ledger`: 정체성·경마장 매핑 미해결 기록
- `performance_history_features`: 경주일 기준 과거 성적 피처
- `prediction_frame_2017_onward`, `race_label_2017_onward`: 학습 프레임과 분리 라벨

표준 구간기록에는 `point_code`와 함께 `time_kind`가 있다. 서울·부산의 G1F/G3F는 누적시간과 해당 구간 소요시간이 모두 존재하고, 서울은 2010–2014 및 2025년 이후 자료에서 시간 형식이 달라진다. 영천 초기 자료는 누적시간이다. `time_kind`와 기간을 구분하지 않은 채 값을 직접 비교하지 않는다.

## 입력 출처와 제한

`manifest.json`에 각 입력 파일의 크기와 SHA-256이 기록되어 있다. 이 빌드는 원천 파일을 읽기 전용으로 열었다.

[KRA 성적표와 이전 경주 출전마 집합 대조](../20260929_calendar_api_v1/planless_positive_result_review.csv)로 확정한 오류 20키 및 [추가 52키](../20260929_calendar_api_v1/result_only_nonfinish_anomaly_review.csv) 중 이 스냅샷에 들어 있던 서울·부산경남 56키를 활성 테이블과 Parquet에서 삭제했다. 연결된 원천 구간 2,040행도 삭제했으며, 과거 이력 피처와 학습 프레임을 다시 계산했다. 빌더는 재생성할 때 동일한 오류 키를 제외한다. 이전 통합 원천 DB 자체는 보존한다.

1. 서울·부산의 2010년 이후 이력 및 이벤트 자료는 `data/research/thoroughbred_unified_20260918/thoroughbred_unified.duckdb`에서 복사했다. 원래 서울·부산 스테이징 SQLite 파일은 현재 저장소에서 찾을 수 없어, 기존 통합 DuckDB가 이 버전의 고정된 과거 원천이다.
2. 2026-09-13 이후 완료 경주와 출전마·결과는 `data/horse_racing.sqlite3`에서 가져왔다. 이를 통해 경주와 표준 구간기록 범위를 2026-09-20까지 맞췄다.
3. 표준 구간기록은 `data/research/section_point_db_20260925/section_points_adjudicated.sqlite3`의 확정 S1F/G3F/G1F 행이다. 원시 구간 출처의 모든 변형을 `section_point`에 추가한 것은 아니다.
4. 조교·진료·조교시험·체중·장구 테이블은 과거 통합 DB의 최신 시점을 유지한다. 경주·결과와 구간기록처럼 9월 20일까지 갱신된 것으로 간주하면 안 된다.
5. 2017년 이후 프레임의 최근 성적 피처는 누출을 피하도록 설계했지만, 이 데이터만으로 모델 성능이나 실전 예측 적합성이 검증된 것은 아니다.

## 재생성 및 검증

프로젝트 루트에서:

```bash
.venv/bin/python thoroughbred/research/20260929_dataset_v1/build.py
```

빌더는 기존 출력 경로가 있으면 중단해 스냅샷을 덮어쓰지 않는다. 내용을 수정해 다시 만들 때는 버전과 출력 디렉터리를 새로 정한다. `validation.json`에는 행 수·경주장별 날짜 범위가, `manifest.json`에는 입력 및 결과물 SHA-256이 남는다.

빌드 후 직접 확인한 핵심 정합성 항목: 경주 ID 중복 0, (경주, 말 번호) 중복 0, 출전 결과의 미연결 경주 0, 표준 구간 키 중복 0, 확인된 말의 당일 중복 출전 0. 검증 상세 요약은 `data/dataset_20260929_v1/validation.json`에서 확인한다.
