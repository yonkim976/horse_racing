# DB4 출발심사 보조원천 감사

## 결과 범위

로컬 `data/raw/kra_text/db4` 텍스트 스냅샷을 읽기 전용으로 감사했습니다. 사용자 범위는 2010-01-01부터 2026-09-29까지입니다. 서울 코드 `1`과 API 권역 코드 `3`을 후보로 집계했고, 제주 `2`는 제외했습니다. 로컬 파일에서 코드 `4`는 발견되지 않았습니다. 코드 `3`은 원문 권역 표기만 보존하며 부산과 영천 중 실제 장소를 추론하지 않습니다.

총 3,219개 `.txt` 파일은 모두 CP949로 디코딩되었고 디코딩 오류는 없었습니다. scoped 파일과 후보 행은 다음과 같습니다.

| Meet | 파일 수 | 본문 날짜 범위 | 후보 행 수 |
|---|---:|---|---:|
| 1, Seoul | 1,127 | 2014-10-16–2026-09-11 | 22,097 |
| 3, Yeongnam API 권역 | 1,087 | 2014-10-18–2026-09-12 | 14,709 |
| 합계 | 2,214 | 2014-10-16–2026-09-12 | 36,806 |

따라서 이 원문 스냅샷은 요청된 2010년 시작 범위 전체를 덮지 않습니다. Meet 1/3의 가장 이른 본문 날짜는 2014년입니다. 경로 디렉터리 날짜, 파일명 날짜, 본문 제목 날짜의 불일치 파일은 발견되지 않았습니다.

API21 구조화 원천이 주 분석 원천이고 이 RPT 텍스트는 날짜·권역 범위를 보조 확인하는 자료입니다.

## 형식과 식별자

파일은 CP949 고정폭 표 형식입니다. 제목 줄에는 본문 심사일, 차수, 경주 번호가 있으며 행에는 `마번`, 마명, 심사사유, 판정과 사유 등이 있습니다. 연도·권역에 따라 표 머리글 간격과 일부 열이 다릅니다. 판정·사유는 각 파일의 자체 머리글 위치를 기준으로 읽으며, 위치가 밀리는 행은 오른쪽 열 토큰을 보조 사용합니다. 후보 CSV에는 원문 행 전체와 파일 SHA-256을 함께 넣었습니다.

`마번`은 해당 표의 경주용 번호입니다. 원문에 KRA 공식 말 식별자 열은 없습니다. 따라서 이 보고서는 마명이나 번호를 이용해 연구 코어의 말을 자동 연결하지 않으며, 아래 후보 목록은 API21 범위·표기 대조용입니다. 원문 오기 가능성이 있으므로 행 대 행 대응도 확정 연결로 해석하면 안 됩니다.

판정과 사유는 원문 표기를 정규화하지 않고 집계했습니다. 판정이 비어 있고 사유만 있는 행도 별도로 보존했습니다. 날짜×meet CSV의 `no_local_rpt_file_in_snapshot`은 현재 로컬 스냅샷에서 파일을 찾지 못했다는 뜻이며, 해당 날짜에 심사나 API21 응답이 없었다는 뜻은 아닙니다.

## 산출물

- `source_manifest.json`: 파일별 상대 경로, SHA-256, 바이트 수, 경로/파일명/본문 날짜, 인코딩, 머리글, 행 수와 감사 플래그. 제주 파일도 제외 확인을 위해 manifest에 기록했습니다.
- `file_counts_by_path_year_meet.csv`: 2010–2026년의 경로 연도·meet별 파일 수 및 날짜/본문 요약. Meet 2는 제외 표기와 함께 집계에 남겼고 meet 4도 0행으로 나타냅니다.
- `date_meet_presence.csv`: 요청 기간 전체의 meet 1/3 날짜별 로컬 RPT 파일·후보 행 존재 여부.
- `judgment_reason_counts.csv`: meet 1/3 범위의 원문 판정·사유 조합별 행 수.
- `api21_comparison_candidates.csv`: 36,806개 후보 표 행, 파일·행 출처, 로컬 마번/명 후보, 판정·사유, 원문 행. 공식 말 ID는 항상 `official_horse_id_present=False`입니다.
- `audit_db4.py`: 위 로컬 파일만 읽어 산출물을 만드는 재실행 스크립트. 네트워크와 운영 DB에 접근하지 않습니다.

이 작업에서는 API21 수집물이나 운영 DB를 읽거나 쓰지 않았고 연구 코어와도 이름 연결을 수행하지 않았습니다. API21 원천 수집 에이전트의 입력이 준비되면 날짜, meet, `daySerial`, `trainNo`, `chulNo`, `hrName` 키가 함께 있어 후보 구조 비교가 가능한지만 점검할 수 있습니다. 키 기반 비교의 필요성은 API21 범위 결과와 함께 별도로 판단해야 합니다.

## 후속 API21 보조 대조

API 입력이 준비된 후 `compare_api21.py`로 읽기 전용 대조를 실행했다. API 전체 52,325행 중 로컬 파일 날짜×지역의 36,786행을 RPT 36,806행과 대조했고, 나머지 API 15,539행은 RPT 공백 판정에서 제외했다. 이 대조도 운영 DB 및 연구 DB를 수정하지 않았다.

키가 동일한 단일 행에서 마명 일치 36,576·마명 차이 156건, API의 ID·마명 공백 39건은 같은 키의 RPT 마명 후보가 확인됐다. API 전체 ID·마명 공백은 42행이며 나머지 3행은 로컬 파일 날짜에 포함되지 않는다. RPT 마명으로 ID를 추정하거나 확정 이름을 보충하지 않았다.

키·마명 일치 행의 판정은 원문 값 일치 36,311·차이 265건이다. 차이에는 RPT 판정란이 빈 35건도 있다. RPT 전용 키 30개와 API 전용 키 5개는 출전번호 차이 등의 가능성이 있으므로 실제 누락 판정이 아니다. API가 같은 키로 반복된 경우는 별도 표시한다.

- `api21_comparison_summary.json`: 입력 해시, 비교 범위와 유형별 건수.
- `api21_comparison_mismatches.csv`: 505개 진단 행. 한 출발심사에 여러 진단 유형이 있을 수 있으므로 505건을 고유 심사 오류 수로 해석하지 않는다. 양쪽 출처 절대 경로·SHA-256·페이지/행 또는 원문 줄 번호를 남긴다.

API 우선 기준을 유지한다. 양쪽 표기 차이의 원인은 확정하지 않았다. 이 대조 결과는 API 원문 전수·DB 보존 검증과 별도로 관리한다.
