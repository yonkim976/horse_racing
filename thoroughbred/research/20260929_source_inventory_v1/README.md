# 더러브렛 원천 목록 및 커버리지 조사 v1

> **현재 작업 기준(2026-09-29):** [API 기반 날짜 원장](../20260929_calendar_api_v1/README.md)이 2010-01-01~2026-09-29 경주계획·시행 근거·심사 실행일의 선행 단계다. 이 문서의 기존 구조화 DB 비교 및 숫자는 **2026-09-20까지의 이전 사전조사**이며 새 날짜 원장의 기준 정답이 아니다. 모델 학습·시간순 평가는 2017-01-01 이후 정식 경주부터다.

## 범위와 조사 수준

- 대상은 더러브렛 경주장 서울(meet=1), 부산경남(meet=3), 영천(meet=4)이다. 제주(meet=2)는 제외했다.
- 원천 조사 범위는 각 구조화 원천의 확인된 최초 기록부터 2026-09-20까지였지만, **새 DB의 적재 범위는 2010-01-01부터**다. 모델 학습과 시간순 평가는 `race_date >= 2017-01-01`로 제한하며, 2010~2016년 경주 이력은 과거 피처용이다.
- 주요 구조화 원천 5개를 읽기 전용으로 조사했다. 파일 시스템의 모든 원시 파일 내용·연도·완전성을 검증한 결과는 아니다.

| 주요 구조화 원천 | 경로 | 역할 |
|---|---|---|
| 운영 SQLite | `data/horse_racing.sqlite3` | 현행 경주·출전·결과, 심사, 엔티티, 보조자료 및 관계 스냅샷 |
| Historical unified DuckDB | `data/research/thoroughbred_unified_20260918/thoroughbred_unified.duckdb` | 장기 경주·심사·구간·조교·진료·미확정 이력 스냅샷 |
| 구간 adjudicated SQLite | `data/research/section_point_db_20260925/section_points_adjudicated.sqlite3` | 확정 구간·완주 결과·말별 통과 위치 |
| 연구 스냅샷 v1 DuckDB | `thoroughbred/data/dataset_20260929_v1/thoroughbred.duckdb` | 2010+ 연구 조합본; 최종 코어가 아니며 출처 대조 기준 정답으로 간주하지 않음 |

테이블·키 후보·주요 날짜 컬럼·경마장별 최초/최종일·연도별 행 수는 [inventory.json](inventory.json)에 있다. 자연키별 경주/출전 차이는 [reconciliation.json](reconciliation.json)에 있다. 날짜가 없는 엔티티 원장과 표본 시점이 아닌 정적 기준표는 `rows_on_or_before_target_cutoff=0`이어도 사용불가를 뜻하지 않는다. JSON의 `date_role`과 메모를 함께 읽어야 한다.

원시 파일 계층에는 `data/raw` 아래 **79,383개 파일, 5,594,808,312 bytes**가 있다. 가족별 파일 수·크기·확장자 및 경로명/폴더명 연도 표기는 [raw_source_families.csv](raw_source_families.csv), 후보 DB 파일 목록은 [database_file_catalog.csv](database_file_catalog.csv)에 기록되어 있다. 두 카탈로그는 파일 메타데이터 조사이며 내용·출처·더러브렛 범위·실제 경주/사건일을 검증하지 않았다. 월별 API 캡처 조사 [monthly_api_capture_coverage.csv](monthly_api_capture_coverage.csv)에서는 `horse_training` 폴더 경로의 1990년 시작 표기가 실제 기록 시작을 뜻하지 않음을 확인했다. 첫 비어 있지 않은 월은 서울 1998-09, 부산경남 2004-06이며 출발조교는 양쪽 모두 2009-05부터다. 경로명이나 파일명에서 읽은 연도는 실제 자료 연도로 단정하지 않는다. `catalog_raw.py`, `catalog_database_files.py`, `catalog_monthly_api.py`는 각 카탈로그 생성 코드다.

후보 DB 카탈로그 67개는 `annual_score_profiled` 31개, `table_profiled` 5개, `backup_key_compared` 5개, `synthetic_experiment_excluded` 11개, `jeju_excluded` 11개, `section_predecessor_unreviewed` 2개, `symlink_alias` 2개 상태로 구분했다. 서울·부산경남·영천 연도별 경주 score SQLite와 running-trials score SQLite 31개 파일의 124개 표를 read-only 프로파일링했다. 상세 스키마·날짜·행수·meet 범위·자연키 중복·운영/historical unified 양방향 키 차이는 [supplemental_score_sources.json](supplemental_score_sources.json), 재현 스크립트는 [supplemental_score_sources.py](supplemental_score_sources.py)다. Running-trials DB 안의 제주 meet=2 심사자료 행 60,974개(일정 1,356, 참가 11,863, 구간 47,755)와 점 정의 사전 50행은 대상 집계와 대조에서 제외했다.

2017+ 경주 score 키는 운영 DB와 16,548경주·179,702출전 모두 일치하고, 표 내부와 연도별 파일 간 자연키 중복 및 공유키 공식 말 ID 충돌은 0이다. historical unified와는 서울 score 전용 21경주·229출전 / unified 전용 88경주·2,429출전, 부산경남 9경주·99출전 / unified 전용 31경주·1,244출전, 영천 score 전용 6경주·65출전 차이가 있다. 이 수량 대조로 어느 쪽이 정답인지 판정하지 않는다.

주행심사 score 2017+ 일정 3,792건은 운영 DB와 일치한다. 참가행은 38,359건으로 운영 DB의 38,331건보다 28건 많고, score에만 있는 28건은 서울이다. historical unified 기준 부산경남은 score 전용 4일정·48참가행, unified 전용 3일정·26참가행이다. score 전용 2026-09-17의 48행은 historical unified에서 venue 미확정 source_meet=3으로 남은 참가행과 참가번호·공식 말 ID가 일치한다. 장소는 여전히 미확정이며 source_meet만으로 부산/영천을 지정하지 않는다.

현재 운영 DB와 달리 `after_historical_backfill_20260918.sqlite3` 및 `horse_racing_pre_sync_20260923.sqlite3`는 같은 16경주·180출전 자연키를 추가로 보유한다. 차이는 2026-07-06/07 서울 및 2026-07-06 부산경남 경주이며, 실제 원천·결과 여부는 미판정이다([operational_backup_key_deltas.json](operational_backup_key_deltas.json)).

구간 원천의 전단계 DB인 `data/research/section_point_db_20260925/section_points.sqlite3`와 `data/research/section_point_db_20260925/section_points_verified.sqlite3`는 아직 adjudicated DB와 내용을 대조하지 않았다. 구간키·원문·판정 상태 차이를 확인할 후속 구간정보 판정 대상으로 남긴다. 모든 score/backup 비교는 자연키 설명이며 원천 진실성·완전성이나 출처 우선순위를 확정하지 않는다.

## 1단계 상태와 후속 판정

1단계의 1차 원천 목록·구조·기간·커버리지 조사는 완료했다. 원천 우선순위와 원문 완전성 게이트는 아직 통과하지 않았다. 후속 판정 목록은 2020 휴장 근거와 충돌하는 historical unified/v1 경주 17건, 백업에만 있는 16경주·180출전, 운영 DB에 없는 심사 score 참가행 28건, section predecessor 2개 DB의 내용 차이, 역사 원시 파일의 provenance/실제 날짜와 비더러브렛 행 포함 여부다. score와 historical unified의 자연키 차이도 원문 대조 전까지 미확정으로 보존한다.

## 운영 DB와 스냅샷의 자연키 차이

비교 키는 경주 `(venue, race_date, race_no)`, 출전 `(venue, race_date, race_no, horse_number)`다. 이 비교는 수량·키 차이를 보여 주며 원천의 우선순위나 어느 쪽이 정답인지 결정하지 않는다. 원천 행과 공개시점 증거를 단계적으로 판정해야 한다.

| 기간·비교 | 경주 키 | 출전 키 | 의미 |
|---|---:|---:|---|
| 2000–2009 historical unified | 14,243 | 157,852 | 로컬 장기 스냅샷의 사전 기간 |
| 2000–2009 운영 DB | 14,220 | 157,553 | unified 대비 23경주·299출전 키가 없고, 운영-only 키는 0 |
| 2010+ historical unified | 29,846 | 331,999 | 운영 DB와 비교한 기준 쪽 |
| 2010+ 운영 DB | 29,730 | 327,555 | unified-only 152경주·4,837출전, 운영-only 36경주·393출전 |
| 2010+ dataset v1 | 29,882 | 332,392 | 운영 DB와 비교하면 v1-only 152경주·4,837출전, 운영-only 0; historical+운영 refresh로 만든 연구 산출물 |

공통 출전 자연키에서 official horse ID 불일치 표본은 0건이었다. 이는 후보 차이 키에 대한 완전성·결과상태·출처 진실성 판정을 대체하지 않는다. v1에 없는 pre-2010 행은 v1 키 비교에서 0으로 나타난다.

기존 계획서의 2010+ 원천 사전조사 수치(서울·부산경남·영천 경주 17,341·12,377·12, 완료 17,322·12,376·12, 출전 192,661·134,775·119)는 `2010+ 사전 조사`로 유지한다. 이 숫자와 위의 전체 자연키 비교 모두 최종 적재 정답 수가 아니다.

## 연결·시점 위험과 휴장 근거

- 운영 DB 경주 출전행(2026-09-20 cutoff): 말 ID 미연결은 서울·부산경남·영천 모두 0, 기수 ID 미연결 0, 조교사 ID 미연결은 각각 1·3·0, 마주 ID는 2·3·0이다. 이 값은 운영 DB 범위의 직접 FK 상태다. Historical unified/v1에서 만든 링크 상태와 같다고 가정하지 않는다.
- 운영 주행심사 참가행: 서울 46,466행 중 말 ID 9, 기수 ID 22,603, 조교사 ID 8,254 미연결; 부산경남 29,779행 중 각각 4, 2,513, 191 미연결. 이름 단독으로 연결 확정하지 말고 원문·원천키·상태를 미확정 원장에 남긴다.
- 엔티티 마스터의 말·기수·조교사·마주 값은 공식 ID/name을 기준으로 보존하되, 정적 마스터 행의 `0` cutoff count는 날짜 비해당이다. 인물/말 레코드가 cutoff 이전에 존재·관측됐다고 추론하지 않는다.
- `horse_profile_snapshots.observed_at_ms`는 KST 관측일로 집계했다. 관측일은 프로필 값의 효력일이 아니며 같은 날 경주 전에 관측됐는지는 시각으로 판정해야 한다. 관계 이벤트도 `event_date`, `observed_on`, `stats_as_of`, `observed_at_ms`, 수집 시각을 나눠 둔다.
- 과거 조교·진료 Text/API, 마체중·장구는 사건일과 게시/관측 시각이 다를 수 있다. 시점이 입증되지 않은 과거 사건은 raw/history에는 보존하되 시간순 평가 feature에서는 제외하거나 `availability_unknown`으로 둔다.
- 조교사 `trainer_affiliation_snapshots`, `trainer_historical_regions`, `trainer_person_links`는 운영 DB에 있다. `owner_change` 전용 테이블은 없으므로 출전 당시 `owner_id`·원문 이름과 프로필 스냅샷을 보존하고, 실제 변경 효력일과 관측일을 혼동하지 않는다.
- 운영 races의 현재 상태에는 completed 28,319(서울)+15,528(부산)+12(영천), `void` 80(서울), `special_only_unresolved` 11(부산)이 있다. 마지막 두 상태는 경주 취소/무효와 원천·결과 처리를 판정할 후속 항목이다. 상태를 임의로 정상 경주나 휴장일로 바꾸지 않는다.
- 공식 시행계획에 적힌 부분 휴장 목록 [closures.csv](../20260929_closure_inventory_v1/closures.csv)은 서울·부산경남 50구간(각 25), 운영 DB 대조 경주행 0건이며 검증 결과는 [validation.json](../20260929_closure_inventory_v1/validation.json)에 있다. 다만 2020-02-23~2020-06-18 공식 휴장 구간과 historical unified/v1을 대조하면 2020-02-23 서울 11경주·부산경남 6경주가 두 스냅샷에 남아 있고 운영 DB 및 연도별 score DB에는 없다. 이는 공식 휴장 근거와 충돌하므로 원문·수집경로 판정 전 학습 후보에서 미확정으로 둔다. 위의 50구간 검증은 운영 DB만 0건이며 모든 보유 원천에서 충돌이 없다는 뜻이 아니다. 부분 휴장 목록은 2000년 이후 완전한 달력이 아니므로, 목록에 없는 무경주일을 휴장으로 판정하거나 경주 공백을 계획 휴장으로 추정하지 않는다.

## 재현과 검증

프로젝트 루트에서 실행한다.

```bash
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python thoroughbred/research/20260929_source_inventory_v1/inventory.py
```

재실행으로 이 폴더에서 생성한 JSON만 갱신하려면 `--replace-output`을 붙인다. 입력 5개 DB는 SQLite `mode=ro` 및 `query_only`/DuckDB `read_only=True`로 열었다. 넓은 원천 파일 해시는 계산하지 않았다.

50개 구조화 표 스펙에서 날짜가 있는 표의 연도별 행 수 합은 target cutoff 내 표 행 수와 모두 일치했다. JSON은 source 범위 전체의 최초·최종일과 cutoff 이후 행을 따로 기록한다. 경주·출전 자연키 비교도 기간별로 중복을 제거해 수행했다. 이는 표본 정확도, 파일 전수 계보, 공개시각, 모든 API/Text 원문의 완전성을 증명하지 않는다. 다음 단계에서 차이 키별 원문·결과 상태·공식 키 근거를 확인하고 출처 우선순위를 판정해야 한다.
