# API20_1 주행심사 기수 결측 감사 v1

이 감사는 더러브렛 core DB의 주행심사 참가자 61,777행 중 `api_jkNo`와 `api_jkName`이 모두 비어 있는 5,121행을 원문 API 응답, 보관된 KRA `dacom23` RPT 및 마사회 공식 웹 성적표와 대조한다. 원천 감사 스크립트는 core DB를 읽기 전용으로 열고 API 원문 필드는 수정하지 않는다. 검증된 보조 ID는 코어 DB의 별도 표·뷰에 적재한다.

## 결론

- 5,121행 전부에서 DB의 `source_record_json`이 원본 API 응답 항목과 같고, 원본 JSON에 `jkNo`와 `jkName` 키가 **둘 다 없다**. `null`, 빈 문자열, `-` 값이 들어온 것이 아니라 항목에서 키가 생략됐다. 따라서 이 결측은 현재 정규화 파서가 두 필드를 잃은 문제가 아니다.
- 공공데이터포털의 [한국마사회 주행심사 상세결과 API 설명](https://www.data.go.kr/data/15056974/openapi.do)은 제공자료에 기수명과 기수 고유번호를 포함한다고 설명하지만, 행별 필드 생략 사유나 생략 규칙은 설명하지 않는다. 원문만으로는 KRA 원 시스템에 기수 정보가 등록되지 않았는지, API 추출 과정에서만 누락했는지까지 나눌 수 없다.
- 같은 시행장 질의 코드·날짜·심사차수·마번으로 RPT 기수명이 후보로 연결된 5,097행을 RPT 마명까지 대조했다. API 마명과 RPT 마명이 같은 5,061행, API 말 ID·이름은 비어 있으나 별도 `trial_participants_resolved` 말 연결의 이름이 RPT 마명과 같은 18행을 합쳐 **5,079행을 RPT 기수명 보조 근거로 확인**했다. API 마명과 RPT 마명이 다른 18행은 RPT 이름만으로 연결하지 않았다. 이후 공식 웹 성적표에서 그 18행의 말 ID가 API와 모두 정확히 일치하고 기수 이름·공식 ID도 확인됐다.
- API 말 ID·이름이 모두 비어 있는 18행은 `trial_horse_identity_links`가 모두 RPT 마명과 정확히 일치한다. 이 중 17행은 `crosschecked_operational_rpt`(RPT·운영 결과의 날짜/차수/마번 연결 및 결과 속성 교차 확인), 1행 해피머니는 `user_confirmed_rpt_profile`(사용자 확인)이다. 이 이름은 API 원문 값이 아니라 별도 말 연결 증거에서 온 값이며 원장에 출처와 판정 근거를 분리 기록했다.
- RPT는 기수 이름만 제공하며 공식 기수 ID를 제공하지 않는다. 이름으로 ID를 역추정하지 않았다. RPT 이름이 검증된 **5,079행도 마사회 공식 웹 성적표 3,505개 화면에서 말 ID·마번과 기록 상태를 다시 대조해 기수 ID를 확인**했다. 양수 주파시간 4,420행은 공식 시간도 API와 일치해 완료 심사 기수로, 0초 659행은 공식 시간 0초 또는 공란을 확인해 편성 기수로 구분한다. 기존의 마명 충돌·로컬 RPT 부재 42행도 공식 웹에서 기수 ID를 확인했으며, 그중 완료 16행·편성 26행이다. 따라서 원문 API 기수 ID가 없는 5,121행 전부에 공식 웹 보조 ID가 있다. 원문 API 필드는 계속 비어 있다.
- 이 중 합격이 3,157행이고 `api_rcTime > 0`인 행이 4,436개이므로, 결측을 “기수가 없는 심사”나 “기록 없는 행”으로 해석할 수 없다. RPT가 API 누락행에 기수명을 싣고 있는 경우가 대부분이다.
- 나머지 24행은 **로컬 RPT가 없다는 뜻**이다. 마사회 [공식 주행심사 결과 화면](https://race.kra.co.kr/referee/RacingTrainCheckList.do?Act=06&Sub=7&meet=1)을 각 날짜·심사차수로 직접 조회한 결과, 24행 모두 정확한 마번·말 ID와 함께 기수 이름·공식 ID가 화면에 있다. [별도 웹 재조회 원장](official_web_missing_24.jsonl)과 [요청·원본 해시](official_web_missing_24_manifest.json)에 보존했다. 이 24행의 기록은 API에서 모두 0초이며, 웹 성적표도 `0:00.0` 또는 공란이므로 **실제 기승 완료로 판정하지 않고 편성 기수 정보로만 둔다.**

| 로컬 RPT가 없는 날짜 | 대상 행 | 공식 웹 기록·사유 표시 |
|---|---:|---|
| 서울 2013-01-25 | 13 | `0:00.0`, `기타` |
| 영남 질의 2019-11-30 | 3 | 기록·판정 사유 공란 |
| 서울 2020-12-24 | 5 | `0:00.0`, `검사취소` |

| 서울 2022-01-21 | 2 | 기록·판정 사유 공란 |

공식 화면의 24개 기수 ID는 코어 기준정보의 같은 ID·이름과 전부 일치한다. `trial_participants_entity_reviewed`에 이름·ID를 `official_web_jockey_*_scheduled` 열로 따로 표시한다. API 원문 열과 API 직접 연결을 뜻하는 `jockey_entity_id`는 변경하지 않는다.

## RPT 이름만 있던 5,079행의 공식 기수 ID

[공식 웹 5,079행 원장](official_web_jockey_ids_5079.jsonl)과 [3,505개 화면의 요청·원본 해시](official_web_jockey_ids_5079_manifest.json)를 보존한다. 각 화면은 [재현 스크립트](fetch_official_web_jockey_ids_5079.py)가 날짜·시행장·심사차수로 조회했고, 행마다 마번·공식 말 ID·API와 같은 주파시간을 확인했다. 원장과 원문 캡처를 다시 읽어도 대상 5,079행 전부 정확히 한 번씩 연결되며 조회·대조 오류는 0건이다.

RPT 기수명과 공식 화면의 이름은 4,903행에서 정확히 같다. 차이 176행은 `이쿠`/`이쿠야스` 142행(ID `080426`)과 `정형래`/`정우주` 34행(ID `080588`)이다. 후자 34행의 공식 개별 심사표는 모두 `정우주`와 ID `080588`을 직접 연결한다. 마사회 [2018-08-31 부산 기수 현황](https://race.kra.co.kr/down/pdf/busan/jockey/jk_run_prize_180831.pdf)은 당시 `정형래`를 표시하지만, 두 이름을 같은 ID의 별칭으로 명시한 변경표는 확인하지 못했다. RPT 이름은 역사 원문으로 보존하고 `rpt_historical_name_official_current_name_crosswalk_unconfirmed`로 구분한다.

공식 기수 ID 28종 가운데 `003097`은 기존 서울·부경 API 기준정보에 없었다. 2026-08-27 서울 심사 3행에서 공식 성적표가 `김동규`와 ID `003097`을 직접 연결하고, 프로필 링크의 시행장 코드는 제주 `meet=2`다. [공식 기수 프로필 원문](raw_official_jockey_profile_003097.html)은 제주 소속 김동규·2026-08-03 데뷔를 확인한다. [보조 기수 기준정보](official_jockey_profile_supplement.jsonl)와 [해시](official_jockey_profile_supplement_manifest.json)에 이 한 명을 추가했다. 제주 경주·심사 기록은 더러브렛 DB 범위에 넣지 않았다.

코어 DB의 `trial_jockey_official_web_rpt_5079`은 개별 확인 자료다. `trial_participants_entity_reviewed.jockey_entity_id_with_review`는 API 직접 ID 또는 공식 웹 ID로 61,777행 모두 채워진다. 그중 양수 주파시간 54,502행은 `jockey_id_for_completed_trial`, 0초 7,275행은 `jockey_id_listed_without_completed_time`으로 분리한다. 0초 행의 기수 ID는 실제 기승 완료를 뜻하지 않는다.

## 마명 충돌 18행의 공식 웹 대조

[공식 웹 대조 원장](official_web_name_conflicts_18.jsonl)의 18행은 날짜·시행장·심사차수·마번과 공식 화면의 말 ID가 API 값과 모두 일치한다. 공식 화면의 말 표기명도 API 이름과 같다. RPT 마명은 아래 KRA `db7` 변경 이력 대조를 통해 일부를 역사적 별칭으로 확인했다. 공식 웹 기수명·ID는 18행 모두 확인됐으며, API와 공식 화면의 시간·합격/불합격 또는 출주취소 결과도 일치한다. 양수 주파시간 16행의 기수는 완료 심사 기수로, 장산타이거(2013-03-08)와 슈퍼강타(2014-06-13) 두 행은 출주취소의 **편성 기수**로 기록한다. RPT 기수명 후보 `이쿠`와 공식 웹의 `이쿠야스`가 다른 2행은 공식 표기와 ID `080426`을 따른다.

`trial_jockey_official_web_conflict_18` 및 `trial_participants_entity_reviewed`의 `official_web_jockey_*_conflict_reviewed` 열에서 조회한다. 공식 화면 원본 18개, 요청 양식, 해시는 [매니페스트](official_web_name_conflicts_18_manifest.json)에 있다. 원문 API 말·기수 열과 RPT 후보는 변경하지 않는다.

### RPT 마명 차이의 원인 재검토

KRA Text 자료실의 `db7`(마명변경내역) 원문에서 9개 마명 쌍, 13행의 변경 이력을 확인했다. 아래 변경일은 각 RPT 심사일보다 뒤이므로, 해당 RPT의 마명은 당시 사용된 이름으로 확인된다. 데이터 처리에서는 API 이름을 기준 이름으로 유지하고, 이 RPT 이름은 확인된 과거 별칭으로 해석한다.

[18행 판정 원장](rpt_name_discrepancy_review.jsonl), [원문 URL·SHA-256 매니페스트](rpt_name_discrepancy_review_manifest.json), [재현 스크립트](fetch_official_db7_name_changes.py)를 보존한다. 스크립트는 KRA 공식 `db7` 파일 8개에서 변경 전후 이름과 날짜가 실제로 들어 있는 행을 확인한다.

| 공식 `db7` 원문 파일 | 변경일 | 변경전 → 변경후 | 해당 RPT 행 |
|---|---|---|---:|
| `20150401sdb7.txt` | 2015-03-18 | 더스트롱 → 라이언글로리 | 4 |
| `20151201sdb7.txt` | 2015-11-04 | 퀸즈골드 → 골드마인 | 1 |
| `20161101sdb7.txt` | 2016-10-29 | 원쿨킹 → 내가잘나가; 황금빛로드 → 성웅 | 2 |
| `20170101sdb7.txt` | 2016-12-02 | 회색유령 → 체인지라떼 | 2 |
| `20181101sdb7.txt` | 2018-10-11 | 과천킬러 → 함양산삼 | 1 |
| `20190701sdb7.txt` | 2019-06-26 | 탭댄스엑스프레스 → 천사박 | 1 |
| `20220301bdb7.txt` | 2022-02-10 | 몬스터브룸 → 모신나강 | 1 |
| `20240901bdb7.txt` | 2024-08-09 | 라온포스트 → 렉스여 | 1 |

나머지 5쌍은 RPT가 2012~2014년 자료이고 현재 확인 가능한 `db7` 목록의 시작점(2015-03-01)보다 오래되어 공식 변경 이력을 찾지 못했다: 부산성화랑 → 부산성킹, 장산비카 → 장산흑풍, 장산태풍 → 장산타이거, 쇼크더멍키 → 골드피버, 진명투혼 → 슈퍼강타. 이 다섯 이름은 개명으로 확정하지 않고 미해결로 둔다.

그중 `장산비카`는 2012-08-31·09-07의 서로 다른 RPT 심사에 반복되고, 두 기록의 날짜·마번·주파시간·마체중·조교사로 API의 동일 말 ID `0028842`를 대조했다. `쇼크더멍키`도 2014-01-10·01-24·02-07의 세 RPT 심사에 반복되며 같은 방식으로 API 말 ID `0030595`에 연결된다. 따라서 이 두 이름은 단발성 오타로 보기 어렵지만, 공식 `db7` 변경행이 없어 당시 등록 마명이었다고 확정하지는 않는다. 다른 세 이름은 현재 보관 RPT에서 각각 한 날짜에만 확인됐다.

파서가 다른 행의 이름을 가져온 정황은 없다. 18행 모두 RPT 본문 날짜·차수·마번이 API 이벤트 키와 맞고, 해당 말 이름이 같은 RPT 편성표와 결과표 양쪽에 나타난다. RPT 결과표의 주파시간·마체중·판정/사유와 조교사명은 API와 각각 18/18행 일치한다. 공식 웹에서도 말 ID·이름·시간·판정/사유·조교사명이 18/18행 일치한다. 기수명은 RPT와 공식 웹이 16/18행에서 같고, 나머지 2행은 RPT의 `이쿠`와 공식 표기의 `이쿠야스`(기수 ID `080426`) 차이다. 원 API 기수 필드는 이 감사 대상 18행 모두 생략돼 있어 API와 기수명을 직접 대조할 수 없다.

결측은 특정 연도나 심사 종류 하나에만 모이지 않는다. 연도별로 2010~2026년 전체에 나타나며, 건수 기준 2020년이 605행으로 가장 많다. `api_reason` 기준으로는 `주행미합(신)` 2,998행, `장기휴양(재)` 1,002행, `주행지정(재)` 479행, `연습주행` 308행 등 여러 유형에 퍼져 있다. `api_wgJkAdd` 값도 1,206행에서 0보다 큰 값(1: 739, 2: 461, 3: 6)이므로, 기수 필드 두 개가 빈 것을 곧바로 무기수로 보기는 어렵다. 이 수치는 원인 그 자체를 증명하지는 않는다.

전체 6,199개 세션 중 3,524개에는 기수 결측 참가자가 일부 있고, 2,675개는 결측이 없다. 세션의 모든 참가자가 기수 결측인 경우는 0개다.

## 감사 원장

[trial_jockey_missing_audit.jsonl](trial_jockey_missing_audit.jsonl)은 한 줄에 결측 참가자 한 행을 보존한다. 주요 필드는 다음과 같다.

- `participant_row_id`, 원 API 파일·0부터 시작하는 item index·SHA-256
- `api_raw_jockey_keys_present`와 `api_raw_item_json`: 원문 두 키가 빠졌다는 증거 및 당시 API item
- API의 날짜·질의 meet·심사차수·마번, 말 ID/이름, 판정·사유·기록 원문 값
- `rpt_jockey_name_candidate`, `rpt_horse_name_candidate`: RPT에서 회수한 후보. `rpt_jockey_name`은 말 이름 확인을 통과한 5,079행에만 채우며 API 원문 필드를 변경하지 않는다.
- `rpt_horse_name_validation_status`, `rpt_jockey_supplement_status`: API 마명과 RPT 마명의 정확 일치, 별도 말 연결에 의한 일치, 미해결 불일치, RPT 부재를 구분한다. 마명 불일치 18행은 `rpt_jockey_name`이 비어 있고 후보 필드에만 남는다.
- `resolved_horse_link_evidence`: API 말 이름이 빈 18행에 한해 별도 코어 뷰/연결표, 해소 방식, 검토 근거, RPT 출처를 기록한다. 이 값은 API 원문 마명으로 취급하지 않는다.
- `rpt_matches`: RPT meet·본문 날짜·심사차수·마번 매칭 키, 원문 파일 SHA-256, 실제 줄 번호와 그 줄의 텍스트
- `rpt_resolution_status`, `jockey_id_resolution_status`: RPT만 대조한 단계의 이름 근거와 ID 미해결 상태를 구분한다. 이후 공식 웹 확인 결과는 별도 원장과 코어 검토 뷰에 기록한다.

RPT 결합에는 말 이름을 키로 사용하지 않았다. RPT 본문에 적힌 시행장 코드·날짜·심사차수와 API `chulNo`/RPT 마번으로 연결했다. RPT 원문 파일명이 아니라 본문 날짜를 사용한다. RPT의 각 이름은 해당 줄, 파일 SHA-256, 행 위치로 검토할 수 있다.

## 재현과 검증

저장소 루트에서 실행한다.

```sh
./.venv/bin/python thoroughbred/research/20260930_trial_jockey_gap_audit_v1/build_audit.py
```

빌더는 DB를 `read_only=True`로 열고 다음을 확인한 뒤 JSONL과 manifest를 다시 만든다.

1. 결측 행이 정확히 5,121개이고, 각 API 원문 응답 파일의 SHA-256과 item이 core DB의 보존값과 일치한다.
2. 5,121개 원문 item 모두 `jkNo`·`jkName` 키가 없다.
3. RPT 기수명 후보 5,097개와 RPT 마명이 실제 보관 파일의 본문 매칭 행에 있으며, 파일 SHA-256과 줄 번호를 함께 기록한다.
4. API 마명 정확일치 5,061행, 별도 말 연결로 RPT 마명까지 확인된 18행, 마명 불일치로 제외된 18행을 재분류한다. API 말 ID·이름이 모두 결측인 18행은 17개 교차확인 연결과 1개 사용자 확인 연결로 구분한다.
5. 로컬 RPT 날짜가 없는 24행의 날짜·질의 meet별 수량이 manifest와 일치한다.
6. RPT 이름만으로 공식 기수 ID를 추정한 건은 0건이다. 공식 웹 화면을 별도 조회해 보조 ID를 검증한다.

실행 당시 출력 SHA-256은 manifest에 기록한다. RPT 경로는 보조 근거이며 API20_1의 원문을 대체하지 않는다.

공식 웹 재조회는 저장소 루트에서 `fetch_official_web_missing_24.py`와 `fetch_official_web_name_conflicts_18.py`를 각각 실행한다. 두 스크립트는 공개 마사회 성적표의 고정 호스트에 날짜·시행장·심사차수를 보내고 응답 원본과 SHA-256을 보존한다. 코어 DB 빌더는 저장된 응답과 두 매니페스트의 해시를 검사한다.

같은 방식으로 `fetch_official_web_jockey_ids_5079.py`가 5,079행의 공식 웹 ID를 채운다. 중단 시 압축된 원본 화면을 재사용하며, 새로운 화면을 요청할 때만 KRA에 접속한다. `fetch_official_jockey_profile_supplement.py`는 기존 기준정보에 없던 김동규 기수의 공식 프로필을 검증한다. 코어 DB 빌더는 두 원장, 매니페스트, 3,505개 화면 및 프로필 원본의 해시를 검사한다.
