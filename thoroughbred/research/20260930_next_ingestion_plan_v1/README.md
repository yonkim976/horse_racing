# 코어 DB 다음 적재 순서와 통과조 설계 (2026-09-30)

대상은 서울·부산경남·영천의 2010-01-01~2026-09-29 자료다. 2017년 이후를 학습·시간순 평가에 사용하고 그 이전은 이력 계산에 쓴다. 제주 자료는 이 코어에 넣지 않는다. 현 [코어 DB](../../data/core_api_2010_20260929_v1/thoroughbred_core.duckdb)에는 경주 일정·결과, 주행심사, 말별 구간 시간·통과착순이 있으나 기준 엔티티 전체 연결과 경주 단위 통과조는 아직 없다.

## 권장 순서

1. **말·기수·조교사·마주 기준정보와 연결 근거.** 공식 ID를 기본 키로 적재하고, 경주·심사 원문 ID와 매칭한다. 이름만 일치하는 행은 확정하지 않고 미연결 원장에 둔다. 소속·마주·위탁관계는 현재 값으로 과거를 덮지 않고 효력 기간과 원천을 따로 둔다. 현재 코어의 확정 출전 330,465행은 말·기수 ID가 모두 있으나 조교사·마주 원문 ID가 각각 38행 비어 있다. 주행심사 참가 61,777행의 API 기수 ID는 5,121행 비어 있고 조교사 ID는 전부 있다. ID가 있는 행도 기준 마스터와 실제 연결 여부는 다음 단계에서 확인한다.
2. **경주 단위 통과조.** 말별 `passing_order_raw`와 별개 테이블로 적재한다. 먼저 2010~2016의 API303 응답 가능 범위를 조사하고, 전체 기간을 날짜·경주번호별로 대조한다. 확인된 원천만 단계적으로 코어에 넣고 미확인 기간은 커버리지 원장에 남긴다.
3. **심판 리포트·제재내역.** 기존 API215 보관본은 서울·부산경남 2025년 이후, 영천 2026년 이후다. 2010~2024의 공식 원천을 먼저 찾고 기간 누락을 구분한다.
4. **조교·출발조교·진료, 소유·위탁 변동.** 원문 사건 시각·발행 시각·말/관계자 ID를 함께 저장한다. 예측 시점 이후 공개된 정보가 과거 피처로 들어가지 않도록 시간순 검증한다.

## 통과조 원천과 키

- 우선 원천은 한국마사회 [API303 경마코너별통과순위](https://www.data.go.kr/data/15119851/openapi.do)의 `/API303/corner_rank` **경주 전체 대열 표기**다. 원문 응답을 요청 연도·경마장·페이지·해시와 함께 보관하고 `totalCount`, 페이지 누락, 중복을 검증한다.
- 보관 `dacom11` 경마성적표 RPT는 2015~2024년에 연도별 자료가 있으며 2025년은 없고 2026년은 일부 날짜만 있다. API 값과 경주별로 대조한다. 2015~2016은 RPT 안의 통과조가 서울 2,223/2,223경주, 부산경남 1,620/1,620경주로 경주 키와 모두 맞았다. 이는 **원천 존재 확인**이며 새 코어 적재·검증 완료 수치는 아니다. 특히 서울 2020~2021은 과거 대조에서 API 코너 열의 지점 대응이 성적표와 어긋나 RPT의 **인쇄 지점명**을 우선 검토해야 한다. 2010~2014 RPT는 현재 보관 자료에서 확인되지 않았다.
- 새 코어의 조인 키는 `(실제 경주장, YYYYMMDD, 경주번호)`다. 경주 결과의 `source_meet`만으로 영남 권역과 영천의 실제 경주장을 추정하지 않고 `confirmed_races.actual_venue_label_raw`와 교차 확인한다. 통과조 행의 키는 여기에 `point_code`를 더한다. 공식 마번은 원문 문자열에 나타나는 말 식별자일 뿐, 말 ID가 아니다.
- `notation_raw`에는 괄호, 쉼표, 하이픈, 등호, `^`, `≡`, `·` 등의 기호를 **원형대로** 저장한다. 첫 단계에서는 이를 정렬된 말 ID 배열로 단정해 파싱하지 않는다. 파싱이 필요하면 표기 문법을 별도로 검증한 후 해당 경주의 마번과 연결한다.
- 지점 매핑은 경마장별로 다르다. 서울은 `S1F`, `1C`~`4C`, `G1F`; 부산경남·영천은 `S1F`, `G8F`, `G6F`, `G4F`, `G3F`, `G2F`, `G1F` 중 거리별 실제 표기만 남긴다. 서울에 없는 경주 단위 `G3F` 통과조를 만들지 않는다.

## 제안하는 적재 단위와 검증

1. `passing_group_raw`에 API/RPT 원문 행과 source file, response item index, hash, 추출 시각을 저장한다.
2. `race_passing_groups`에 경주 키·지점·`notation_raw`·선택된 원천·판정 근거를 한 행씩 둔다. 서로 충돌한 원천은 원장에 함께 보존하고 근거 없이 덮어쓰지 않는다.
3. `race_passing_group_coverage`에는 **확정 경주마다 한 행**을 두고 `present`, `source_gap`, `source_conflict`, `no_value_official` 등을 기록한다. 취소·불성립 경주는 `confirmed_races`에 넣지 않으며 빈 표기를 채워 넣지 않는다.
4. 검증은 경주 키·지점 중복 0, 확인된 경주 외 조인 0, 거리별 허용 지점, API 페이지 완전성, 성적표 표본 대조를 포함한다. 마번 목록과 말별 통과착순의 대조는 기호 문법을 검증한 범위에서 수행한다.
5. 모델 피처에는 대상 경주 당일의 결과 통과조를 직접 사용하지 않는다. 과거 경주의 공식 공개시점을 확인하고 시간순으로 누적한다.

기존 [통과 원천 스냅샷](../../data/section_passing_raw_2010plus_20260929_v1/section_passing_raw.duckdb)에는 2017년 이후 서울·부산경남·영천 통과조 80,180행이 있다. 이는 **대조 기준**일 뿐 새 코어의 정답 원천으로 복사하지 않는다. 로컬 API303 JSON은 현재 2010~2016에 없고, 2015~2016에는 위의 RPT가 있다. 2026-09-30에 API303의 2010~2016 서울·부산경남 연도 조회는 모두 성공했고, 각 응답의 반환 행 수가 `totalCount`와 같았다. [예비 건수 원장](api303_pre2017_count_probe.csv)에 API 행 수와 새 코어의 확정 경주 수를 비교해 두었다. **응답 원문·정확한 경주 키는 저장하지 않았으므로 이 원장은 적재 근거가 아니라 재수집·대조 대상**이다. API 행 수가 확정 경주보다 많은 연도는 2010·2011·2016 서울과 2015·2016 부산경남이다. 이를 곧바로 통과조 누락이나 유령 경주로 판정하지 않고 116건 비시행 판정 원장과 키별로 대조해야 한다. 기존 [통과착순·통과조 인수인계](../../../docs/PASSING_RANK_GROUP_HANDOFF_2026-09-26.md)는 지점 대응과 예외의 참고 자료다.
