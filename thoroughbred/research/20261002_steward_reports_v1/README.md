# 심판리포트와 제재내역 적재 및 말별 연결 결과

2026-10-02 마사회 API215 심판리포트와 API180_1 말·기수 제재내역을 연구 코어에 적재했다. 공식 마번으로 해당 말과 관련된 리포트 문단을 조회할 수 있다. 경주 전체 원문, 연결 근거, 미확정 후보도 함께 보존한다.

대상은 2010-01-01~2026-09-29의 서울·부산경남·영천이며 제주를 제외한다. 연구 및 시간순 평가는 2017년 이후 기준을 유지한다. 운영 DB와 서비스는 이번 작업에서 열거나 변경하지 않았다.

후속 [이상 여부 재점검](RECHECK.md)에서 DB 해시·입력38개·원문102페이지와 저장·연결 무결성을 다시 확인했다. 15가지 검사에서 위반은 0건이었으며 원천 표기 불일치와 미확정 연결은 별도로 보존한다.

## 말별 문단 연결 규칙

원문의 출전번호와 인용된 마명을 해당 경주의 공식 출전번호·마명·마번과 대조한다. 이름만 있는 언급은 같은 원문 필드와 대상 경주 안에 유일하고 검증된 번호·마명 근거가 있을 때만 연결한다. 근거는 문서상 앞이나 뒤에 있을 수 있으며 필드·대상 경주·말 ID를 넘어서 재사용하지 않는다. 충돌하면 연결을 보류한다. `[영남]` 같은 마명 앞의 소속 표시는 원문에 보존하며 실제 시행 장소로 해석하지 않는다.

여러 말이 함께 나온 문단은 각 관련 말에 같은 문단을 연결한다. 이 연결은 **해당 문단에 말이 언급되었다는 뜻**이다. 원인 제공, 피해 여부, 제재 대상은 문단 연결만으로 판정하지 않는다. 제재 대상은 별도의 API180_1 공식 ID로 확인한다.

`addJudgement`는 하루의 여러 경주에 동일하게 반복되며 과거 경주에 관한 내용도 있다. 문단 앞에 명시된 날짜·경주번호가 하나이고, 요일과 달력이 일치하며, 대상 경주의 공식 명부가 존재할 때만 해당 경주에 연결한다. 날짜 없음, 복수 대상, 미래 대상, 요일 불일치 등은 미확정으로 보존하며 날짜를 추정 수정하지 않는다. 같은 추가사항의 반복은 말별 이력에서 묶되 모든 원문 관측 위치를 남긴다.

### 확인 가능한 예시

2026-09-20 서울 1경주, 3번 **울트라크라운**(공식 마번 `0061578`)의 조회 결과는 다음 원문 문단이다.

> ③“울트라크라운”은 왼 뒷다리 절음으로 「출전취소」 조치 및 출전신청 전 마체검사 지정.

같은 경주의 나르샤고트에는 히다카의태양과 충돌했다는 문단이 연결된다. 그 문단에는 엠파이어스타와 빅토리라이프도 등장하므로 각 말에서 함께 조회된다. [실제 조회 예시](horse_history_examples.json)에 원문과 공식 마번을 저장했다.

## 주요 조회 구조

연구 DB는 `thoroughbred/data/core_api_2010_20260929_v1/thoroughbred_core.duckdb`다.

| 테이블 또는 뷰 | 용도 |
| --- | --- |
| `horse_steward_history` | 공식 마번별 관련 문단, 대상 경주, 원문 관측 위치, 반복 추가사항 정리 |
| `steward_report_horse_paragraph_history` | 반복을 포함한 말별 연결 전체 원장 |
| `steward_report_observations` | 경주 전체 심판리포트 원문과 출처 |
| `steward_report_horse_mentions` | 연결 성공과 미확정 후보의 원문 위치·검토 상태 |
| `steward_report_horse_link_candidates` | 미확정 후보 목록 |
| `steward_report_event_coverage` | 전체 29,826개 경주 원장 키별 리포트 보유와 공백 |
| `steward_horse_sanctions` | 공식 말 ID에 연결한 제재 대상 원장 |
| `steward_sanction_observations` | 처분 종류·사유·시작일·종료일 등을 담은 제재 원문 |
| `steward_source_year_meet_coverage` | 정상 0행 응답을 포함한 수집 파티션 상태 |

말별 조회 예시는 다음과 같다. 마번의 앞자리 0을 유지한다.

```sql
SELECT horse_id, event_date, actual_meet_code, race_no,
       paragraph_raw, source_report_text_field,
       full_report_observation_locators_json
FROM horse_steward_history
WHERE horse_id = '0061578'
ORDER BY event_date, actual_meet_code, race_no;
```

제재 상세는 `steward_horse_sanctions.sanction_observation_locator`와 `steward_sanction_observations.observation_locator`를 연결한다. 제재 원문의 `reason`에 등장하는 다른 말 번호를 제재 대상 ID로 사용하지 않는다. 공식 ID·출전번호는 일치하지만 마명 표시가 다른 제재 199행도 원문 차이를 보존했다.

## 남은 공백과 이용 시점

확정 시행 29,710경주 중 API215 원문이 없는 경주는 **14,857개**다.

| 기간 | 원문 없는 확정 경주 |
| --- | ---: |
| 2010~2016 | 13,163 |
| 2017 | 1,448 |
| 2020 | 121 |
| 2021 | 125 |
| 2018~2019 및 2022~2026 | 0 |

2010~2016은 정상 0행 API 응답을 보존했다. 2017년 API 첫 원문은 부산 10-13, 서울 10-14다. 공식 홈페이지의 이전 심판리포트 게시판 경로와 2017년 보고서 첨부 목록을 확인했으나, 과거 첨부파일 전량 수집·판독은 이번 적재에 포함하지 않았다. [공식 홈페이지 경로 확인](official_web/README.md)과 [경주별 공백 목록](source/api215_missing_confirmed_race_keys.csv)에 후속 보완 근거를 남겼다. API 공백을 사고 없음이나 리포트가 역사적으로 존재하지 않았다는 뜻으로 처리하지 않는다.

미확정 후보는 대상 경주 문맥 부족 4,580행, 출전번호·마명 불일치 916행, 경주 명부에 없는 인용 마명 257행, 파싱 잔여 228행, 번호 근거 없는 이름 163행, 원문 내부 근거 충돌 12행, 명부에 없는 출전번호 6행이다. 후보 수는 반복 원문을 포함하며 미확정 말 수와 다르다.

과거 리포트의 공개 시각은 미확정이다. 경주일, 제재 효력 시작·종료일, API `etlTime` 문자열, 요청 시각, 수집 시각을 구분했다. 현재 조회한 리포트·제재를 해당 경주의 사전 예측에 사용해서는 안 된다. 2017년 이후 모델을 동결하기 전 정보 이용 시점 검증이 필요하다.

로컬 RPT 처분표의 별도 보완과 주행심사 리포트 범위 검증은 이번 정식 경주 API 적재와 구분한다. 공식 휴장 목록의 역사적 보완, 마주·조교사 관계 변경 및 위탁계약 이력 추적은 기존 계획의 잔여·보류 사항이다. 전체 연구 DB의 최종 동결 완료로 표시하지 않는다.

- [원문 검증](root_source_verification.json): 102개 원문 페이지와 61,439개 JSON 항목, 필드 타입·존재 여부·범위 분리 일치.
- [문단 연결 검증](root_linking_verification.json): 149,008개 연결의 대상 경주·출전번호·공식 마번·마명 및 원문 위치 일치, 원형 숫자 전량 추적.
- [긍정 및 반례 검증](root_parser_control_verification.json): 실제 3경주 40개 수기 기대 연결, 빈 ID·잘못된 번호·복수 대상·요일 불일치·한국어 날짜 표기 확인.
- [적재 전 검증](loader/dry_run_report.json)과 [적재 결과](loader/apply_report.json): 고정한 입력 해시, 백업, 기존 객체 충돌, 전체 원문·연결 규칙 확인.
- [재개방 후 독립 대조](root_loaded_data_verification.json): 원천 테이블 전체 행 일치, 제재 46,562관측 대조 불일치 0건, 말별 이력 출처 조합 불일치 0건, 저장된 모든 신규 테이블·뷰 조회 성공.
- [기존 자료 보존 검증](root_preservation_verification.json): 기존 180객체의 스키마, 테이블 전체 행 내용, 뷰 정의를 대조했다. 원천 명세만 1행 추가됐고 기존 행 손실은 0건이다. DB 명세의 206개 행 수와 최종 DB 해시도 일치했다.
- 적재 전 DB와 명세를 `backups/20261002_before_steward_reports/`에 쌍으로 보관했다. [백업 검증](root_backup_attestation.json)에 기존 DB·명세와 동일한 해시를 기록했다.

수집·연결·적재의 세부 파일은 [원천](source/README.md), [말별 연결](linking/README.md), [적재 코드](loader/README.md)에서 확인할 수 있다. 구현과 원천 검토는 사용자 지정 GPT-6 Luna xhigh 서브에이전트에 맡기고 주 에이전트가 별도 검증 및 최종 적재를 수행했다.
