# API78 미관측 출전행 로컬 원문 검토

점검일: 2026-10-01. 입력은 운영 출전과 공식 말 ID가 연결됐지만 API78 관측시각이 NULL인 원장 104행이다. 운영 SQLite는 `mode=ro`·`query_only`, 코어 DuckDB는 read-only로 열었다. 네트워크를 사용하지 않았고 DB를 변경하지 않았다.

## 판정

- 현재 운영 DB에서 104행 모두 `equipment_card_observed_at_ms`와 `equipment_card_raw`가 NULL이다. `confirmed_runners.horse_id_raw`는 104행 모두 있고, 운영 말 기준표의 KRA 말 ID와 104/104 일치한다.
- 대상은 96개 날짜·경주장 조합이다. 각 조합의 최신 페이지 완전 API78 저장본을 `source_documents`에서 찾아 원문을 읽었다. SHA-256, HTTP 200, 응답 코드, 요청·응답 날짜와 페이지 번호, 전체 `totalCount`, 중복 경주·마번 키를 확인했다. 대상 조합의 최신 문서 96개와 이전 완전 관측 1개, 총 97개 문서가 모두 통과했으며 불완전 배치는 0개다.
- 최신 저장 원문에서 대상 104행은 모두 정확한 경주번호·마번 조합이 없다. 같은 날짜·경주장 카드의 다른 경주·마번에도 정규화된 같은 말 이름이 나타난 대상은 0행이다. 따라서 이 원문에서는 장구 값만 비어 있는 것이 아니라 출전행 자체가 확인되지 않는다. API78 원문은 공식 말 ID 필드를 제공하지 않는다.
- 이전 완전 관측이 추가로 있는 날짜·경주장 조합은 1개다. 그 대상행도 이전·최신 원문 모두 경주·마번 키가 없고 상태 변화가 없었다. 나머지 95개 조합은 저장 완전 관측이 1회씩이다.
- 최신 저장본의 `ingestion_runs.status`는 조합별 `completed` 26개, `partial` 70개다. 이 상태값과 별도로 원문 페이지의 전체성을 검사했고, 96개 모두 페이지 검사에 통과했다. 상태값은 원장에 남겼다.

## 미관측 모집단과 이름 접두어

2017-01-01~2026-09-29 코어 출전 전체를 운영 출전 키와 공식 말 ID로 대조했다. `[부산경남]` 접두어는 서울 meet=1, `[서울]` 접두어는 부산경남 meet=3에서 모두 104개 미관측행을 차지한다. 다만 접두어가 누락을 일으킨 이유라고 이 자료만으로 결론내리지는 않는다.

| meet | 코어 말 이름 접두어 | API78 관측 | API78 미관측 | 운영 출전 없음 |
|---:|---|---:|---:|---:|
| 1 서울 | `[부산경남]` | 726 | 37 | 10 |
| 1 서울 | `[영남]` | 24 | 0 | 0 |
| 1 서울 | 접두어 없음 | 103,855 | 0 | 1,460 |
| 3 부산경남 | `[서울]` | 551 | 67 | 6 |
| 3 부산경남 | 접두어 없음 | 74,312 | 0 | 895 |
| 4 영천 | 접두어 없음 | 119 | 0 | 0 |

미관측 104행의 말별 빈도는 자이언트홀드 29, 쇼트스톱 23, 청춘열차 18, 마이블레이드 11, 환희의별 10, 해란강자 7, 슈퍼철인 5, 금포엔젤 1이다. 연도·meet별 수량과 말 ID는 `report.json`에 있다.

## 재현과 산출물

저장소 루트에서 아래 명령으로 재현한다.

```sh
.venv/bin/python thoroughbred/research/20261001_equipment_unobserved_review_v1/local/audit_unobserved_api78.py
```

- `report.json`: 총계, 연도·meet·말별 분포, 접두어 비교, 읽기 전용·원문 검증 조건.
- `row_ledger.csv`: 104행별 core·운영 말 ID, 현재 관측 NULL, 최신 API78 키 존재 판정, 이전 관측 비교.
- `validated_documents.csv`: 원문 document ID, date·meet·page, batch 상태, 저장 경로와 SHA-256.
- `target_date_meets.json`: 96개 날짜·meet의 최신 페이지 완전 batch와 원문 document ID.
- `audit_unobserved_api78.py`: SQL 입력은 바인딩하며, `local_path`를 `data/raw/` 안으로 제한하고 저장 SHA-256 확인 뒤 JSON을 읽는다. `source_url`이나 요청 파라미터 blob을 선택·출력하지 않는다.

이 로컬 검토는 저장 API78 원문에 행이 있었는지만 판정한다. 원천에서 행이 빠진 배경은 별도 공식 조회와 원천 비교가 필요하다.
