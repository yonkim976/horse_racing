# 출전표 장구 미관측 104행 재점검

> 후속 작업: 사용자 보완 지시에 따라 104행을 연구 코어에 적재하고 독립 검증을 완료했다. [실제 적재·검증 보고서](../20261001_equipment_score_supplement_v1/README.md). 아래 본문과 후보 원장의 미적재 표시는 조사 완료 당시 상태로 보존한다.

점검일: 2026-10-01 (Asia/Seoul). 대상은 새 연구 코어와 운영 출전행의 경주장·날짜·경주번호·마번·공식 말 ID가 일치하지만 운영 API78 관측시각이 없는 104행이다. 서울·부산경남 대상이며 제주를 포함하지 않는다. 서브에이전트는 사용자 지정 `gpt-6-luna xhigh`를 사용했다.

**판정: 104행 모두 API78에서 해당 출전행을 제공하지 않는 사례이며, 공식 성적표의 장구 표시로 104행 전부 보완할 수 있다.** 실제 DB 적재는 하지 않았고 검증된 보완 후보 원장만 작성했다.

## 왜 미관측인가

현재 확인 가능한 원인 범위는 **보존된 API78 응답 및 현재 API78 재조회가 해당 출전행을 제공하지 않는 것**까지다. 페이지 미수집이나 해당 행의 말 ID 연결 실패로 분류할 근거는 없었다. 과거 원문 페이지는 해시·응답 성공 코드·페이지 메타데이터·총 항목 수를 검증했고, 현재 재조회도 96조합 모두 정상 응답의 전체 항목 수를 확인했다.

각 말의 대표 출전 1건씩 **8건의 홈페이지 과거 출전표**를 직접 확인했을 때도 해당 말의 행이 없었다. 반면 공식 성적표는 104행 모두 말 ID·마명·정상 착순을 제공하고 장구 문자열도 있었다. 즉 과거 출전표 조회 계열과 성적표 계열의 보유 행이 다르다. 대표 8건의 출전표 확인을 전체 103경주 홈페이지 출전표 전수 확인이라고 확대하지 않는다.

104행의 결과 원문 마명에는 모두 다른 경주장 소속을 나타내는 `[부산경남]`·`[서울]` 표시가 있다. 다만 같은 지역 표시를 가진 다른 출전 중 API78 관측이 정상 연결된 행도 **1,301행**이므로, 소속 표시 자체를 누락의 원인으로 확정하지 않는다. 8마리의 이적·원정·원천 생성 내부 처리 중 어떤 절차가 영향을 줬는지는 공개 자료로 확인하지 못했다. 원문에서 부재한다는 판정과 내부 발생 원인을 구분한다.

예를 들어 [2017-01-07 서울 12경주 1번 금포엔젤의 공식 성적표](https://race.kra.co.kr/raceScore/ScoretableDetailList.do?Act=04&Sub=1&meet=1&realRcDate=20170107&realRcNo=12)는 말 ID `0029670`, **9착**, 장구 `망사눈, 승인재갈`을 제공한다. 그 출전의 API78 및 현재 홈페이지 과거 출전표에는 해당 말 행이 없다. `승인재갈`처럼 상세 종류가 없는 표시를 임의의 구체 재갈로 확장하지 않는다.

## 보완 방법

성적표에서 확인한 장구 원문을 **별도 출처의 후향 관측**으로 보존하여 연결한다.

- 원천: `KRA_official_score_html`.
- 사건 키: 경주장·날짜·경주번호·마번·공식 말 ID.
- 원문: 당시 경주의 공식 성적표가 현재 제공하는 장구 문자열.
- 관측: 실제 이번 조회 시각, 보존 HTML 경로, SHA-256.
- 정보 이용시점 상태: `retrospective_score_observation_not_verified_pre_race`.
- API78 상태: `row_not_provided_in_requeried_api` 유지.

신규·해제 표시가 있는 7행도 성적표의 명시 표식을 그대로 보존했다. [장구별 보완 후보](score_supplement_tokens.csv)는 부호 없는 163항목·신규 3항목·해제 4항목, 합계 170항목이다. 부호 없는 값은 변경 표시 없음으로 남기고 이전 경주와의 차이만으로 신규·해제를 만들지 않았다. 해제 항목은 보완 원장에 보존하고 출전표 기준 사용 목록을 만들 때 별도 처리한다.

성적표 장구 표시의 신원 연결에 추가 사용자 검토가 필요한 행은 없다. **API78 값으로 직접 채우거나 당시 경주 전 관측으로 소급하여 표시하지 않는다.** 실제 적재는 이번 요청 범위에 포함하지 않았다.

## 2010~2016년 API78 장구 제공 표본

기존 운영 카드 수집의 시작은 2017년이지만 공식 과거 장구 표시가 전혀 2017년부터만 제공되는 것은 아니었다. 실제 시행일 중 연도별 서울·부산 첫 시행일 14조합과 2016년 2월 첫 시행일 2조합을 API78로 확인했다.

- **2010~2015년 각 첫 시행일 및 2016년 1월 첫 시행일:** 출전행은 제공되지만 14개 표본의 `equipCrs`는 모든 행에서 공백이었다.
- **2016-02-13 서울:** 150출전행 중 장구 비공백 104행, 신규/해제 표시가 있는 13행.
- **2016-02-12 부산경남:** 138출전행 중 장구 비공백 123행, 신규/해제 표시가 있는 11행.

마사회 성적표 주석도 신규·해제 표시를 2016년 2월 성적표부터 제공한다고 설명한다. 따라서 2016년 2월 이후의 API78 장구 수집 범위를 추가 검토할 근거가 있다. 이는 **16개 시행일 표본 조사**이며 2010~2016년 전체 날짜를 조회한 결과는 아니다. 표본 공백을 그 시기의 모든 말이 장구를 사용하지 않았다는 뜻으로 해석하지 않는다. 해당 기간의 일반 장구 상세 원문은 API24·RPT 등 원천별로 별도 보완 검토가 필요하다.

## 검증·보존 근거

로컬 조사에서는 대상 96조합의 최신 저장 원문 96개와 이전 중복 관측 1개, 합계 97개를 검증했다. 최신 배치의 DB 상태는 `completed` 26개·`partial` 70개지만 모든 선택 배치는 응답 페이지가 완전했다. DB 배치의 `partial`만 보고 원문 페이지가 빠졌다고 판정하지 않았다. 자세한 내용은 [로컬 조사](local/report.json)와 [행별 원장](local/row_ledger.csv)에 있다.

공식 재조회는 API78 대상 96회·역사 표본 16회·성적표 103회·대표 출전표 7페이지(8개 출전 사례)로, 서로 다른 URL/파라미터별 한 번씩 합계 **222회 순차 요청**했다. 같은 경주의 두 대표 말은 보존 응답을 재사용했다. 요청 사이 1초 간격을 두고 자동 반복 재시도나 병렬 조회를 하지 않았다. HTTP 200 이후에도 API 성공 코드·총 건수·응답 날짜, HTML의 실제 날짜·경주번호·경주장 제목, 말 ID·마명·착순을 검증했다. [공식 재조회 원장](official_checks.json), [주 에이전트 원문 재검증](root_verification.json), [조회 코드](check_official.py), [검증·후보 생성 코드](verify_and_prepare.py).

이번 응답의 수집시각은 원문 파일이 저장된 시각에서 확인한 응답 확보 시각의 상한이며 `retrieved_at_basis=response_file_saved_time_upper_bound_reconstructed`로 표시했다. 요청 시작시각은 별도로 보존했다. 정확한 서버 게시시각이나 당시 경주 전 관측시각으로 해석하지 않는다.

운영 SQLite 및 코어 DuckDB는 읽기 전용으로만 열었다. 원본·운영·연구 DB의 장구 값은 수정하지 않았다. 보완 후보 104행의 적재와 2016년 2월 이후 수집 범위 확대는 다음 작업이다.
