# 미확정 심사 조교사 22행: 말 프로필/통산 기록 대조

2026-10-01. 미확정 심사 조교사 22행의 말 13마리에 대해 저장된 공식 KRA API8_2 프로필 원문, 코어 DuckDB의 확정경주·심사 행, 기존 공식 KRA 심사 결과 페이지 캡처를 대조했다. **말 자체나 통산 경주 이력이 없는 것은 아니다.** 빠진 값은 22개 심사 사건의 조교사 ID·이름이다. 조사에서는 기존 원문을 수정하지 않고 코어 DuckDB를 `read_only=True`로 열었다. 이후 주 에이전트가 별도 오류 처리 원장을 코어에 반영했다.

## 확인 결과

- 고유 말 ID 13개 모두 2026-09-23 공식 API8_2 프로필 스냅샷에 정확한 ID와 말 이름이 있고, 생년월일·성별·산지·혈통 정보도 있다. 캡처 요청범위는 모두 `request_scope=inactive`이며, 각 프로필의 현재 조교사 ID·이름과 마주 ID·이름 값은 `-`다. 이 요청 범위 값만으로 실제 은퇴·활동 상태를 확정하지 않았다. 기존 엔티티 감사에서도 `act_gubun=y/n` 결과가 상호 배타적인 상태 목록으로 작동하지 않는 점을 경고했다.
- API8_2의 통산 출전 수 `rcCntT`는 13마리 합계 356회다. 코어에는 총 359개 출전 원문 행이 있고, 그중 `ord=94/95`인 미출전 행 3개를 빼면 시작한 행이 356개다. 각 말별 `rcCntT`와 코어의 시작 행 수도 13/13 일치한다. 따라서 프로필 자체나 말 ID 연결이 빠졌다는 설명은 저장 자료와 맞지 않는다.
- 22개 심사 행은 API 원문에서 모두 `trNo='-'`, `trName='-'`다. 동일 사건 날짜·심사 차수의 기존 공식 KRA 심사 결과 화면 22개는 날짜/장 헤더와 표가 확인되지만, 해당 마번 행과 정확한 말 ID 행은 모두 0개다. RPT는 18행에서 같은 사건·마번의 조교사 **이름만** 확인하고 ID는 제공하지 않는다. 나머지 4행은 로컬 RPT의 고유한 사건·마번 행이 없다.
- 13마리 전부 다른 날짜의 확정경주 원장에 같은 공식 말 ID로 나타난다. 경주 원장에는 총 359개 출전 행이 보존되어 있다. 일부 ID는 여러 경마장 코드의 경주에 등장하지만, 출전 원문의 동일 말 ID가 직접 일치하므로 `meet_query`를 이력 누락이나 말 ID 오류 근거로 해석하지 않았다.

## 표적 사례

- `0030352` 코지파크: API8_2 프로필에는 `rcCntT=31`, 산지·혈통, 이름·ID가 있다. 코어 확정경주 31행도 같은 ID다. 2014-04-05 영남 2차 4번 및 2014-04-25 영남 1차 2번 심사는 API 조교사 값이 `-/-`이고, 공식 웹 화면에도 각각 해당 마번·말 ID 행이 없다. 두 페이지 원문은 `raw_official_trainer_scores/meet_3_date_20140405_trial_2.html`, `...20140425_trial_1.html`에 보존돼 있다.
- `0031896` 비바플라이: 프로필 `rcCntT=23`, 코어에는 비출발 1행을 포함해 24개 출전 행이 있고 시작 수는 23회다. 대상 심사는 2014-07-12 영남 2차 4번, 2015-10-17 영남 5차 12번, 2015-10-31 영남 4차 11번이다. 세 심사 API 행은 모두 `trNo/trName='-'`이며 공식 웹 캡처에서도 일치 말 행은 0개다. 그 밖의 확정경주 원장에는 같은 ID의 행이 2014-08-22부터 2016-12-24까지 있다.

공식 API 프로필 명세는 [KRA 경주마 상세정보 API8_2](https://www.data.go.kr/data/15058115/openapi.do), 공식 심사 화면 경로는 `https://race.kra.co.kr/referee/RacingTrainCheckScoreTable.do`다. 저장된 심사 화면은 `POST`로 `meet`, `date`, `trno`, `Act=06`, `Sub=7`을 전달한 캡처다. 공식 심사 화면 소스의 말 프로필 이동 코드는 `/racehorse/profileHorseItem.do`에 `hrNo`, `meet`를 전달하지만, 서브에이전트의 웹 도구에서는 프로필 GET이 접근되지 않았다. 이후 주 에이전트가 공식 HTTPS 직접 요청으로 비바플라이(`0031896`, meet=3 및 1)와 환희의별(`0032569`, meet=1)의 마적사항 원문을 확보했다. 세 응답 모두 HTTP 200이고 요청한 말 ID가 폼에 유지되지만 마명·마번·생년월일 등 마적사항 값이 공란이다. 정상 대조용 원더풀삭스(`0053272`, meet=1)는 같은 요청 방식에서 이름·ID·통산전적 등이 채워졌다. 따라서 확인한 두 말의 빈 화면은 GET 도구 실패나 단순 경마장 코드 선택만으로 설명되지 않는다. 직접 확인은 두 말에 한정하며, 13마리 전체의 웹 마적사항을 전수 조회한 것은 아니다. URL·시각·원문 해시는 `targeted_profile_capture.json`, 원문 HTML은 `raw_profiles/`에 남겼다.

## 원인 및 처리

저장 원문으로 확인된 현상은 **해당 심사 사건의 API 조교사 ID·이름이 `-`이고, 사건별 공식 웹 표에도 참가 행이 없어 보완 ID가 없다는 것**이다. 홈페이지 마적사항이 비어 있는 현상과 해당 심사 조교사 결측의 내부 원인이 같다는 근거는 없다. API가 왜 그 사건 조교사 값을 생략했는지는 현재 자료만으로 알 수 없다. 현재 프로필의 `-` 값이나 다른 날짜 경주의 조교사로 과거 심사 조교사를 채울 수 없다.

따라서 사용자 지시에 따라 미확정 22행의 **조교사 ID·이름만** 원인 미상 원천 오류값으로 종료하는 것이 타당하다. 이 판단은 말 ID, 말 프로필, 통산 경주·심사 기록의 오류 또는 무효 판정이 아니다. 원문 심사 말 행과 기존 source/evidence 행은 그대로 보존한다.

## 코어 반영과 검증

사용자가 원인 불명일 경우 오류값으로 넘기도록 지시한 내용을 `user_disposition.json`에 보존했다. `source_error_decisions.csv` 22행은 조교사 ID·이름 두 필드의 처리이며 `cause_status=unknown`, `record_validity=not_determined`다. 심사 행 전체를 허위라고 확정하지 않는다.

코어의 `trial_trainer_source_error_decisions`와 `trial_trainer_errors_closed`에 22행을 적재했고, 현재 검토 뷰에서 `source_error_unknown_cause` / `closed_user_accepted_source_error`로 분류했다. 조교사 ID는 NULL을 유지했다. 기존 `trial_trainer_review`와 과거 미확정 CSV는 최초 검토 이력으로 보존한다. 현재 역할 예외는 비인물 164행·오류 처리 종료 22행이며, `role_link_exceptions_pending`은 0행이다. 이는 검토 대기 종료를 뜻하며 인물 ID 연결 완료를 뜻하지 않는다.

빌더 검증 57개가 모두 통과했다. [주 에이전트 검증](root_verification.json)은 변경 전 백업과 원문·기준정보·관계자 및 장소 뷰 8종의 차이 0건, 심사 검토 뷰에서 처리 분류 2컬럼 외 전부 차이 0건, 정확히 22행의 분류만 변경됨, 조교사 ID NULL 유지와 DB 해시 일치를 확인했다. 앞서 보완한 2026-09-17 부산경남·1,000m 4회차도 유지됐다. 이전 DB는 `thoroughbred/data/core_api_2010_20260929_v1/backups/20261001_before_trial_trainer_error_disposition/`에 보관했다.

gpt-6-luna xhigh 서브에이전트의 [독립 검증](validation_independent.json)도 통과했다. 읽기 전용 대조에서 대상 22개 키 일치, 원문과 관계자 ID 보존, 오류 처리 후 ID 결측 유지, 매니페스트 검증 57개 및 근거 파일 해시 일치를 확인했다.
