# 장구 저장 방식과 운영 DB 차이 — 읽기 전용 점검

점검일: 2026-10-01. 범위: 사건일 2010-01-01~2026-09-29, 서울(1)·부산경남(3)·영천(4). 제주와 2010년 이전 행은 아래 수량에서 제외했다. 새 코어와 이전 연구 DB는 DuckDB read-only, 운영 SQLite는 mode=ro·query_only·읽기 트랜잭션으로 조사했다. 이번 작업은 장구 적재나 원본 수정이 아니다.

## 현재 보관 위치

| DB/위치 | 범위 내 수량 | 내용과 제한 |
|---|---:|---|
| 새 연구 코어 | 장구 전용 열·테이블 **0개** | API4_3 결과 중심 코어이며 장구를 아직 넣지 않음 |
| 이전 연구 `equipment_event` | **329,297행** | 서울·부산 RPT `dacom71` 기반 `detail_raw`와 영천 운영 자료. 장구·진료 혼합 원문. 최신일 2026-09-13 |
| 운영 `entry_equipment` | **329,602행** | 경주장·날짜·경주번호·마번·말 ID, `equipment_raw`, 폐출혈·질환 보조열, 관측시각. **API24 전용이 아니라 과거 연구/RPT 백필과 API24 수집이 공존하는 혼합 표** |
| 운영 `race_entries.equipment` | 비공백 **32,325행** | API156 `pthrEquip`과 API24 보완이 같은 열에 쓰임. 이 열만 복사하면 공백이 매우 많음 |
| 운영 `race_entries.equipment_card_raw` | 관측시각이 있는 **179,599행** | API78 `equipCrs` 원문. 사건일 2017-01-06~2026-09-20. 이 중 **16,114행은 공백만 있는 관측값** |
| 운영 `entry_equipment_changes` | **37,312행** | API78 원문 토큰에 직접 적힌 `+`→added **24,709**, `-`→removed **12,603**. 순서(position)·관측시각 보존 |

`entry_equipment`의 사건 범위는 서울 2010-01-09~2026-09-20, 부산경남 2010-01-08~2026-09-18, 영천 2026-09-13~20이다. 원문의 비공백 수가 곧 장구 사용을 정상 추출한 수라는 뜻은 아니다. 운영 표의 `equipment_raw`에는 실제로 날짜·진료 문장만 있는 값도 존재한다.

독립 집계에서 이 표의 2010~2014년은 105,884행, 2015~2024년은 190,687행, 2025~2026년은 33,031행이다. 앞의 두 기간에는 각각 98,574행·182,860행이 날짜 형식의 문구를 포함하며 각 기간에 관측시각 값이 하나뿐이다. 이는 혼합·일괄 이관 상태의 진단이며 정규식만으로 행별 출처나 진료 여부를 확정한 결과가 아니다. 이 표에는 행별 `source_document` 외래키가 없어 모든 값의 원천을 바로 역추적할 수 없다.

## 같은 출전행 기준 대조

새 코어의 유효 시행 경주 출전행 **330,465행**을 기준으로 경주장·날짜·경주번호·마번이 일치하고 **공식 말 ID도 같은 경우만** 연결했다. 이름만으로 합치지 않았다.

| 운영 자료 | 새 코어에 동일 말 ID로 연결되는 행 |
|---|---:|
| 운영 출전행 | 327,309 |
| 혼합 `entry_equipment` 원문 이벤트 | **328,259** |
| API78 장구 관측 출전행 | **179,587** |
| API78 `+/-` 표시 | **37,311** |

동일 경주장·날짜·경주번호·마번의 말 ID 충돌은 운영 출전과 `entry_equipment` 모두 **0건**이다. 다만 이는 연결 검증이며, 혼합 원문을 장구 목록으로 정제·검증했다는 뜻이 아니다. 운영 전체 범위 수와 코어 연결 수는 기준 모집단이 다르다. 유효 시행 경주 밖의 자료를 수량 차이만으로 삭제하지 않는다.

코어 출전행 중 운영 `entry_equipment` 이벤트가 없는 **2,206행**은 [별도 원장](core_missing_equipment_event.csv)에 남겼다. 이는 운영 보유 이벤트와의 차이이며 공식 API에도 장구가 없다는 판정이 아니다. 운영 출전행과 연결된 2017년 이후 행 중 API78 관측이 없는 **104행**도 [별도 원장](matched_operational_api78_missing_2017plus.csv)에 남겼다. 104행을 장구 없음이나 변경 없음으로 채우지 않는다. 기존 9월 30일 독립 감사는 이 104행의 공식 성적표에 장구 문자열이 있음을 기록했으나 이번에는 웹 재조회나 보완을 수행하지 않았다.

## 실제 값이 다른 예

**2022-09-04 서울 7경주 8번 컴퓨터패치, 말 ID `0052153`**:

| 보관 위치 | 값 |
|---|---|
| `race_entries.equipment` | NULL |
| `entry_equipment.equipment_raw` | `계란형큰고리재갈` |
| API78 `equipment_card_raw` | `계란형큰+,양털뺨+,혀끈+` |

같은 출전행에서도 약칭·상세 원문·변경 표시와 보관 범위가 다르다. 문자열 차이를 바로 오기입으로 확정하거나 서로 덮어쓰면 안 된다. 약칭 대응과 원문의 장구 누락은 별도 검토해야 한다.

**같은 날 서울 5경주 12번 캠프세이버, 말 ID `0044154`**의 운영 `equipment_raw`에는 `망사눈가면`, `계란형큰고리재갈`과 날짜가 붙은 진료 문장이 함께 있다. API78에는 `계란형큰,망사눈+`가 별도로 보존돼 있다. 혼합 원문을 쉼표만으로 분해해 장구 목록으로 만들 수 없는 사례다. 비교 원문 일부는 [대조 결과 JSON](comparison.json)에 보존한다.

## 코드에서 확인한 원천 차이

- `src/horse_racing/parsers/race_supplemental.py`: API24 `toolName`→`equipment_raw`, `bleedingCnt`→폐출혈 수, `illName`→질환 문구.
- `src/horse_racing/services/race_supplemental.py`: API24 값을 별도 표에 upsert하고, 장구 문자열이 있을 때 운영 출전의 `equipment`도 보완한다.
- `src/horse_racing/services/race_day.py`: API156 결과의 `pthrEquip`을 같은 `race_entries.equipment`에 대입한다. 따라서 현재 공란의 원인을 코드만으로 모든 행에서 확정할 수 없다.
- `scripts/backfill_operational_history.py`: 과거 연구 `equipment_event.detail_raw`를 집계하고 `clip(...,200)`해 운영 `entry_equipment.equipment_raw`로 옮기는 경로가 있다. 혼합 원문 적재와 일부 길이 제한을 확인했다. 현재 표의 모든 과거 행에 정확한 원천을 역으로 부여한 것은 아니다.
- `src/horse_racing/services/gate_entry_sheet.py`: API78 원문·관측시각과 명시 `+/-`만 분해한 변경 표를 저장한다. 새 관측으로 출전별 현재값·변경 표를 갱신하며, 과거 응답은 `source_documents`와 로컬 원문으로 별도 보존한다.

이전 연구 스냅샷의 상세 원천·의료 혼합 특성은 [이전 연구 조사](legacy/README.md), 운영 스키마와 입력 코드·현재값의 상세 대조는 [운영 조사](operational/README.md)에 있다. 서브에이전트는 사용자 지정 `gpt-6-luna`, `xhigh`를 사용했고, 주 에이전트가 강한 키와 행 수를 독립 대조했다.

## 새 코어 적재 방향

1. **사용현황 원문과 원천 관측:** API24·API78·API156·RPT의 원문, 사건 키, 수집시각·원문 해시·출처를 각각 보존한다. 운영 혼합 문자열을 API24 원문으로 둔갑시키지 않는다. 저장된 API 원문을 우선 재사용하고 제공 범위·공백을 확인한다.
2. **장구별 사용 정보:** 공식 원문에서 장구를 분리하고 약칭 대응을 검증한 뒤 별도 구조로 연결한다. 진료·폐출혈은 장구 이름에서 분리한다. 빈 문자열·미관측·파싱 실패를 구분한다.
3. **명시 변경 표시:** API78 `+/-` 표시를 별도로 보존한다. 앞뒤 경주의 장구 문자열 차이만으로 공식 신규·해제 사건을 만들지 않는다.

과거 API78의 2026년 소급 조회시각은 과거 경주 전 관측시각이 아니다. 후향적 공식 최종 표시와 당시 예측에 이용 가능했던 관측을 구분해야 한다. 과거 장구 목록의 게시시점·초기 출전표 상태 확인은 후속 검증이다.
