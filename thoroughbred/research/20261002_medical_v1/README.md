# 연구 DB 진료 기록 적재 · 2026-10-02

## 범위와 상태

- 사용자 승인에 따라 진료 원천을 수집·검증하고 연구 코어에 추가한다.
- 진료일 2010-01-01~2026-09-29, 서울(meet=1)·영남(meet=3). 제주 진료 이벤트는 제외한다.
- 연구 코어에 원문·사전·설명 출처 적재를 완료했고, 주 에이전트의 독립 검증을 모두 통과했다. 진료 이력 전체의 완전성이나 모든 말의 연결 완료를 뜻하지 않는다.
- 연구·모델 개발은 2017년 이후이며, 진료일과 해당 정보의 실제 공개일은 서로 다른 항목이다.
- 운영 DB·운영 서비스는 조회하거나 수정하지 않는다. 기존 연구 검토표와 보존된 공식 원문을 재사용한다.

## 저장 원칙

1. API16 원문 항목과 페이지·행 번호·해시·수집 시각을 보존한다. 진단명 두 칸의 원문을 따로 저장한다.
2. 공식 Text `dacom72` 원문 행·파일·줄번호·해시를 보존한다. 숫자 칸은 소속조로 관리하며 진단 슬롯 번호로 해석하지 않는다.
3. 주간 Text 파일의 반복 관측은 원장에 전부 남긴다. 같은 내용의 기록 후보를 묶은 수치는 실제 진료 횟수의 확정값이 아니다.
4. 공식 마번은 출처에 실제 존재하는 값만 사용한다. Text에 마번이 없으면 이름만으로 연결하지 않는다. 교차 원천 후보는 확정 ID와 분리한다.
5. API에서 응답이 정상적으로 끝났어도 전 기간 진료 기록의 완전성을 뜻하지 않는다. API 0건과 진료 없음은 구분한다.
6. API33 질병명 사전과 KRA 화면에서 얻은 설명은 별도 원천으로 관리한다. 현재 수집된 API33 설명은 모두 `-`다.
7. 기존 용어 검토표의 내부 운영 ID는 옮기지 않는다. 정확한 원문 문구와 해시로 대응하며, 문맥에 의존한 판정은 조건을 충족하기 전에는 일반 규칙으로 적용하지 않는다.
8. 질병명 대응에서 제외된 표현도 진료 원문에서는 삭제하지 않는다. 설명이 없으면 결측으로 남긴다.
9. 과거 경기 전 공개 시점은 아직 검증되지 않았다. 본 적재만으로 예측 시점 사용 가능 판정을 내리지 않는다.

## 주 에이전트의 원문 사전 검증

[`root_text_inventory.json`](root_text_inventory.json)에서 전체 대상 Text 파일을 독립적으로 읽었다.

- 대상 파일 3,377개, 범위 내 날짜가 있는 원문 1,619,071행, 범위 밖 32행.
- 날짜 오류 0행, CP949 문자 해독 대체 문자 0개, 날짜 없는 비어 있지 않은 행 0행.
- 마명 공백은 서울 2011-07-10·2011-07-31 각 1행이다. 원문과 결측을 보존한다.
- 본문 진료일과 파일 기준일은 다를 수 있다. 주간 자료의 정상적인 과거 날짜를 파일 오류로 처리하지 않는다.

## 검증 산출물

- `source/`: API 수집과 Text 원장, 원천 커버리지, API/Text 대조.
- `dictionary/`: API33 사전 원문·파생 사전, 기존 문구 판정·구성요소, 설명 출처.
- `loader/`: 입력 계약과 읽기 전용 사전 검증, 코어 추가 로더.
- `root_preservation_verify.py`: 기존 코어의 모든 객체·내용·명세 보존을 독립 검증한다.

- API meet=3은 영남 구분이다. 개별 진료의 부산경남·영천 실제 장소를 임의로 나누지 않는다. `meet_raw`를 보존한다.
- 범위 밖 원문은 제외 원장에 보존한다. 임상 이벤트에는 제주를 포함하지 않는다. 질병 설명의 출처에 제주 화면이 있더라도 이는 사전 설명의 출처이며 제주 진료 이벤트 적재가 아니다.
- 코어는 기존 109객체에 **25개 테이블·19개 뷰**를 추가해 153객체가 됐다. `source_manifests`에는 `medical_research_v1` 1행만 추가했다(24→25).

## 파싱 교정

전체 Text 행은 CP949 기준 145바이트 고정 폭이었다. 공백으로 나누던 과거 방식은 `스마일 동물`, `에이펙스 홀` 같은 병원명의 뒷부분을 진료명에 섞거나 마명 공백 행을 놓칠 수 있었다.

- 날짜 `[0:10]`, 마명 `[11:29]`, 소속조 `[29:31]`, 병원 `[32:44]`, 진료명 `[45:]`의 바이트 위치로 분리했다. 진료명은 하나의 전체 원문이며 쉼표로 나누지 않는다.
- 종전 공백 파싱과 다른 **272,079행**은 `medical_dacom72_layout_reconciliation`에 두 파싱 결과와 근거를 보존했다. 원문 파일은 변경하지 않았다.
- 앞선 검토의 ‘병원명 일부 접두어를 API가 생략한다’는 설명은 이 파싱 문제를 다시 고려해야 한다. 종전 파서에 의존한 접두어 판정 356개는 감사 자료로 남기고 일반 연결에서 차단했다.

## 말 연결과 용어·설명

| 원천 | 공식 ID로 코어 말과 연결 | 원천 ID는 있으나 코어 말 없음 | 원천에 공식 ID 없음 |
| --- | ---: | ---: | ---: |
| 이번 API16 | 238,344 | 5,067 (416개 ID) | 0 |
| 보존 API16 | 228,615 | 9,976 (402개 ID) | 0 |
| Text | 0 | 0 | 1,619,071 |

미연결 API 마번은 원문 값으로 보존한다. 코어 말 기준정보에 없다는 사실만으로 오류 마번으로 판정하지 않는다. Text/API 비교의 이름·날짜·병원·진료명 일치는 후보 근거이며, 말 ID 확정으로 사용하지 않았다.

- API33 원문 3,523행, 정확한 사전 튜플 3,511행(한국어 제목 3,500개)을 보존했다. 영어명 이형을 임의로 하나로 합치지 않았다. API33 `illDesc`는 모두 `-`다.
- 기존 문구 판정 5,397개·구성요소 9,113개, 설명 원천 관측 145개·정확한 설명 튜플 119개를 추가했다. 설명 원문·URL·파일 해시·수집 시각을 보존했다.
- 문구 5,028개만 확인된 비문맥 의존 대응으로 조회할 수 있다. 사건별 근거가 필요한 8개와 과거 파서 의존 356개, 제외 표현 5개를 구분한다. 이를 새로운 질병 진단으로 해석하지 않는다.
- 이번 API의 진료명 두 슬롯 486,822개 중 `-` 등 미기재 266,411개, 검토된 정확한 원문 대응 220,237개, 검토표에 없는 **18표현·174슬롯**이다. 미기재와 미대응 표현을 구분한다.
- Text 전체 진료명은 9,164표현이다. 정확한 검토 대응 3,590표현·1,598,981관측, 문맥 보류 3표현·482관측, 제외 5표현·141관측, 검토표에 없는 **5,566표현·19,467관측**이다. 복합 표현을 임의로 쪼개지 않았다. 제외·보류·미대응 원문은 모두 남아 있다.
- 설명이 연결된 이번 API 슬롯은 156,390개다. 설명 출처와 대응 구성요소가 여러 개면 조회 행 수가 늘어나므로 설명 뷰의 행 수를 진료 건수로 사용하지 않는다.

## 조회 안내

- `medical_observations`: 세 원천의 원문 관측 원장. 출처별 중복과 이형을 보존한다.
- `medical_current_api_records`: 이번 연간 API 조회와 공식 말 ID 연결 결과. 기본 API 조회에는 이 뷰를 사용한다.
- `medical_entity_links`, `medical_link_exceptions`: 공식 ID 연결과 미연결 원장.
- `medical_api16_archived_candidates`, `medical_text_record_candidates`, `medical_union_candidates`: 과거 수집 근거·Text 보완 후보. 확정 진료 이벤트의 통합 뷰가 아니다.
- `medical_raw_diagnosis_slots`: API의 두 칸과 Text의 전체 문구를 구분한다.
- `medical_observed_diagnosis_components`, `medical_observed_diagnosis_explanations`: 안전 조건을 충족한 기존 문구 판정과 실제 설명 출처. 원문 사건과 별도인 일대다 조회다.
- `medical_api16_current_phrase_review`, `medical_text_phrase_review`: 대응·보류·제외·미대응 상태.
- `medical_api_comparison_ledger`, `medical_source_year_meet_coverage`: 원천 차이와 연도별 보유 범위.

## 주 에이전트 최종 검증

1. [원문→입력 전수 대조](root_input_verification.json): 2,101,073행의 JSON 항목·Text 행·필드·행번호·원문 파일 해시를 확인했다. Text 파일 수집 시각은 경로와 전체 해시가 일치하는 기존 다운로드 manifest에서 확인했다.
2. [사전 독립 검증](root_dictionary_verification.json): API33 원문, 판정·구성요소 순서, 설명 출처, 파서 접두어 규칙 차단을 확인했다.
3. [입력→DB 독립 검증](root_core_input_verification.json): 21개 원문·파생·사전 테이블의 스키마와 전체 행 해시를 양방향 대조했다. 추가·누락 차이 0건이며 메타데이터 JSON 7개도 원본과 일치한다. 이름만의 말 연결, 보류 규칙 적용, 근거 없는 과거 공개 시각은 0건이다.
4. [기존 코어 보존 검증](root_preservation_verification.json): 기존 109개 객체 중 원천 manifest를 제외한 테이블은 전체 행·스키마, 뷰는 정의·스키마를 대조했다. 기존 manifest 24행과 명세의 기존 입력·보완 이력을 보존했다. 등록된 객체 151개의 실제 행 수와 DB SHA도 명세와 일치한다.
5. [적재 보고서](loader/apply_report.json): 트랜잭션 적재와 명세 갱신을 완료했다. DB SHA-256은 `c30202a65a1a82c2927efc8e0ef150c03a0c9950e953ee445beb1b3a7f8c2de6`이다.

적재 직전 DB·명세 쌍은 `thoroughbred/data/core_api_2010_20260929_v1/backups/20261002_before_medical/`에 보존했고, 두 파일의 해시는 [백업 확인서](root_backup_attestation.json)에 남겼다. 서브에이전트는 GPT-6 Luna xhigh로 원천·사전·로더를 담당했고, 주 에이전트가 적용과 독립 검증을 수행했다.

## 남은 검토

- Text 말 ID의 직접 근거 확보와 API 미연결 마번의 기준정보 보완.
- 신규 복합 진료명 및 문맥 보류 표현 검토. 병원명 고정 폭 절단 때문에 API/Text 병원명이 정확히 일치하지 않을 수 있어 비교 불일치를 오류로 확정하지 않는다.
- 역사적 진료 이력의 완전성, 실제 게시 시각, 모델의 경기 전 이용 가능 시점. 수집 시각을 과거 게시 시각으로 대체하지 않는다.
- 연구 DB 전체에서 경주 단위 통과조와 심판 리포트·제재 내역은 별도 미적재 단계로 남아 있다.
