> 2026-10-15 사용자 승인으로 [일별조교 기승자 이름 연결](../20261015_daily_training_rider_links_v1/README.md)을 적재했다. `daily_training_rider_linked`에서1,599,487행의 이름을 조회하며 송당스카이 충돌1행은미확정, 번호 미연결70개·190,375행은별도 원장으로 관리한다. 기존 원문·객체의 전체 행·스키마·뷰 정의 보존을 독립 검증했다. 현재 코어213객체·원천manifest28행이다.

> 2026-10-15 [일별조교 기승자 번호·이름 연결 검토](../20261015_daily_training_rider_identity_review_v1/README.md)를 완료했다. 공식 설명상 `prNo`는 기승자 사번이며, 보유 기수 프로필과282개 번호·1,599,488행이 직접 일치해 이름 후보를 연결할 수 있다. 홈페이지2026-09-28 서울·영남1,248행도 직접 조회했다. 이름 충돌1건과 번호 미대응·미기재를 보존하며 DB의 이름 연결은 아직 추가하지 않았다. 아래는 최초 원문 적재 당시 기록이다.

## 범위와 결과

사용자 지시에 따라 일상조교(API18_1), 출발조교(API22_1), 수영조교(API216)를 연구 코어 DB에 추가했다. 언덕훈련은 제외했다. 사건일 범위는 **2010-01-01~2026-09-29**이며 모델 연구·평가는 기존 합의대로 2017년 이후다.

마사회 API meet=1 서울, meet=3 영남 자료를 사용했다. 제주 meet=2는 제외했다. API18_1 안내상 영남은 부산경남·영천 통합 지역이므로, 원문에 실제 장소가 구분되지 않은 조교를 임의로 두 경주장에 나누지 않았다.

| 자료 | 서울 | 영남 | 합계 | 기존 말 기준정보와 공식 마번 일치 | 공식 마번은 있으나 기준정보 미연결 |
|---|---:|---:|---:|---:|---:|
| 일상조교 | 2,763,930 | 2,409,103 | 5,173,033 | 5,139,741 | 33,292 |
| 출발조교 | 216,252 | 215,265 | 431,517 | 426,332 | 5,185 |
| 수영조교 | 288,119 | 171,485 | 459,604 | 456,662 | 2,942 |
| 합계 | 3,268,301 | 2,795,853 | **6,064,154** | **6,022,735** | **41,419** |

마번 자체가 없는 행은 0건이다. 미연결 행도 공식 마번과 원문을 보존했다. 이름으로 다른 말에 연결하지 않았다. 종류별 미연결 공식 마번은 일상조교 1,064개, 출발조교 932개, 수영조교 235개이며 자료군 간 중복이 있어 합산한 고유 말 수가 아니다. 조교만 관측된 말 등은 후속 말 기준정보 보완 대상이며 미연결만으로 오류 판정하지 않는다.

## 수집 공백과 출처

날짜×지역×조교 종류 **36,696칸**을 확인했다. 조회 원문 부재·불완전 응답은 0칸이다.

| 자료 | 행이 있는 완전 응답 날짜·지역 | 정상 0행 응답 날짜·지역 | 누락·불완전 |
|---|---:|---:|---:|
| 일상조교 | 10,211 | 2,021 | 0 |
| 출발조교 | 5,688 | 6,544 | 0 |
| 수영조교 | 5,691 | 6,541 | 0 |

정상 0행은 해당 API 응답에 기록이 없다는 뜻이다. 실제 조교가 없었다는 별도 판정은 하지 않는다. 과거 월별 API 파일, 운영 원장에 등록된 일별·연별 API 원문, 이번에 새로 조회한 2026년 9월 월별 API18_1/API22_1 응답을 대조해 날짜·지역별 최신 완전 응답을 선택했다. 월·연 응답에 들어 있는 9월 30일 이후 행은 적재 범위에서 제외했다.

각 행은 원문 파일 경로·SHA-256·페이지·1부터 시작하는 행 번호·수집 묶음 ID·수집 시각 근거로 추적된다. 과거 파일의 다운로드 원장 시각과 실제 HTTP 수신 시각을 구분했다. 시각 열은 UTC 기준이며 원래 시각과 근거도 원장에 보존했다. 수집 파일 원장에는 최신 선택 파일과 이전 파일 메타데이터 4,884행을 남겼다.

## 원문 이상값과 운영 DB 차이

- **일상조교:** 음수 시간 8행, 0초 11행, 종료가 시작보다 이른 기록 9행, 원문 시간차와 `trTerm` 불일치 337행을 그대로 보존했다. 같은 말·날짜·시작·종료 키의 서로 다른 원문 8그룹·16행도 유지했다. 각 항목은 중복될 수 있으며 시간·키 검토 대상은 총 371행이다.
- **출발조교:** 선택된 API 원문에는 같은 말·지역·날짜의 반복 키가 없었다. 운영 DB에는 44개 키에 추가 행이 각각 1행씩 있다. 원문에는 운영에 없는 키 1개가 있어 운영보다 순수 43행 적다. 이 차이를 근거 없이 별도 훈련 회차로 추가하지 않고 [키 차이 원장](start_swim/start_training_operational_difference_ledger.csv)에 남겼다. 운영의 기승자 이름 정규화 결과와 원문 문자열의 단순 차이를 오류로 판정하지 않았다.
- **수영조교:** 동일 원문 반복 8그룹·24행을 유지했다. 한 행씩으로 줄인 집계보다 16행 많다. 0값 3행과 20 이상 33행도 유지했다. `cnt`를 분·거리·바퀴 등으로 일괄 변환하지 않았다. 반복 원문을 훈련량에 그대로 합산하지 않도록 후속 집계 규칙이 필요하다.
- 일상조교는 운영보다 15행 많다: 같은 키의 원문 이형 보존분 +8행, 원문에만 있는 키 +8개, 운영에만 있는 키 -1개다. [집계 비교](daily/row_count_comparison.md)와 [9개 차이 키 원장](daily/row_count_difference_key_ledger.json)을 보존했다.

API22의 순번은 익명 저장 순번이며 실제 훈련 ID·시각·횟수 확정 근거가 아니다. 일상조교의 `prNo` 역시 기수 공식 ID로 임의 연결하지 않았다. 수영조교의 `horsepart`·`trpart`는 별도 원문 값으로 유지했다.

## 코어 DB에 추가한 항목

DB: `thoroughbred/data/core_api_2010_20260929_v1/thoroughbred_core.duckdb`

- 테이블: `training_raw_observations`, `training_capture_coverage`, `training_source_files`
- 조회 뷰: `daily_training_raw`, `start_training_raw`, `swim_training_raw`
- 검토 뷰: `training_observation_qa`, `training_date_coverage`, `training_source_entities`

기존 경주·심사·장구·엔티티 테이블과 뷰 91개의 내용·구조는 동일하다. 출처 원장에 1건을 추가해 총 23건이며 DB 객체는 92개에서 101개로 늘었다. 기존 코어 상태 `staged_core_not_frozen`은 유지했다.

모든 조교 행은 후향 관측 상태이며 **당시 경주 전에 공개됐다는 검증은 아직 하지 않았다.** 사건일과 수집일을 구분했고 현재 홈페이지의 14시 갱신 관행을 과거 전체에 소급하지 않았다. 2017년 이후 모델에 실제로 투입하기 전에는 경기 당일 정보 이용 시점과 반복행 집계 규칙을 검증해야 한다.

## 검증과 복구 기록

GPT-6 Luna xhigh 서브에이전트들이 원문 복원·적재기를 작성했고 주 에이전트가 적용과 독립 검증을 수행했다.

- [적재 전 검증](loader/pre_apply_dry_run_report.json): 6,064,154개 고유 관측 ID, JSON 오류·마번 누락·조회 공백 0건.
- [적재 결과 및 해시](loader/load_manifest.json): DB와 명세를 함께 백업하고 새 객체만 추가했다.
- [주 에이전트 독립 검증](root_verification.json): 원문 전수 대조, 기존 91객체 보존, 적재값과 입력의 행 전체 SHA-256 양방향 비교, 모든 등록 파일 해시·선택 페이지 수량, 날짜별 수량·출처 연결, 기존 명세·파일 해시 등 13항목 통과.
- [읽기 전용 재실행 검증](loader/root_bounded_replay_report.json): 원문 입력을 뷰로 읽어 적재기의 전체 검증을 다시 수행했고, 등록된 출처 명세·코드 해시가 동일했다. 원문의 19열과 상태 3열을 포함한 전체 행 해시 양방향 차이는 0행, 수집 원장과 날짜 원장 차이는 0행이며 검증 전후 DB 해시도 같다. 검증 명령은 `.venv/bin/python thoroughbred/research/20261002_training_three_v1/root_replay_bounded.py`다.
- 최초 적용에서 명세 집계 키 이름 오류가 발생했으나 백업으로 자동 복구했고 원래 DB 해시가 일치함을 확인했다. 주 에이전트가 키 접근 한 줄을 고친 후 동일 입력으로 다시 검증·적용했다. [복구 기록](loader/first_apply_recovery.json)을 남겼다.
- 큰 원문을 그대로 임시 저장하는 후속 비교는 디스크 공간 제한으로 중단됐다. 원문 전수 대조 함수를 그대로 보존했음을 AST로 확인하고, 적재 비교만 행 전체 SHA-256 방식으로 바꿔 통과했다. 초기 검증 코드와 원문 전수 대조 결과·해시는 보존돼 있다.

운영 SQLite 및 다른 운영 서비스에는 쓰지 않았다.
