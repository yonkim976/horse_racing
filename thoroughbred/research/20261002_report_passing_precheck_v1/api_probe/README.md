# API215 / API180_1 / API303 과거자료 사전 확인

기준일: 2026-10-02 KST · 연구 범위: 2010-01-01–2026-09-29 · 대상 `meet=1` 서울, `meet=3` 부산경남, `meet=4` 영천 · 제주 제외

## 결론

세 API 모두 공식 페이지의 시간 범위는 `-`로 표시되어 있고, 공식 페이지의 등록일만으로 실제 과거자료 범위를 판단할 수 없다. 실제 API를 연도별로 제한 조회한 결과는 다음과 같다.

| API | 실제로 확인한 과거반환 | 이번 확인으로 말할 수 있는 것 |
|---|---|---|
| 심판리포트 [API215](https://www.data.go.kr/data/15063980/openapi.do) | 서울·부경 2010–2016은 매년 정상 0행. 2017은 서울 257행(2017-10-14–12-24), 부경 194행(2017-10-13–12-31). 2018–2026은 두 경마장 모두 매년 양수 `totalCount`. 영천은 표본 연도 2010·2017·2020·2024·2025에서 0행, 2026에 12행(2026-09-13–20). | 2010–2016 심판리포트는 이 API에서 반환되지 않는다. 2017도 4분기 행만 있으므로 연간 전체가 아니다. 2018–2026에는 매년 자료가 반환되지만, `totalCount`는 조회행 수이지 전체 경주 대비 완전성 증명이 아니다. |
| 제재내역 [API180_1](https://www.data.go.kr/data/15037098/openapi.do) | 서울·부경 모두 2010–2026의 모든 연도에서 양수 `totalCount`. 서울 2010년 1,445행부터 2026년 1,509행, 부경 2010년 696행부터 2026년 906행. 영천은 표본 연도 2010·2017·2020·2024·2025에서 0행, 2026에 19행. | 요청한 모든 서울·부경 연도에 API가 자료를 반환했다. 일부 연도는 한 행만 probe했고 일부는 첫 1,000행만 저장했다. 전 기간 전체 행을 수집하거나 재결·제재의 누락 여부를 대조한 결과는 아니다. |
| 통과조 [API303](https://www.data.go.kr/data/15119851/openapi.do) | 연도 표본에서 2010 서울 1,059 / 부경 736, 2016 서울 1,113 / 부경 808, 2017 서울 1,094 / 부경 805, 2025 서울 1,042 / 부경 717, 2026 서울 759 / 부경 536행. 2026 영천 12행. | API303은 2010·2016에도 실제 과거 행을 돌려준다. 이는 샘플 연도별 `totalCount`다. 2011–2015를 조회하지 않았고 어떤 샘플도 모든 API 페이지를 전수 보존한 것은 아니다. 이 확인만으로 연도별 전체 경주 커버리지를 확정하지 않는다. |

`meet=1`/`meet=3`의 API215와 API180_1 연간 `totalCount` 전체는 [CSV](annual_counts_meet_1_3.csv)에 있다. API215의 2010–2016 0행은 **이번 API 조회에서 해당 연도의 행이 반환되지 않은 상태**다. 다른 공식 원천의 원문 부재나 당시 심판사항·제재 미발생을 뜻하지 않는다.

## API별 판독

### 심판리포트 API215

공식 문서는 필터로 `rc_year`(YYYY), `rc_month`(YYYYMM), `rc_date`(YYYYMMDD)를 명시한다. 프로젝트 일별 수집 코드는 `meet`, `rc_date`를 보낸다. 이번 연도 probe에서는 `meet`, `rc_year`를 함께 보냈고, `meet=1` 응답의 모든 확인 행은 `서울`, `meet=3`은 `부경`이었다. 2010–2026의 서울·부경 요청에서 각 해의 반환 `rcDate`가 요청연도와 일치했다.

2017년은 `totalCount`가 1,000 미만이어서 표본 응답 전 행을 저장했다. 응답일 범위가 서울은 10월 14일부터 12월 24일, 부경은 10월 13일부터 12월 31일까지다. 프로젝트 경주결과 연간 기준(서울 1,094경주, 부경 805경주)과 비교하면 각각 257행·194행은 크게 적다. 따라서 2017년 자료를 연간 전체로 사용하면 안 된다. 2018–2026은 각 해 `totalCount`를 확인했고, 첫 행의 날짜로 연도 필터를 검증했다. 이 연도들은 페이지 전체를 전수 수집하지 않았다.

2018년 이후 자료도 전기간 완전하다고 볼 수 없다. core race population과 대조한 2020년 API215 수는 서울 565건 대 core 630경주, 부경 418건 대 473경주이고, 2021년은 서울 790건 대 865경주, 부경 538건 대 588경주다. 적어도 이 두 연도에서는 API215 응답 행 수가 경주 모집단보다 작다. 반대로 2023년 서울 1,062건 대 core 1,051경주, 2024년 서울 1,051건 대 1,050경주, 2025년 부경 717건 대 716경주처럼 응답 수가 더 많기도 하다. 취소·불성립 경주 또는 양쪽 모집단의 정의 차이를 포함할 수 있으므로 `totalCount`의 차이만으로 행을 오류로 분류하지 않는다. 각 경주키와 취소/불성립 이력을 대조해야 한다.

2026년 API 응답 전체는 서울 759, 부경 536, 영천 12행이며 마지막 `rcDate`는 모두 2026-09-20 이하다. 연구 cutoff(2026-09-29) 뒤 심판리포트는 이번 응답에 없었다.

### 제재내역 API180_1

공식 공개 페이지는 제공 항목과 `meet=4` 영천 조회 안내를 명시하지만, 이 페이지에 `rc_year`/`rc_date` 요청변수 표와 시간 범위는 표시하지 않는다. 프로젝트 키를 쓴 실제 요청에서 `meet`, `rc_year`로 서울·부경 각각 2010–2026의 양수 `totalCount`를 얻었으며, 연도별 1행 probe의 `rcDate`는 요청연도와 일치했다. 따라서 이 보고서에서 `rc_year`는 **실호출에서 동작을 확인한 필터**다. 공식 페이지 시간 범위 `-`만으로 2010년 이전 데이터가 없다고 단정하지 않는다.

2026년 서울은 API total 1,509행으로 첫 페이지 1,000행과 두 번째 페이지 509행을 모두 저장했다. 두 페이지의 완전 일치 행은 0이고 결합한 행 수는 total과 일치한다. 전체 반환 `rcDate` 범위는 2026-01-03–09-20으로 cutoff 이후 행은 없었다. 부산경남은 906행이 한 페이지에 모두 들어갔고, 그중 2026-10-02가 4행이다. 이 4행은 원문을 보존했으며 2026-09-29 cutoff 분석에서는 제외해야 한다. 영천은 19행 모두 2026-09-20까지다.

2010–2026 서울·부경의 해별 `totalCount`는 매년 양수다. 다만 한 행 probe를 한 해에는 첫 행만, 표본연도에 1,000행 요청을 한 경우에도 total이 1,000을 넘으면 첫 페이지까지만 실제 보존했다. 이 확인은 “API가 해당 연도에 무언가 반환하는가”에는 답하지만, “제재가 누락 없이 전부 반환되는가”에는 답하지 않는다.

### 통과조 API303

공식 설명은 경주 후 경마장별 통과 그룹·코너 정보와 3F/4F 통과시간을 설명하고, 영천 시행 이후 `meet=4`로 조회할 수 있다고 밝힌다. 프로젝트 API client는 연도 요청에 `rc_year`, 날짜 요청에 `rc_date`를 사용한다. 이번에는 최대 허용한 14회(서울·부경 각 2010, 2016, 2017, 2025, 2026; 영천 2010, 2017, 2025, 2026)를 호출했다. 2010·2016에도 양수 응답이 있으므로 통과조는 심판리포트보다 훨씬 과거 자료를 API에서 받을 수 있다.

한 페이지로 다 받지 못한 표본연도는 `totalCount`를 기록했지만 이후 페이지를 가져오지 않았다. 특히 2010·2016·2017·2025 서울 응답은 `totalCount > 1,000`이어서 실제 저장한 원문은 첫 1,000행이다. API303은 경주 단위 요약이고 말 ID가 없다. 저장 시 경주결과의 말별 통과착순과 한 행으로 합치지 말고 `(meet, rcDate, rcNo)`로 연결되는 별도 경주 단위 원천으로 두는 편이 맞다.

## 저장 구조 초안

- **API215**: 한 경주의 보고서 텍스트(`judgement`, `addJudgement`, `jkChange`)와 `member`, `weather`를 경주 단위로 저장한다. 조인 키는 `(meet, rcDate, rcNo)`. 보고서 안의 말·기수 언급을 API 행으로 쪼개면 원문 의미가 달라지므로 원문 텍스트와 payload를 그대로 남긴다. 명세 필터명은 `rc_year`, `rc_month`, `rc_date`다. `vsrc_date`는 이 API의 공식 명세와 프로젝트 코드에서 확인하지 못했다.
- **API180_1**: API가 반환한 제재 건을 행 단위로 보존한다. `gubun`, `meet`, `rcDate`, `rcNo`, `chulNo`, `prNo`, `prName`, `kind`, `reason`, `fine`, `stDate`, `spDate`, `etlTime`은 원문 타입 그대로 둔다. `rcDate`(관련 경주일)와 제재 시작/종료일을 별도 필드로 유지한다. 중복이나 사후 수정에 대비해 수집시각·원문 페이지 해시·페이지 내 행 순서도 함께 남긴다.
- **API303**: 경주별 한 행의 통과군·주로값을 별도 저장하고 `(meet, rcDate, rcNo)`로 연결한다. 출전마별 통과착순은 말별 결과 원천에 따로 보관한다.
- **공통**: 정상 `totalCount=0`, API 호출 오류, 아직 요청하지 않은 연도를 각각 구분한다. API215의 0행은 “이 API에서 report 행 없음”이고 제재 미발생을 뜻하지 않는다. `totalCount>0`도 해당 연도/경주 집합의 전부라는 증거가 아니므로 예상 경주 키와 비교한 뒤에만 coverage를 확정한다.

- 원문 JSON 95개는 `raw/` 아래에 있다. manifest는 요청 파라미터 중 공개 필터만 담고 키를 포함하지 않는다.

이번 확인은 총 95개의 읽기 전용 OpenAPI 호출이다. 모든 응답은 HTTP 200, `resultCode=00`이었고, 보존된 원문 95개 모두 manifest SHA-256과 일치했다. 원문에서 서비스 키 문자열은 0건이었다. 운영 DB나 서비스를 열거나 변경하지 않았다. 샘플 응답이므로 전체 페이지 적재와 경주별 완전성 검증은 수행하지 않았다.
