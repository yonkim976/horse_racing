# 통과조 미대응 값 직접 재확인

2026-10-02 사용자 요청으로 미대응 API 칸의 의미를 재점검했다. 마사회 홈페이지 성적표 5경주를 직접 조회하고 보관 성적표·API 원문과 비교했다. **다섯 사례 모두 홈페이지와 보관 성적표의 지점별 값이 일치했다. 전체414칸의 로컬 원문 재대조에서도 모두 두 공식 지점의 동일값 반복이며, 관련518개 경주·지점은 성적표로 보완돼 최종 조회값 누락이0개다.** API 칸의 개별 지점 대응 근거는 미확정 상태로 유지한다.

## 공식 홈페이지에서 확인한 예시

| 서울 경주 | 공식 성적표 | API 원문 |
| --- | --- | --- |
| [2020-01-04 1경주](https://race.kra.co.kr/raceScore/ScoretableDetailList.do?meet=1&realRcDate=20200104&realRcNo=1) | S-1F와3코너에 동일 통과조 | `corner_3`·`corner_7`에 동일 값 |
| [2020-01-04 8경주](https://race.kra.co.kr/raceScore/ScoretableDetailList.do?meet=1&realRcDate=20200104&realRcNo=8) | S-1F와3코너에 동일 통과조 | 같은 값이`corner_2` 한 칸에 있음. `corner_3`은G-1F 값, `corner_7`은4코너 값과 일치 |
| [2021-01-08 1경주](https://race.kra.co.kr/raceScore/ScoretableDetailList.do?meet=1&realRcDate=20210108&realRcNo=1) | S-1F와3코너에 동일 통과조 | `corner_3`·`corner_7`에 동일 값 |
| [2020-07-11 12경주](https://race.kra.co.kr/raceScore/ScoretableDetailList.do?meet=1&realRcDate=20200711&realRcNo=12) | 1코너와2코너에 동일 통과조 | `corner_3`·`corner_4`에 동일 값 |
| [2021-10-09 4경주](https://race.kra.co.kr/raceScore/ScoretableDetailList.do?meet=1&realRcDate=20211009&realRcNo=4) | 3코너와4코너에 동일 통과조 | 같은 값이`corner_4` 한 칸에 있음 |

1경주와8경주는 같은 날 서울 경주임에도 API의 지점 값 배치가 다르다. 따라서 `corner_3`을 항상3코너로 간주하거나 연도 전체에 하나의 칸 교환 규칙을 적용하면 잘못 연결할 수 있다. 홈페이지 자체가 S-1F와3코너에 같은 값을 기재하므로 동일 값 반복을 오류로 판정하지 않았다. 자료 제공 시스템 내부에서 API 필드 배치가 달라진 이유는 확인하지 못했다.

## 직접 확인 범위와 근거

- 이번에 새로 온라인 조회한 것은 **5경주**다. 259경주 전체를 다시 온라인 조회한 것은 아니다.
- 각 페이지 본문 날짜·경주번호·서울 표기와 통과조 표의 지점 라벨을 확인했다. HTTP200 원문·조회 시각·SHA256은[수집 원장](official_web/capture_manifest.jsonl)에 보존했다.
- 성적표 보관 파일의 전체 해시와 실제 줄 바이트를 확인했다. API 보관 응답의 전체 해시 및 해당 원문 JSON 항목도 확인했다.
- [직접 대조 결과](official_examples_verification.json): 5경주의 모든 비어 있지 않은 공식 홈페이지 지점 값이 보관 성적표와 동일하다. HTML 표시용 공백만 비교 시 정리했고 원문 파일은 유지했다.
- 홈페이지에서 '각 코너별 통과순위'로 표시하는 경주 단위 표를 비교했다. 말별 '구간별 통과순위' 표와 구분했다.
- 연구·운영 DB는 수정하지 않았다. 심판리포트는 이번 점검 대상이 아니다.

## 기존 미대응의 의미

서울2020년170칸·114경주,2021년244칸·145경주, 합계414칸·259경주다. 이는 API 칸의 지점 대응을 보류한 수이며 경주 전체의 통과조 미수집 수가 아니다. 공식 성적표의 지점 라벨을 사용한 보완 값과 미대응 API 원문은 각각 보존했다.

## 414칸 전수 재대조

원천 API와RPT를 경주별로 직접 비교해414칸을 독립 재현했다. 주 에이전트의 별도 계산과 GPT-6 Luna xhigh 서브에이전트의 원천·DB 대조 수치가 일치했다.

| 동일값 반복 유형 | 경주 수 | 미대응 API 칸 수 |
| --- | ---: | ---: |
| API2칸·공식 성적표2지점에 같은 값 | 155 | 310 |
| API1칸·공식 성적표2지점에 같은 값 | 104 | 104 |
| 합계 | 259 | 414 |

일치하는 성적표 후보가 없는 미대응 칸은0개다. 지점쌍별 칸 수는S1F/1C206·S1F/3C193·S1F/2C12·1C/2C2·3C/4C1이며 합414다. 앞서 설명한S1F/3C는 대표 예시이고 전414칸을 그 지점쌍으로 한정하지 않는다.

259경주의 관련 지점은 각각2개로 총518개다. **518개 모두 성적표의 지점별 유일값으로 선택돼 있으며 최종 DB의 누락·원문 불일치는0개다.** 주 에이전트는 기존 독립 기대값 파일에서도518개 모두RPT 선택이고 지점·값이 일치함을 재확인했다. 서브에이전트는 읽기 전용 기준DB의 최종값을 직접 대조했다.

이 결과로 보완 값의 존재와 일치는 확인됐다. API 칸을 개별 공식 지점에 연결하는 관계는 원문 값만으로 유일하게 정해지지 않으므로 미대응 원장을 삭제하거나 자동 확정하지 않았다. DB의 원문·선택값은 변경하지 않았다.
