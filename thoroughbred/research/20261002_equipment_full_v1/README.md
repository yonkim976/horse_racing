기존 보관 응답을 재사용하고, 미보유 1,343개 날짜×경주장 조합을 보완했다. 16개는 기존 조사 원문을 재사용했으며 실제 추가 요청은 1,327회였다. 요청은 순차 실행했고 실패는 0건이었다. [공식 API78 설명](https://www.data.go.kr/data/15160316/openapi.do)의 출전표 `equipCrs`를 사용했다. 운영 DB 장구 혼합 테이블을 출전표 API 원문으로 간주하지 않았다.

## 전체 확정 출전 330,465행의 상태

| 상태 | 출전행 |
|---|---:|
| API78에 장구명 기재 | 180,611 |
| API78 출전행 존재, 장구란 공백 | 149,495 |
| API78 출전행 부재, 기존 공식 성적표 보완 사용 | 104 |
| API78 출전행 부재, 보완값 미관측 | 255 |

API78 출전행 부재는 총 **359행·13개 공식 말 ID**다. 같은 날짜×경주장의 선택된 완전 출전표에서 해당 말의 정규화된 이름도 발견되지 않았다. 기존 104행은 모두 이 부재 집합에 포함되며 성적표 보완을 유지한다. 추가 255행은 2013~2016년 254행과 부산경남 2018-08-19 6경주 3번 `0034359 [서울]쇼트스톱` 1행이다. 부재 이유를 증명하는 원천은 확인되지 않았으므로 장구 없음이나 출전 취소로 바꾸지 않았다.

부재 상세는 [core_runner_absence_evidence.csv](inventory/core_runner_absence_evidence.csv), 출전별 상태는 [api78_core_runner_ledger.csv](inventory/api78_core_runner_ledger.csv)에 있다. 1,344개의 확정 명부 밖 원문에는 같은 경주·출전번호의 코어 후보가 없으며 같은 키의 이름·ID 충돌은 0건이다. 원문은 삭제하지 않았다.

이번 응답 집합에서 장구명이 처음 관측되는 날은 서울 2016-02-13, 부산경남 2016-02-12, 영천 2026-09-13이다. 이전 원문의 공백은 실제 장구를 전혀 착용하지 않았다는 증거가 아니다.

## 저장·조회 규칙

- `equipment_api78_card_observations`: 원문 장구 문자열, 필드 존재·JSON NULL·공백 상태, 경주·출전번호·마명, 확정 말 ID 연결 근거, 실제 원문 파일 경로와 SHA-256, 요청·수집 시각을 저장한다.
- `equipment_api78_card_tokens`: 쉼표별 원문과 위치를 보존한다. 장구명 뒤 `+`는 `new`, 뒤 `-`는 `removed`, 표시가 없으면 `unmarked`다. 단독 `-`는 장구 해제가 아니다. 같은 이름의 신규·해제 항목을 임의로 상쇄하지 않는다.
- `equipment_api78_active_declared`: 해제 항목을 제외한 신고 장구 목록이다. 실제 착용 여부는 `physical_wear_status='unknown'`을 유지한다.
- `equipment_core_coverage`: 확정 출전 330,465개 키가 정확히 한 행씩 나오며 공백과 미관측을 구분한다.
- `equipment_declared_union_fallback`: 확정 말 ID에 연결한 API78을 우선하고, 해당 API78 출전행이 없을 때 기존 공식 성적표 보완을 사용한다. 신고 장구 311,790항목이다.
- 원천 문서·완전 응답·페이지·확정 출전 원장·명부 밖 행을 별도 보존한다. 총 7개 표·4개 뷰를 추가했다.
- 현재 재조회한 역사 자료의 경기 전 공개 여부를 입증하지 못했으므로 `retrospective_api78_observation_not_verified_pre_race`로 기록한다. 저장 완료와 모델 피처 사용 승인은 다르다.

## 주 에이전트 검증

[root_verification.json](root_verification.json)의 독립 검사 13개가 모두 통과했다. 모든 선택 원문 3,117개 페이지의 해시·날짜·총계·장구값을 대조하고 장구 항목을 원문에서 다시 분해했다. 공식 코어 말 ID와 이름, 출전 키 중복, 신규·해제 처리와 성적표 보완 우선순위를 확인했다.

기존 표·뷰 80개의 양방향 `EXCEPT ALL`과 스키마 비교가 모두 일치했다. 기존 `source_manifests` 21행은 보존하고 새 원천 1행만 추가했으며 이전 manifest 메타데이터·입력 고정 정보·적재 이력을 보존했다. 적재 전 DB와 manifest는 [백업 폴더](../../data/core_api_2010_20260929_v1/backups/20261002_before_equipment_api78_full/)에 있다.

적재 후 DB SHA-256: `087914d31ac0f7025c6f399e5a5aef7ebd221c7bc5dfe08078caf1207847eae1`.

적재기 재검증도 `dry_run_replay_passed`를 반환했다. 표 7개의 내용 및 고정 원천 manifest가 일치했고 재검증 중 DB 파일 해시는 변하지 않았다. [적재 manifest](loader/load_manifest.json), [적재 전 검사](loader/pre_apply_dry_run_report.json), [재실행 검사](loader/dry_run_report.json), [재실행 파일 검증](replay_verification.json)을 참조한다. 운영 SQLite에는 이번 작업의 쓰기 작업이 없었다.
