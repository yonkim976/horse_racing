# 공식 휴장 목록·미시행 세부 유형 재검토

검토일: 2026-10-01. 대상 사건 범위는 2010-01-01~2026-09-29, 서울·부산경남·영천이며 제주 사건은 제외한다. API의 경주·심사 원장을 유지하면서 문서로 확인한 휴장과 공식 성적표의 취소 표기를 보완했다. 서브에이전트는 gpt-6-luna xhigh로 조사하고 주 에이전트가 원문·날짜·DB 보존을 검증했다.

## 1. 취소·불성립 구별이 불명확했던 29경주

- 공식 모바일 전체 경주 성적표의 날짜·경주번호와 인접한 `취소` 표기를 직접 대조해 **27경주를 `race_cancelled`로 확정**했다.
- **부산경남 2015-03-29 5·6경주만 세부 유형 미확정**으로 유지한다. 2015년 공식 마사연감 63쪽은 4경주 결과에 불만을 품은 고객의 경주로 입장통로 점거와 보전경주 2개 시행을 기록한다. 당시 미시행 사유는 확인되지만 이 문서는 해당 경주번호와 취소·불성립 구별을 명시하지 않는다. 모바일/RPT에는 1~4경주만 있고 5·6경주 PC 응답에서도 판정 가능한 성적 내용이 확인되지 않았다.
- 기존 **116경주 모두 `no_valid_completed_race` 판정과 경주 키는 그대로**다. 이번 변경은 그중 27경주의 세부 유형과 근거 보완이다. 새로운 경주불성립 판정은 없다.

## 2. 공식 휴장 근거 보완

기존 53구간·389개 경주장별 날짜에 **22구간·61개 날짜**를 추가해 **75구간·450개 날짜**가 됐다. 같은 날짜에 서울과 부산경남이 각각 휴장이면 2개 날짜로 집계한다. 모든 추가 날짜에서 API 실제 시행 경주는 0건이며, 전체 목록에서도 시행 충돌은 0건이다.

| 보완 원천 | 추가 구간 | 경주장별 날짜 |
| --- | ---: | ---: |
| 2016년 KRA 연간 시행계획 | 10 | 25 |
| 2017년 KRA 연간 시행계획 | 8 | 24 |
| 2021년 KRA 3분기 시행계획 | 4 | 12 |
| 합계 | 22 | 61 |

2016·2017년 자료는 마사회 공식 PDF의 실제 10쪽/인쇄 8쪽 휴장표다. 2016년 여름 두 구간은 원문의 `휴장(예비)`를 `summer_rotation_reserve`로 보존한다. 2016년 서울 연말 구간은 문서에 있는 12월 30~31일까지만 넣고 다음 해 1월 1일로 확대하지 않았다.

2021년 자료는 **마사회 작성 HWP를 부산경남마주협회가 재게시한 문서**다. 마사회 서버에서 받은 파일로 표시하지 않는다. HWP 표의 열·셀 위치를 재확인했으며, 7월 말은 서울 휴장·부산경남 시행이다. 초기 평문 판독에서 경주장 열을 잘못 읽은 결과는 DB 반영 전에 바로잡았다. 거리두기 조정 문서도 함께 보존한다.

- 서울: 2021-07-30~08-01.
- 부산경남: 2021-08-06~08-08.
- 서울·부산경남: 2021-09-24~09-26.

## 3. 남겨 둔 자료 공백

휴장 목록은 아직 **역사 전체의 완전한 목록이 아니다**.

- 2010~2015년 정기 휴장 전체 일정은 검증 가능한 연간 계획 자료를 아직 확보하지 못했다. 시험한 특정 PDF 경로의 실패를 자료 부존재로 판정하지 않는다.
- 2021년은 3분기 표를 보완했으며 나머지 분기·연간 전체 일정의 완전성은 미확정이다.
- 2020년 후반 코로나 중단 구간의 정확한 시작·종료일을 명시한 공식 공지 근거는 이번 조사에서 확인하지 못했다. 실제 경주 공백만으로 휴장 기간을 확정하지 않는다.
- 과거 연감의 우천·추모·전산 장애에 따른 실제 취소와 보전경주 정보는 정기 휴장표와 별도로 남겼다. 2013년 연감의 서울 2012-06-30 전 경주 취소는 기존 판정의 추가 근거이며 새로운 정기 휴장 구간이 아니다.
- 관객 입장 중단·사업장 휴장은 무관중 경주 시행 여부와 구분한다. 휴장 근거를 주행심사 중단으로 자동 확대하지 않는다.

[연도별 검토 범위](reviewed_year_coverage.csv), [2010~2013년 원천 감사](../20261001_early_closure_sources_v2/README.md).

## 4. DB 반영·검증

반영 대상은 [현재 API 코어 DB](../../data/core_api_2010_20260929_v1/thoroughbred_core.duckdb)다. 기존 운영 SQLite와 이전 연구 스냅샷은 수정하지 않는다. 기존 날짜·연간 요약·116경주 판정은 `_prior_review` 테이블에도 보존하고, 29경주 검토표는 `race_nonexecution_subtype_review`에 적재한다.

- `approved_inputs.json`에서 입력·원문 파일 해시를 고정하고 빌드 시 재검증한다.
- 날짜 원장의 변경은 휴장 표시와 미시행 세부 유형 집계에 한정한다. 경주·심사 시행 수는 유지한다.
- 이전 DB 사본과 `EXCEPT ALL` 양방향 비교로 이번 변경 대상 외의 기존 테이블·뷰가 동일한지 검증한다.
- 빌더 검증 60개, 주 에이전트의 DB 대조 13개, 독립 검증 11개가 모두 통과했다. 독립 검증에서 빌드 입력 180개 기록과 승인 원문 100개 파일의 해시도 일치했다.
- [빌드 입력·산출물 매니페스트](manifest.json), [주 에이전트 DB 대조 결과](root_verification.json), [독립 DB 검증](validation_independent.json).

이 작업으로 코어 DB를 최종 동결하지 않는다. 예측 시점·자료 이용 가능 시각·누출 검증은 별도 단계다.
