# 로컬 운영 페이지 사용 안내

## 실데이터 읽기 전용 대시보드 (2026-10-19)

기존 안내 페이지의 색상·탐색 구조를 재사용한 **별도 로컬 서버**를 추가했다. 서비스 웹앱에는 운영 경로나 관리 기능을 붙이지 않았다. 아래 명령을 프로젝트 루트에서 실행하고 [로컬 운영 대시보드](http://127.0.0.1:8765)를 연다.

```bash
.venv/bin/python -m horse_racing.operations
```

기본 주소는 `127.0.0.1:8765`이며 `--port 8766`처럼 포트만 바꿀 수 있다. LAN·외부 호스트로 바인딩하는 옵션은 없다. 터미널에서 `Ctrl+C`로 종료한다. 자동 시작·수집 예약을 추가하지 않으므로 다음에 사용할 때 다시 실행한다.

| 화면 | 제공 범위 |
| --- | --- |
| 수집 현황 | 15개 수집 항목의 마지막 실행·마지막 성공·응답/기록 처리 수, 실패·장시간 실행·갱신 지연 의심. 일정은 기존 운영 문서 기준이며 실제 Scheduler/launchd 활성 상태는 별도 확인 필요 |
| 실행 이력 | KST 날짜·종류·상태 필터, 최대 31일, 실행 ID 역순 50행씩. 실행 상세에서 직접 연결된 원문 응답 경로·HTTP 상태·크기·SHA-256 최대 20개 표시 |
| 데이터 검색 | 출마표/결과, 일반·출발·수영·언덕조교, 진료 원문, 구간시간/개별 순위, 통과조 원문, 심판리포트, 주행심사. 최대 31일/100행. 조교·진료는 공식 마번/이름 검색 후 말 선택 필수 |
| 누락 의심 | 최근 14일 중 오늘·어제를 제외한 완료 경주 최대 500개. 비취소 출전행의 결과 전무, 정상 완주마의 구간시간 전무, 경주 통과조·리포트 본문 전무 검사. 목록 최대 200행 |

일반조교의 기수 이름/나머지 직책 표시는 서비스와 같은 검증 함수를 쓴다. 제주 출발조교 같은 날 여러 행은 저장 슬롯별로 보존하며 슬롯을 실제 시행 순서로 해석하지 않는다. 언덕조교는 `horse_hill_training_current` 뷰만 조회해 원문 메타데이터 버전 중복 표시를 피한다. 구간·통과조는 `race_section_times`/`race_passing_groups` 정본에서 읽으며 원천이 제공하지 않은 순위는 생성하지 않는다.

### 연결과 보안

- 운영 조회 대상은 Supabase 프로젝트 `xkykmhhkjtosptoibduo`의 `postgres` DB다. 운영 최신성을 유지하지 않는 로컬 SQLite로 대체 조회하지 않는다.
- 자격 증명 우선순위: 환경 변수 `HORSE_RACING_OPERATIONS_DATABASE_URL` → 기존 `.env`의 `HORSE_RACING_WEB_DATABASE_URL` → PostgreSQL인 기존 `HORSE_RACING_DATABASE_URL` → 기존 Google Secret Manager `horse-racing-database-url` 버전 3. 마지막 경로는 터미널의 기존 Google 인증과 해당 Secret 읽기 권한이 필요하다. API 키·Discord 웹훅은 필요 없다.
- 별도 SELECT 전용 계정이 있으면 `HORSE_RACING_OPERATIONS_DATABASE_URL`로 지정하는 것을 권장한다. 이 작업에서 DB 계정·권한·스키마는 변경하지 않았다. 기존 웹 전용 계정이 운영 원장/정본 뷰를 읽지 못하면 오류를 표시하며 더 높은 권한으로 자동 전환하지 않는다.
- 모든 DB 트랜잭션은 `READ ONLY`, 조회 제한 8초·잠금 대기 1초, 연결 풀 1개/추가 연결 0개다. 조회 후 세션은 rollback/close된다. 계정 자체의 SELECT 전용 권한을 대체하는 완전한 권한 분리라고 주장하지 않는다.
- 서버는 루프백 IP·Host·Origin을 검사하고, API는 실행 때 발급한 비공개 토큰을 요청 헤더로 받는다. 비밀값·응답 URL·요청 파라미터·원문 로그를 브라우저에 보내지 않는다. 외부 JS/CSS/CDN·CORS 공개는 없다. 프록시/터널/외부 호스팅용이 아니다.
- 화면의 ‘조회 새로고침’은 SELECT만 수행한다. 상태·누락 의심은 최대 60초 캐시이며 자동 폴링은 없다. 수집기 실행, 재예측, Discord 발송, DB 쓰기, 배포, 클라우드 리소스 생성은 하지 않는다. 기존 DB 조회 트래픽과 Secret 읽기는 발생한다.

### 판정의 한계

실행 성공은 모든 지역·날짜의 누락 없음이나 데이터 최신성을 보장하지 않는다. 마지막 실행이 자식 작업이면 그 요청 하나의 값일 수 있다. 응답 0건은 자료 미공개를 포함하므로 ‘훈련/진료 없음’으로 확정하지 않는다. `records_written`은 수집기의 처리 수이며 신규 행 수와 같지 않을 수 있다. 일일 48시간·주간 10일의 완충 기준으로 갱신 지연을 의심하며 실제 예정 시각의 미실행 판정은 아니다. 수동 수집·조건부 항목은 같은 단순 주기로 판정하지 않는다.

누락 의심 0건도 전체 DB 정상 판정이 아니다. 일부 지점 누락·통과순위 미제공·원천 값 충돌, 예정 경주 자체의 누락은 이 첫 버전의 관계 검사에 포함하지 않는다. 진료·조교의 날짜 공백도 누락으로 표시하지 않는다. 의심 항목은 저장값 검색으로 이동해 확인하며 자동 보완하지 않는다.

### 대시보드 검증

```bash
.venv/bin/pytest tests/test_operations_dashboard.py tests/test_operations_page.py -q
```

서버를 실행한 상태에서 Playwright/Chrome을 사용할 수 있으면 `scripts/check_operations_dashboard.cjs`로 실제 조회, 이력 상세/페이지 이동/필터, 말 검색, 누락 목록 연결, 원문 XSS 방어, 데스크톱·모바일 가로 넘침과 외부 브라우저 요청이 없음을 확인한다. 테스트는 DB 읽기만 하고 XSS 시험값은 브라우저 응답 가로채기로만 주입한다.

## 기존 오프라인 운영 안내

기존 서비스 웹앱과 별개인 읽기 전용 운영 안내다. [운영 페이지](index.html)를 브라우저로 열면 예약 일정, 수집 범위, 저장·로그 위치, API 연결, 보류 항목과 관련 Markdown 문서를 확인할 수 있다. 별도 서버나 패키지 설치가 필요하지 않다.

## 화면에서 확인할 내용

- 운영 개요: 등록 예약 12개와 요일별 KST 일정, 조건부 작업, 데이터 저장 흐름
- 수집 작업: Mac·Google 필터, 작업명·API 검색, 적용 조건, 알림 정책, 확인·수동 실행 명령 복사
- 저장과 로그: Supabase 운영 DB, 로컬·GCS 원문, 실행 로그, 매일 로그 정리 정책
- 원천과 문서: 운영 문서 9개 읽기와 운영 수집 API 경로 21개의 작업 연결
- 보류와 다음 작업: 아직 자동화하지 않은 항목과 운영 범위

위 개수는 2026년 10월 12일 통합 문서의 전체 예약 목록 기준이며, 후속 변경 이력은 각 문서의 날짜를 따른다. 오프라인 안내 페이지는 DB·서버·예약 상태를 실시간 조회하지 않는다. 새로고침으로 수집기가 실행되거나 최신 실행 결과가 조회되지는 않는다. 수동 실행 명령은 복사만 하며, 터미널에서 직접 실행하면 DB 변경·API 호출·Discord 알림·기존 클라우드 실행 비용이 발생할 수 있다.

## 문서 변경 후 화면 갱신

프로젝트 루트에서 다음 명령을 실행한 뒤 브라우저를 새로고침한다.

```bash
.venv/bin/python scripts/build_operations_page.py
```

일정·실행 위치·수집 대상은 [자동 수집 통합 운영 안내](../docs/DATA_COLLECTION_AUTOMATION_OPERATIONS_2026-10-05.md)의 전체 목록에서 읽는다. 보류 항목도 같은 문서에서 읽으며, 관련 문서는 HTML 안에 함께 저장한다. 생성 시각과 원문 확인 기준 날짜는 별도로 표시한다.

작업을 추가하거나 제거하면 생성기가 중단된다. 담당자는 `scripts/build_operations_page.py`의 `META` 매핑에 명령·알림·적용 조건·확인 날짜를 먼저 반영해야 한다. 화면의 고정 안내와 과거 검증 건수는 `operations/page.template.html`에서 함께 검토한다. 기준 날짜가 갱신돼도 과거 실행 근거가 새 확인 결과로 바뀌지는 않는다.

`index.html`은 생성 결과이므로 직접 수정하지 않는다. 수정 대상은 원문 Markdown, 생성기와 HTML 템플릿이다. 생성기는 허용 목록의 문서와 템플릿만 읽으며 DB·비밀값·실행 로그에는 접근하지 않는다. 문서 안의 대표적인 자격 증명 형태는 생성을 차단하지만, 공유 전에 비밀값·개인 경로 등 내부 정보가 없는지 별도 확인한다. 이 페이지는 공개 배포용이 아니다.

## 검증

```bash
.venv/bin/pytest tests/test_operations_page.py -q
```

선택적으로 Playwright와 Chrome이 있는 환경에서는 `scripts/check_operations_page.cjs`로 일정 선택, 작업 필터·검색, 문서 열기, 명령 복사, 모바일 가로 넘침과 외부 요청 여부를 검증할 수 있다. 서비스 웹앱·배포 설정·수집 예약에는 연결하지 않는다.
