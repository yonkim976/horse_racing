# 진료 문구와 질병 설명 연결 검증 현황

2026년 10월 2일 `API33 질병 설명 연결 범위 검증` 세션과 그 산출물을 읽고 독립 점검했다. 이 작업은 기존 검증을 다시 활용할 수 있는지 확인하는 것이며 운영 DB에 설명을 적재하거나 기존 진료 원문과 연구 산출물을 수정하지 않았다.

참조 세션의 최종 결론은 [질병 용어 대조 현황](KRA_DISEASE_GLOSSARY_COVERAGE_2026-09-30.md), [문서 등록부](KRA_DISEASE_GLOSSARY_DOCUMENT_REGISTER_2026-10-01.md), [최신 진료 DB 대조 보고서](../data/research/kra_disease_glossary_api33_20260930/profile_hover_expansion_20261001/db_refresh_comparison_20261001.md)에 반영돼 있다. 파일명 날짜가 오래됐더라도 본문의 기준일과 등록부를 확인한다. 초기의 설명 50개와 완전 일치 10개 수치는 현재 최종 연결 범위가 아니다.

## 설명 연결 보류 결정

2026년 10월 2일 사용자 요청으로 질병 설명의 운영 DB 적재와 웹 화면 연결은 보류한다. 아래의 다음 운영 연결 단계는 재개 시 참고할 제안이며 실행 지시가 아니다. 사용자가 재개를 요청하기 전에는 설명 컬럼이나 연결 테이블을 추가하거나 설명을 자동 게시하지 않는다.

기존 진료 원문, 고유 문구 목록, 슬롯 연결, 검증된 표제 대응과 확보한 설명 및 출처는 보존한다. 설명 연결 보류가 이미 검증된 5,397개 문구 목록의 일치를 취소하거나 표제 대응 5,392개를 미검증으로 되돌리는 뜻은 아니다. 신규 설명 확보도 이번에는 진행하지 않는다. 진료 원문 수집 자동화나 설명 없는 표제 구성 연결은 별도 후속 작업이며 이번 보류 결정만으로 실행하지 않는다.

## 현재 DB와 원문 보존

이번 로컬 SQLite mode=ro 조회와 Supabase READ ONLY 트랜잭션에서 아래가 일치했다.

| 항목 | 로컬 SQLite | Supabase |
|---|---:|---:|
| 진료 원문 행 | 699,063 | 699,063 |
| 최초 진료일 | 2003-09-18 | 2003-09-18 |
| 최신 진료일 | 2026-09-30 | 2026-09-30 |
| 고유 진료 문구 | 5,397 | 5,397 |
| 진단 슬롯 연결 | 677,219 | 677,219 |
| 문구별 사용 빈도와 최신 연구 검토표 | 전체 일치 | 전체 일치 |

699,063개 진료행과 677,219개 진단 연결은 서로 다른 집계다. 빈 진료 슬롯 등은 연결 대상이 아니므로 차이를 곧바로 누락 건수로 해석하지 않는다. 해당 문구에는 질병뿐 아니라 검사, 처치, 예방접종, 행정성 항목도 있어 5,397개를 모두 서로 다른 질병이라고 부르지 않는다.

현재 연결은 다음 세 테이블이다.

| 실제 테이블 | 역할 |
|---|---|
| horse_medical | 말, 경마장, 진료일, 병원과 diagnosis_1 및 diagnosis_2 원문 보존 |
| medical_diagnosis_terms | id와 raw_text로 고유 원문 문구 관리 |
| horse_medical_diagnoses | 진료행의 원래 슬롯 1 또는 2를 고유 문구에 연결 |

로컬과 Supabase의 `medical_diagnosis_terms`에는 id와 raw_text만 있고 설명 컬럼은 없다. Supabase의 진료 및 질병 관련 테이블도 위 세 개만 확인됐다. 모델 정의와 수집 코드에서도 설명 저장은 확인되지 않았다.

중요하게, 슬롯 분리와 복합 문구 구성요소 분리는 다르다. `진단1=A,B`와 `진단2=C`일 때 지금 운영 연결은 `A,B` 한 문구와 `C` 한 문구에 대한 두 슬롯이다. `A`와 `B`를 각각 공식 표제로 연결하는 연구 판정은 있으나 운영 구성요소 테이블로 적재한 상태는 아니다.

## API33 원천 검증

[공식 마필 질병 정보 API](https://www.data.go.kr/data/15036577/openapi.do)의 보존 응답 JSON을 다시 계산했다.

- 원응답 3,523행의 설명 illDesc는 모두 `-`다. 현재 보존본에서 실제 설명 문장은 얻을 수 없다. 오늘 공식 API를 새로 호출한 것은 아니다.
- 한글명, 영문명, 설명이 완전히 같은 중복 12행을 제외한 고유 조합은 3,511개다. 원본은 삭제하지 않았다.
- 같은 한글명이라도 영문명 등 다른 필드가 다른 경우는 남겨야 한다. 한글명 하나만으로 모든 원천 행을 무조건 병합하지 않는다.
- API33은 질병 표제 대조 원천이고 실제 설명 출처는 마사회 공개 질병용어 화면, 마필 프로필 진료 상세, 출처를 따로 기록한 사용자 제공 자료다.

## 설명 원문과 해시 확인

마필 프로필 설명의 추가 수집 자료는 [프로필 수집 보고서](../data/research/kra_disease_glossary_api33_20260930/profile_hover_expansion_20261001/coverage_report_20261001.md)에 있다. 기존 세션은 10마리의 진료행 288개를 확인하고 38개 한글명, 영문명, 설명 조합을 보존했으며 그중 새 조합은 34개라고 보고했다. 누적 프로필 설명 출처 표제는 67개다. 288개 확인 행, 선택 표제 관측 136건, 고유 설명 조합 38개는 서로 다른 수치다.

이번에는 공식 화면을 다시 열어 전체 288행을 재수집한 것이 아니라 보존 증거를 독립 점검했다.

- 설명 관측 CSV 두 개의 SHA-256이 source_manifest와 일치했다.
- 고유 설명 관측 38개의 표제, 영문명, 설명 원문 해시가 모두 일치했다.
- 문구 사용량 스냅샷 CSV의 SHA-256이 메타데이터와 일치했다.
- 현재 양쪽 운영 DB의 전체 문구별 사용량이 연구 검토표와 일치했다.

이전 세션의 전체 277개월 진료 내용 해시 일치 결과는 기존 [DB 재대조 보고서](../data/research/kra_disease_glossary_api33_20260930/profile_hover_expansion_20261001/db_refresh_comparison_20261001.md)의 근거다. 이번에 그 월별 해시 전수를 다시 계산한 것은 아니므로 이번 검증 범위와 구분한다.

연구 검토 CSV에는 표제와 설명 상태 및 출처 라벨이 있으며 모든 실제 설명 본문이 그 CSV에 들어 있는 것은 아니다. 운영 적재 시 관측 CSV와 이전 보존 설명 원문을 함께 읽어야 한다. `설명 있음` 상태나 출처 이름을 설명 본문으로 저장해서는 안 된다.

## 재개할 때 참고할 운영 연결 단계

아래는 제안이며 아직 DB 변경을 실행하지 않았다. 설명 적재와 화면 연결은 위 보류 결정에 따라 사용자 재개 요청 후에만 진행한다.

1. 진료 원문과 기존 슬롯 연결은 그대로 보존하고, 고유 원문 문구와 검증된 구성 표제 사이의 별도 연결을 만든다. 복합 문구는 이미 승인된 구성 대응만 적용하고 단순 쉼표 분할이나 부분 문자열을 새 의학적 대응 근거로 사용하지 않는다.
2. 표제 사전과 설명 원문 및 출처를 분리한다. 출처 종류, URL 또는 근거 파일, 확인 시각, 원문 해시, 검토 상태를 함께 관리한다. 사용자 제공 근거를 직접 관측한 API 또는 웹 원문과 혼합하지 않는다.
3. 양쪽 DB의 수치 ID가 같다고 가정하지 말고 각 DB의 고유 raw_text를 정확히 대조해 운영 term_id를 해석한다. 현재 승인된 대응 5,392문구만 연결하고 제외 5개는 원문과 제외 사유를 유지한다.
4. 설명이 없는 구성요소는 NULL 또는 미확보 상태로 남긴다. 일부 설명만 있는 복합 문구를 전체 설명 완료로 표시하지 않는다. illDesc의 `-`를 유효 설명으로 쓰지 않는다.
5. 새 진료 수집 시 기존 raw_text는 승인된 연결을 재사용하고 처음 보는 문구는 미검토 목록으로 보낸다. 자동 후보 생성과 확정 연결을 구분한다.
6. 설명은 용어 안내로 서빙하며 개별 말의 현재 질병 정도, 완치, 출전 가능 여부나 경주 영향도를 자동 판정하지 않는다. 위험도와 성능 영향 연구는 별도 과제다.

현재 당일 2분 수집기와 매일 조교 worker는 진료를 수집하지 않는다. 진료 원문을 갱신하는 API16 작업과 API33 표제 및 웹 설명 관리 작업은 별개다. 진료 정기 자동화의 일정과 최근 날짜 겹침 조회는 기존 공개 주기 계획을 바탕으로 후속 승인 후 구현한다.

최초 검증에서는 이 문서와 [자동 수집 운영 문서](LOCAL_RACE_DAY_COLLECTION_AND_DISCORD_HANDOFF_2026-10-02.md)만 신규 작성했다. 이후 사용자 요청으로 설명 연결 보류 결정을 관련 문서에 추가했다. 로컬 운영 DB, Supabase, 모델, 기존 연구 파일, 웹 서비스와 예약은 변경하지 않았다.
