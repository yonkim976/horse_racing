## 저장 의미

두 종류를 구분한다.

| 원천 | 운영 저장/조회 | 의미 |
| --- | --- | --- |
| KRA 출마표의 말별 편집 문구 | 기존 `horse_steward_phrases` | 말별 홈페이지 셀에 실제로 배치된 문구. 기존 48,130건 유지 |
| KRA 당일 심판위원 Report | 새 `steward_report_versions` + `horse_steward_report_mentions` | 원문 문단에 해당 말의 출전번호가 명시되어 있고 운영 출전 행·공식 마번·마명이 일치하는 중립적 연결 |
| 통합 말별 조회 | `horse_steward_history` | 기존 편집 문구와 최신 검증 통과 원문 연결을 `text_basis`로 구분해 조회 |

새 연결의 `text_basis='official_report_paragraph'`, `website_text_verified=false`는
KRA의 말별 편집 셀 자체와 일치한다고 검증한 결과가 아니라는 뜻이다.
원문 자체는 공식 홈페이지에서 직접 수집한다. 원문 문단을 임의로 축약하거나 다시 쓰지 않는다.
한 문단에 여러 말이 언급되면 해당 말마다 같은 원문 문단을 연결한다.
가해/피해·출발 지연 등 상황 유형·불리 정도는 분류하지 않는다.

## 추가·수정·보류

- 내용이 같은 보고서는 새 버전이나 말별 연결을 중복 생성하지 않는다.
  원문 재관측·최근 관측 시각은 기록한다.
- 원문 내용이 달라지면 새 버전을 저장하고 검증 통과분을 최신으로 전환한다.
  이전 버전과 연결은 삭제하지 않는다. 동일 내용으로 되돌아오면 기존 내용 버전을 재사용한다.
- 원문이 비어 있거나 공개되지 않았거나 요청/파싱이 실패하면 기존 버전을 유지하고 대기/오류를 기록한다.
- 출전번호·마명이 충돌하거나 다른 과거 경주의 문단으로 보이면 원문을 저장하고 해당 경주의 새 연결을 보류한다.
  보류가 있는 새 버전은 `needs_review`, `is_current=false`다. 이전 검증 통과 최신본이 있으면 유지한다.
- 말 번호가 없는 일반 문단은 버전의 전체 원문에 남기며 임의로 특정 말에 귀속하지 않는다.
- 과거 최초 게시 시각은 추정하지 않는다. 새 관측 시각도 정확한 최초 게시 시각과 구분한다.

HTML의 선택 경마장·실제 표시 날짜·경주 번호를 확인한다. BeautifulSoup과 독립 lxml 순회로

## 조회 예시

```sql
SELECT h.kra_horse_id, h.name_ko, c.kra_meet_code,
       r.race_date_local, r.race_number, s.historical_program,
       s.phrase_text, s.text_basis, s.report_version_id
FROM public.horse_steward_history s
JOIN public.horses h ON h.id=s.horse_id
JOIN public.races r ON r.id=s.race_id
JOIN public.racecourses c ON c.id=r.racecourse_id
WHERE h.kra_horse_id='0046016'
ORDER BY r.race_date_local DESC, r.race_number;
```

보류 원장은 `steward_report_versions`의 `linkage_status='needs_review'`와 `review_json`을 조회한다.
새 원문의 URL·HTML SHA256·파일 위치는 버전의 `source_document_id`,
가장 최근 재관측은 `latest_source_document_id`로 `source_documents`에 연결한다.
