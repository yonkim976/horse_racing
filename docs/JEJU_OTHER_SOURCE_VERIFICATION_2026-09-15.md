# 제주마 경주결과 외 원천 검증 (2026-09-15)

## 판정

**확보한 제주마 조교·출발조교 부분집합은 보존된 월별 공식 원문과 행 수·내용이 정확히 일치한다. 실측 체중도 보존된 제주마 출전 키의 99.16%에 연결되고, 공통 키의 DB/옛 결과 체중값과 충돌이 없다. 그러나 다른 자료까지 전 말·전 기간 완전 적재됐다고 판정할 수 없다.** 진료 21행의 동일 payload 반복, 체중 미연결 771키, 출전마 진료·장구 Text가 없는 확인 경주 138개, Text/공식 결과의 마명 충돌 4행을 별도 원장에 남겼다. 진료·체중 API의 혼합 응답 본문은 보존하지 않고 응답 해시만 남겼으므로, 이 두 원천의 전체 반환행을 이번에 독립 재추출할 수는 없다.

검증 대상은 2002~2014년 공식 결과에서 `제`가 명시된 말과 2015년 이후 기존 SQLite의 완료 제주 경주에서 확인된 **3,996두**다. 말 ID는 원문 JSON에 숫자형으로 오는 경우가 있어 대조 시 숫자값을 문자열로 정규화했지만, 원문은 수정하지 않았다. 이 검증은 제주마로 확인되지 않은 말이나 한/래 경주를 새로운 연구 원장에 편입하지 않는다.

체중 공통 키는 **2015년 이후 DB 66,629행의 체중/증감값** 및 **2002~2014년 공식 결과 24,084행의 체중값**과 모두 일치했다. 넓은 키의 미연결 771개는 옛 결과 172개와 DB 출전 599개로 나뉜다. DB 599개 중 체중이 `0`인 행 333개, NULL 222개, 양수 44개다. 양수 44개는 앞서 격리한 2019년 말 ID 충돌의 DB 쪽 4개와 2026-07-07 제주 4경주·40출전행이다. 2026-03-20~21의 139개 미연결 출전에는 DB 양수 완주시간도 없다. **2026-07-07은 양수 결과와 DB 체중이 있지만 이 월별 체중 부분집합에는 40행 모두 없다.** 원래 API 응답 본문이 없어 원천 누락인지 수집·필터 과정의 문제인지는 확정하지 않는다. 2019년 공식 결과 쪽 4키는 기존 DB 기반 체중 필터의 대상 키 밖에도 있으므로 미연결 원장에 별도 기록했다.

제주 `dacom71` 출전마 진료·장구 Text **532파일**에서 경주 제목 **8,320개**를 파싱했다. 2015년 이후 정상 양수 결과가 확인된 **6,731경주** 중 Text 제목이 있는 경주는 **6,593개**, 없는 경주는 **138개**(2015년 134, 2026-07-07 네 경주)다. 제목이 있는 확인 경주의 공식 결과 출주번호 **65,665개**와 Text 출주번호는 추가·누락 없이 일치한다. 이 중 마명까지 같은 것은 **65,661행**이고, 다른 **4행**은 2019년 `푸른대왕`(Text) / `푸른장군`(공식 결과) 사례로 기존 말 ID 충돌과 같다. 이름만으로 하나의 말 ID를 선택하지 않았다. `dacom71`의 진료·장구·폐출혈 내용 자체와 다른 Text 8종의 말별 행은 이번에 검증하지 않았다.

기계 판독 결과는 [`verification.json`](../data/research/jeju_other_sources_verification_20260915/verification.json), 미연결 체중·반복 진료·Text 부재/충돌은 [`issues.jsonl`](../data/research/jeju_other_sources_verification_20260915/issues.jsonl)에 있다. `all_checks_passed=false`는 **진료의 완전 동일 payload 21행**을 조용히 통과시키지 않기 위한 판정이다. 조교·출발조교 원문 재추출, 체중 키/값, Text 파일 해시 및 `dacom71` 출주번호 대조 검사는 각각 통과했다. 누락과 반복은 원장에서 상태를 유지한다.

프로젝트 루트에서 다음 명령으로 같은 입력 스냅샷을 재검증한다. 실행 결과에는 SQLite 및 공식 ID 연결 산출물의 SHA-256, 원천/산출물 검사, 이슈 원장 SHA-256이 기록된다.

```bash
.venv/bin/python scripts/verify_jeju_other_sources.py
.venv/bin/ruff check scripts/verify_jeju_other_sources.py
```

이 검증은 기존 DB·원문·데이터셋·모델·registry를 바꾸지 않는다. 조교·진료 사건은 말 ID로만 연결되며 사건 날짜의 조교사·마주 귀속, 과거 경주 전 공개 시각, 예측 성능은 검증하지 않았다.
