# 기수 목록의 현역·기본 소속 기준

기수 목록은 경주 출전 장소가 아닌 공식 기본 소속으로 서울(1)·부산(3)·제주(2)를 구분한다. API의 영남은 부산 그룹으로 표시한다. 교류 출전과 영천(4) 출전으로 기본 소속을 추정하거나 변경하지 않는다.

`jockey_affiliation_snapshots`는 공식 현역 웹 명단과 API307의 번호·이름·소속·등록 종료 여부를 교차 확인한 날짜별 명단이다. 목록과 검색 모두 최신 **전체 지역 명단**에 포함된 기수만 조회한다. 이전 명단에만 있거나 미연결인 기수는 제외하며, 과거 경주/기수 원본은 유지한다. DB 이름 앞의 감량 표시 `(-1)`~`(-4)`는 동일 번호의 이름 검증에서만 제외한다. 목록 이름은 공식 명단의 이름을 사용한다.

2026-10-08 확인: 서울 39명, 부산 30명, 제주 25명, 총 94명. API 등록 종료일이 비어 있으나 현역 웹 명단에 없는 서울 9명은 포함하지 않았다. 현역 명단에 올라 있는 미활동 기수는 포함한다.

- 현역 명단: https://race.kra.co.kr/jockey/ProfileJockeyListActive.do?meet=1 (3, 2도 확인)
- API307: https://apis.data.go.kr/B551015/API307/jockeyInfo
- 원문 보관: `data/research/jockey_roster_20261008/` (로컬 데이터, Git 제외). 원문 SHA-256과 출처 URL, 관측 시간을 함께 보존한다.
- DB 변경: Alembic `20261008_0027`, Supabase `20261008124010_jockey_affiliation_snapshots.sql`. RLS 활성화, anon/authenticated 직접 접근 권한 없음. 서버 DB 연결로만 사용한다.

갱신은 `python scripts/sync_jockey_affiliations.py`로 전체 지역 자료를 수집·검증한다. 기본은 dry-run이며 `--apply`를 붙여 설정된 DB에 원자적으로 저장한다. 보관한 자료 재사용 시 `--source-dir <directory>`를 지정하며 manifest의 최초 관측 시각을 유지한다. 수집 실패·불완전 페이지·이름 불일치·지역 중복은 저장하지 않는다. 같은 날짜의 명단 구성 변경은 자동 덮어쓰지 않고 검토를 요구한다. 새로운 공식 번호가 DB에 없으면 먼저 번호 기준으로 연결을 검토해야 한다. 별도의 정기 수집 작업은 추가하지 않았다.

검증: `tests/test_jockey_directory.py`에서 현역 웹 명단 소속, API 충돌/불완전 자료 거부, 교류·영천 출전과 기본 소속 분리, 이전 명단/미연결 제외, 날짜별 저장과 멱등성을 확인한다. 조교사·말 목록 관련 회귀 검증을 포함해 31개 테스트 통과. 실제 브라우저의 세 지역 필터와 비현역 검색 제외도 확인했다.

## 목록 전적 표시

컬럼: 번호, 이름, 지역, 출전, 1위, 2위, 3위, 승률, 복승률, 입상률. 지역은 세 모드 모두 공식 기본 소속을 표시한다. 기존 기간별 전적 묶음은 표시하지 않고, 지역 필터는 유지한다. 번호는 페이지 간 연속된다. 기수번호 컬럼과 이름 밑줄은 표시하지 않으며 프로필 링크와 기수번호 검색은 유지한다.

테이블 위의 최근 1개월(`period=month`)·최근 1년(`period=year`)·통산(`period=career`, 기본값) 버튼으로 기간을 선택한다. 기간 전환 시 첫 페이지로 돌아가고 검색어·지역·정렬 설정을 유지한다. 검색·지역 변경·페이지 이동도 선택 기간을 유지한다. 캐시 키에 기간을 포함한다. 잘못된 기간 값은 통산으로 처리한다.

전적은 수집된 완료 경주의 실제 출전을 기수번호 기준으로 일괄 집계한다. 최근 1개월/1년은 오늘부터 직전 달/직전 해 같은 날짜까지(해당 날짜가 없으면 말일) 포함하는 이동 기간이며 화면에 날짜 범위를 표시한다. 승률은 해당 기간 1위/출전수, 복승률은 1·2위 합계/출전수, 입상률은 1·2·3위 합계/출전수다. 경주 취소·출전 제외·미래 경주·결과 빈 행은 제외한다. 중지·실격은 출전수에 포함하되 실격을 입상으로 집계하지 않는다. 출전이 없으면 횟수는 0, 비율은 `—`로 표시한다. 공식 API 전적 대신 수집된 실제 출전 범위를 사용하므로 원본 API 수치와 다를 수 있다.

선택 기간의 집계 결과를 목록 쿼리에 결합해 출전수 내림차순 정렬한 다음 페이지를 나눈다. 이름순 선택 시 공식 이름 기준으로 정렬한다. 다른 지역 교류 출전도 기본 소속 기수의 실적으로 집계한다.

검증: 월/년 경계, 취소·실격·미래/예정 경주 제외 및 세 비율, 기간별 전역 정렬 후 페이지 분할, 기간별 캐시 및 필터 유지, 기본/잘못된 모드 처리. 관련 회귀 테스트 총 33개 통과. 실제 브라우저에서 세 기간의 수치·정렬 변화, 지역 변경 시 기간 유지, 선택된 날짜 범위와 전체 컬럼을 확인했다.

## 기수 상세의 동반 입상 기간과 기본정보 확인 (2026-10-09)

기수 상세 `?tab=partners`는 기본 통산이며 `period=month|year|career`로 조교사와 마주 두 순위를 함께 전환한다. 해당 기간에 함께 출전한 경주를 분모로 하고 1~3위 합계를 동반 입상으로 집계한다. 기간 경계는 목록과 같은 이동 1개월·1년이며, 화면 날짜 범위를 표시한다. 기간별로 입상 횟수 → 1위 횟수 → 출전수 → 이름·번호 순으로 상위 10명을 선정한다. 다른 상세 탭을 오가도 기간을 유지한다. 기본정보 및 연도별 성적의 전체 집계는 동반 입상 기간 선택의 영향을 받지 않는다.

성적표의 마지막 입상률 열에는 경주 출전표의 8번째 열 간격을 적용하지 않는다. 성적표 전용 숫자 오른쪽 정렬과 좌우 여백을 사용한다.

기본정보가 비어 있는 것은 원천정보 전체가 없다는 뜻이 아니다. `data/research/jockey_roster_20261008/api_{1,3,2}.json`을 공식 현역 명단과 대조한 결과, 현역 94명(서울 39·부산 30·제주 25) 모두 `debut`, `wgPart`, `wgOther` 값이 있다. 최범현(080361)은 데뷔 `20010706`, 소속조·타조 기승가능중량 모두 `53`이다. 사용자 요청에 따라 `jockey_affiliation_snapshots`에 `debut_date`(date), `riding_weight_own_kg`·`riding_weight_other_kg`(numeric(4,1))을 추가하고 현역 94명 모두 채웠다. 관측일과 원문 출처·해시는 유지한다. 생년월일은 DB에 추가하지 않고 기수 기본정보 화면에서도 제외했다.

보관된 API307 응답에는 생년월일 필드가 없다. 공식 웹 프로필 보관 자료 `thoroughbred/research/20260930_trial_jockey_gap_audit_v1/raw_official_jockey_profile_003097.html`에서는 김동규의 생년월일·데뷔일·기승가능중량을 확인할 수 있다. 전체 기수의 생년월일 확보 여부는 이 한 사례로 판단하지 않으며 별도 공식 웹 수집·검증이 필요하다. 공공데이터포털 기수 상세정보 설명: https://www.data.go.kr/data/15056828/openapi.do

데뷔일·기승가능중량은 `scripts/sync_jockey_affiliations.py`의 공식 현역 명단 갱신에서 함께 검증·저장한다. 누락·0 표시는 null로 보존하며 잘못된 날짜, 미래 데뷔일, 음수·100kg 이상 또는 소수 둘째 자리 중량은 저장 전에 거부한다. 화면은 가장 최근 기수 스냅샷의 프로필 값을 사용하고, 현역·현재 기본 소속 판정은 최신 전체 명단 기준을 유지한다. 두 중량이 같으면 `53kg`, 다르면 `소속조 52.5kg · 타조 53kg`처럼 구분한다.

마이그레이션: Alembic `20261009_0030`, Supabase `20261008190329_jockey_profile_fields.sql`. 운영 DB 반영 및 94/94명 세 필드 저장을 조회로 확인했다. RLS와 API 접근 권한은 기존 설정을 유지했다. `test_jockey_profile_migration.py`에서 기존 행 보존·null·제약·되돌리기를, 기수 목록/상세 테스트에서 파싱·갱신·중량 소수·화면 연결을 검증했다. 관련 테스트 총 42개 통과.
