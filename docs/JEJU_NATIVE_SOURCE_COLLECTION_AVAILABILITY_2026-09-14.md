# 제주마 전용 원천 수집과 자료별 시작일 (2026-09-14)

## 결론

**경주결과·실측 마체중은 첫 제주마 경주인 2002-07-28부터, 말 번호가 연결되는 일별 조교 행은 2007-10-01부터 수집 가능함을 실제 응답으로 확인했다.** 다만 2007년부터의 초기 조교 행은 훈련시간이 0이고, **양수 훈련시간의 첫 기록은 2008-11-10**이다. 출발조교는 2007-10-17부터다. 진료 API에는 제주마 말 번호의 2008-04-02 행이 있지만 진단명이 비어 있다. **진단 내용이 있는 첫 ID 확인 제주마 진료는 2012-10-21**이다. 이 날짜들은 최초 *양성 관측*이며 전 기간·전 말의 완전성이나 당시 경주 전 공개 시각을 보증하지 않는다.

2002~2014 결과는 공식 [경주기록 API](https://www.data.go.kr/data/15058305/openapi.do)의 **`rank`가 명시적으로 `제`로 시작하는 경주행만** 새 경로에 저장했다. 한라마·래 경주 응답은 메모리에서 폐기했고 새 원문 파일에 기록하지 않았다. 2015년 이후 제주마 출전 키는 기존 완료 경주 DB에서 가져왔다. 그 두 원천에서 확인된 말 **3,996두**의 말 번호만 공식 [일별훈련 API](https://www.data.go.kr/data/15058782/openapi.do)·[출발훈련 API](https://www.data.go.kr/data/15059043/openapi.do)·[마필진료 API](https://www.data.go.kr/data/15057799/openapi.do)에 적용했다. 경주에 아직 나오지 않았거나 분류가 불명확한 말의 이력은 제주마로 추측해 새 보존 파일에 넣지 않았다.

체중은 `rc_year`가 **무시되고 최근 월 자료를 되돌려주는 실제 응답**을 발견해 첫 시도 25년 출력을 전부 격리했다. 수정 후 `rc_month`로 2002-01~2026-09 **297개월**을 조회했고, 응답 행 날짜가 요청 월과 같지 않으면 즉시 실패하도록 했다. 실제 `wgHr > 0`과 제주마 `(경주일, 경주번호, 말 ID)`의 완전한 키 일치를 요구했다. 현재 보존된 제주마 경주·말 키 **91,484개 중 90,713개(99.16%)**에 체중이 있으며 중복·추가 키는 0, 체중 없는 키는 771개다. 이것은 확인된 출전 키에 대한 커버리지이며 2002~2026년 모든 공식 제주마 경주를 수집했다는 뜻은 아니다. [출전마체중 공식 원천](https://www.data.go.kr/data/15057498/openapi.do)

## 더 오래된 Text와 다른 자료

공식 제주 [Text 자료실](https://race.kra.co.kr/dbdata/textData.do?Act=12&Sub=1&meet=2)의 혼합 마종 파일은 이미 기존 수집에서 보존됐다. **제주 자료실 첫 파일일과 제주마 첫 연결일은 다르다.** 제주 출전표 첫 파일은 2003-07-10이지만 `제1` 경주가 명시된 첫 파일은 **2003-08-28**이다. 체중표 첫 파일 2003-07-12에는 `래3`·`산3`만 있고, `제1` 경주 체중이 명시된 첫 파일은 **2003-08-30**이다. 그보다 오래된 체중은 위의 공식 API에 2002-07-28부터 있다.

제주 말 진료 Text는 **2005-11-03 파일에 2005-10-31 진료 사건**이 들어 있지만 말 ID가 없다. 첫 파일의 마명을 새로 보존한 2002~2014 명시적 제주마 결과와 대조해도 해당 말임을 확인하지 못했다. 따라서 이를 `제주마 치료 시작일`로 사용하지 않는다. 제주 주행심사 Text는 2003-07-11, 출발심사는 2014-10-19부터 파일이 있으나 첫 파일의 각 말을 제주마 ID에 전수 연결하지 않았다. 조교·진료·체중 이외에도 출전표, 주로상태, 기수변경, 장구, 폐출혈 원문이 존재하지만 파일 존재만으로 말별·경주 전 정보 적격성을 승인하지 않는다. [기존 자료실 전수 수집 감사](HISTORICAL_SOURCE_COLLECTION_2026-09-14.md)

구형 [수영훈련 API216](https://www.data.go.kr/data/15063981/openapi.do)은 현재 계정으로 HTTP 200·정상코드를 받았지만, 제주 `meet=2`의 **2000~2026년 연도별 첫 페이지 `totalCount`가 전부 0**이었다. 이 경로에서 제주마 수영 기록의 시작일은 확인되지 않는다. 연도 파라미터가 빈 응답에 대해 실제 적용됐는지 양성 대조가 없으므로 제주에서 수영을 하지 않았다는 결론도 아니다. [연도별 응답 해시](../data/logs/jeju_native_swim_api_year_probe_20260914.json)를 보존했다. 신규 [경주마 수영조교 API144](https://www.data.go.kr/data/15144291/openapi.do)와 [언덕주로 조교 API](https://www.data.go.kr/data/15086327/openapi.do)는 기존 카탈로그상 활용신청이 미완료여서 시작일을 제시하지 않는다.

예방접종·장제·약물·ECG 등의 이름도 [공식 공개 목록](https://www.mafra.go.kr/home/5017/subview.do)에 있지만, **이번에는 계정 접근 가능 여부와 제주마 첫 실제 기록일을 확인하지 않았다.** 서비스 목록에 이름이 있다는 사실을 수집 완료나 해당 말의 건강 이력으로 해석하지 않는다. 심판보고서는 경주 뒤 사건 기록이므로 해당 경주의 경주 전 입력으로 사용할 수 없다. [프로젝트 원천 카탈로그](DATA_SOURCE_CATALOG.md)

## 보존 파일과 사용 범위

- 2002~2014 제주마 결과: [`data/raw/jeju_native_results`](../data/raw/jeju_native_results), 연도별 JSONL와 원본 혼합 응답의 **해시만** 담은 manifest. 원본 한라마 응답 본문은 이 경로에 저장하지 않았다.
- 제주마 조교·출발조교: [`data/raw/jeju_native_training`](../data/raw/jeju_native_training)의 두 압축 JSONL 및 manifest. 기존 혼합 경마장 원문을 다시 요청하지 않고 ID로 분리했다.
- 제주마 ID 확인 진료와 실측 체중: [`data/raw/jeju_native_health_weight`](../data/raw/jeju_native_health_weight)의 연도별 진료·월별 체중 JSONL와 각 응답 해시 manifest.
- 기계 판독 수집·검증 요약: [`data/logs/jeju_native_collection_availability_20260914.json`](../data/logs/jeju_native_collection_availability_20260914.json). **647개**의 출력 해시·원천 응답 건수 대조에 불일치 0.
- 무효 `rc_year` 체중 시도는 [`격리 기록`](../data/logs/jeju_native_weight_invalid_rc_year_20260914/rejection.json)에 원인·해시와 함께 분리했다. 학습 경로에서 사용하지 않는다.

이번 수집은 원문과 제주마로 확인된 부분집합을 확보한 것이다. **정량 비교용 통합 학습표는 아직 아니다.** 2002~2014년의 `제` 코드가 없는 모호 경주, 기존 2015년 이후 DB의 공식 전수 대비 누락, 과거 조교사 소속, Text 진료의 마명 중복, 그리고 당시 실제 공개 시각은 분리해 평가해야 한다. 진료 기록이 없는 말에는 `건강함`, 조교 원천 시작 전에는 `훈련 0회`라는 값을 주지 않는다. 모델 학습·운영 변경은 하지 않았다.
