## 수동 재실행과 중복 방지

신규 [수동 갱신기](../src/horse_racing/jobs/horse_profile_medical.py)는 Supabase 프로젝트·TLS 연결을 확인하며 SQLite로 우회하지 않는다. 기본 실행은 네트워크와 DB 입출력 없는 계획 출력이고, `--apply`를 명시해야 수집·저장이 시작된다. 날짜 미지정 시 실행일 포함 최근 7일을 조회한다.

```sh
cd /Users/kimyongjin/Desktop/horse_racing
.venv/bin/python -m horse_racing.jobs.horse_profile_medical
.venv/bin/python -m horse_racing.jobs.horse_profile_medical --start 2026-10-01 --end 2026-10-07 --apply
```

모든 페이지의 완전성·요청 지역·진료일을 먼저 확인한다. 현역 기본정보가 빈 응답이거나 같은 지역 응답에 말 ID가 중복되면 해당 조회를 적용하지 않는다. 진료를 먼저 처리하고 현재 기본정보를 마지막에 적용해 과거 진료의 마명으로 현역 기본정보가 끝나지 않도록 했다.

기존 저장기를 배치 조회 방식으로 개선했다. 진료 자연키에 병원명·진단명 null이 있어도 같은 입력을 반복 저장하지 않으며, PostgreSQL 지역·진료일별 트랜잭션 잠금으로 같은 저장기를 사용하는 동시 수집을 직렬화한다. 과거에 이미 존재하는 중복 행을 일괄 삭제하지는 않았다. 기본정보는 같은 관측 시각 재실행 시 중복 스냅샷을 만들지 않지만, 새로운 관측 시각에 조회하면 이력 보존용 스냅샷이 추가되는 것이 정상이다.

## 공식 홈페이지와의 차이: 장제사항 (2026-10-17)

사용자 결정으로 웹의 진료 목록과 건수 집계에서 장제소 기록을 제외한다.
경주 상세의 조교·진료 탭과 말 상세 진료 이력에 같은 기준을 적용한다.

| 항목 | 한국마사회 공식 홈페이지 | 현재 우리 서비스 |
|---|---|---|
| 진료와 장제 | 말 프로필의 진료사항·장제사항 탭으로 분리 | 진료만 제공하며 장제소 기록은 진료 목록·건수에서 제외 |
| 장제일·장제소 | 장제사항에서 제공 | API 원본의 날짜·기관명은 보존하지만 웹에서 장제로 제공하지 않음 |
| 장제부위 | 예: 사지 | 별도 수집·저장하지 않으며 표시하지 않음 |

공식 [어플리트런던 프로필](https://race.kra.co.kr/racehorse/profileTreatmentItem.do?Act=08&Sub=1&hrNo=0055953&meet=1)의
진료사항과 장제사항을 2026-10-17 직접 대조했다. 2026-09-20·2026-08-20의 트리플장제 두 건은
진료사항에 없고 장제사항에 있으며 부위는 모두 `사지`다. 우리 API16_1 원문에는 해당 행의
`illName1`·`illName2`가 `-`여서 진료 테이블에 기관명·날짜와 빈 진단명으로 들어왔다.
`horse_medical.stable_part`는 마방 번호이며 장제부위가 아니다.

표시 제외 기준은 **기관명(`hospital_name`)에 `장제`가 포함된 행**이다.
진단명이 비어 있다는 이유만으로 일반 동물병원 또는 기관 미제공 행까지 제외하지 않는다.
행 수 제한을 적용하기 전에 필터링하며, 목록·건수·최근 진료일을 같은 기준으로 계산한다.
API에 별도 장제 유형 값이 없으므로 기관명이 명시되지 않은 장제까지 분류했다고 보장하지 않는다.

원본 API 응답과 `horse_medical` 행, 진단명 연결은 삭제·변경하지 않는다.
이번 변경은 웹 표시 정책이며 진료 수집기나 연구용 원장·모델 입력의 제외 정책을 바꾼 것이 아니다.
