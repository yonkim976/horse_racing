## 독립 재현

H1 봉인 parquet과 protocol에 저장된 encoder에서 네 partition의 행렬을 다시 구성해 hash를 대조했다. 저장 Booster를 읽어 다음을 직접 계산했다. 검증 과정에서 실제 경마 tree를 학습하지 않았다.

- BINARY selector 252회, RACE_SOFTMAX selector 200회: 각 iteration의 raw-margin hash와 SciPy logsumexp로 계산한 경주 평균 CE가 제출 기록과 일치. CE 차이 1e-12 미만. 최소 CE iteration은 각각 172, 120이며 양쪽 모두 이후 80회에서 종료했다.
- 저장 refit의 calibration margin에서 독립 beta 도함수와 brentq로 temperature를 복원했다. T는 각각 1.1042565024236866, 1.0375393166443으로 일치했다. 두 끝 도함수 부호는 모두 음수/양수여서 내부해와 일관된다.
- calibration 1,808행·169경주와 validation 3,051행·288경주의 키·마번·중복을 원본과 대조했다. 저장 raw margin과 재추론의 최대 오차는 0, 독립 확률 계산 오차는 2.22e-16 이하다.
- validation에 공동우승·정확 확률 동점이 없음을 확인했다. log-domain winner-set NLL, CE, binary NLL, Brier, Top1/3/5를 독립 재계산했다. 모든 지표 차이 1e-12 미만이다.

## P2: 양 후보 temperature 통과 전 validation 계산

`scripts/run_confirmed_starter_e5b.py:584`에서 한 후보의 validation 예측을 만들고, 596행에서 지표를 계산한다. 이 함수는 1012행의 루프에서 BINARY부터 호출된다. 따라서 RACE_SOFTMAX의 temperature 검사 전에 BINARY validation 지표가 산출된다.

승인 지시서는 “양 후보가 승인된 flat 또는 interior 상태를 통과한 뒤에만 validation 비교를 수행한다”고 요구했다. 최종 paired comparison은 두 후보가 끝난 뒤 생성되지만, 개별 validation 평가에도 공통 통과 조건이 적용되도록 실행 경계를 명확히 해야 한다. 두 번째 후보가 실패할 때 첫 후보 평가만 남는 현재 경로는 재사용 전에 수정한다.

이번에는 양쪽 temperature가 통과했고, 첫 후보의 validation 값에 따라 둘째 후보 설정을 바꾸는 코드 분기도 발견하지 않았다. 저장 수치와 최종 비교는 재현되므로 이 편차 때문에 결과를 무효화하거나 실제 학습을 반복하지 않는다. 새 연구 runner에서 준비·학습·보정과 validation 평가를 분리하고, 두 번째 후보 실패 시 validation 함수 호출과 산출물이 모두 0인 합성 회귀 테스트를 추가한다. 기존 E5-B 봉인 파일은 보존한다.
