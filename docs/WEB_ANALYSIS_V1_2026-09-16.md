# 예측·검증·개인 분석 웹서비스 V1 보고서

작성일: 2026-09-16 (KST)

## 구현 범위

- 기존 경주·거리·말·기수·조교사·마주·데이터·예측 원장 화면과 URL을 유지했다.
- `/forecast`: 예정 경주를 날짜, 경마장, 거리, 등급으로 선택하고 출전마·기수·마번·부담중량,
  최근 성적, 동일거리 표본, 초반 통과순위 및 G1F 근거를 조회한다. 불변 원장에 연결된 확률만
  정식 예측으로 표시한다.
- `/validation`: 사전 공개(`live`)와 과거 재현(`historical`)을 분리하고 모델 데이터셋 버전별로
  조회한다. 예상/실제 순위 차이와 정산된 표본의 Top1, Top3 포함률, MAE, Win Log Loss를
  표시한다. DB에 결과가 있어도 원장이 미정산이면 비교만 보여 주고 지표에서는 제외한다.
- `/analysis`: 공통 필터, 최대 8두 비교, 최근 순위, 거리별 입상률, 초반 위치/G1F 표본,
  기수 요약, 말·기수 조합, 동반 출전 상대전적, 정렬·열 선택 표, 연결 강조, CSV 내보내기,
  조건 저장 및 메모를 제공한다.
- 예상 전개는 출발/초반/중반/종반, 재생/정지, 슬라이더, 느림/보통/빠름 가정을 제공한다.
  이는 공식 GPS가 아니라 과거 구간 통과순위 기반 탐색용 배치이며 모델 원장을 변경하지 않는다.

## 데이터 및 신뢰성 경계

- 미래 경주 이력은 현재 경주일보다 이른 경주만 조회한다.
- 실격 및 90 이상 예외 순위 코드는 일반 순위 통계에서 제외한다.
- 우승/입상 확률은 `model_predictions`에 발행된 값만 표시한다. 점수나 휴리스틱을 확률로
  변환하지 않는다.
- 현재 DB의 2026-09-17~19 예정 경주는 제주 출전표이며 연결된 불변 모델 예측이 없어
  `예측 미발행`으로 표시된다.
- 현재 두 live 발행(2026-08-28, 2026-09-04)은 아직 `prediction_settlements`가 없다.
  실제 순위 비교는 가능하지만 성능 요약 표본은 0으로 유지된다.
- 분석 조건과 메모는 브라우저 `localStorage`에 저장되므로 다른 기기와 공유되지 않는다.

## 성능과 운영 구조

- 필터 범위와 응답 행 수를 제한하고, 예정 경주 및 기수 조회용 복합 인덱스 2개를 추가했다.
- 데이터/HTML 응답 모두 20초 TTL 캐시를 사용한다. 같은 키의 첫 계산은 한 번만 실행되어
  빈 캐시에 동시 요청이 몰려도 동일 통계를 반복 계산하지 않는다. 출전표 변경 반영 지연은
  최대 20초다.
- 수집과 모델 계산은 계속 CLI/배치 경로에 남아 공개 GET 요청과 분리된다.
- 재현 가능한 혼합 부하 도구는 `scripts/load_test_web.py`다. 경주 목록, 미래 목록/상세,
  검증, 개인 분석, 경주 상세의 6개 경로를 순환한다.

로컬 단일 Uvicorn 프로세스, SQLite WAL, Apple Silicon 환경에서 측정한 결과:

| 상태 | 동시 클라이언트 | 총 요청 | 처리량 | 중앙값 | p95 | 오류율 | 서버 최대 RSS | 서버 최대 CPU |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 캐시 없음 | 30 | 120 | 263.9 req/s | 67.5 ms | 298.5 ms | 0% | 143.3 MiB | 86.9% |
| 캐시 준비 | 1,000 | 1,000 | 176.6 req/s | 5,440.9 ms | 5,611.8 ms | 0% | 154.2 MiB | 0.6% |

1,000명 테스트는 1,000 RPS가 아니라 **1,000개 연결이 동시에 각 1회 요청**한 조건이다.
모든 요청은 성공했지만 p95 5.6초이므로 운영 1,000명 성능을 통과했다고 보지 않는다. 로컬
클라이언트와 서버가 같은 장비에서 동시에 1,000 소켓을 여는 영향도 포함되어 있다.

## 보안

- 공개 웹 계층은 읽기 전용 GET이며 수집·모델 실행·관리 명령은 CLI에만 있다.
- FastAPI 타입/범위/길이 검증과 SQLAlchemy 바인딩을 사용한다.
- Jinja 자동 이스케이프와 동적 SVG 문자열 이스케이프를 적용했다.
- CSP, `nosniff`, frame deny, referrer 및 permissions 정책 헤더를 설정했다.
- 프로세스 단위 IP 버스트 제한은 분당 2,400 요청이며 429와 `Retry-After`를 반환한다.
- `.env`와 SQLite 데이터는 Git에서 제외되며 브라우저 응답에 비밀값을 포함하지 않는다.

## 검증과 남은 작업

- 전체 테스트: 812 passed, 경고 2건(기존 Starlette deprecation 및 Polars sortedness 경고).
- 실제 브라우저에서 미래 전개 시나리오 변경, 말 선택에 따른 지도/표 강조, 분석 그래프,
  열 숨김, 메모 자동 저장, 검증 실제순위 표시를 확인했다.
- 반응형 레이아웃은 1,100/720/430px 구간을 구현했다. 이번 실행 환경에서는 별도 모바일
  viewport 캡처를 만들지 못했으므로 실제 iOS/Android 터치 검증은 배포 전 남은 항목이다.
- 운영 전에는 PostgreSQL/Supabase 이전, Redis 같은 공유 캐시·분산 rate limit, 다중 worker,
  reverse proxy의 신뢰할 수 있는 client IP 설정, 구조화 로그/메트릭/알림이 필요하다.
- 실제 배포 환경에서 브라우저 캐시 무효화, 1,000 동시 연결과 목표 RPS를 별도로 측정하고
  서비스 SLO에 맞는 p95 기준을 통과해야 한다.
