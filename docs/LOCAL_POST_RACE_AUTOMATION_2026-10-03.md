# 로컬 확정배당과 결과 보완 자동화

로컬·Google Cloud 예약과 매일 03:00 로그 정리의 현재 전체 목록은 [자동 수집 통합 운영 안내](DATA_COLLECTION_AUTOMATION_OPERATIONS_2026-10-05.md)에 있다. 로컬 로그는 압축 보관 후 내용만 비우고 7일 초과 압축본만 삭제하며, 이 문서의 상태·원문·검증 기록은 삭제 대상이 아니다.

2026년 10월 3일 사용자 요청으로 이 Mac에 확정배당 수집과 최근 결과 정정 및 누락 보완 예약을 추가했다. 실행 위치는 노트북이며 저장 대상은 기존 Supabase `horse-racing-prod` 프로젝트 `xkykmhhkjtosptoibduo`다. 로컬 SQLite 자동 동기화, 모델 재예측, 웹 배포나 신규 Google Cloud 리소스 생성은 포함하지 않는다.

기존 주간 출마표와 매일 조교 클라우드 예약 및 당일 2분 수집기는 유지한다. 이번 추가 작업은 예측 모델이나 AI 채팅을 호출하지 않는다.

## 실행 일정

| 작업 | 로컬 예약 이름 | 실행 주기 | 대상 |
| --- | --- | --- | --- |
| 확정배당 | `com.horse-racing.closing-dividends` | 약 15분 간격 | 오늘 출마표의 완료 경주 |
| 결과와 배당 사후 보완 | `com.horse-racing.post-race-repair` | 매일 09:00 및 20:30 | 실행일 포함 최근 7일 중 운영 출마표가 있는 날짜 |

배당은 오늘 첫 경주 예정 시각 1시간 전부터 마지막 경주 예정 시각 2시간 후까지 조회하며, 09:00 이상 22:00 미만 제한도 적용한다. 예정 시각이 누락되면 기존 당일 수집기의 09:00~21:00 대체 창을 따른다. 아직 시작 예정 시각이 되지 않은 오늘 경마장은 사후 보완 조회에서도 건너뛴다. 미래 날짜의 값은 적재하지 않는다.

출마표가 있으면 서울·제주·부경·영천을 각각 대상으로 한다. 모든 API의 지역별 제공 완전성을 보장하는 것은 아니며 미제공과 오류를 실행 기록에 남긴다. 없는 경주나 출전마를 API 응답만 보고 자동 생성하지 않는다.

Mac의 시스템 시간대 `Asia/Seoul`을 확인했다. 두 LaunchAgent 등록을 확인했고 배당 예약의 최초 야간 실행은 수집을 건너뛰며 종료 코드 0으로 끝났다. 실제 예약 시각이 정확히 15분마다 보장되거나 API 공개 뒤 15분 안에 반영된다는 뜻은 아니다.

## 확정배당 저장 기준

원천은 [한국마사회 확정배당율 통합 정보](https://www.data.go.kr/data/15058559/openapi.do)의 API301이다. 단승·연승·복승·복연승·쌍승·삼복승·삼쌍승의 제공 조합을 기존 `odds_snapshots`에 저장한다. 경주 전 실시간 변동 배당 수집이 아니다.

- 운영 출마표의 결과 범위가 갖춰지고 완료 상태이며, 1위 말의 양수 완주기록이 있는 경주만 선택한다. 공식 공동 1위도 허용한다.
- API에 양수 값이 있어도 미완료 경주와 전체 취소 경주는 적재하지 않는다.
- 날짜, 지역, 경주번호, 출전번호, 승식, 선택 조합과 중복 충돌을 검사한다.
- 원문 페이지 수와 전체 건수를 확인한다. 선택한 경주의 7개 승식 중 빠진 승식이 있으면 해당 경주는 발표 대기로 남긴다.
- 0과 미제공 값으로 정상 저장값을 덮어쓰지 않는다. `9999.9` 등 원문 특수값은 보존하며 일반 배당과의 표시·분석 구분은 별도다.
- 업무 키는 경주·승식·선택 조합이다. 같은 값의 재조회는 새 행을 만들거나 관측 시각을 덮어쓰지 않는다.
- 배당 정정은 기존 행을 수정하고 이전 값과 관측 시각을 로컬 변경 기록에 보존한다. 저장 후 다시 읽어 원문과 대조한다.
- 원천에서 사라진 기존 양수 조합은 임의 삭제하지 않는다. 공식 출전 제외와 현재 원천의 0값으로 확인되는 예외만 보존하며, 설명되지 않는 누락은 오류로 처리한다.

과거 취소 관련 6,645행의 보존 정책과 미확인 8월 자료는 [2026년 배당 검증 보고서](DIVIDEND_BACKFILL_2026_THROUGH_2026-10-02.md)를 따른다. 이번 작업에서 과거 예외 행을 삭제하거나 화면 필터를 바꾸지 않았다.

## 결과 정정과 누락 보완

API155는 결과가 없는 출전행의 빈 부분을 채우고, API156 상세 결과는 공식 제공된 착순·완주기록·착차·상금·비고 등의 정정을 반영한다. 레이팅과 주로 및 날씨 등 제공된 상세 값도 기존 반영 규칙을 따른다. 기존 마체중은 결과 응답으로 덮어쓰지 않는다.

기존 출마표와 공식 말 ID, 출전번호, 날짜, 지역, 거리의 연결이 맞아야 한다. 미발표 착순 0은 결과로 넣지 않으며, 빈 응답이나 null은 정상 기록을 지우지 않는다. 기수변경·취소·출마표를 이 사후 작업에서 재적재하지 않는다. 상세 결과의 말별 제공 범위가 부족하거나 결과·배당이 아직 준비되지 않으면 미완료로 남긴다.

누락 보완은 기존 경주와 출전행에 대한 결과 보완이다. 운영 출마표 자체가 빠진 경주를 복원하는 작업은 아니다. 새 구간시간·통과착순·통과조 원천과 심판리포트도 포함하지 않는다. 7일을 넘어 뒤늦게 정정된 자료는 별도 수동 검증이 필요하다.

## 중복 방지와 운영 안전성

두 새 작업과 기존 당일 수집기는 같은 로컬 파일 잠금과 PostgreSQL advisory lock을 공유한다. 기존 배당 백필 잠금도 함께 사용한다. 겹치면 새 작업은 건너뛰며, 장시간 대기하거나 동시에 쓰지 않는다. 한 번 건너뛴 사후 보완은 다음 예약이나 수동 실행으로 재확인해야 한다. 다른 모든 수집기까지 막는 전역 잠금은 아니다.

API를 가져오는 동안 쓰기 트랜잭션을 유지하지 않는다. 단계별 저장은 독립적으로 커밋되므로 일부 오류가 있어도 성공한 다른 단계는 남을 수 있다. 실행 상태 `completed`, `partial`, `failed`를 구분한다. 변경 전 값은 커밋 전에 별도 파일로 남긴다.

원문은 내용 해시가 달라질 때만 `data/raw/kra/post_race_*`에 새로 보관하고 기존 `source_documents`에 출처를 연결한다. 실행 이력은 매 실행 남는다. 상태 파일을 잃으면 동일 원문이 다시 보관될 수 있지만 업무 키 중복 방지는 유지한다.

사후 작업끼리 하루 endpoint별 300회 안전 제한을 공유한다. 이는 노트북 사후 수집기만의 제한이며 기존 2분 수집기·클라우드 작업·다른 프로그램의 호출량을 합산한 계정 한도는 아니다. HTTP 재시도는 최대 두 번이며 무한 재시도하지 않는다. 남은 로컬 디스크가 2GiB 미만이면 중단한다.

## Discord 알림

기존 웹훅을 그대로 사용한다. URL과 API 키 및 DB 비밀번호를 코드·문서·로그에 기록하지 않는다.

- 배당 자동 수집은 신규·수정 또는 오류가 있을 때 요약을 보낸다. 변경이 없거나 발표 대기만 있으면 알리지 않는다.
- 매일 사후 보완과 수동 실행은 변경이 없어도 완료·미완료·오류 집계를 보낸다.
- 알림은 DB 잠금과 연결을 정리한 뒤 보낸다. 메시지 저장 확인을 받으며 전체 mention을 끈다.
- 알림 실패로 성공한 DB 적재를 되돌리거나 다시 수집하지 않는다. 전송 결과가 모호하면 자동 재전송하지 않는다.
- Mac 종료·권한 차단 등 프로그램 시작 전의 장애를 독립적으로 감시하는 경보는 없다.

## 수동 실행과 상태 확인

프로젝트 위치에서 아래 명령을 사용한다. 기본은 계획 확인이며 `--apply`가 있어야 실제 쓰기가 발생한다.

```sh
.venv/bin/python -m horse_racing.jobs.local_post_race --mode dividends --apply
.venv/bin/python -m horse_racing.jobs.local_post_race --mode repair --apply
.venv/bin/python scripts/manage-local-post-race.py status
```

최근 특정일까지 확인할 때는 `--through YYYY-MM-DD`와 필요하면 `--lookback 1`을 사용한다. 실행일 기준 최근 7일 밖이나 미래 날짜는 거부한다. 예약 실행은 날짜 override를 허용하지 않는다.

```sh
.venv/bin/python scripts/manage-local-post-race.py stop
.venv/bin/python scripts/manage-local-post-race.py install
```

위 관리 명령은 새 로컬 예약 두 개만 대상으로 하며 기존 당일 2분 예약이나 클라우드 예약을 변경하지 않는다.

2026-10-05 복구 이후 자동 실행 로그는 `/Users/kimyongjin/Library/Logs/horse-racing/local-closing-dividends.log`와 같은 폴더의 `local-post-race-repair.log`, 각각의 `.err.log`다. 기존 `data/logs` 로그는 과거 기록으로 보존한다. 상태는 `data/state/local-post-race.json`, 실행 검증은 `data/state/post-race-audit-실행ID.json`, 변경 전후 값은 `data/state/post-race-change-*`에 남는다. Supabase 실행 원천은 `laptop/post-race/v1`이다.

## 사용 조건과 남은 작업

Mac 로그인·인터넷·잠자기 해제가 필요하다. Codex와 터미널을 닫아도 launchd는 실행할 수 있지만, Mac을 끄거나 뚜껑을 닫으면 계속 수집된다고 보장하지 않는다. 컴퓨터가 꺼져 놓친 자료는 다음 최근 7일 보완 또는 수동 실행에서 재조회한다.

신규 유료 클라우드 리소스를 만들지 않았지만 기존 Supabase와 비밀값 접근·네트워크·저장 용량 등 비용이 0이라는 뜻은 아니다. 정확한 추가 청구액은 이번에 측정하지 않았다.

새 구간 원천·심판리포트·진료·주행심사·기본정보 등의 별도 정기 자동화, 최신값의 프론트 표시와 취소 배당 필터, 입력 변경에 따른 모델 재예측은 여전히 별도 작업이다.

## 2026-10-05 재시동 복구

macOS의 바탕화면 로그 접근 차단으로 시작 실패한 자동 작업의 로그를 `Library/Logs/horse-racing`으로 분리하고 두 LaunchAgent를 재등록했다. 배당 900초 간격·로그인 시 실행과 결과 보완 09:00·20:30 예약은 유지했다. 이전 예약 파일은 `tmp/launchd-recovery-20261005/*before.plist`에 보존했다. 재부팅 자체를 다시 실행하지는 않았다.
