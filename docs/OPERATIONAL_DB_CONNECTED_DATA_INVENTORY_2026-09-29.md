# 운영 DB 연결 데이터 전수 목록 — 2026-09-29

## 범위와 읽는 법

- 대상: 로컬 `data/horse_racing.sqlite3`와 Supabase `horse-racing-prod` (`xkykmhhkjtosptoibduo`)의 애플리케이션 `public` 테이블.
- 조회 기준일: 2026-09-29. 아래 수치는 각 테이블의 `count(*)`로 확인한 **실제 행 수**다. Supabase 목록 도구의 추정 행 수는 사용하지 않았다.
- 로컬의 `alembic_version` 및 Supabase의 `auth`·`storage` 등 플랫폼 관리 스키마는 업무 테이블 수에서 제외했다. 로컬 업무 테이블은 **46개**, Supabase 업무 테이블은 **44개**다.
- `로컬 / Supabase` 순서로 건수를 썼다. `—`는 0행이 아니라 **테이블 자체가 없음**을 뜻한다.
- 같은 행 수는 내용의 완전한 동일성을 증명하지 않는다. 이 문서는 구조·연결·건수 목록이며 전체 행별 해시 비교는 아니다.
- 이 조사와 문서 작성은 읽기 전용으로 진행했다. 운영 DB 데이터와 스키마를 수정하지 않았다.

## 핵심 연결 구조

```text
racecourses → races → race_entries → race_results
                    │               └→ race_section_times / race_section_results
                    ├→ race_passing_groups / race_passing_summaries
                    └→ odds_snapshots

horses / jockeys / trainers / owners → race_entries
horses → 프로필·등급·레이팅·마체중·진료·조교·수영·언덕훈련

prediction_runs → model_predictions → model_prediction_explanations
                └→ prediction_model_components
```

`race_entries`가 경주와 말·기수·조교사·마주를 연결하는 중심 테이블이다. 다만 일부 부가 자료는 외래키로 경주에 직접 연결되지 않고 **경마장·날짜·경주번호·마번**의 조합으로 대응한다. 아래에서 이 차이를 표시한다.

## 확인된 차이와 최신성

1. **로컬 전용 구조:** `medical_diagnosis_terms` 5,397행, `horse_medical_diagnoses` 676,047행. Supabase에는 두 테이블이 없다. 반면 양쪽에 `horse_medical` 원문 697,695행은 있다.
2. **Supabase에만 실제 예측 설명 데이터:** `prediction_runs`는 로컬 2·원격 10, `model_predictions`는 326·729, `prediction_model_components`는 0·14, `model_prediction_explanations`는 0·2,418이다.
3. **기타 건수 차이:** 말 기본정보 로컬이 1건 많고, 프로필은 로컬이 3건 많으며, 등급변동은 로컬이 1건 많다. 원천 문서는 Supabase가 126건, 수집 실행은 108건 많다. 이 차이의 원인은 이 목록 조사만으로 확정하지 않았다.
4. **연결 범위 주의:** 언덕주로는 3,576건 중 364건만 운영 말 ID에 연결돼 있다. 심판리포트·취소·기수 변경 등 일부 자료는 경주 ID가 아니라 날짜·번호를 통한 논리적 연결이다. 조교사 상태표 59행은 전체 조교사 분류표가 아니다.
5. **최신성:** 양쪽 `races`의 마지막 경주일은 **2026-09-20**이다. 로컬 기준 진료일의 마지막은 2026-09-22, 일반 조교일은 2026-09-21, 언덕주로 훈련일은 2026-09-22다. 2026-09-29 현재 경주·결과가 완전히 최신이라고 간주하면 안 된다. 가장 최근 경주 이후 실제 시행 여부와 누락 범위는 별도 수집 점검이 필요하다.
