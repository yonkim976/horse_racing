# 경마장별 주로 상태 이력 확인 (2026-09-14)

## 결론

한국마사회 경주기록 API(`API4_3/raceResult_3`)에서 서울·제주는 2000-01-08, 부산경남은 2004-11-28부터 경주별 과거 주로 상태가 확인된다. 따라서 주로 상태의 **사후 기록 유무만을 이유로** 앞서 제안한 API 기반 경주결과 수집 시작일을 늦출 필요는 없다. 다만 이는 2026년에 조회한 역사적 결과값이며, 해당 값이 각 과거 경주 출발 **전에** 공개되어 있었다는 증거는 아니다.

| 경마장 | 확인된 API 첫 날짜 | 초기 값 예시 | 첫 확인 연도 행/경주 | 주로 상태 비어 있지 않은 행 | 숫자 함수율 파싱 행 | 경주 내 값 충돌 |
|---|---|---|---:|---:|---:|---:|
| 서울 | 2000-01-08 | `다습 (13%)` | 12,519 / 1,114 | 12,519 | 11,910 | 0 |
| 제주 | 2000-01-08 | `양호 (8%)` | 8,488 / 903 | 8,488 | 8,488 | 0 |
| 부산경남 | 2004-11-28 | `양호 (6%)` | 306 / 38 | 306 | 306 | 0 |

서울 2000년의 나머지 609행은 숫자가 없는 `불량 (%)` 형태였다. 상태 범주는 있지만 함수율을 임의로 채우면 안 된다. 동일 날짜에도 경주마다 함수율이 달라질 수 있으므로 날짜 단위 상수로 묶지 않는다.

위 수치는 [첫 연도 API 감사 JSON](../data/logs/historic_track_first_year_20260914.json)의 응답 원문 집계다. 공식 [경주기록 API 안내](https://www.data.go.kr/data/15058305/openapi.do)는 제공 항목에 날씨와 주로를 명시한다.

## 현재 로컬 DB

`data/horse_racing.sqlite3`의 `races.track_condition` / `track_moisture_percent`를 2026-09-13까지 읽기 전용으로 확인했다. 2015년에는 서울 상태 1,113/1,113경주·함수율 1,033경주, 제주 상태 428/428·함수율 400, 부산경남 상태 803/813·함수율 774였다. 2025년 상태는 서울 1,042/1,042, 제주 722/722, 부산경남 717/717이다. 2026년은 서울 751/751, 제주 534/534, 부산경남 530/530이며, 2026-09-13 뒤로 등록된 제주 예정 경주 22건의 상태 공란은 이 시행 경주 분모에 넣지 않았다. 이 DB는 2000년부터 정규화된 이력을 담고 있지는 않으므로, 오래된 API 자료를 수집·정합 검증해야 한다.

## 더 오래된 공식 웹 화면의 부분 기록

공식 영문 경주 상세 화면의 연도별 **1경주 표본**에서는 서울 [1986-12-22](https://race.kra.co.kr/globalEn/resultsRaceDetailSeoul.do?rcDate=19861222&rcNo=1)에 `Sloppy` 범주, [1993-12-26](https://race.kra.co.kr/globalEn/resultsRaceDetailSeoul.do?rcDate=19931226&rcNo=1)에 `Good (6%)`가 보였다. 제주 [1993-12-19](https://race.kra.co.kr/globalEn/resultsRaceDetailJeju.do?rcDate=19931219&rcNo=1)에 `Sloppy`, [1994-12-18](https://race.kra.co.kr/globalEn/resultsRaceDetailJeju.do?rcDate=19941218&rcNo=1)에 `Good (10%)`가 보였다. 하지만 서울 1985년과 제주 1990~1992년의 조사한 표본에는 상태가 없고, 다른 연도 표본에는 범주 또는 함수율 한쪽만 있는 사례가 있었다. [표본·URL·원문 해시](../data/logs/pre2000_track_web_year_samples_20260914.json). 이는 각 연도의 마지막 경주일 1경주만 확인한 결과로, 절대 최초일이나 전 경주 coverage가 아니다.

Text `dacom13`은 경마장마다 형식이 다르다. 로컬 원문 조사에서 제주 2,122개 파일 중 2,025개에 `주로상태`가 있었고 2003-07-12 첫 파일에도 `불량 (20.0%)`이 있었다. 그 파일 헤더의 시각은 **18:55**이므로 사전 공개 근거가 아니다. 서울 약 2,202개, 부산경남 1,928개 파일에는 같은 필드가 없었다. [원문 수집 감사](../data/logs/historical_text_dacom13_audit_20260914.json). 따라서 `dacom13`을 세 경마장의 공통 주로 상태 원천으로 취급하면 안 된다.

## 모델에서의 취급

과거 경주의 결과 API 주로 값은 말의 이전 경주 당시 조건을 설명하는 **이력 feature**로 사용할 수 있다. 대상 경주 당일의 상태는 사전 시점에 실제 관측된 버전만 사용해야 한다. `AI학습용 경주계획` API의 역사적 `going` 응답 역시 현재 조회 결과일 뿐 과거의 게시 시점을 증명하지 않는다. 따라서 이력 학습과 실전 예측에서는 `관측 시각 <= 예측 cutoff`를 확인하고, 근거가 없는 대상 경주의 최종 주로 상태를 T-30 예측 입력으로 섞지 않는다. 현재 실전에서 당일 주로 상태를 확보할 수 있다면 상태 갱신 전 기본 예측과 갱신 후 예측을 분리하는 것이 타당하다.
