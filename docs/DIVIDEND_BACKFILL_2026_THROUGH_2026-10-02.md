# 2026년 배당 적재와 검증 결과

2026년 1월 1일부터 10월 2일까지 운영 DB에 등록된 확정 경주의 배당을 로컬 SQLite와 Supabase에 보완하고 전량 대조했다. 양쪽에 각각 58,944행을 추가했으며, 확인 대상 배당의 누락과 값 불일치 및 중복은 0건이다. 실행 중 날짜가 10월 3일로 바뀌었지만 요청 당시 기준일인 10월 2일을 유지했다.

이 결과는 운영 DB의 확정 경주 범위에 대한 완료다. API에 있지만 정식 경주 여부가 확인되지 않은 8월 자료까지 모두 적재했다는 뜻은 아니다. 취소 관련 기존 값과 특수 배당값도 정상 정산 배당과 구분해야 한다.

## 대상과 저장 결과

- 기존 모델, 예측 원장, 제주 및 더러브렛 연구 DB, 배포와 자동화 예약은 변경하지 않음

## 원천과 검증 방법

공식 API301 재조회 자료 134개 날짜와 경마장 조합 및 보존된 공식 API 원문 90개 조합을 사용했다. 과거 보존 자료는 페이지별 SHA256, 전체 응답 건수, 페이지 완전성, 날짜와 지역 및 운영 경주와 출전번호 연결을 확인했다. 모두 이번 시각에 재조회한 자료는 아니다.

검증에 사용한 원문은 총 2,273,480행이다. 0과 미제공 값은 정상 양수 배당으로 새로 넣지 않았으며, 전체 취소 경주의 양수 응답도 확정 정산 배당에서 제외했다. 적재 후 별도 검증 프로그램이 두 운영 DB의 대상 기간 전체 배당을 다시 읽어 원문과 대조했다.

관련 프로그램 테스트는 기존 당일 수집 테스트를 포함해 13개가 통과했다. 스키마 변경, 유료 인프라 추가, 배포, 별도 Discord 발송이나 배당 자동 수집 예약은 하지 않았다.

## 정상 정산과 구분해야 하는 값

### 전체 경주 취소

제주 3월 20일 8경주, 3월 21일 6경주, 4월 4일 6경주가 취소로 확인됐다. 특히 4월 4일은 취소인데도 API와 기존 운영 DB에 양수 배당 6,240행이 남아 있다. 이를 실제 정산 가능한 확정 배당으로 취급하지 않았다. 기존 관측값은 삭제하지 않고 그대로 보존했다.

### 출전 제외 말이 포함된 기존 조합

서울 9월 5일 4경주 5번 말 관련 229행과 제주 같은 날 7경주 7번 말 관련 176행은 공식 출전 제외 상태이며 현재 API 배당이 0 또는 미제공이다. 기존 DB에는 양수 값이 남아 있어 총 405행을 별도 보존 예외로 기록했다.

위 6,240행과 405행의 합계가 보존 예외 6,645행이다. 검증에서만 별도로 분리했으며 운영 테이블에서 삭제하거나 유효성 컬럼을 새로 만들지는 않았다. 프론트 조회도 변경하지 않았다. 화면 표시와 환급 계산에서는 취소 경주 및 출전 제외 말이 포함된 조합을 필터링하는 별도 적용이 필요하다.

### 특수 배당값

확인 대상 양수 배당 중 `9999.9`가 222,812행 있다. 원문 그대로 보존했으며 이번에 일반 배당값으로 재해석하지 않았다. 기존 분석 코드의 특수값 제외 규칙과 구분하여 사용해야 한다.

## 보류한 API 자료

8월 월별 API 응답에는 운영 DB에 없는 날짜와 경주번호의 자료가 있다. 제주 8월 25일과 26일, 부경 8월 26일, 영천 8월 24일과 25일 및 31일 자료가 이에 해당한다. 서울도 월별 건수와 운영 경주일별 합계에 차이가 있지만 월 전체 조회가 일시적 API 오류로 끝나 세부 범위를 확정하지 못했다.

영천의 해당 날짜 결과 API에는 착순 0이나 기록 미제공 행 등이 있다. 정식 시행과 정산 여부가 미확인인 상태이므로 시험 자료라고 단정하지도, 새 운영 경주를 만들어 배당을 넣지도 않았다. 원문과 조사 결과는 별도 검증 폴더에 보존했다. 이 자료의 공식 개최 및 성적표 대조는 후속 과제다.

10월 월별 응답에는 아직 종료하지 않은 10월 3일과 4일의 양수 값도 있었다. API에 양수 값이 있다는 사실만으로 확정 배당이라고 판단하면 안 되므로 이번 적재 범위에서 제외했다.

## 검증 근거와 재실행

검증 자료는 `data/research/dividend_backfill_20261002_verified/`에 있다.

- `report.json`: 날짜와 경마장별 적재 결과, 보존 예외 값, 전량 검증 완료 표시
- `verification.json`: 두 운영 DB의 전량 대조 결과
- 날짜와 경마장별 JSON: 원문 페이지 경로와 SHA256
- `monthly_header_audit.json`, `monthly_scope_audit.json`: 월별 API 범위 조사
- `preopening_results_audit.json`: 미확인 영천 날짜의 결과 API 조사

재검증은 기존 비밀값 로딩 환경에서 아래 명령으로 실행한다. 운영 DB는 읽기만 하며 검증 보고서 파일을 갱신한다.

```sh
.venv/bin/python scripts/verify_dividend_backfill.py \
  --run-dir data/research/dividend_backfill_20261002_verified
```

실제 보완 프로그램은 `scripts/backfill_dividends_verified.py`이며 기본은 검토 모드다. DB 쓰기는 `--apply`를 명시해야 한다. 매일 배당을 자동 수집하도록 연결한 것은 아니므로, 이번 완료와 앞으로의 자동 최신화는 별개다.
