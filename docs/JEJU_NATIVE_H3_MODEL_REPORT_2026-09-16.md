# 제주마 H3 출전 조건 보강·세 목표 재평가 결과

작성일: 2026-09-16 · 실험: `jeju_h3_declared_conditions_v3`

## 1. 결론

**출전표 원문 기반 조건 데이터와 과거 기수·조교사 상태를 추가하고 세 목표의 학습·평가를 완료했다.** 같은 2025년 715경주에서 이번 수치상 최고는 한 마리 입상 **445/715(62.24%, P_H3)**, 세 마리 집합 **57/715(7.97%, R_H3)**다. 정확순서는 기존 **18/715(2.52%, M0_H2)**가 최고를 유지했다.

입상은 이전 최고보다 1경주, 집합은 8경주 증가했지만 **짝지은 적중률 차이의 95% 구간이 0을 포함하므로 개선이 확정되었다고 판단하지 않는다.** 확률 손실은 개선됐으며, 현재 확인한 결과는 ‘정답에 부여하는 확률은 나아졌지만 최고확률 결과의 완전 적중은 아직 뚜렷하게 좋아지지 않았다’이다.

현재 입력 변수는 중복 alias를 제외한 기존 49개에 H3 19개를 추가한 **68개**다. 상대 비교 14개까지 시험한 H3R은 **82개**다. 전체 등록·검토 항목은 기존 57개와 신규 33개로 총 90개이며, 이 중 중복 alias 8개를 학습에서 제외한다. 결측 표시와 시대 인코딩을 거친 실제 입력 열 수는 H3 83개, H3R 105개였다.

## 2. 실제로 보강한 데이터

### 원문 파서 누락과 복구

기존 text dataset의 `entry_card` 추출기는 마주 이름 뒤에 레이팅 숫자가 추가된 행을 인식하지 못했다. 그 표만 사용하면 레이팅이 있는 출전마가 누락될 수 있었다. 새 H3 파서는 원본 `dacom01` 파일을 읽고 **선택적 레이팅 열, 수습기수 감량 표기, 구형 ‘출주’ 거리 헤더**를 처리한다. 기존 DB나 봉인 dataset을 덮어쓰지 않고 별도 feature artifact를 생성했다.

문서의 해당 경주일·경주번호·마번과 공식 출전 키를 연결하고 마명·제주마 표시·거리를 대조했다. 예측 경주 전전날보다 늦은 날짜의 문서는 사용하지 않았다. 구형 ‘승군순위’ 열을 레이팅으로 오인하지 않도록 **헤더에 ‘레이팅’이라고 적힌 경우에만 숫자를 채택했다.**

| 구간 | 출발행 | 출전표 연결 | 비고 |
|---|---:|---:|---|
| 2018-08-31 이전 상태 초기화 | 36,523 | 36,117 | 미연결은 결측으로 유지 |
| 2018-08-31~2024 계수 학습 후보 | 36,255 | 36,249 | 6행 결측, 경주·말 삭제 없음 |
| 2025 개발 | 6,953 | **6,953** | 715경주 전부 유지 |
| 2026 역사 구간 | 4,852 | 4,852 | feature만 구성, 모델 평가 없음 |

2025년 레이팅은 **5,648/6,953행**, 숫자 등급은 **6,874/6,953행**에서 관측됐다. 공란이나 특별 경주 등의 값을 실제 0등급·0레이팅이라고 만들지 않는다. 결측 대체는 각 FIT의 통계와 결측 표시로 처리한다.

### 당시 정보의 의미와 한계

현재 출전 조건은 결과 API의 사후 값으로 대체하지 않고 **해당 경주 선언 출전표**에서 가져왔다. 실제 최종 기수·중량으로 선언 값을 덮어쓰지 않는다. 문서 날짜가 T-2 이전이라는 근거는 있지만, 보관된 자료를 수집한 시점은 2026년이다. **정확한 역사 공개시각과 이후 정정 이력은 입증하지 못했으므로 `DATED_DECLARATION_ASSUMED_PUBLICATION_NO_REVISION_ARCHIVE` 연구 조건이다.** 실제 경주 전에 확보한 원장을 복원했다고 주장하지 않는다.

`declared_horse_number`는 출전표의 **마번**이다. 실제 출발대 게이트 번호와의 대응을 독립적으로 확인하지 않았으므로 게이트 자체로 확정하여 표현하지 않는다. 현재 체중·당일 주로·배당·사후 교체 사실은 이번 H3에 넣지 않았다.

## 3. 현재 고려하는 모든 변수의 구조

아래는 중복 제외 후 변수 수다. 상세 문서에는 중복 alias 8개도 별도로 표시해 기존 57개 registry와 빠짐없이 대조할 수 있다.

| 묶음 | 변수 수 | 내용 |
|---|---:|---|
| H0 결과 상태 | 16 | 전역·거리 Elo, 불확실성 대용치, 전체·거리별 출전/완주/우승/입상 횟수, 최근 출전·완주 이후 일수, 최근 5회 성적·입상률·변동성 |
| 공통 경주 조건 | 3 | 거리, 실제 출발 두수, 시대 구분 |
| H1 시간·구간 | 10 | 같은 거리 100m당 시간, 거리·시대 기준 대비 시간 잔차 평균/표준편차, 시간 관측 수, 전체·거리별 유효 시간 횟수, 초반 200m/210m와 결승 전 200m/600m 평균 |
| H2 상태 보조 | 20 | 최근 28일 조교 횟수/시간/구보/습보, 출발조교, 90일 진료, 과거 주행심사 횟수/기록, 최근 과거 체중/관측 수, 각 원천의 관측 및 coverage 미확인 표시 |
| H3 출전표·사람 이력 | 19 | 출전표 관측 여부, 마번, 연령, 암말/거세 여부, 부담중량, 레이팅, 등급, 기수 감량, 기수/조교사 과거 출전·승률·입상률, 말×기수 출전·입상률, 과거 ID 연결 확인 여부 |
| H3R 상대 비교 | 14 | 전역 Elo·거리 Elo·보정 시간·레이팅·중량·연령·기수 입상률 각각의 현재 경주 평균 대비 차이와 상대 순위 |
| 합계 | **82** | H3 후보는 상대 비교 14개를 제외한 68개 사용 |

기수·조교사 이름과 ID는 모델에 그대로 넣지 않았다. 대상 출전표 이름을 **T-2까지 관측한 이름→공식 ID 연결**로 확인하고, 유일한 ID에 연결되는 경우에만 과거 실제 출전 성적을 집계한다. 이름이 모호하면 관측 부족 상태로 둔다. 대상 경주의 결과로 이름을 연결하거나 효과를 계산하지 않는다.

과거 사람 상태의 고정 수축식은 기수/조교사 승률 `(우승+2)/(출전+20)`, 입상률 `(입상+6)/(출전+20)`, 말×기수 입상률 `(입상+3)/(출전+10)`이다. 이번 실험에서 이 사전값을 최적화하지 않았다. 대상일·전날 결과를 추가하거나 바꾸어도 앞선 출전의 사람 상태가 바뀌지 않는 검사를 포함했다.

모든 82개 변수가 별도의 정보 원천인 것은 아니다. 14개 상대 변수는 기존 값의 변환이고, 성별 두 열도 하나의 원천 범주를 표현한다. **변수 개수가 늘어났다는 사실 자체는 예측력 개선의 증거가 아니다.**

변수 사전 검토 중 `normal_usable_count_pre`의 registry 기간 설명과 실제 구현의 차이도 명시했다. 실제 값은 전역 비400m 유효 시간 관측 수이며, 거리별 값은 `distance_normal_usable_count_pre`다. 봉인된 값을 바꾸지 않고 실제 의미를 문서화했다.

## 4. 같은 경주에서의 성능 비교

기간은 2025-01-03~12-27, 715경주·98경주일이다. 모든 후보의 예측 coverage는 100%다. 입상·집합·순서 적중은 전체 715경주, PL/이진 입상 확률 품질은 기존과 동일하게 3착 경계 동착 6경주를 제외한 709경주에서 비교한다. Brier와 NLL은 낮을수록 좋다.

| 후보 | 한 마리 입상 | 세 마리 집합 | 정확순서 | 입상 PL Brier | Set NLL | Order NLL |
|---|---|---|---|---:|---:|---:|
| M0_H2 | 425/715 · 59.44% | 49/715 · 6.85% | 18/715 · 2.52% | 0.1927 | 4.2626 | 6.0037 |
| P_H2 | 444/715 · 62.10% | 44/715 · 6.15% | 10/715 · 1.40% | 0.1911 | 4.2277 | 5.9629 |
| P_H3 | 445/715 · 62.24% | 52/715 · 7.27% | 14/715 · 1.96% | 0.1859 | 4.1111 | 5.8393 |
| P_H3R | 438/715 · 61.26% | 44/715 · 6.15% | 11/715 · 1.54% | 0.1859 | 4.1095 | 5.8419 |
| R_H3 | 437/715 · 61.12% | 57/715 · 7.97% | 15/715 · 2.10% | 0.1876 | 4.1493 | 5.8771 |
| R_H3R | 435/715 · 60.84% | 45/715 · 6.29% | 15/715 · 2.10% | 0.1874 | 4.1437 | 5.8739 |

P는 입상 여부를 학습하는 이진 LightGBM, R은 상위 착순 relevance를 학습하는 LambdaRank다. H3는 기존 H2에 출전 조건·사람 이력 19개를 더한 경우, H3R은 상대 변수 14개까지 더한 경우다. 기존 P_H2와 M0_H2는 새로 학습하지 않고 저장 예측을 재사용했다.

### 적중률 차이의 해석

- P_H3 대 기존 입상 후보 P_H2: 한 마리 **+0.14%p**, 경주일 95% 구간 **[−2.55, +2.74]%p**. 입상 적중률 개선은 판정 유보다.
- R_H3 대 기존 집합 후보 M0_H2: 집합 **+1.12%p**, 구간 **[−0.69, +2.91]%p**. 집합 적중률 개선도 판정 유보다.
- 정확순서 최고는 기존 M0_H2의 18회다. 새 H3 후보의 최고 15회가 이를 넘지 못했다.
- R_H3R은 R_H3보다 집합 적중이 57→45회로 감소했다. 그 차이의 경주일 구간은 **[−3.34, −0.14]%p**다. 이번 상대 변수 묶음을 자동으로 기본 채택하지 않는다.

### 확률 손실의 해석

P_H3의 입상 Brier는 기존 P_H2보다 0.00527 낮아졌고, 경주일 차이 구간은 약 `[−0.00677, −0.00372]`였다. 순서 NLL도 5.9629→5.8393으로 낮아졌다. R_H3에서도 기준 M0_H2 대비 확률 손실 감소를 관측했다.

이 결과는 **2025 개발에서 여러 후보를 본 뒤의 탐색적 비교**다. 경주·경주일 5,000회 paired bootstrap의 모든 비교를 저장했으며 다중 비교 보정은 하지 않았다. 개발상의 손실 개선을 실제 미래 적중률 보장으로 표현하지 않는다.

## 5. 어떤 변수에 모델이 반응했나

새 모델들의 학습 분기·seed별 분할 개선량(gain)을 각각 정규화하여 평균했다. P_H3에서는 최근 5회 성적 점수가 약 31.05%, 과거 주행심사 최근 유효 시간 4.80%, 기수 과거 입상률 4.77%, 기수 과거 승률 4.21%였다. R_H3도 최근 성적 점수가 가장 컸다.

이는 모델 내부에서 분할에 활용한 정도이며 인과효과나 제거 실험 결과가 아니다. 예컨대 체중 관측 횟수는 체중의 효과만이 아니라 경력·자료 가용성도 반영할 수 있다. 중복·상관 변수 사이에 중요도가 나뉠 수 있으므로 모든 변수와 실제 입력 열 목록을 함께 보관한다.

## 6. 검증과 산출물

- H3 feature 84,583행, 출전 키 유일성과 조인 일치. 기존 dataset·DB·실험 v1/v2 보존.
- 출전표 원본 SHA와 행 hash·문서 ID·문서 날짜·관측 상태를 별도 lineage로 기록.
- 새 모델 **32회 적합**, 확률 보정 **24회**, **16개 모델 묶음** 재현 검사.
- 이번 비교의 경주 예측 **4,290행**, 말별 확률 **41,718행**. 기존 두 후보의 예측·손실 불변 확인.
- 관련 테스트 **68개 통과**, Ruff 검사 통과. 레이팅/승군순위 구별·감량·구형 헤더·T-2·미래 ID 충돌·동일일 불변·경주 상대값 결측을 검사했다.
- 2026년에는 feature만 구성했고 모델 예측·평가·선택을 하지 않았다.

## 7. 다음 단계의 판단

1. **H3를 확률 품질 개선 후보로 유지한다.** 입상·집합 적중이 확정 개선되었다며 기존 후보를 폐기하지 않는다. 상대 변수 14개를 전부 기본 채택하지 않는다.
2. **집합과 순서를 함께 학습하는 구조를 다음 우선순위로 둔다.** 현재의 단일 말 점수 기반 PL은 상대를 먼저 선택한 뒤 2·3착 점수가 달라지는 전개를 직접 표현하지 못한다. 목표별 차이를 숨기지 않고 같은 비교점으로 검증한다.
3. **H3 가용시점은 실제 사전 수집으로 보강한다.** 향후 출전표 버전·수집시각·교체 이력을 경주 전에 저장한다. 마번과 실제 게이트 대응도 별도 확인한다.
4. 후보·feature·보정·출력 정책을 고정한 뒤 2026 역사 평가와 이후 사전 예측 원장으로 검증한다. 여러 개발 후보 중 최고값을 100%에 가까운 성능이라고 표현하지 않는다.
