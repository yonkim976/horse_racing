# 전국 경마장 경주로 근사 시각화 구현 프롬프트

최초 작성: 2026-08-27 (Asia/Seoul)  
상태: 1차 정적 경주로·체크포인트 시각화 구현 완료  
대상 경마장: 서울(`meet=1`), 제주(`meet=2`), 부산경남(`meet=3`)

이 문서는 다른 에이전트가 별도의 대화 맥락 없이 현재 프로젝트의 경주로 시각화 작업을
이어갈 수 있도록 작성한 구현 프롬프트다. 아래 내용을 작업 지시서로 사용한다.

---

## 구현 요청

현재 `horse_racing` FastAPI 대시보드에 **서울·제주·부산경남의 경주로 구조와 경주 진행을
보여주는 근사 시각화**를 구현해 주세요.

목표는 한국마사회가 연속 GPS 좌표나 정밀 측량 좌표를 공개하지 않는 상황에서도, 공식
경주로 구조 설명과 프로젝트 DB의 경주·출전마·구간기록을 결합하여 사용자가 경주 흐름을
직관적으로 이해할 수 있게 하는 것입니다.

시각화는 실제 GPS 재현이 아니라 공식 공개자료 기반의 설명용 근사 모델입니다. 실제 좌표처럼
오인되지 않도록 정확도 수준과 추정 부분을 UI에 명시해야 합니다.

## 1. 지원 범위

현재 실제 경마가 시행되는 다음 세 경마장을 모두 지원합니다.

| `meet` | 경마장 | 초기 지원 상태 |
|---:|---|---|
| `1` | 서울 | 필수 |
| `2` | 제주 | 필수 |
| `3` | 부산경남(부경) | 필수 |

영천은 공식 페이지 일부에 탭이나 코드가 나타나더라도 현재 시행 경마장으로 간주하지 않습니다.
초기 구현 대상에서는 제외하고 향후 추가할 수 있는 확장 대상으로만 남겨 주세요.

## 2. 공식 원천

경주로 형상과 표시 기준은 다음 한국마사회 공식 페이지를 1차 원천으로 사용합니다.

- [서울 경주로 구조](https://race.kra.co.kr/chulmainfo/RacingcourseStructure.do?Act=02&Sub=11&meet=1)
- [제주 경주로 구조](https://race.kra.co.kr/chulmainfo/RacingcourseStructure.do?Act=02&Sub=10&meet=2)
- [부산경남 경주로 구조](https://race.kra.co.kr/chulmainfo/RacingcourseStructure.do?Act=02&Sub=10&meet=3)
- 프로젝트 원천 목록: `docs/DATA_SOURCE_CATALOG.md`

공식 페이지의 설명문뿐 아니라 평면도 이미지도 직접 확인하고, 출발선·결승선·코너·펄롱봉의
상대 위치를 경마장별로 대조해야 합니다. 이미지 픽셀 좌표를 실제 측량 좌표로 취급해서는 안
됩니다.

## 3. 경마장별 초기 구조 정보

### 3.1 서울

- 타원형 경주로이며 외주로와 내주로를 사용합니다.
- 외주로는 일주 1,800m입니다.
  - 직선부 450m
  - 곡선부 450m
  - 곡률반경 143.24m
- 내주로는 일주 1,600m입니다.
  - 직선부 450m
  - 곡선부 350m
  - 곡률반경 111.44m
- 내·외주로 폭은 기본 25m이며 외주로 결승 직선 구간은 30m입니다.
- 외주로와 연결되는 1,000m 전용 연장주로가 있습니다.
  - 출발 후 약 130m는 직선
  - 이후 4코너까지 곡선 형태
- 공식 설명에 표시된 출발 위치에는 1,000m, 1,200m, 1,300m, 1,400m, 1,700m,
  1,800m, 1,900m, 2,300m가 있습니다.
- 펄롱 표지는 200m 간격입니다.
- 종단 고저차는 약 4m이며 공식 설명상 2펄롱 부근이 가장 낮고 7펄롱 부근이 가장 높습니다.
- 직선 횡단 경사는 양쪽으로 약 1.5%, 곡선은 내측이 낮은 약 2.5%입니다.

서울 1,000m는 일반 타원 위의 임의 지점에서 시작하는 것으로 그리지 말고 **전용 연장주로**를
반드시 표현해야 합니다.

### 3.2 제주

- 일주 1,600m인 단일 타원형 경주로입니다.
- 폭은 20m, 곡률반경은 97.5m입니다.
- 공식 출발 거리는 800m, 900m, 1,000m, 1,110m, 1,200m, 1,400m, 1,610m,
  1,700m, 1,800m입니다.
- 결승선에서 200m 간격으로 펄롱 위치를 표시합니다.
- 전체 고저차는 약 10.2m입니다.
  - 1코너 부근: 결승선보다 약 1.7m 낮음
  - 3코너 부근: 결승선보다 약 8.5m 높음
- 직선 횡단 경사는 약 1.5%, 곡선은 내측 방향으로 약 2.5%입니다.

제주는 서울·부경과 달리 내주로와 외주로를 선택하는 UI가 필요하지 않습니다. 공식 설명에서
코너 번호와 펄롱 위치를 설명하는 방향 표현이 혼동될 수 있으므로, 실제 주행 방향은 평면도와
경주 영상 또는 다른 공식 자료를 교차 확인한 뒤 설정하세요. 확인 전에는 공통 방향을 임의로
적용하지 마세요.

### 3.3 부산경남

- 내주로, 외주로, 조교주로가 있으나 경마 시행에는 내·외주로만 사용합니다.
- 현재 공식 `경주로 구조` 페이지의 표시값:
  - 내주로: 반경 115~137m, 일주 1,460m, 폭 25m
  - 외주로: 반경 149~175m, 일주 2,008m, 폭 25m
  - 조교주로: 반경 87~110m, 일주 1,292m, 폭 20m
- 경주는 반시계 방향으로 진행합니다.
- 1~9번 펄롱봉이 200m 간격으로 표시됩니다.
- 종단 고저차는 약 1m이며 1,200m 지점이 가장 낮고 결승점이 가장 높습니다.
- 직선 횡단 경사는 양방향 약 1.5%, 곡선은 외측에서 내측으로 약 2%입니다.

공식 페이지 사이에 다음과 같은 불일치가 확인되었습니다.

- 최신 `경주로 구조` 설명: 단거리는 외주로 사용
- 다른 검색 결과나 `경주로 현황` 설명: 단거리는 내주로 사용
- 일주 거리도 내주로 1,460/1,470m, 외주로 2,008/2,000m처럼 차이가 나타남

따라서 단거리 사용 주로와 제원값을 코드 곳곳에 하드코딩하지 말고 설정 파일 또는 단일 데이터
구조에 `source`, `verified_at`, `confidence`, `notes`와 함께 보관하세요. 초기 화면에서는 현재
`경주로 구조` 페이지 값을 사용하되, 사용 주로가 미확정임을 안내해야 합니다.

## 4. 데이터 확인 원칙

구현 전에 현재 SQLite 스키마와 실제 저장 데이터를 확인하세요.

- 경주: 경마장, 날짜, 경주번호, 거리, 등급, 상태
- 출전마: 마번, 마명, 기수, 조교사, 부담중량, 취소 여부
- 결과: 최종 순위, 기록, 착차
- 구간기록: `S1F`, 코너, `G3F`, `G2F`, `G1F` 등 실제 저장 코드

지원 거리를 소스 코드에 추측으로 나열하지 말고 다음 순서로 결정합니다.

1. DB에 실제 존재하는 경마장별 거리 목록을 조회합니다.
2. 공식 구조 평면도에 표시된 출발선과 대조합니다.
3. 공식 도면에 없는 거리나 좌표가 불명확한 거리는 근사 규칙과 신뢰도를 별도로 기록합니다.
4. 예정 경주와 완료 경주 모두 같은 경주로 설정을 사용하되, 완료 경주만 실제 구간기록을
   표시합니다.

프로젝트의 구간 데이터는 연속 GPS 좌표가 아닙니다. `S1F`, 코너 통과순위, 종반 기록을
경주로 위의 설명용 체크포인트로 매핑하는 데이터입니다.

## 5. 구조 설계

하나의 타원형 SVG를 세 경마장에 공통으로 복사하지 말고, **공통 렌더러 + 경마장별 설정**으로
구현하세요.

권장 개념 구조:

```text
racecourse config
├── meet / name / source / verified_at
├── direction
├── track surfaces
│   ├── inner
│   ├── outer
│   ├── extension
│   └── training (표시용, 경주 경로에서는 제외)
├── finish line
├── corners
├── furlong markers
├── distance-specific starts and route rules
└── confidence / notes

racecourse renderer
├── 구조 레이어
├── 선택 경주의 실제 사용 경로 레이어
├── 구간 체크포인트 레이어
├── 출전마 또는 순위 레이어
└── 근사·검증 상태 안내 레이어
```

경마장별 차이는 최소한 다음과 같이 표현되어야 합니다.

- 서울: 내주로 + 외주로 + 1,000m 연장주로
- 제주: 단일 주로
- 부산경남: 내주로 + 외주로, 조교주로는 선택적 배경 표시

화면 좌표와 거리의 변환, 출발 지점, 사용 주로, 진행 방향은 JavaScript 곳곳에 분산시키지
말고 설정과 변환 함수로 분리하세요. 향후 공식 좌표나 영상 추적 결과를 얻었을 때 설정만
교체할 수 있어야 합니다.

## 6. 시각화 요구사항

현재 FastAPI, HTML, CSS, JavaScript 구조와 기존 대시보드 디자인을 유지하면서 SVG 기반으로
구현하는 것을 우선합니다.

필수 표시 요소:

- 경마장 이름과 코드
- 경주일, 경주번호, 거리, 등급, 예정/완료 상태
- 경마장별 실제 구조에 가까운 주로 형태
- 내주로·외주로·연장주로·단일주로 구분
- 결승선, 출발선, 1~4코너
- 진행 방향 화살표
- 200m 펄롱 표지
- 선택한 거리의 주행 경로 강조
- 구간기록 체크포인트
- 출전마 목록과 마번별 색상
- 완료 경주의 구간기록 및 최종 순위
- 예정 경주의 `경주 전` 상태
- 확대/축소에도 읽을 수 있는 범례

반응형 요구사항:

- 데스크톱과 모바일에서 경주로가 잘리지 않아야 합니다.
- SVG `viewBox`를 사용하고 고정 픽셀 위치 의존을 줄입니다.
- 작은 화면에서는 상세 수치보다 경로와 현재 구간을 우선 표시합니다.
- 색상만으로 내·외주로와 말 상태를 구분하지 말고 선 형태나 라벨을 함께 사용합니다.

## 7. 구간 데이터 매핑

`START → S1F → 코너/중간구간 → G3F → G2F → G1F → FINISH` 흐름을 지원하되,
모든 경주에 모든 코드가 있다고 가정하지 마세요.

- 실제 DB에 존재하는 구간만 표시합니다.
- 구간 코드의 의미와 거리 매핑을 파서·원천 문서에서 먼저 확인합니다.
- 정확한 거리 좌표가 없으면 해당 경주 거리의 비율에 따라 임시 배치합니다.
- 임시 배치한 체크포인트에는 `estimated` 상태를 부여합니다.
- 코너 통과순위는 위치 좌표가 아니라 해당 시점의 순서라는 사실을 UI에서 구분합니다.
- 구간기록이 없는 예정 경주는 출발선과 예상 경로만 표시합니다.

말 아이콘을 애니메이션으로 움직이는 경우 실제 경주 재현처럼 보이지 않도록 `기록 기반 근사
재생`이라고 명시하고, 기록 사이 위치는 보간값임을 안내하세요.

## 8. 인터랙션

1. 경마장 선택: 서울 / 제주 / 부산경남
2. 경주일 선택: 기존 달력 UI 재사용
3. 경주번호 선택
4. 선택 경주의 거리와 사용 주로 표시
5. 출전마 선택 또는 전체 표시
6. `START`, 사용 가능한 구간, `FINISH` 타임라인 선택
7. 선택한 지점까지 경로 강조
8. 완료 경주는 기록·순위 표시, 예정 경주는 출전 정보만 표시
9. 근사 표시 켜기/끄기 또는 범례에서 정확도 상태 확인

데이터가 없거나 매핑 규칙이 미검증인 경우 빈 화면을 만들지 말고, 경주로 구조는 표시하면서
부족한 정보와 원인을 알려 주세요.

## 9. 사용자 안내 문구

시각화 하단에 항상 다음 문구를 표시합니다.

> 본 경주로와 구간 위치는 한국마사회 공개자료 및 경주기록을 바탕으로 구성한 근사
> 시각화입니다. 실제 측량 좌표 또는 GPS 주행 데이터와 차이가 있을 수 있습니다.

미검증 규칙이 적용될 때는 다음 문구도 표시합니다.

> 이 거리의 출발 위치 또는 사용 주로는 공개자료를 바탕으로 추정했으며 추가 검증이
> 필요합니다.

부산경남 단거리처럼 공식 설명이 충돌하는 경우에는 다음 문구를 표시합니다.

> 거리별 사용 주로에 관한 한국마사회 공개 페이지의 설명이 서로 달라 현재 구조 페이지를
> 우선 적용했습니다.

## 10. 구현 순서

1. 현재 프로젝트 구조, 대시보드 라우트, 템플릿, CSS, JS, 테스트를 확인합니다.
2. DB에서 경마장별 실제 거리와 구간 코드 종류를 집계합니다.
3. 세 공식 평면도를 직접 확인해 경마장별 설정 초안을 만듭니다.
4. 공통 SVG 렌더러와 경마장별 설정을 구현합니다.
5. 예정 경주 한 건과 완료 경주 한 건씩, 총 6건 이상을 표본 검증합니다.
6. 기존 기능과 반응형 레이아웃 회귀 테스트를 수행합니다.
7. 확인된 사실, 추정값, 미확정값을 문서에 갱신합니다.

## 11. 완료 조건

- 서울·제주·부산경남을 선택했을 때 서로 다른 경주로 구조가 표시됩니다.
- 서울 1,000m 경주가 전용 연장주로를 사용해 표시됩니다.
- 제주는 단일 주로로 표시되며 존재하지 않는 내·외주로 선택 UI가 나오지 않습니다.
- 부산경남은 내·외주로가 구분되고 단거리 사용 주로의 미확정 상태가 안내됩니다.
- 경주별 실제 거리, 출전마, 구간기록이 DB에서 연결됩니다.
- 예정 경주와 완료 경주의 표시 상태가 구분됩니다.
- 모든 근사 좌표와 보간값이 실제 GPS 데이터와 명확히 구분됩니다.
- 모바일·데스크톱에서 SVG와 범례가 잘리지 않습니다.
- 기존 대시보드 테스트가 통과하고 신규 설정·경로 변환 테스트가 추가됩니다.
