작업 위치: `/Users/kimyongjin/Desktop/horse_racing`

목표: 서울경마장 `meet=1`의 **2000년부터 실행 시점에 공식 결과가 확정된 최신 경주까지** 결과와 관련 이력을 실제 수집·정규화·연결하여 재현 가능한 연구 데이터셋을 구축하라. 가능성 보고서로 끝내지 말고 원문, 연결 테이블, coverage와 미해결 원장을 제출하라. 기존 운영 모델·registry·예측/배팅 경로는 변경하지 말고, 동시에 진행 중인 제주·부경 작업이나 기존 dirty 파일을 덮어쓰지 말라.

시작 전에 `docs/SEOUL_BACKFILL_REGIME_BOUNDARIES_2026-09-15.md`, `docs/PRE2015_RACE_RESULT_AVAILABILITY_2026-09-14.md`, `docs/HISTORICAL_SOURCE_COLLECTION_2026-09-14.md`, `docs/SEOUL_SECTION_AUDIT_2026-09-08.md`, `docs/CANONICAL_SECTION_RESEARCH_2026-09-11.md`를 읽고 선행 수치와 source hash를 직접 대조하라.

1. **원문 확보:** 이미 보존된 서울 `meet=1` 일별 조교·출발조교 API와 KRA Text `dacom01/11/12/13/55/71/72` 등 해당 원천을 우선 재사용하라. 공식 경주결과 API의 2000~2014년은 연도별 응답 집계만 있어 전체 말별 원문이 현재 DB에 전수 적재되지 않았다. 필요한 API 응답을 2000년부터 새 원문 경로에 보존하고, 2015년 이후 기존 DB·원문과 전수 대조하라. 연도·경마장·페이지·`totalCount`를 확인하고 재실행 시 중복 저장하지 말라. 새 HTTP 요청은 누적 요청 원장, 응답 해시, 누락/재시도 상태를 남기되 서비스 키를 기록하지 말라. 최신 결과는 공식 확정 상태까지만 포함하고 미래 경주 결과를 넣지 말라.
2. **warm-up과 이력:** 2000년 첫 경주의 과거 조교 이력을 위해 1998-09-25 이후 서울 일별 조교 원문을 연결하라. 체중 Text는 2003-09-06, 진료 Text는 2003-09-25, 출발조교 API는 2009-05-21 이후 실제 관측 범위부터 연결하라. 각 원천의 첫 *파일일*, 첫 *사건일*, 당시 게시/관측 가능 시각을 혼동하지 말라. 원천 시작 전은 `source_unavailable`, 실제 관측 가능한 기간의 사건 없음과는 구분하라.
3. **식별키와 원천 테이블:** `(meet, race_date, race_no)` 경주 키와 공식 `hrNo`를 더한 출전마 키로 `races`, `entries`, `results`, `sections`, `training_events`, `start_training_events`, `weight_observations`, `medical_events`, `equipment`, `track_conditions` 등을 별도 구축하라. 공식 `jkNo/trNo/owNo` 및 말의 당시 소속 관계를 경주 시점에 맞춰 보존하라. 마명·사람 이름만으로 자동 ID 연결하지 말고, 불확실한 Text 진료·장구는 `confirmed / ambiguous / unmatched / source_unavailable` 상태와 원문 근거를 남겨라. 한 원천의 결측 때문에 경주행을 inner join으로 삭제하지 말라.
4. **결과와 구간:** 정상완주, 동착, 실격, 주행중지, 미출주, 취소, 무효경주를 구별하고 원문 순위·시간을 보존하라. 서울 API의 누적 구간시간과 과거 Text의 종반 주파시간은 출처·정의를 확인한 뒤 별도 보관 또는 명시적으로 변환하라. 거리별 측정 지점과 `S1F`, `1C~4C`, `G3F`, `G1F`가 같다고 추정하지 말라. 각 출전마의 원문 구간값과 canonical 값이 역추적 가능해야 한다.
5. **시대 경계:** 레이팅 도입은 KRA 문서상 2015년 2월 경계지만 정확한 첫 적용 경주일은 2015년 원문으로 확인하라. 2016년 8월 내주로·외주로 모래 두께 변경 시기는 전환 상태로 분리하고, 불명확한 경주에 정확한 표면 상태를 부여하지 말라. 서울 1600m는 2019-08-25 첫 관측 경주를 공식 원문으로 재확인하라. `rating_system`, `surface_regime`, `mile_1600_era`, 원문 등급·부담종류·함수율·거리·주로 출처를 결과 테이블에 남겨, 전후 비교 시 같은 숫자의 등급이나 원시 주파시간을 무조건 동일하게 보지 않도록 하라.
6. **검증과 진행:** 매년 공식 API의 경주·말 행 수, 페이지 합, 기본키 중복, 공식 ID 결측·충돌, Text/DB 키 차이와 원천별 연결률을 자동 산출하라. 선행 감사의 2000년 서울 1,114경주·12,519행, 2004년 1,110경주·11,734행 및 2014년 1,127경주·12,945행을 대조하되 차이는 원문으로 설명하라. 이 수치는 API 관측값이며 전체 시행경주 완전성의 절대 증거는 아니다. 전 연도의 이상 사례만 표본 원문으로 수작업 확인하라. 진료 등의 미해결 ID가 있어도 검증된 경주·결과·조교 데이터셋 구축을 계속하라.

산출물은 기존 경로를 덮어쓰지 않는 서울 전용 새 버전 경로에 저장하라: 원문/요청 원장, 정규화 테이블, 연결형 연구 데이터셋, 연도×원천 coverage 표, 경주·말·사람 ID 충돌/미해결 원장, 시대 경계 판정 표, 데이터 사전, 테스트·감사 로그, SHA256 manifest, 실행 명령 및 최종 보고서. 보고서에는 자료 종류별 실제 첫 유효 연도와 **2000년부터 어느 시기의 어떤 열이 모델 입력으로 사용 가능한지**를 구분하라. 현재 경주의 사후 결과나 미래 심판보고서를 예측 입력으로 넣지 말라. 이번 작업에서는 모델 학습·성능 비교·운영 승격을 하지 말라.
