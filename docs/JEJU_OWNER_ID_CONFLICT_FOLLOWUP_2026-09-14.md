# 제주마 마주번호 충돌과 API 전용 행 후속 분석 (2026-09-14)

**후속 반영 완료:** 양수 정상 결과가 확인된 9,288경주에서 세 공식 ID를 연결한 **90,863행**을 [최종 연구용 연결 원장](../data/research/jeju_confirmed_race_time_ids_20260914/linked_official_ids.jsonl)에 별도 물질화했다. 남은 **29행만** [행별 미해결 문서](JEJU_RACE_TIME_ID_UNRESOLVED_29_2026-09-14.md)와 [기계 판독 원장](../data/research/jeju_confirmed_race_time_ids_20260914/unresolved_29.jsonl)에 기록했다. 기존 DB·원문·데이터셋·모델은 수정하지 않았다.

## 마주번호 충돌: 경주별 공식 번호는 1,133행 모두 연결 가능

최초 연구 원장의 마주번호 충돌 **1,133행**을 공식 경주결과, 기존 제주 Text 성적표, DB의 마주명·번호에 대해 `(제주, 경주일, 경주번호, 말 ID, 출주번호)`로 전수 대조했다. **1,128행**은 세 원천의 마주 이름이 일치하고 공식 결과 `owNo`만 DB 번호와 다르다. 기존 [Text 적재 코드](../src/horse_racing/services/dacom11.py)는 성적표의 사람 **이름만** 가지고, DB 전체에서 동명이인 후보가 하나면 그 마주 레코드를 선택한다(`person`, 450~455행). 마주 후보의 경마장 범위도 `0`으로 처리한다. 따라서 제주 성적표 이름을 서울·부경 등에서 이미 사용 중인 공식 번호에 연결할 수 있다. 이는 **DB 이름 연결의 구조적 한계**이며, 공식 번호가 역사적으로 바뀌었다는 증거는 아니다.

| 마주 이름 | 공식 제주 경주결과 `owNo` | DB `owNo` | 충돌 행 |
| --- | --- | --- | ---: |
| 양치복 | `206005` | `106055` | 631 |
| 손광섭 | `117048` | `121049` | 280 |
| 이용대 | `001048` | `010641` | 97 |
| 정동진 | `001193` | `010298` | 71 |
| 김종식 | `001098` | `065067` | 49 |

이 다섯 쌍의 1,128행은 기존 Text 원문의 마주명까지 **전부** 공식 결과 이름과 같았고 말·경주·출주번호도 일치했다. 예를 들어 2015-01-09 제주 4경주 `와흘으뜸`의 Text는 `양치복`, 공식 결과는 `양치복/206005`, DB는 `양치복/106055`다. DB의 `106055`는 부경 출전에도 사용되며 [KRA 부경 마주 페이지](https://race.kra.co.kr/owner/posessStateSoyuHorsesState.do?Act=08&Sub=1&meet=3&owNo=106055)에도 같은 이름으로 나온다. 이 사실은 *동일 실인물*을 입증하지 않으므로 **두 공식 번호를 하나의 인물 ID로 병합하지 않는다.** 다만 제주 **해당 경주행의 공식 `owNo`는 공식 결과에 직접 적힌 번호**로 연결할 수 있다.

나머지 **5행**은 Text 성적표·DB의 마주 이름과 공식 결과 이름도 달랐다. 각각 같은 날짜의 공식 [출전표 상세 API](https://www.data.go.kr/data/15058677/openapi.do)를 다시 요청해 말 ID·경주번호·출주번호를 대조했고, **5행 모두 출전표의 `owName/owNo`가 공식 [경주기록 API](https://www.data.go.kr/data/15058305/openapi.do)와 일치**했다. 해당 5행은 아래와 같다.

| 경주일·경주 | 말 | Text/DB 이름·번호 | 공식 결과+출전표 이름·번호 | 해석 |
| --- | --- | --- | --- | --- |
| 2018-01-19 제주 3R | 황금의신 | 강학민 `001184` | 김경국 `117043` | 전후 경주 사이 소유 표기 전환 경계 |
| 2018-02-03 제주 1R | 계림미소 | 청룡 `117051` | 김태옥 `001092` | 전후 공식 결과는 모두 김태옥; Text 1행만 다름 |
| 2018-02-24 제주 6R | 탐라신비 | 돈마 `116033` | 한병용 `001154` | 전후 경주 사이 전환 경계 |
| 2022-03-11 제주 5R | 검은맹주 | 허영철 `001111` | 김무현 `001105` | 전후 경주 사이 전환 경계; 조교사 필드는 별도 `외부마` 미해결 |
| 2024-05-25 제주 3R | 녹원제일 | 부용식 `001078` | 부건영 `116021` | 전후 경주 사이 전환 경계 |

전환 경계의 **정확한 소유권 효력 시각**은 이번 자료로 확인하지 못했다. 따라서 Text가 왜 옛 이름을 남겼는지까지 확정하지 않는다. 하지만 같은 말·출주번호의 **두 공식 경주별 API**가 같은 이름·번호를 제시하므로, 연구용 경주행의 공식 `owNo` 연결 근거는 충분하다. [다섯 공식 출전표 요청·응답 해시와 대상 `제` 행](../data/research/jeju_owner_boundary_entry_sheets_20260914/five_native_entry_sheet_rows.json)에 기록했다. 이 판단은 **서로 다른 번호를 사람 하나로 통합하는 판단과 다르다.**

[1,133행 경주별 마주번호 연결 원장](../data/research/jeju_owner_conflict_followup_20260914_v4/supported_race_specific_owNo.jsonl)은 원래 API 값, 앞자리 0을 보존한 문자열 `race_time_owNo`, DB 이름·번호, Text 원문 SHA-256, 공식 결과와 출전표 증거를 행별로 담는다. **1,133행 모두 해당 경주 `owNo`는 연결 가능**하며, 그중 조교사가 `0BBBBB`인 1행은 세 ID 완전 연결로 세지 않는다. 기존 DB와 최초 원장의 충돌 값은 수정하지 않고 후속 원장으로 판정만 추가했다.

## “API 결과의 DB 부재” 728행의 정확한 뜻

이는 **API가 `제`로 표기한 행의 자연키가 DB 출전행에 없었다**는 기계적 차집합이지, 실제 완료된 제주마 경주 728출전이 DB에서 누락됐다는 뜻이 아니다.

- **724행·73경주**는 경주 전체가 DB에 없다. 이 73경주의 API 행은 모두 **양수 완주시간이 없고 정상 착순도 없다**. 51경주·512행은 그 날짜의 보존된 Text 파일에는 있지만 해당 경주 블록이 없고, 22경주·212행은 해당 날짜 Text 파일 자체가 없다. 2026-08-25~26의 15경주·142행도 후자에 속하며 API `ord=0`, `rcTime=0`이다. 2015~2024년 대부분은 `ord=99`와 `rcTime=0`이다. 이 자료만으로 각 경주의 공식 취소·불성립 사유를 모두 확정할 수 없으므로 **정상 완료 경주로 취급하지 않는다**. DB에는 양수 정상 결과가 없는 *다른* 경주도 남아 있어, 이를 단일한 DB 제외 규칙으로 설명해서도 안 된다.
- **4행·4경주**는 정상 완료기록이 있는 2019년 경주에 속한다. 같은 출주번호의 말 ID가 DB `3018834`와 API `3017931`로 달라서 정확키 연결이 안 된 경우다. DB·API 양쪽 행을 보존하고 어느 ID도 임의 채택하지 않았다.

[77경주별 차집합·Text 대조 원장](../data/research/jeju_owner_conflict_followup_20260914_v4/api_rows_absent_from_db_by_race.jsonl)에 각 API 행의 원문 위치와 Text 파일 유무·해시가 있다. `제` 코드가 있더라도 정상 양수 결과가 없는 경주는 [별도 135경주·1,316행 격리 목록](../data/research/jeju_owner_conflict_followup_20260914_v4/no_positive_result_races.jsonl)에 표시했다. 기간 전체의 명시적 `제` API 경주키 **9,423개** 중 양수 정상 결과가 하나 이상 있는 것은 **9,288경주·90,892행**이다. 이 엄격한 범위에서 후속 마주 연결까지 반영한 세 공식 ID 연결은 **90,863행(99.97%)**, 미해결은 **29행**이다. 그 29행은 조교사 `외부마` 25행과 2019년 말 ID 키 충돌 API측 4행이다. [연도별 수정 coverage](../data/research/jeju_owner_conflict_followup_20260914_v4/positive_result_annual_coverage.json)에 연도별 분모·분자를 별도로 남겼다.

## 사유 간 중복

원래의 미해결 사유 건수는 `owNo` 충돌 **1,133**, API 행의 DB 키 부재 **728**, 개별 조교사 번호 부재 **57**이다. **32행은 “DB 키 부재”와 “조교사 `외부마`”를 동시에**, **1행은 “마주번호 충돌”과 “조교사 `외부마`”를 동시에** 갖는다. 따라서 `1,133 + 728 + 57 - 32 - 1 = 1,885`개의 *서로 다른 API 행*이다. 여기에 API 쪽과 짝을 못 맞춘 DB측 말 ID 충돌 4행을 따로 더하면 최초 미해결 원장 **1,889행**이다. 마주 `owNo`를 후속 연결해도 `외부마` 한 행은 여전히 조교사 ID 미해결이다.

[검증 결과](../data/research/jeju_owner_conflict_followup_20260914_v4/verification.json)는 1,133행 경주별 마주번호 근거, 출전표 5행, 비정상 결과 경주 135개, DB 차집합 728행의 분류와 수정 연결률을 통과했다. 이 분석으로 과거 자료의 **경주 전 공개 시각**이나 예측 성능이 입증되지는 않는다.
