# 로컬 기준정보와 사후 경주기록 자동 갱신

2026년 10월 7일부터 Mac의 LaunchAgent 5개가 공식 자료를 수집해 Supabase 운영 DB를 갱신한다. 로컬 SQLite는 갱신하지 않는다. 기존 Google 출마표·조교 예약, 당일 2분 수집, 확정배당, 결과 보완은 유지한다. 모델 예측과 웹 배포는 실행하지 않는다.

## 실행 일정

모든 시각은 한국 시간이며 Mac의 시스템 시간대도 한국 시간이어야 한다.

기존 Google `mapilog-weekly-entry-cards`의 수요일 17:10·18:10·19:10은 유지한다. 로컬 15:10·16:10은 조기 공개분을 받는 추가 예약이다. 클라우드·로컬 주간 수집기는 같은 PostgreSQL 잠금을 사용하고, 동일 출마표 fingerprint의 완료 실행은 중복 저장하지 않는다. 미공개 출마표는 대기로 기록하고 정상 출마표를 지우지 않는다. 이미 시작한 경주의 당일 변경을 초기 출마표로 되돌리지 않는다.

## 저장과 정정 원칙

2026-10-12 보완: 진료 창을 7일에서 14일로 넓혔다. 예약 시각·LaunchAgent 설정은 동일하며 다음 프로세스부터 변경된 로컬 코드를 읽는다. 각 날짜·지역 저장 후 공식 응답의 고유 자연키가 실제 DB에 모두 존재하는지 다시 확인하고, 현재 응답에 없는 기존 기록은 유지한다. 10/5~11 누락 739건을 추가했고 기존 1,962건의 업무 값과 ID는 보존됐다. 실행 근거는 통합 운영 안내의 10월 12일 절을 따른다.

운영 저장 대상은 Supabase `xkykmhhkjtosptoibduo`다. 대상 프로젝트·접속 호스트·TLS를 검증하고 SQLite로 우회하지 않는다. 기존 비밀 설정과 Discord 웹훅을 사용하며 문서·로그에 비밀값을 쓰지 않는다. 새 Google 리소스나 AI 호출은 만들지 않았다. 기존 Supabase 사용량과 API 호출은 발생한다.

로컬 파일 잠금과 당일 수집기의 PostgreSQL 잠금을 공유한다. 로컬 잠금은 최대 45초 기다리고, 계속 사용 중이거나 DB 잠금이 사용 중이면 종료 코드 75로 건너뛴다. 이 경우 수집 완료가 아니며 수동 실행이나 다음 예약이 필요하다. 무한 자동 재시도는 없다. 클라우드 조교 등 모든 수집기를 막는 전역 잠금은 아니다. 디스크 여유가 2GiB 미만이면 수집하지 않는다.

- 진료는 기존 자연키를 재사용한다. 같은 진료를 다시 조회해도 새 사건으로 추가하지 않는다. 새 원문 진단명은 용어 목록과 연결행을 만들지만 의학적 설명·위험도는 자동 확정하지 않는다. 빈 응답으로 이전 기록을 삭제하지 않는다.
- 말 기본정보는 관측 시각별 스냅샷을 보존하므로 새로운 관측 시각의 이력 추가는 정상이다. 현역 응답에 없다는 이유만으로 은퇴 처리하지 않는다.
- 조교사는 공식 API와 홈페이지의 현역 번호·이름·지역·조가 일치할 때 적용한다. 등록 종료와 공식 은퇴 목록 확인을 분리한다. 기존 DB에 없는 과거 조교사 전체를 일괄 생성하거나 해외 초청 조교사를 은퇴로 추정하지 않는다. 구자흥·김윤섭·최용구도 API308과 공식 명단에 남아 있는 동안 현역으로 유지한다.
- 주행심사는 이름만으로 관계자를 결정하지 않는다. Text와 API의 날짜·지역·심사번호·출전번호·말·관계자 이름·완주기록·정상 순위를 대조한 뒤 공식 번호로 연결한다. 없는 공식 번호만 최소 기본행으로 생성하며 과거 원문 이름은 보존한다. 기존 사람의 최신 표시 이름을 과거 명칭으로 바꾸지 않는다.
- 10월 8일 보완부터 주행심사는 날짜·지역별 독립 검증·저장을 한다. Text가 있고 API가 정상 0건이면 `waiting_for_publication`으로 기록하고 해당 날짜의 DB를 변경하지 않는다. 비어 있지 않은 API의 이름·기록·범위 불일치는 계속 오류로 처리한다. 다른 날짜·지역의 검증 완료분은 계속 저장한다. 일부 저장과 대기가 함께 있으면 `partial`, 대기만 있으면 `waiting_for_publication`, 실제 오류만 있으면 `failed`다. pending/error 상세와 Text/API 원문을 실행 폴더에 보존하며 API 미공개를 실패로 숨기거나 완료로 표시하지 않는다.
- 심판과 구간은 독립 단계로 처리해 심판 미공개·검증 실패가 구간 수집을 막지 않게 한다. 기존 연도별 구간 원천은 변경하지 않는다. 신규 날짜 자료와 이번 갱신 경로로 적재한 자료만 검증 후 정정할 수 있다. 기존 값이 빠지는 응답이나 연간 원천과 다른 값은 자동 삭제·교체하지 않고 확인 대상으로 남긴다.
- 구간 정정 전 값은 로컬 `before_*.json`에 먼저 보존한다. 변경 업무 값은 저장 후 다시 조회해 일치해야 커밋한다. API가 제공하지 않는 개별 통과순위는 null을 유지하며 통과조나 시간으로 추정하지 않는다.

구간의 `race_point_source_batches` 건수는 해당 캡처 원천 전체의 행 수다. 겹침 재조회에서는 신규·정정된 업무 행만 새 배치를 참조하므로, 현재 FK 참조 행 수와 원천 캡처 전체 행 수가 같아야 한다고 해석하지 않는다. 과거 배치와 해시는 보존한다.

## 알림과 기록

출마표는 기존 주간 수집기의 Discord 알림을 사용한다. 나머지는 완료·부분 완료·실패와 건수 요약을 기존 웹훅으로 보낸다. Discord가 실패해도 성공한 DB 쓰기를 되돌리거나 도착 여부가 불명확한 메시지를 재전송하지 않는다. Mac이 꺼졌거나 Python 실행 자체가 차단된 경우에는 알림을 보장할 수 없다.

실행 로그는 `/Users/kimyongjin/Library/Logs/horse-racing/local-catalog-{cards,medical,profiles,trials,canonical}.log`와 각 `.err.log`다. 기존 매일 03:00 로그 정리의 허용 목록에 추가하여 수집 로그 총 16개를 압축 후 비우고 7일 초과 압축본을 정리한다. 원문·검증·DB 기록은 자동 삭제하지 않는다.

최신 상태는 프로젝트 `data/state/local-catalog-<mode>.json`, 원문과 보고서는 `data/research/local_catalog_*` 또는 `data/research/score_point_updates_auto_*`에 남는다. 실제 DB 처리 이력은 `ingestion_runs`, 원문 경로·해시는 `source_documents`에서 확인한다. 변경 없는 심판·구간 재조회도 `canonical_post_race_scan` 실행 원장에 남긴다. 출마표의 `worker_finished` 상태는 호출 종료 상태이며 실제 신규 적재·변경 없음·미공개 판단은 주간 수집기 로그와 DB 실행 원장을 따른다.

## 실행과 상태 확인

프로젝트 폴더에서 실행한다. `--apply`가 없으면 비밀값·네트워크·DB·파일 쓰기 없는 계획만 표시한다.

```sh
cd /Users/kimyongjin/Desktop/horse_racing
.venv/bin/python scripts/manage-local-catalog.py status
.venv/bin/python -m horse_racing.jobs.local_catalog --mode cards --apply
.venv/bin/python -m horse_racing.jobs.local_catalog --mode medical --apply
.venv/bin/python -m horse_racing.jobs.local_catalog --mode profiles --apply
.venv/bin/python -m horse_racing.jobs.local_catalog --mode trials --apply
.venv/bin/python -m horse_racing.jobs.local_catalog --mode canonical --apply
```

`manage-local-catalog.py install`은 이 5개 예약만 등록한다. `stop`은 이 5개만 중지하고 plist는 남긴다. `--mode trials`처럼 지정하면 한 예약만 관리한다. 다른 로컬 예약이나 Google 예약은 변경하지 않는다. 설치 plist는 `/Users/kimyongjin/Library/LaunchAgents/com.horse-racing.catalog-<mode>.plist`다.

Mac 로그인·인터넷·잠자기 해제·Desktop 프로젝트 접근 권한·기존 Google 비밀값 접근 인증이 필요하다. 노트북이 꺼져 있는 동안 실행되지 않는다. 잠자기로 놓친 달력 예약은 깨어난 뒤 실행될 수 있지만 전원이 꺼져 놓친 예약과 시각 조건을 벗어난 기본정보 수집까지 보장하지 않는다.

- 조교 Discord 실패 상세에 날짜·지역·종류·오류 유형만 표시하는 코드를 보완했다. 임의 예외 메시지·인증값은 보내지 않고 최대 6건만 표시한다. **이 코드는 로컬에서 검증한 상태이며 기존 Google 조교 컨테이너에는 아직 배포하지 않았다.** 운영 반영에는 해당 Job 이미지 갱신이 필요하고, 비용 확인 전 새 빌드·배포는 실행하지 않는다. 주행심사 로컬 예약 보완과 구분한다.
- 실제 수동 재조회 실행 21696에서 10월 2일 제주 일반조교 338행을 다시 처리했다. 신규·변경·삭제는 0건이었다. 최초 감사 보고서의 `unchanged=1847`은 같은 날짜 세 지역 전체를 비교한 수치이며 제주 338행의 건수와 혼동하지 않는다. 이후 도구의 변경 집계는 요청한 지역만 비교하도록 제한했다.
- 18:29 주행심사 보완 경로를 실제 실행했다. 10월 1일 서울 60두·제주 26두·부경 17두는 검증·저장 재처리됐고 실행 21697·21699·21701에 남는다. ID 연결 누락 0건이다. 오늘 10월 8일 133두는 API 0건으로 세 지역 모두 대기에 남았고 실제 오류 0건이다. 요약 상태는 일부 저장·API 공개 대기이며 Discord 메시지 ID `1557686428878774403`으로 전송 확인됐다. 오늘 결과를 저장 완료했다고 해석하지 않는다.

## 10월 10일 공식 Text 기준 보완

사용자 승인에 따라 API20_1에서 기수명/공식 번호만 미제공이면 공식 dacom23의 기수명을 보존하고 공식 번호는 null로 저장한다. 말·조교사 공식 ID와 날짜·지역·심사·출전번호·기록·순위의 독립 대조는 유지한다. API가 제공한 이름이 다르거나 번호가 잘못된 경우는 계속 차단하며, 같은 이름의 기존 기수나 임시 ID를 추정 연결하지 않는다. 원문 API는 그대로 보존하고 `text_jockey_fallbacks.json`에 보완 근거를 별도로 남긴다. 기존에 연결된 ID는 후속 API 미제공 응답으로 지우지 않는다.

부산 10/8 5심사·53두를 저장하고 모든 말별 업무 필드와 제공된 공식 ID를 재조회 검증했다. 4두는 `jockey_name_raw=김성현`, `jockey_id=null`이며 결과 자체는 저장됐다. 이때 `partial`과 Discord의 `결과 저장 · 일부 공식 ID 미제공`은 공식 ID 미연결을 뜻한다. 추후 API가 번호를 제공하면 같은 자연키로 연결한다. 정기 실행은 기존 예약과 수정된 코드를 사용하며 예약 시간이나 Google 리소스는 변경하지 않았다.

같은 날 부산 dacom11의 빈 착순 및 빈 종반 구간 칸을 보존하도록 수정했고 10/9 제주·부산 16경주의 심판·구간·통과조 적재도 완료했다. 자세한 건수·예외·원문 위치·실행 ID는 [통합 운영 안내](DATA_COLLECTION_AUTOMATION_OPERATIONS_2026-10-05.md)의 `2026-10-10 공식 Text 기준 보완 완료`를 따른다.
