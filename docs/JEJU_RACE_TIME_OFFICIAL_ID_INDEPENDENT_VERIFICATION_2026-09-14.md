# 제주마 경주 당시 공식 ID 연결: 독립 검증 보고서 (2026-09-14)

> **후속 정정:** 아래 9,423경주·92,208행은 `제`로 표기된 **API 경주행 전체**이며 실제 양수 완주기록이 없는 135경주·1,316행도 포함한다. API에는 있으나 DB에는 없는 728행 중 724행은 그런 경주 73개의 행이고, 실제 결과가 있는 경주의 DB 키 불일치는 4행이다. 마주번호 충돌 1,133행은 [후속 원인 분석](JEJU_OWNER_ID_CONFLICT_FOLLOWUP_2026-09-14.md)에서 경주별 공식 번호를 추가 연결했다. 양수 정상 결과가 확인된 경주의 **최종 연결 90,863행과 미해결 29행**은 [최종 산출물](../data/research/jeju_confirmed_race_time_ids_20260914) 및 [29행 문서](JEJU_RACE_TIME_ID_UNRESOLVED_29_2026-09-14.md)를 기준으로 한다.

## 판정과 범위

2002-07-28~2026-09-12에 공식 경주결과의 `rank`가 명시적으로 `제`로 시작하는 제주 **9,423경주·92,208출전행**을 별도 연구 원장에 보존했다. 그중 경주행의 말·조교사·마주 세 공식 번호를 충돌 없이 연결한 행은 **90,323행(97.96%)**이다. **1,885개 공식 결과 행은 한 개 이상 미해결 조건**이 있으며, 기존 DB에만 있는 **4행**도 별도 미해결 원장에 있다. 이 판정은 *확보한 공식 결과*와 DB를 대조한 범위다. 공식 시행 경주 전체가 빠짐없이 API에 남아 있는지까지 독립 확정한 것은 아니다.

기존 [2002~2014년 `제` 원문](../data/raw/jeju_native_results)의 **2,592경주·24,256행**은 파일 SHA-256을 기존 manifest와 다시 대조하여 그대로 재사용했다. 2015~2026년은 KRA `API4_3/raceResult_3`, `meet=2`, 연도별 조회 12건에서 `제` 행만 새 경로에 저장했다. **2015~2024년 기존 DB 55,023행 중 55,019행**은 `(경마장, 경주일, 경주번호, 말 ID)`가 API와 같았다. 나머지 4행은 2019년 같은 경주·출주번호에서 DB 말 ID `3018834`, API 말 ID `3017931`로 충돌하므로 연결하지 않았다. 2015~2024년 API의 DB 없는 **586행 중 582행**은 경주 전체에 양수 정상 완주기록이 없는 행이고, 나머지 4행이 위 말 ID 차이다. 이 차이를 DB에 임의 추가하거나 모델 표본에 섞지 않았다.

모든 ID는 문자열이다. API가 사람 번호를 JSON 숫자로 반환하면 6자리로 왼쪽 0을 복원하며, 원래 API 값도 `raw_ids`에 보존한다. 말 번호는 7자리로 정규화한다. `0BBBBB`/`외부마`처럼 개별 조교사 번호가 아닌 값을 개인 공식 ID로 인정하지 않았다. 이름 일치, 현재 말 프로필, 현재 소속, 조교·진료 원문의 사람 이름으로 과거 사람 번호를 채우지 않았다. 조교·진료 사건은 말 ID를 통한 별도 연결 가능성만 있으며, 이 결과는 사건 날짜의 조교사·마주 귀속 증거가 아니다.

## 미해결 범위와 충돌

공식 결과의 **1,885행**에 붙은 이슈는 중복될 수 있다. API 행이 DB에 없는 행 **728개**(2015~2024년 586, 2026년 142), DB의 공식 마주 번호와 API 번호가 다른 행 **1,133개**, 개별 조교사 번호 대신 `0BBBBB`/`외부마`가 나온 행 **57개**다. 여러 조건이 같은 행에 겹치므로 단순 합산하면 안 된다. 728개 API 전용 행 중 **724개는 양수 정상 완주기록 없는 73경주의 행**이다. 나머지 4개는 2019년 말 ID 충돌이다. 728개 중 **696개**에는 원문상 세 번호가 있으나, DB 출전 키 연결이 빠져 최초 엄격 연결 완료 수에서는 제외했다. DB 전용 4행은 같은 말 ID 충돌의 반대편이며, 총 미해결 원장은 **1,889행**이다. 중복 공식 키·중복 DB 키·출주번호 불일치는 이번 실행에서 0이었다.

마주 충돌 **1,133행 중 1,128행**은 두 번호의 마주 이름이 같고, **5행**은 마주 이름도 다르다. 예를 들어 2015-01-09 제주 4경주 8번 `와흘으뜸`의 DB 마주 번호는 `106055`, API의 `owNo`는 `206005`이고 양쪽 이름은 `양치복`이다. 최초 원장은 이 번호 차이를 임의 해결하지 않고 `linked_official_ids.owNo=null`로 보류했다. **1,133개 충돌 행 전부**에 DB 번호·API 원값·해시·파일 행 번호가 있다. [미해결 행 원장](../data/research/jeju_race_time_official_ids_20260914/unresolved_rows.jsonl)을 독립 조사 대상으로 유지한다. 후속 원인 분석과 연결 가능 범위는 [별도 후속 보고서](JEJU_OWNER_ID_CONFLICT_FOLLOWUP_2026-09-14.md)에 있다.

질문의 출발점인 2015~2024년 `text:` 조교사 또는 마주 ID **21,879행** 중 **21,875행**은 정확한 공식 결과 출전 키와 맞았고, 그중 **21,774행**은 세 번호 모두 충돌 없이 연결됐다. 나머지 맞은 101행은 마주 번호 충돌 100행과 조교사 `외부마` 1행이다. 맞지 않은 4행은 위 말 ID 충돌이다. 임시 조교사 번호가 있던 맞은 **8,411행**, 임시 마주 번호가 있던 맞은 **17,724행**은 각각 공식 결과에 해당 사람 번호가 있어 필드 단위로 연결됐다. 두 집합은 서로 겹친다.

## 대조 사례와 재현

- **첫 경주**: 2002-07-28 제주 4경주 `제1`, 8행 모두 세 번호 확인. 예를 들어 `꿈바위`는 출주번호 3, `hrNo=3005576`, `trNo=002027`, `owNo=001018`이다. [기존 원문 1행](../data/raw/jeju_native_results/native_results_2002.jsonl).
- **2015년 경계**: 2015-01-09 공식 결과 39행 중 38행은 엄격 연결 완료, 1행은 마주 번호 충돌. `새물결` 출주번호 1은 DB의 두 `text:` 번호를 경주 결과의 `002025`, `001027`로 연결했다.
- **2025년 대조**: 722경주·7,071행에 DB 임시 조교사·마주 번호가 없고, 공식 결과와 모든 경주·출전 키 및 세 번호가 일치했다.

재현 코드는 [수집·대조 스크립트](../scripts/reconcile_jeju_race_time_ids.py)와 [독립 검증 스크립트](../scripts/verify_jeju_race_time_ids.py)다. 프로젝트 루트에서 `PYTHONPATH=src .venv/bin/python scripts/reconcile_jeju_race_time_ids.py --output <새 경로>`로 별도 산출물을 생성하고, `.venv/bin/python scripts/verify_jeju_race_time_ids.py <새 경로>`로 검증한다. API 키는 기존 `.env` 설정에서 읽고 요청 URL에는 기록하지 않는다. [요청·응답 해시](../data/research/jeju_race_time_official_ids_20260914/source_requests_and_hashes.json), [`제` 경주행별 연결 원장](../data/research/jeju_race_time_official_ids_20260914/race_time_official_id_links.jsonl), [연도별 coverage](../data/research/jeju_race_time_official_ids_20260914/annual_coverage.json), [검증 결과](../data/research/jeju_race_time_official_ids_20260914/independent_verification.json)는 모두 새 연구 경로에 있다.

검증 실행은 기존 13개 원문 파일의 SHA-256, 새 API 응답 12건의 HTTP 200·반환행 수와 요청별 SHA-256 기록, **92,208개 행별 원천 위치와 값**, 자연키 유일성, `제` 필터, ID 형식, DB snapshot 해시, 위 세 대조 사례를 통과했다. 혼합 API 응답 본문 자체는 한/래 행의 신규 저장을 피하기 위해 보존하지 않았고 **해시·`제` 외 또는 기간 밖 제외 건수만** 남겼다. 따라서 응답 바이트를 나중에 독립 재해시할 수 없으며, API가 변경되면 재조회 결과가 달라질 수 있다. 기존 DB·원문·데이터셋·모델·registry는 수정하지 않았다. 이 작업은 과거 경주 전 정보 공개 시각이나 예측 성능을 검증하지 않는다.
