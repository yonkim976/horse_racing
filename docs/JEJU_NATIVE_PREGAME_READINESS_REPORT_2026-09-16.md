## 2. 구현한 저장·재현 규칙

- 원문 HTML, 요청·응답 시각, URL, HTTP 상태, 응답 날짜, SHA-256, 파서 버전, 정규화 결과를 관측별 새 디렉터리에 보존한다. 기존 운영 DB의 값을 덮어쓰지 않는다.
- 원문과 정규화 메타데이터를 저장한 뒤 별도 수락 표시를 남긴다. 이 표시의 시각을 보수적 `known_at`으로 사용한다. 저장이 중단되어 수락 표시가 없으면 재현 대상에 넣지 않는다.
- 재현 시각 이후에 수집한 자료는 공지에 더 이른 시간이 적혀 있어도 과거 모델 입력에 소급하지 않는다. 시각만 있고 날짜가 없는 공지는 날짜를 임의로 붙이지 않는다.
- 요청한 경주와 원문 제목의 날짜·경주번호, 말 고유 ID·마번·마명을 확인한다. 다른 말이나 다른 날짜의 자료가 일치하지 않으면 적용하지 않는다.
- 출마표의 편성 수·출전 수·상세 행 수가 다르면 완전한 편성으로 표시하지 않는다. 최신 상세 페이지가 실패하면 이전 정상 페이지로 조용히 대체하지 않는다.
- 동일 시각의 서로 다른 버전은 무작위 파일명으로 순서를 정하지 않고 불명확하게 처리한다. 파서 버전이 다른 정규화 결과를 실제 출마표 변경으로 잘못 집계하지 않는다.
- 취소 공지는 원래 선언 행을 삭제하지 않고 `withdrawn_observed`로 남긴다. 예측 대상 후보 목록은 별도로 산출한다. 새 화면에서 과거 공지가 사라져도 이미 관측한 취소 사실을 잊지 않는다.
- 기수 변경을 적용할 때 새 기수 이름만 확인된 경우 기존 기수 ID를 남기지 않는다. 확인되지 않은 ID는 결측 처리한다.
- 당일 체중은 정확한 경주·말 ID가 일치할 때만 적용한다. 주로는 명시 상태 날짜가 경주일과 같고 상태 시각이 재현 시각 이전일 때만 연결한다. 범례의 함수율 구간을 실제 주로 관측으로 읽지 않는다.
- 출마표에서 확인한 출발시각 이후의 시각으로는 사전 편성 재현 결과를 내지 않는다. 실제 출발시각 변경의 완전한 추적은 별도 후속 연결이 필요하다.

아직 예측 운영에 연결하지 않았다. 취소 공지의 완전한 수집 범위, 출발시각 변경, 수집 간격에 따른 정보 지연 및 시점별 필수 변수 정책을 확정한 뒤 모델 입력 연결을 진행해야 한다.

## 3. 과거 2025년 공개 시각 감사

기존 H3 자료의 2025년 출전 6,953건은 원문 출마표 49개에 연결된다. **해당 경주일 전에 로컬에서 관측했다는 기록은 0건**이었다. 모두 사후 수집된 문서이므로 원문 파일 날짜만으로 당시 최초 공개·수정본을 인증할 수 없다.

이 사실은 2025년 개발 실험의 모든 변수에 실제 결과 누수가 있었다는 뜻이 아니다. 다만 당시 이용 가능했던 정확한 버전을 입증할 근거가 부족하므로, 그 성능을 수요일 실전 성능으로 확정할 수 없다는 의미다. 이번 저장소부터 실제 관측 증거를 쌓는다. 과거 문서를 현재 다시 내려받아 과거 `known_at`으로 등록하지 않는다.

독립 검증기는 78개 관측의 원문·메타데이터 해시를 확인하고, 현재 파서로 성공한 52개 페이지를 다시 읽어 같은 값이 나오는지 검증했다. 확정 시각의 편성을 다시 산출해 JSON·Parquet의 **22경주·206행**과 일치함을 확인했다.

관련 테스트 **70개 통과**, 새 코드의 Ruff 검사 통과. 검사에는 공지 지연, 미래 수정, 취소 공지 소멸, 기수 ID 혼동, 날짜·말 ID 불일치, 오래된 체중·주로, 변경된 HTML, 중단 저장, 해시 변조, 같은 시각의 상충 버전, 출발 후 재현 차단이 포함된다. 테스트 수와 정적 검사 결과는 함께 보존한 `tests.log`, `lint.log`가 원문이다.
