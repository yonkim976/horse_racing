# 부산경남 2006~2026 연결형 역사 데이터셋 구축 결과

실행 시각 2026-09-15 KST. 범위는 공식 `meet=3` 부산경남만이다. 공식 결과 API에서 관측된 가장 늦은 부경 경주일은 **2026-09-11**이다. 경주 라벨 후보는 2006년 이후 정식 경주로 두고, 2005-09-30 이후 정식 경주는 warm-up, 그 전 모의경주 328개는 별도 `mock`으로 보존했다. 2004-06-30부터의 조교도 초기 이력으로 보존했다. 운영 DB·모델·registry·예측·베팅 코드는 변경하지 않았다.

## 실제 구축물과 재현

새 경로 `data/research/busan_history_20260915/`에 공식 결과 연도별 원문 22페이지와 진료 API 11페이지, 비밀키 없는 요청 원장, 정규화 SQLite `history.sqlite3`, 경주 시점 연구 표 `research_entry`/`research_source_features`, 연도별 표, 미해결 원장, 원문 역추적 표본, SHA256 manifest를 만들었다. 보관 중이던 부경 월별 조교 762개 월과 KRA Text 원문을 **기존 경로에서 읽기만** 했다. `dacom23` 주행심사는 `trial_result_text`에 `trial_only`로 별도 보존해 정식 결과 라벨에 섞지 않았다. 실제 사용한 원문·기존 원장도 manifest에 해시로 연결된다. API·Text 원문 자체는 수정하지 않았다.

주행심사 Text는 1,053파일에서 첫 성적표 형식의 5,413행을 별도 파싱했다. 이름만으로 공식 말 ID를 붙이지 않았고, 이 수치를 주행심사 전체 출전행의 완전한 전사 건수로 주장하지 않는다.

`dacom13`의 말 취소·기수 변경 공지는 `race_notice_text`에 별도 사건으로 보존하고, 경주일·번호·출전번호·마명과 공식 결과가 일치하는 행만 말 ID를 붙였다. 해당 공지의 작성·공개시각을 경주 전 가용 시각으로 승인하지 않았다.

```bash
cd /Users/kimyongjin/Desktop/horse_racing
.venv/bin/python scripts/collect_busan_history_results.py --start-year 2005 --end-year 2026
.venv/bin/python scripts/collect_busan_medical_api.py --start-year 2019 --end-year 2026
.venv/bin/python scripts/build_busan_history.py
.venv/bin/python scripts/verify_busan_history.py
.venv/bin/pytest -q tests/test_busan_history_build.py
```

수집기는 이미 있는 연도·페이지 파일을 재사용하고 신규 응답마다 출처, 범위, 페이지, `totalCount`, 실측 행 수, UTC 수집시각, 키를 제거한 URL, 원문 SHA256을 기록한다. 페이지 합계가 `totalCount`와 다르면 실패한다. 구축은 새 임시 DB를 만들고 최종 DB로 교체하므로 행을 중복 삽입하지 않는다. 검증기도 고유키에 재실행 가능한 upsert를 사용한다.

공식 2006 결과 578경주 중 **576경주**에는 정상 도착 순위가 있고, **2006-01-13 9·10경주**는 전 출전행 순위가 0이다. 따라서 578은 정식 경주 표제·출전의 기준값이지 578개의 유효 승부 라벨을 뜻하지 않는다. 같은 구별 방식으로 2015년 API 815경주 중 순위 양성은 813, 2026년 540경주 중 530이다. 2026년의 순위 없는 10경주는 8월 26일에 몰려 있다. 2006년 결과의 `hrNo/jkNo/trNo/owNo` 결측은 모두 0이지만, 전체 기간에서는 조교사·마주 ID가 각각 21행 비어 있어 연도별 표에 표시했다. 2006 마주 ID는 숫자형 5,807행·문자열형 762행이므로 원문 타입과 선행 0을 보존했다.

`dacom11` 보관 결과표는 2015년 이후 912파일을 파싱했고, 확인 연결 77,673행에서 순위·시간 불일치 0, 체중 불일치 1이다. 체중 불일치는 2020-10-16 3경주 6번 원더러너의 Text `0` 대 API `507kg`이다. 연결 충돌 633행은 [원장](dacom11_conflicts.csv)에 남겼다. `meet=3` Text 경로의 일부 본문에서 타 경마장으로 표시된 경주 6개도 적재하지 않았다. 2006년 `dacom11` 보관본은 없으므로 2006 결과 시간·순위의 별도 Text 전수 교차검증을 주장하지 않는다. 대신 공식 결과 API 페이지의 보관 해시와 `dacom01` 출전·`dacom12` 체중·`dacom71` 경주 키를 대조했다.

연도 전체의 경주·출전·원문 페이지·ID 결측·특수 결과·원천 간 불일치는 [연도 품질표](year_quality.csv), [원천 coverage](coverage_year_source.csv), [사건 시작·끝 날짜](event_coverage.csv), [출전마 28일 연결률](source_link_coverage.csv)에 있다. 기본키 중복은 SQLite 제약으로 거부하고, 월별 조교 762개 월의 페이지 연속성·원문 `totalCount`·적재 행 수 차이는 0이다. `PRAGMA integrity_check=ok`이며 API 출전·조교와 Text 진료의 원문 위치를 각각 5건 역추적했다. [검증 로그](verification.json)와 [표본](sample_trace.json)에 근거를 보존했다.

연구 표는 **167,960행**으로 공식 출전 171,064행에서 2005년 모의경주 출전 3,104행만 분리한 수와 같다. 조교·진료가 없는 출전마를 inner join으로 탈락시키지 않았다. Text 진료 사건일이 해당 Text 파일일보다 늦은 행은 0건으로 확인했다.

연구 표의 모든 과거 합계는 `event_date < race_date` 또는 `past_race_date < race_date`를 강제한다. `current_finish_order`와 `current_result_status`는 목적변수 영역이며 입력 집계에 들어가지 않는다. 다만 과거 자료의 **당시 게시·관측 시각이 확인되지 않았으므로 연구 표 전체를 `retrospective_only`**로 표시했다. 실제 T−30분 예측·배팅용 사용 승인은 이 데이터셋의 범위 밖이다.
