코드 91~95의 의미는 보존된 2026년 공식 AI 결과의 `rk`와 API4_3의 같은 경주·말 키를 대조했다. 확인 표본은 각각 91 실격 1, 92 주행중지 32, 93 출발제외 1, 94 경주제외 94, 95 출전취소 50행이다. 99는 겹치는 AI 표본이 없어 원문 코드와 기존 KRA 표시 계약에 따른 취소 분류이며, `result_code_crosscheck.json`에 표본 범위와 원천 해시를 남겼다.

## 구간 의미와 시대 경계

서울 API의 `seS1fAccTime`, `se_*cAccTime`, `seG3fAccTime`, `seG1fAccTime`은 출발 누적시간으로 저장했다. `dacom11`의 S1F·코너는 누적, G3F/G1F는 **마지막 600/200m 주파시간**이므로 `text_sections.csv`에 별도 basis로 보존했다. 유효한 API 완주시간에서만 G3F/G1F 누적값을 빼 `canonical_closing_s`를 만들고, 0·결측·비정상은 변환하지 않았다. 거리별 코너의 실제 좌표를 추정하지 않았다. Text 구간 598,343행 중 공식 출전키가 확인된 591,304행을 API와 대조했고, 0.11초 초과 차이 59행은 `text_section_mismatches.csv`에 남겼다. 파싱 실패 파일은 0이다. 차이를 자동 덮어쓰지 않았다.

- **레이팅:** 2015-02-01 마지막 서울 경주 11R의 원문 조건은 `혼1 / 5,000점이상`; 다음 시행일 **2015-02-07 1R**은 `국6등급 / R0~140`이다. 해당 연도 API 원문으로 첫 적용 경주를 확인했고 경주별 `rating_system`을 부여했다. 6등급 말의 개별 레이팅 0이 제도 미적용을 뜻하지는 않는다.
- **모래 변경:** 2016-08-15~26의 서울 23경주는 내·외주로 작업일과 실제 경로가 경주별로 확정되지 않아 `surface_transition_or_unknown`이다. 그 전 18,342경주, 8월 27일 이후 10,141경주를 별도 시대 값으로 유지한다. 작업 근거는 [경계 문서](../../../docs/SEOUL_BACKFILL_REGIME_BOUNDARIES_2026-09-15.md)에 기록된 당시 보도다.
- **1600m:** 공식 API 결과에서 첫 경주는 **2019-08-25 서울 7R**이며, 2019년 해당 날짜 전 1600m 결과가 없다. `mile_1600_era`를 경주별로 기록했다.

서로 다른 시대의 등급 숫자와 2016년 주로 변경 전후 절대 주파시간을 직접 같은 척도로 합치지 않는다. 정확한 거리·당시 함수율·시대 상태로 분리해야 한다.

## 자동 검증과 미해결 원장

`coverage_year_source_verified.csv`가 매년 공식 경주·출전·페이지·조교·체중·진료·장구 및 공식 사람 ID 결측과 이전 28일 연결 출전 수를 제공한다. 선행 감사의 2000년 **1,114경주·12,519행**, 2004년 **1,110경주·11,734행**, 2014년 **1,127경주·12,945행**을 포함한 2000~2014년 연도별 행 수·경주 수·응답 SHA256이 모두 일치했다. 페이지별 `totalCount`와 실제 행 수, 원문 재해시, 출전/결과/연구 기본키 수, 신규 요청 원장의 경로/해시 검사도 통과했다. 이는 **API 현재 관측 결과의 완전 적재**를 증명하며, 2000~2002년의 독립 공식 시행 캘린더 전체와의 대조까지 완료했다는 주장은 아니다. 보존된 Text에서만 관측되는 경주 키는 0이다.

관련 코드 Ruff 검사와 서울 특수순위·초기 체중 레이아웃·`dacom11`·구간·Text 보관 회귀 테스트는 **29 passed**이며 `test_audit.json`에 명령·출력을 보존했다. SQLite `quick_check=ok`, 외래키 오류 0건은 `database_integrity.json`에 기록했다. 2000년 첫 경주 한 말의 결과 원문 행과 과거 조교 사건 원문 행, 레이팅·1600m 첫 경주 근거는 `sample_trace.json`에 추적 가능하게 묶었다.

공식 `hrNo/jkNo` 결측은 0, `trNo/owNo` 결측은 각각 59행이다. Text 체중 269,617행 중 267,993행 확정 연결, 1,624행 미연결이다. 진료 1,349,468사건 중 368,626건만 두 원천과 출전 키로 확정했고, 941,071건은 마명 후보가 있으나 불확실, 39,771건은 후보도 없다. 이 미해결 진료를 0건으로 채우지 않았고 검증된 결과·조교 데이터셋은 완성했다.

2015년 이후 기존 완료 운영 DB와 대조하면 API 경주 11,973개 중 11,892개가 겹친다. API에만 있는 81개는 취소 50, 특수·미확정 31개이며 **양수 정상 결과가 있는 API 경주는 모두 기존 완료 DB에도 있다**. `operating_db_race_gaps.csv`에 전부 남겼다. 공통 출전 키는 129,338개다. 운영 DB의 이름 기반 `text:` 말 ID 9개와 사람 ID 102,194개는 공식 ID와 충돌이라고 가정하지 않고 별도 legacy 원장에 분리했다. 공식 ID 또는 완주시간의 실질 불일치는 **311개 필드**(마주 302, 기수 3, 조교사 2, 2023-03-04 8R 완주시간 4)이며 `operating_db_disagreements.csv`에 양쪽 값을 보존했다. 기존 DB는 수정하지 않았고 이 값들을 이름 유사도로 봉합하지 않았다. 공식 ID의 이명/표기 변형 25개도 `id_name_variants.csv`에 기록했다.

## 재현과 해시

프로젝트 루트에서 실행한다. `.env`의 공공데이터포털 키는 새 HTTP 요청에만 필요하며 요청 원장에 기록되지 않는다. 이미 저장된 연도 페이지는 해시 확인 후 재사용해 중복 다운로드하지 않는다.

```bash
.venv/bin/python scripts/collect_seoul_backfill_results.py --start-year 2000 --end-year 2026
.venv/bin/python scripts/build_seoul_backfill.py
.venv/bin/python scripts/finalize_seoul_backfill.py
.venv/bin/python scripts/audit_seoul_result_status_codes.py
.venv/bin/python scripts/verify_seoul_backfill.py
.venv/bin/ruff check scripts/collect_seoul_backfill_results.py scripts/build_seoul_backfill.py scripts/resume_seoul_backfill.py scripts/finalize_seoul_backfill.py scripts/correct_seoul_special_98.py scripts/correct_seoul_zero_time_ranks.py scripts/audit_seoul_result_status_codes.py scripts/verify_seoul_backfill.py tests/test_seoul_backfill_status.py
```

`request_ledger.jsonl`은 새 API 요청·재사용·실패 상태, 공개 조회 범위, 페이지, `totalCount`, 응답 SHA256을 보존한다. `source_inventory`는 재사용한 서울 월별 API/Text 원문의 경로·바이트·SHA256을 보존한다. `sha256_manifest.csv`는 신규 결과 원문, DB, 표·원장·보고서, 실행 스크립트의 출력 해시를 담는다. 주요 값은 2000년 API 원문 `e452317f8bbc03b919ec03388637aba6e8cc282267d16dccd3f6e2cc75a77538`, 2014년 `e741753997436556ed20a6f09e9688941215a1e8622e75214f04fb34ac27a22d`, 연구 DB `bdbe501365fc59bdbe515a22daad373c8192788a31c382787d43f45b6278ef72`다. `verify_stdout.json`, 임시 WAL/SHM, manifest 자신은 자기참조/실행 중 상태 때문에 해시 대상에서 제외한다.

`correct_seoul_special_98.py`와 `correct_seoul_zero_time_ranks.py`는 이미 생성된 v1 DB에서 발견한 오분류를 수정한 일회성 재현 코드다. 새로 빌드할 때는 수정된 `build_seoul_backfill.py`가 처음부터 특수코드·시간 0 순위를 격리하므로 실행할 필요가 없다.

첫 샌드박스 DNS 시도는 서버에 도달하지 못했고 초기 수집기에서 원장 경로 생성도 실패했다. 이 무응답 시도는 실제 시각을 복원할 수 없어 `preconnect_failure_retrospective`로 사후 기록했다. 성공한 권한 상승 재시도와 27개 응답 해시는 각각 별도 원장 행으로 남아 있다.
