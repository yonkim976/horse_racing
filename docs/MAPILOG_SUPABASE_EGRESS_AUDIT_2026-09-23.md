# Mapilog Supabase egress 원인 점검

점검: 2026-09-23 약 22:24~22:29 KST. Supabase 대시보드, 운영 PostgreSQL 통계, 기존 Cloud Run 요청 로그, 로컬 코드를 읽기 전용으로 확인했다. 애플리케이션·DB·클라우드 설정은 변경하지 않았다.

## 판정

**봇의 과거 날짜별 메인 페이지 순회와, 메인 페이지가 매번 전체 날짜 메타데이터를 다시 조회하는 구조가 결합해 전송량을 증폭한 것이 주원인이라는 근거가 강하다.** 다만 DB 통계에는 HTTP 요청의 UA/추적 ID와 실제 전송 바이트가 없어 62.269GB 중 봇 몫을 정확한 비율로 확정할 수는 없다.

## Cloud Run 로그 대조

범위: 서비스 `mapilog`, 요청 로그, 메인 경로 `/` 및 쿼리 포함, HTTP 200. 최근순 제한 조회이므로 전체 기간의 무작위 표본은 아니다. UA는 자기 신고 문자열이며 실제 운영 주체의 인증 결과가 아니다.

날짜별 URL 대량 순회와 DB의 전체 날짜 목록 반복 조회가 연결된다. 조회 비용은 봇만의 특성이 아니므로 정상 사용자 요청도 같은 SQL 경로를 실행할 수 있다.

## 직접 DB 노출 여부의 제한적 확인

- 현재 public 스키마의 애플리케이션 테이블 34개 모두 RLS 활성.
- public 테이블에 대한 `anon`, `authenticated`, `PUBLIC`의 직접 테이블 권한 조회 결과 없음.
- 대량 조회는 앱이 사용하는 SQL 쿼리 형태이며 postgres 역할의 통계에 나타난다.

확인 범위에서는 익명 사용자가 Data API로 테이블을 직접 대량 다운로드했다는 근거보다, 웹서버를 통한 정상 SQL 반복 조회라는 설명이 훨씬 강하다. 이는 함수·뷰·자격 증명 유출 등을 전수 조사한 침해사고 포렌식 결과는 아니다.

## 기존 보안 수정으로 해결되는 범위

- 앱 도달 전 차단과 DB 실행 전 속도 제한은 DB 전송량도 줄인다.
- 동일 URL의 응답 캐시는 도움이 되지만 날짜가 달라지면 캐시 키가 달라진다. 현재 응답 캐시는 20초이며 인스턴스별이다.
- 현재 `/` 핸들러는 응답 캐시 미스 시 `load_dashboard()`를 직접 실행한다. 날짜 메타데이터 전용 공유 캐시는 없다.
- 응답 크기 제한은 DB 조회 후에 적용되므로 이미 받은 DB 전송량을 되돌리지 못한다.
- HTML gzip은 Supabase에서 받은 SQL 결과의 전송량을 줄이지 않는다.
- CSS/JS CDN 적용만으로 이 DB 조회 경로가 없어지지 않는다.

## 수정 우선순위

1. **전체 날짜·상태 메타데이터를 요청별 조회에서 분리**한다. 데이터 갱신 주기에 맞춘 공통 캐시나 사전 생성 파일로 제공한다. 갱신 무효화, 캐시 용량, 동시 미스 합치기를 함께 설계한다. 인스턴스별 캐시부터 적용할 수 있지만 복제 수만큼 별도 조회가 남는다.
2. **달력을 필요한 월/기간만 조회**하도록 바꾼다. 이전·다음 날짜도 SQL에서 필요한 값만 구한다. 과거 조회 기능을 보존하되 모든 날짜를 매 HTML에 포함하지 않는다.
3. **최근 성적을 SQL 단계에서 말당 5행으로 제한**한다. 화면의 정렬·실격 처리와 기존 결과가 같음을 검증한다. 작은 기간을 임의로 잘라 최근 성적을 누락시키지 않는다.
4. 과거 경주처럼 거의 변하지 않는 화면은 더 긴 캐시와 데이터 변경 시 무효화를 검토한다. DB 조회 전 IP/경로/계정 제한은 별도로 유지한다.
5. 검증 시 HTTP 응답 크기 외에 **요청당 SQL 횟수·반환 행 수·캐시 미스**를 측정한다. 제한된 정상 요청 재현과 전후 `pg_stat_statements` 증분으로 확인하고, 최종 효과는 Supabase Shared Pooler Egress 추이로 확인한다. 통계 초기화나 운영 부하 테스트는 이번 조사에서 하지 않았다.

## 한계

정확한 봇별 DB 바이트, 각 SQL별 네트워크 바이트, 모든 로컬 분석·수집 작업의 기여율은 현재 통계만으로 복원할 수 없다. 따라서 **주원인은 높은 확신으로 추정하지만 62.269GB 전부가 봇 때문이라고 확정하지 않는다.** 이번 작업은 원인 조사이며 위 최적화의 구현·배포는 수행하지 않았다.
