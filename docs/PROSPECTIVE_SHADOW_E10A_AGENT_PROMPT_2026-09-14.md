## 이번 작업의 범위

기존 코드·문서·요청 원장·모델 메타데이터를 읽어 실행 준비물과 차단 조건을 제출한다. 실제 HTTP, 자동화 등록, 상시 수집, 모델 학습·추론·확률 발행, 결과 조회, 운영 DB 변경은 이번에 하지 않는다. 준비를 실제 관측 성공이나 F_t 적격으로 표현하지 않는다.

## 해야 할 일

1. **기존 상태를 재사용한다.** E8의 실제 원문 수집/페이지 검사 기능과 E8-A의 합성 field/snapshot 계약이 어디까지 연결되어 있는지 구분한다. 새 journal/CAS/상태머신을 만들지 않는다. 실제 raw를 합성 원천으로 위장해 기존 synthetic gate를 통과시키지 않는다.

2. **최소 성공 조건을 고정한다.** 대상은 서울의 예정 경주일 하나, 사례 경주 하나다. 기존 대상 2026-09-19의 예정 여부와 공식 게시 여부는 이번 로컬 기록만으로 확인되지 않으면 unknown으로 남긴다. 수집 성공은 적어도 실제 비어 있지 않은 일정·출전표, 명시적 페이지 계약, 해당 경주 source key, 실제 영속화 완료 시각 및 당시 원천 예정시각 기준 cutoff를 요구한다. 그보다 일찍 수집한 자료를 정확히 T−30 당시 최신 상태였다고 표현하지 않는다. API의 취소/정정 반영 범위가 불명하면 F_t 적격은 계속 unverified다.

3. **착수표를 작성한다.** 공식 게시 확인 → 날짜/원천/예산 봉인 → 일정·출전표 수집 → 원문/키/관측 시각 검사 → 독립 검증 제출의 한 번짜리 순서를 적는다. 게시 근거가 없으면 `waiting_for_publication_evidence`로 끝낸다. 이는 경주 미개최 또는 API 미게시 원인 판정이 아니다. 사용자가 실제 수집을 지시했을 때 필요한 실행 명령·환경 전제·예상 산출물을 구체적으로 적되 지금 실행하지 않는다. 인증값은 기록하지 않는다.

4. **예산을 보존한다.** 마지막 독립 검증상 실제 전송은 누적 7/12회였다. 읽을 수 있는 요청 원장에서 추가 사용 여부를 확인한다. 새 단계라고 12회를 자동 초기화하지 않는다. 잔여 예산이 불명하면 새 수집을 승인 가능한 상태로 표시하지 않는다. redirect/retry/page도 실제 전송으로 센다. 빈 응답을 피하려고 날짜를 계속 바꾸거나 반복 조회하지 않는다.

5. **모델 연결은 별도 준비 상태로 구분한다.** 후향 A 기반의 136열 모델이 실제 사전 F_t에서 곧바로 사용 가능하다고 가정하지 않는다. 기존 문서와 feature 메타데이터에서 이미 알려진 차단 사항만 정리한다: 출전집합/취소 사건 정의, 시간가변 source 관측, snapshot 성별 등 PIT 미확인 항목, 실제 raw feature snapshot 연결 여부. 모든 feature 모듈을 새로 전면 감사하거나 재구현하지 않는다. 실제 입력 계약을 통과하기 전에는 고정 모델이라도 운영 적격으로 표시하지 않는다.

6. **E9 결과를 과잉 사용하지 않는다.** 이번 30문서에서 precision 81/82, recall 81/121이었고 interference 회수는 10/33이었다. 미추출을 실제 사건 없음으로, 추출 행을 실제 피해 횟수로 바꾸지 않는다. E9 자료의 당시 공개 시각이 미확인이므로 전향 feature로 연결하지 않는다. E9의 봉인 규칙·라벨·최초 점수는 보존한다.

## 제출물 및 완료 조건

새 `docs/PROSPECTIVE_SHADOW_E10A_READINESS_2026-09-14.md`와 작은 기계 판독 readiness JSON을 제출한다. 표에는 조건별 `verified / unverified / unavailable`와 근거 파일을 붙인다. 실제 수집 시작에 필요한 조건, 기존 코드로 가능한 일, 꼭 필요한 최소 연결 작업을 구분한다. 최소 연결 작업이 있으면 검토 가능한 설계와 수정 대상만 제시하고 이번 범위에서 구현하지 않는다.

완료의 의미는 **한 번짜리 실제 capture를 착수하거나 보류할 수 있는 구체적 준비표가 완성됐다는 것**이다. 실제 출전표가 없다면 `waiting_for_publication_evidence`가 정직한 결과다. 새 소스/모델을 만들지 않은 경우 전체 pytest를 반복 실행할 필요는 없다. 읽은 입력과 새 문서/JSON hash만 보존하고 기존 dirty 파일은 수정하지 않는다.

제출 후 종료한다. 별도 실제 수집 지시 전에는 HTTP·자동화·학습·운영 연결을 실행하지 않는다.
