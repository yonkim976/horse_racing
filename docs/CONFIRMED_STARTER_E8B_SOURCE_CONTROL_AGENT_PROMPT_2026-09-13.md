# E8-B 후속: 과거 양성 대조군으로 원천 동작 확인

작업 경로는 `/Users/kimyongjin/Desktop/horse_racing`이다. E8-B에서 서울 2026-09-19 조회는 transport 시도 5회, 연결 실패 2회, 빈 정상 응답 3회로 종료됐다. 미공개라고 단정할 수 없으므로 원천 동작을 작은 대조군으로 확인한다. 이번 지시를 사용자가 전달하면 아래 제한 수집을 진행한다.

## 범위

1. 기존 원문 index/manifest에서 **2026-05-31 이전의 서울 날짜 하나**를 고른다. 같은 공식 API26_2 출전표 또는 API154 일정의 비어 있지 않은 원문이 존재하는 날짜를 우선한다. 결과 테이블의 성적을 조회해 고르지 않는다. 날짜와 기존 원문 존재 근거·hash를 HTTP 전송 전에 고정한다. 존재 근거가 없으면 날짜를 추측해 순회하지 말고 이 한계를 보고한다.
2. 공식 API26_2·API154의 해당 날짜 **첫 페이지만** 읽는다. endpoint당 최대 2회 시도, 신규 실제 transport 총 **최대 4회**다. 이전 E8-B 5회와 합쳐 누적 9/12 이내로 끝낸다. 여러 날짜·경마장·다른 API·추가 pagination으로 넓히지 않는다. 이 작업은 양성 대조 확인이며 전체 날짜 수집 완료 판정이 아니다.
3. 2026-09-19를 즉시 재조회하거나 백그라운드 대기를 하지 않는다. 기존 5회 요청·빈 원문·실패 산출물은 보존한다.

## 검사와 해석

- 원 요청 파라미터, 실제 HTTP 시도 수, raw, 요청/수신/파싱/commit 완료 시각, 메타데이터, 첫 페이지 item 수 및 날짜·경마장 키를 남긴다. 비어 있지 않은 응답을 얻어도 `first_page_nonempty`와 `complete_dataset`을 구별한다.
- 기존 원문과 현재 응답의 날짜/경주/말 키를 대조한다. 첫 페이지만 요청했으면 미수집 페이지를 누락 오류가 없는 완전 집합으로 표시하지 않는다. 과거 응답의 수정 가능성·제공 기간 변경도 고려한다.
- 과거 대조군이 nonempty면 그 날짜·원천에서 현재 요청 경로가 동작한다는 결론까지만 내린다. 미래 날짜가 비는 원인이 미공개였다는 확증은 아니다.
- 대조군까지 비거나 인증/통신 오류이면 공식 KRA/공공데이터포털 문서에서 파라미터·지원 기간을 확인한다. 검증되지 않은 요청 형태를 추측하여 남은 예산 밖 추가 요청을 하지 않는다. 공개 주기나 미래 조회 지원을 설명할 때는 확인한 공식 문서의 URL·문구와 확인 시점을 남긴다. 근거가 없으면 unknown으로 기록한다.
- 명백한 수집 코드 결함을 발견하면 해당 부분만 별도 보완하되 기존 코드와 수집 당시 source snapshot/hash를 보존한다. 새 수집 시에는 실행 전 정확한 source 내용을 보존해 hash만 남는 한계를 반복하지 않는다. secret 값은 source snapshot·원장·문서에서 제외한다.

## 금지와 종료

운영 DB·registry·UI·scheduler를 변경하지 않는다. 결과·구간·확정배당 endpoint, 2026-06-01 이후 실제 결과/holdout은 조회하지 않는다. 사후 수집한 과거 출전표를 T−30 관측으로 표기하지 않는다. 학습·추론·확률 발행·성능 계산·자동 수집은 0회다.

새 격리 폴더에 protocol, raw/요청 원장, control comparison, 보존/실행 source/출력 hash manifest와 간결한 보고서를 제출한다. 모델/운영은 `not_activated`, F_t는 `unverified`다. 수정한 코드가 있으면 관련 회귀·Ruff와 필요한 전체 pytest를 수행한다. 단순 네트워크 관측만 하고 코드 수정이 없으면 전체 테스트를 불필요하게 반복하지 않는다.

최종 보고에는 다음 미래 수집을 실행할 **조건**을 제시한다. 예를 들어 공식적으로 해당 출전표가 게시됐다는 근거를 확인한 때이며, 근거 없는 특정 요일/시각을 확정하지 않는다. 예약이나 반복 수집을 실제로 등록하지 않는다. 제한된 원천 진단 후 종료한다.
