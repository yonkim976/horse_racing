## 2026-10-12 언덕조교 조회 경로 통일 및 Google 반영

|---|---|

## 각 수집기의 범위와 시간 제한

주간 출마표는 실행일이 속한 수요일부터 다음 화요일까지의 아직 지나지 않은 공개 일정을 탐색한다. 연휴의 월·화요일도 포함하며 이미 시작된 경주나 경주 당일 변경을 초기 출마표로 덮어쓰지 않는다. 늦게 공개된 출마표는 같은 수요일의 후속 예약에서 재확인한다.

매일 조교는 실행일 포함 최근 7일을 다시 조회해 지연 공개와 정정을 흡수한다. 제주 출발조교의 하루 여러 회는 `occurrence_no`별로 보존하며 같은 조회를 반복했다고 업무 행이 계속 증가하지 않도록 같은 저장 슬롯을 갱신한다. 슬롯 번호는 공식 훈련 시각이나 이벤트 ID가 아니다. 빈 응답으로 기존 기록을 지우지 않는다.

10월 8일 보완의 Google 조교 실패 상세 알림은 당시 이미지 반영 대기였으며 10월 12일 후속 승인 이미지에 포함됐다. 기존 자동 조교 수집 예약은 그대로 유지한다. 한 날짜·지역의 일반조교 수동 재확인은 `scripts/recheck_daily_training.py`를 사용한다. 주행심사 로컬 수집은 이미 보완 경로를 사용하며 Text/API 원문과 대기·오류 상세를 날짜·지역별로 보존한다. 상세 원인과 정책은 [10월 8일 보완](LOCAL_REFERENCE_DATA_AUTOMATION_2026-10-07.md#10월-8일-장애-원인과-보완)을 따른다.

당일 수집은 다음 경주 하나가 아니라 오늘 DB에 출마표가 있는 경마장 전체를 날짜 단위로 확인한다. 정상 조회 창은 첫 경주 예정 1시간 전부터 마지막 경주 예정 2시간 후까지며, 08:00 이상 22:00 미만 제한도 적용한다. 예정 시각이 누락되면 09:00 이상 21:00 미만을 사용한다. 한 경마장이 모두 완료되면 해당 경마장 원천 재확인은 10분 간격으로 줄이고 다른 경마장은 계속 확인한다. 창 밖의 2분 예약은 수집을 건너뛴다.

확정배당은 같은 경주 시간 창과 09:00 이상 22:00 미만 제한을 적용한다. 완료 여부와 결과 범위를 검증한 경주만 적재한다. 경주 전 변동 배당이 아니며 미공개·0값으로 정상 배당을 덮어쓰지 않는다.

결과 보완은 기존 출마표에 연결된 출전행의 결과·정정을 보완한다. DB에 출마표 자체가 없는 경주를 자동 생성하는 작업은 아니다. 아직 시작 전인 오늘 경마장은 건너뛰고, 아직 상세 결과가 공개되지 않은 출전행은 대기로 남긴다. 7일을 넘어 뒤늦게 수정된 과거 자료는 별도 수동 검증이 필요하다.

당일·배당·결과 보완은 로컬 파일 잠금과 관련 PostgreSQL 잠금을 공유한다. 겹치면 기다리며 동시에 쓰는 대신 건너뛴다. 보완 작업이 한 번 건너뛰면 다음 예약이나 수동 실행으로 재확인해야 한다. 클라우드 조교 등 다른 모든 작업을 막는 전역 잠금은 아니다.

## 디스코드 알림

기존 사용자 웹훅을 유지한다. 주소·토큰·DB 비밀번호·API 키는 이 문서에 기록하지 않는다. 클라우드는 Secret Manager, 노트북은 기존 비밀 설정을 사용한다.

| 작업 | 보내는 시점 | 조용히 건너뛰는 경우 |
|---|---|---|
| 주간 출마표 | 완료·변경 없음·수집 실패 요약 | 프로그램 시작 전 장애는 알림을 보장하지 못함 |
| 매일 조교 | 종류별 신규·변경·유지·최신일과 실패 요약 | 프로그램 시작 전 장애는 알림을 보장하지 못함 |
| 당일 수집 | 체중·기수·취소·결과 변경, 새 완료 경주, 오류·복구 | 변경 없는 예약 실행. 같은 오류는 30분 간격 제한 |

압축 파일 이름에는 원래 로그 이름·UTC 보관 시각·고유값이 포함된다. 압축을 풀어 SHA-256이 원본과 같은지 확인한 다음 원본 파일의 내용만 비운다. 파일 자체와 inode는 유지하므로 기존 launchd 출력 연결을 끊지 않는다. 비어 있는 로그는 압축본을 만들지 않는다. 정상 완료 후 같은 한국 날짜에는 다시 비우지 않는다. 압축본은 성공한 정리 시각 기준 168시간을 초과하면 삭제하며, 매일 작업이 실행될 때 삭제되므로 정확히 168시간째 즉시 없어지는 것은 아니다.

수집기 공유 잠금을 얻지 못하면 건너뛰고, 압축 중 원본 변경을 감지하면 원본을 유지하며 `partial`로 기록한다. 압축 실패·검증 실패에도 원본을 비우지 않는다. 심볼릭 링크·다중 하드링크·특수 파일은 거부한다. 로그 디렉터리와 압축 폴더는 0700, 압축본과 결과 파일은 0600이다.

이 방식은 copytruncate다. 같은 잠금을 쓰지 않는 임의 프로세스가 마지막 변경 검사와 내용 비우기 사이에 쓰면 극히 짧은 경합 구간의 로그 유실 가능성은 남는다. 기존 worker도 잠금 밖에서 일부 계획·건너뜀 메시지를 쓰므로 무손실을 보장하지 않는다. 경주 시간이 아닌 새벽 03:00에 실행해 겹침을 줄이며, DB·원문·검증 기록은 별도로 보존한다. 실패나 건너뜀에 대한 무한 자동 재시도는 없으며 결과를 확인해 수동 실행하거나 다음 날 예약을 기다린다.

## 로컬 상태 확인과 수동 실행

아래 명령은 프로젝트 폴더에서 실행한다. 수집 명령은 `--apply`가 있어야 실제 DB 쓰기를 한다. 로그 정리는 `--apply`가 없으면 계획만 표시한다.

```sh
cd /Users/kimyongjin/Desktop/horse_racing
.venv/bin/python scripts/manage-local-race-day.py status
.venv/bin/python scripts/manage-local-post-race.py status
.venv/bin/python scripts/manage-local-log-rotation.py status
.venv/bin/python scripts/manage-local-catalog.py status

.venv/bin/python -m horse_racing.jobs.local_race_day --apply
.venv/bin/python -m horse_racing.jobs.local_post_race --mode dividends --apply
.venv/bin/python -m horse_racing.jobs.local_post_race --mode repair --apply
.venv/bin/python -m horse_racing.jobs.local_log_rotation
.venv/bin/python -m horse_racing.jobs.local_log_rotation --apply
.venv/bin/python -m horse_racing.jobs.local_catalog --mode medical --apply
.venv/bin/python -m horse_racing.jobs.local_catalog --mode profiles --apply
.venv/bin/python -m horse_racing.jobs.local_catalog --mode trials --apply
.venv/bin/python -m horse_racing.jobs.local_catalog --mode canonical --apply
.venv/bin/python -m horse_racing.jobs.local_catalog --mode cards --apply
```

네 관리 스크립트의 `install`은 해당 예약만 재등록하고, `stop`은 해당 예약만 중지한다. `manage-local-post-race.py`는 배당과 결과 보완 두 예약, `manage-local-catalog.py`는 신규 5개를 관리한다. 후자는 `--mode trials`처럼 한 작업만 지정할 수 있다. 로그 정리를 멈추려면 `manage-local-log-rotation.py stop`만 사용한다. 기존 `scripts/install-launchd.sh`는 과거 전체 동기화 예약 설치기이므로 현재 작업 설치기로 사용하지 않는다.

보완 정책:

- 최초 DB 연결에만 최대 3회(추가 대기 2·5초) 재시도한다. 인증·명시적 TLS 오류는 재시도하지 않는다. 이미 시작한 트랜잭션이나 도착 여부가 모호한 커밋을 자동 재실행하지 않는다. 잠금 연결 종료 오류가 이미 커밋된 수집 요약을 실패로 덮어쓰지 않도록 별도 경고로 기록한다.
- DB 오류는 고정 분류와 SQLSTATE, 실패 단계로 기록한다. Discord는 고정 오류 사유·재시도 가능 여부를 기록한다. DB URL·웹훅·API 키·원래 예외문은 로그에 저장하지 않는다.
- Discord의 연결 전 실패만 짧게 재시도한다. 수신 응답 대기/송신 중 오류와 잘못된 성공 확인은 `delivery_unknown`으로 남기고 자동 재전송하지 않는다. 429는 후속 복구 대상이며 인증·404 등은 대상이 아니다.
- 새 로컬 복구기는 로그인 시 및 깨어 있는 동안 5분 간격으로 상태 파일만 점검한다. 네트워크 연결 사전 점검 실패는 재실행 한도를 소비하지 않는다. DB 최초 연결 실패만 최근 24시간 범위에서 하루·작업별 최대 3회 재실행한다. 재실행 후 대기 간격은 5·20·60분이다. 공개 대기, 검증 충돌, 작업 도중 실패, 인증 오류는 자동 재적재하지 않는다.
- 수집 성공 후 알림만 확실히 미전송됐다면 수집 없이 알림만 재시도한다. 전송 중 프로세스가 종료된 `sending` 상태는 중복 방지를 위해 자동 재전송하지 않는다. 알림 재시도는 최근 당일·전일 요약에 한해 요약별 최대 3회다.
- 결과 보완 전용 `data/state/local-post-race-repair-status.json`을 두어 빈번한 배당 작업이 결과 보완 실패와 알림 상태를 지우지 않게 했다. 복구 횟수는 `data/state/local-recovery.json`에 기록한다.
- 서울 10/10 1R은 모든 11출전행의 공식 비고가 `경주불성립`, 착순 98, 완주시간 null이고 공식 Text에는 2~10R만 있다. 구간 검증은 모든 말의 명시적 비고와 API4_3의 말 ID·거리·98·완주시간 null이 독립적으로 일치한 경주만 구간 대상에서 분리한다. 98만으로 불성립을 추정하지 않는다. 기존 결과·원문은 보존하고, 다른 정상 경주의 검증을 생략하지 않는다. 새 캡처에는 결과 비고도 포함하며 이전 관측물은 수정하지 않았다.
- 서울 10/10 6R 5번 레이스디바는 공식 Text에 주행중지·`0:00.0`, API에 착순 92·기록 0·통과순위 99가 있다. 공식 주행중지 표기와 API의 완주시간 결측이 일치한 경우에만 0시간·99 통과순위를 결측 표지로 처리하고 품질 사유를 보존한다. 정상 완주마의 99는 여전히 검증 오류다. 원문·결과 착순을 바꾸거나 실제 통과순위를 추정하지 않았다.

10/10 심판 API215 및 통과조·상세구간 API303·API6_1은 야간 재조회에서도 정상 0건이었다. 따라서 DB 연결 복구와 별개로 당일 심판·정규화 구간 적재는 아직 완료가 아니다. 다음 기존 정기 재조회는 10/11 09:15 KST다. Mac 전원을 켜거나 강제로 깨우는 기능은 추가하지 않았으므로 종료·덮개 닫힘·네트워크 단절 중 실행은 보장하지 않는다. 웹훅 재발급·클라우드 신규 리소스·배포·모델·SQLite 변경은 없다.

**자동화 상태: 현재 미포함.** 실제 등록된 LaunchAgent 목록과 실행 코드를 확인했으며 `catalog-profiles`는 말 프로필·조교사만 수집한다. 기존 Google 출마표·조교 작업에도 등급변동 단계는 없다. 구형 `sync-daily` 전체 동기화에는 수집 함수가 있지만 `sync-morning`·`sync-evening`이 등록되어 있지 않아 활성 자동화로 세지 않는다. 이번에는 신규 예약 등록, 기존 예약의 수집 항목 변경, Discord 전송을 하지 않았다.
