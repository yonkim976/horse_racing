## 1. 가장 중요한 결론

운영 DB의 공식 과거 데이터는 로컬 SQLite와 Supabase에 거의 동일하게 적재되어 있다. 그러나 현재 운영 모델이 읽는 연구용 이력은 별도의 고정 스냅샷이므로, 운영 DB를 최신화해도 모델 입력이 자동으로 최신화되지는 않는다.

현재 상태는 다음과 같다.

1. 더러브렛의 정상 경주 결과는 모델 지원 기간 안에서 전부 반영되어 있다.
2. 제주의 정상 경주 결과는 99.94% 반영되어 있으며, 2019년 4개 경주·40두가 연구 이력에서 제외되어 있다.
3. 현역 제주마 중 `흥국강타`의 2019-05-25 제주 9경주 1착 이력 1건이 현재 `HY_R_FORM` 과거 상태 계산에서 빠져 있다.
4. 모델 이력 cutoff는 더러브렛 2026-09-13, 제주 2026-09-12다. 로컬/Supabase 공식 결과는 2026-09-20까지 있으므로 9월 13일 이후 결과가 현재 고정 모델 입력에는 반영되지 않았다.
5. 수영훈련과 언덕주로 데이터는 로컬/Supabase에 적재되어 있지만 현재 주력 모델 변수에는 포함되지 않는다.

따라서 다음 작업의 초점은 모델 재학습이 아니라 **현재 운영 모델을 유지한 채 최신 운영 DB로 과거 상태·특징을 다시 만드는 입력 파이프라인**이다.

## 2. 반드시 지켜야 할 작업 제한

- 기존 운영 DB, 기존 모델 아티팩트, 기존 연구 산출물을 수정하거나 삭제하지 않는다.
- 기존 연구 폴더를 덮어쓰지 않는다. 재생성 결과는 새로운 버전 폴더에 기록한다.
- 실험 모델을 자동 승격하지 않는다.
- 운영 모델은 `config/prediction_model_registry.json`에서 명시적으로 승격되고 해시 검증을 통과한 모델만 사용한다.
- 더러브렛과 제주 모델의 특징, 보정값, raw score 계약을 서로 섞지 않는다.
- 과거 데이터 보완 과정에서 미래 결과 누수가 생기지 않도록 각 예측 대상 시각보다 엄격히 이전 데이터만 사용한다.
- Supabase 쓰기, 기존 예측원장 수정, live 발행은 별도 사용자 승인 없이는 하지 않는다.
- DB 비밀번호, service role 키, 연결 문자열을 로그·문서·프론트엔드에 출력하지 않는다.

## 8. 수영훈련과 언덕주로

두 데이터는 로컬과 Supabase에 적재되어 있고 parity도 맞는다.

그러나 현재 모델 번들을 감사한 결과:

- 더러브렛 110개 변수에 `swim`/`hill` 변수 없음
- 제주 `HY_R_FORM` 순위 108개·순서 68개 변수에 `swim`/`hill` 변수 없음

따라서 이 두 데이터는 현재 확률에 영향을 주지 않는다. 반영하려면 별도 연구 후보 변수 생성, 시점 누수 감사, 과거 검증, 재학습, 명시적 모델 승격이 필요하다. 현재 과거 이력 보완 작업과 섞지 않는다.

## 9. 다음 에이전트가 수행할 권장 작업

### 우선순위 1: 읽기 전용 재검증

1. 두 운영 모델 resolver를 실행하고 해시·검증 gate를 확인한다.
2. 로컬 운영 DB `PRAGMA quick_check`를 실행한다.
3. 로컬과 Supabase의 공식 핵심 테이블 count/max date parity를 다시 확인한다.
4. 위 2019년 제주 4개 경주의 운영 DB 원본, 연구 DB `source_row`, `entry`, `resolution_issue`, `quarantined_entries`를 읽기 전용으로 추적한다.
5. `흥국강타(3017958)`뿐 아니라 해당 경주 전체 출전마 identity가 왜 제외됐는지 증거를 남긴다.

### 우선순위 2: 제주 이력 복구 설계

1. 기존 연구 DB·Parquet을 수정하지 않는다.
2. identity 해결 규칙을 코드 또는 명시적 보정 매핑으로 만든다.
3. 새로운 연구 버전 폴더에서 4개 경주를 포함해 `history_results`, states, context history를 재생성한다.
4. 기존 90,122개 이력 키가 변경·삭제되지 않았는지 확인한다.
5. 새로 추가되는 정상 결과가 정확히 40행인지 확인한다.
6. 현역마 `흥국강타`의 win/top3/ELO/form 상태 변화량을 별도로 보고한다.
7. `HY_R_FORM` 모델 파일은 바꾸지 않고 새 입력으로만 예측 재현성을 검증한다.

### 우선순위 3: 최신 결과 delta 반영

1. 더러브렛은 2026-09-14~20, 제주는 2026-09-13~20의 완료 결과를 로컬 운영 DB에서 읽는다.
2. 예측 시점별 as-of 규칙을 지키며 과거 상태와 특징을 증분 또는 전체 재생성한다.
3. 모델 학습·보정·평가 데이터에 미래 결과를 섞지 않는다.
4. 현재 모델 가중치와 registry는 유지한다.
5. 기존 고정 예측과 새 입력 예측의 확률 변화가 입력 이력 변화로 설명되는지 확인한다.

### 우선순위 4: 범용 예측 입력 생성기

더러브렛:

- 고정 27경주·294두 Parquet 의존성을 제거하지 말고, 별도 범용 입력 생성기를 추가한다.

제주:
