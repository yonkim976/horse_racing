## 2. 말·기수·조교사와 결과 연결

**DB 내부의 관계 구조는 잘 정리돼 있다.** SQLite 외래키 위반 0, 경주 자연키 중복 0, 경주별 마번 중복 0, 경주별 말 ID 중복 0, 같은 말의 당일 복수 출전 0이다. 출전행의 말·기수·조교사 연결 결측도 0이다. 출전행과 결과행은 1:1로 연결된다.

다만 ID가 채워져 있다는 것과 공식 인물이 끝까지 검증됐다는 것은 다르다.

- 말 임시 ID는 **1두·9출전**이다. 나머지 출전은 공식 형식의 말 ID에 연결된다. 구형 Text 원천은 이름·출생연도·경마장·성별 후보 매칭을 거쳤으므로 전수 공식 ID 직접 관측과 구분한다.
- 기수 **179개**, 조교사 **434개**가 `text:` 임시 ID다. 과거 이름을 일관된 내부 ID로 만든 것으로 모두 잘못됐다는 뜻은 아니다.

## 3. 과거 결과는 원문과 얼마나 일치하는가

로컬 Text 성적표 **2,725파일**을 읽고 hash·파싱을 확인했다. 불일치·파싱 예외 0. 한라마를 별도 분리한 뒤 파싱된 22,895경주의 경주 키는 DB에 모두 존재했다. 이 중 2015~2024 DB 경주 **22,827개 모두** 대응 로컬 원문이 있다. 비교한 공통 출전의 착순·완주시간·부담중량 차이는 0, 마체중 차이 1개는 원문 0 대 DB null이다.

이것은 **확보한 원문과 DB의 일치**다. 공식 전체 시행 목록을 새로 조회해 모든 과거 출전자를 독립 확정한 것은 아니다. 특히 과거 Text와 최근 API는 취소·중지 등 비정상 출전행을 담는 범위가 다를 수 있다.

실제로 남은 예외:

- **2015-04-10 부경 8경주**는 원문 안에서 첫 출전마 표와 마체중·기록 표의 말 번호 집합이 다르다. 해당 날짜의 정상 숫자 착순 **11행**에 완주시간이 없다. DB를 잘못 읽은 것이 아니라 원문 내부 모순을 재현했다. 다른 공식 원천으로 해결하기 전 해당 8경주를 신규 모델 표본에서 격리하는 것이 적절하다.
- 원문·최근 DB의 출전 키 차이 9경주는 최근 Text와 API의 표본 범위 차이로 따로 남겼다. 취소·중지 등을 포함할 수 있어, key count만 보고 DB 행을 삭제하면 안 된다.
- 2026-09-13 Text 6경주는 경로가 `meet=3`이지만 문서 제목은 영천이며 DB에서는 meet=4다. 제목을 기준으로 대조하면 누락 0. 원문 저장 디렉터리만으로 실제 경마장을 정하면 안 된다.
- 정상 착순(1~89) 287,139행 외 **1,467행**은 특수코드 또는 착순 null이다. 전체 모델에서 숫자 순위로 섞어 학습하지 않는다. 기존 E1/E2의 DNF·실격·미출주 구분을 새 데이터셋에도 적용하되 원천별 의미를 확인한다.
- 우승마가 없는 37경주는 정상 숫자 착순도 없는 경주다. 학습/평가 제외 정책이 필요하며, 정상 완료 경주의 우승 결과 누락 37건으로 표현하지 않는다.
- `field_size`와 저장 출전행 수가 다른 경주는 502개다. 취소 등을 포함하는 저장 출전집합과 실제 출발두수의 의미 차이를 구분해야 한다. 이를 모두 데이터 오류로 단정하지 않는다.

오래된 장기 dataset 10개에 한라마 archive 키가 남아 있다. 대표 272,904행 장기 dataset은 12,415행, racefit_v2_history는 16,181행이다. 과거 산출물 보존은 정상이며, 현재 마종 계약에 맞는 신규 학습 입력으로 무심코 재사용하면 안 된다. 해당 파일을 삭제하거나 덮어쓰지 않았다.

대표 6개 Parquet의 명시 feature 목록(일반 manifest 목록 또는 H1의 실제 선택 136열)을 검사했다. feature 열 누락·NaN/Inf 0. 제주 recent/history 두 파일에서 `pace_fade_avg5`가 전부 NULL이다. 이는 파일을 읽고 수치 계산할 수 있다는 검사이며, 모든 feature의 시점·의미·수식이 옳다는 증명은 아니다. 저장된 feature 목록과 모델이 실제 선택한 열 수는 다를 수 있다.

과거 정상완주 조건부로 생성된 dataset과 H1의 DNF 포함 계약도 다르다. 새 통합 dataset에서는 목적에 맞는 출발집합과 label/mask를 하나로 정해야 한다.

## 7. 모델을 위한 정리 방향

**출전표의 이번 주 게시를 기다리지 말고, 신규 모델용 dataset 정리로 진행할 수 있다.** 학습자료 전체가 완전해질 때까지 API 수집기·시간 원장을 계속 보완할 필요는 없다.

1. **최근 상세층**: 2025~2026-09-13, 서울·부경과 제주를 구분. 성적·말/기수/조교사·과거 구간·조교를 활용한다. 동작이 검증된 feature 코드를 재사용하고, 전수 ID 단절·불명 구간·모순 원문은 제외/결측/신뢰도 표시로 처리한다. 서울은 구간 정상화가 상대적으로 잘 돼 있어 첫 상세 모델의 출발점이 된다.
2. **장기 공통층**: 2015년 이후 성적과 연결 가능한 말·관계자 이력. 한라마를 분리하고, 조교/진료 미보유 시대를 0으로 만들지 않는다. 이력 시작 경계와 세대/경마장/등급 차이를 표시한다. 장기층을 최근 상세층과 무조건 같은 feature 행렬로 섞지 않는다.
3. **이번에 필요한 정리만 묶어 실행**: 최신 원천에서 새 immutable dataset 생성, 2015 모순 8경주·불명 특수 결과 처리, 오래된 한라마 포함 dataset 배제, 구간 시간 기준이 확인된 값만 사용, 조교사/조교 기수 연결 불명값 처리. 사용자 원문과 DB를 수정하는 작업과 파생 dataset에서 격리하는 작업을 구분한다.
4. **그 다음 모델 비교**: 고정 기준 모델을 먼저 두고 장기 이력·조교·구간의 추가 가치를 시간순 검증으로 비교한다. 반복 사용한 개발기간은 독립 시험으로 부르지 않는다. 이번 보고서는 모델 연구 시작 근거이지 우월성/수익성 판정이 아니다.

당일 주로·마체중·배당은 사용자가 설명한 발표 일정에 맞춰 별도 입력 단계로 다룬다. 발표 전 모델은 이 값 없이, 발표 후 모델은 확보된 값으로 설계할 수 있다. 최종 배당과 대상 경주 결과·구간·심판보고서를 사전 입력으로 섞지 않는 원칙만 유지하면 된다. 실제 공개 시각의 정밀 원장을 모든 과거 자료에 소급 복원하는 일을 지금 모델 개발의 무기한 차단 조건으로 두지 않는다.
