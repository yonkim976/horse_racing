## H1 — 신원 충돌을 전 경로에서 차단

새 `_markers`가 출전번호→단일 runner dict로 중복을 덮는 문제를 수정하라. 같은 번호/다른 이름, 같은 번호/같은 이름/다른 source ID의 독립 로그 반례를 모두 처리한다. 중복·충돌은 순서에 따라 해결하지 말고 명시적으로 거부하거나 affected identity를 abstain 처리한다. 구체 정책을 문서에 고정한다.

기존 추출기의 신원 충돌 abstain이 `_scoped_predicates`나 복구 경로에서 clear로 되살아나지 않아야 한다. 원문 번호·이름·source ID의 유일성 판단을 경로별로 다르게 하지 않는다. 정상 유일 roster, 입력 순서 역전, 이름/번호 치환, 중복 키 반례를 검사하라. 범위 밖 정상 말의 처리 정책도 명시하되 신원 충돌을 정상으로 추정하지 않는다. 실제 표본 roster에 중복이 없다는 현재 검증 결과와 합성 회귀를 구분해서 보고한다.

## H2 — actor를 동일 피해 사건과 연결

같은 말의 아무 이동 문구를 찾으면 actor clear로 승인하는 분기를 제거하라. 독립 로그의 `actor_disconnected`에서는 ②나래를 actor clear로 출력하면 안 된다. ①의 명확한 피해 관측은 유지할 수 있으며, ③의 관계가 파서 지원 밖이면 actor를 보류해도 된다. 특정 말 이름·race ID·문장 문자열 예외를 하드코딩하지 않는다.

actor/행위/피해 관측/관계 근거를 같은 사건에 연결해 검증한다. 지원 가능한 명시 관계 패턴만 clear로 승인하고, 불확실한 인과 귀속은 hold/unknown으로 남긴다. 이동 자체가 피해 원인이라고 추정하지 않는다. 서로 다른 문장·반복 등장한 동일 말·상호 접촉 후 별도 방해·관계 부정·명시 원인 판단의 정상/반례를 검사한다. 원문의 `것에 대해 … 원인으로 판단`처럼 피해가 먼저 제시되는 정상 표현도 유지해야 한다.

실제 race 1698의 ⑦라온더어펌드 actor는 첫 이동 문구 대신 뒤의 `이후 … 지속해서 … ⑧ … 불편` 관계를 근거로 연결한다. 귀속 자체가 틀렸다고 보고하지 않는다. 하나의 clause로 담기 어려우면 복수 source span과 관계 유형을 명시해도 된다. 각 span은 원문 offset과 일치해야 한다.
