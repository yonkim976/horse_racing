## 1. 목표와 성공의 정의

장기 목표는 **실제 경주 전에 예측한 제주마 전체 경주의 Top1 적중률을 100%에 최대한 가깝게 높이는 것**이다. 여기서 Top1은 확률이 가장 높은 말 한 마리가 공식 우승마 집합에 포함되는지를 뜻한다. 우승마가 후보 3두에 포함되는 비율, 일부 자신 있는 경주만 고른 적중률, 출전행의 승/패 분류 정확도를 전체 경주 Top1과 혼동하지 않는다.

100%는 연구 방향이며 보장 가능한 성능이나 V1 완료 조건이 아니다. 미관측 상태·전개·사고와 유한 표본 때문에 표본에서 전부 맞혔다고 미래의 무오류를 증명할 수 없다. 실패 경주를 분모에서 빼거나 정답을 본 뒤 조건을 고르는 방식으로 목표를 달성하지 않는다.

V1은 말의 장기 능력·조건 적성·최근 상태·불확실성을 먼저 추정하고, 같은 경주 상대들과 경쟁시켜 확률합 1의 우승분포를 만드는 **말 중심 연구 단계**다. 최고의 최종 모델은 이 단계에서 멈추지 않고 전개·기수·조합·당일 정보를 검증하며 확장한다.

```text
장기 기본 능력 + 거리별 적성 + 최근 상태
+ 이번 경주의 사전 조건과 상대 편성
+ 능력 추정의 불확실성 + 경기마다 발생하는 변동
→ 말별 잠재 성능분포 → 경주 전체의 우승확률
```

성공을 두 축으로 관리한다.

- **사용자 목표:** 전체 적격 경주 Top1, 적중 경주 수/전체 경주 수, 경주일 단위 95% 신뢰구간. 40%·50%·60% 등은 진행을 보여주는 눈금이며 검증 전 예상 성능으로 제시하지 않는다.
- **확률 품질:** 경주별 winner-set NLL(정답 우승마 집합에 준 확률의 음의 로그)을 주 선택 지표로 사용한다. 무리한 확신을 벌점으로 반영하고 Brier·calibration을 함께 확인한다.
- Top1 최대 후보와 NLL 최저 후보가 다르면 둘을 명시한다. 확률모델 승격에는 NLL과 Top1의 사전 고정 비열등 기준을 모두 요구한다. 성능이 개선되지 않아도 정확한 기준선·실패 원인·재현 가능한 결과가 있으면 연구 제출은 완료할 수 있다.

## 3. 모집단: 행 연결과 경주 전체 완결성을 구별한다

### 3.1 확정된 기반 사실과 이번 정정

명시적 제주마 `제` 경주는 2002-07-28~2026-09-12의 9,423경주·92,208행이다. 양수 정상 결과가 있는 경주는 9,288경주·90,892행이며 나머지 135경주·1,316행은 격리돼 있다. 한라마 `한/래`를 target·학습·능력 척도에 섞지 않는다.

**기존의 9,288경주·90,177행을 ‘출발마 ID가 모두 완결된 경주 집합’이라고 부른 것은 잘못이다.** 이는 정상 경주에서 공식 연결이 완료된 출발행을 합친 수다. 미해결 29행 중 25행은 실제 출발, 4행은 미출주이고, 실제 출발 미해결 25행은 8경주에 걸쳐 있다. 그중 3행은 우승마다.

따라서 기본 정책은 다음과 같다.

1. 공식 착순 코드로 **필터 전 기대 출발집합**을 먼저 만든다.
2. 출발마 중 공식 연결 미완료·키 충돌·결과 의미 불명인 말이 하나라도 있으면 그 경주 전체를 주 학습·평가에서 격리한다. 확정 미출주마의 ID 미해결만으로 경주를 제외하지 않는다.
3. 상대가 빠진 경주의 Elo/상대 순위 업데이트도 기본 arm에서 제외한다. 해당 경주의 개별 시간 활용은 후속 민감도 실험으로만 분리한다.
4. 구간·조교 등 feature 결측으로 출발마를 제거하지 않는다. 결측 정책이나 사전 고정 fallback으로 모든 출발마에 예측한다.

아래는 위 DB에 **경주 전체 ID 완결성 규칙만 추가한 실측**이며, 거리 등 추가 계약을 적용하기 전이다.

400m 598경주·5,539행은 위 완결 집합 안에 있으며 현재 target에서 제외하고 별도 거리의 과거 이력으로만 보존한다. 최종 builder는 날짜·거리·상태별 제외 사유를 중복 없이 집계하고 최종 경주/행 key hash를 봉인한다. 9,280/90,122를 추가 검증 전 최종 승인 수로 강제하지 않는다.

### 3.2 라벨과 동착

- 정상 착순 1~89: 완주. `win`은 1착 여부, `topK`는 공식 착순이 K 이하인 사건.
- 91 실격, 92 주행중지: `win/topK=0`. 정상 순위·완주시간 auxiliary target 및 정상 능력 업데이트는 mask한다. 임의 최하위 시간으로 바꾸지 않는다.
- 93/94/95 미출주: confirmed-starter 집합에서 제외하며 패배 라벨을 주지 않는다.
- 98/99·미확정·상충·무효·의미 불명: 사유를 남기고 위 경주 완결성 계약에 따라 처리한다.
- `record_status='normal_completed'`만으로 판단하지 않는다. 양수 시간이 저장된 91 코드가 162행 있다.
- 우승자 집합 `W`를 보존한다. 동착 경주에서 `q_i=1/|W|`(우승자), 나머지 0의 soft label을 별도로 저장한다. `label_win`과 `q_i`를 다른 열로 관리한다.
- 평가 `set_nll=-log(sum(p_i for i in W))`, `soft_ce=-sum(q_i*log(p_i))`를 **모두** 출력한다. 두 loss는 동착에서 같지 않으며 교환 가능한 정의로 취급하지 않는다.
- 확률합 1의 p는 동착 승리를 각 말에 1씩 부여한 주변확률과 같지 않다. 주 Brier는 q 기준 경주별 합, 공식 win 이진 지표는 별도 보조 진단이며 동착을 분리한다.
- TopK 경계의 실제 동착은 공식 착순으로 판정하므로 양성 말이 K마리보다 많을 수 있다. 우승마 후보 포함률과 말별 TopK 진입확률을 혼동하지 않는다. 후자를 출력하려면 별도 순위분포 계약이 필요하다.

공통 label adapter를 builder·학습·평가에서 공유한다. 각 경주에 우승자 1마리 이상, 유효 출발마 2마리 이상, 키 유일성을 검사한다. 원문에는 대상 결과/배당이 존재할 수 있지만 feature table에는 허용하지 않는다.

## 4. 시간 계약: 사건일·공개일·수집일을 분리한다

### 4.1 기준 시점과 원천 계약

기본 cutoff는 **경주 전날 18:00 Asia/Seoul**이다. 역사 연구의 이름은 `retrospective confirmed-starter conditional, assumed day-before availability`이며 실제 전날 출전집합을 복원했다고 주장하지 않는다.

각 feature의 registry에 다음을 기록한다.

```text
feature_name, source_table, source_columns, unit, entity_key,
event_at, available_at, ingested_at, revision_id,
availability_evidence, availability_class, lag_policy,
aggregation_window, missing_policy, dedup_key, quality_rule, arm
```

- `event_at`: 사건 발생 시점. `available_at`: 외부에 공개되었거나 실제 예측 시스템에 도착한 이용 가능 시점. `ingested_at`: 현재 snapshot 수집 시점. 2026년에 백필한 과거 기록의 수집 시각을 과거 공개 시각으로 오인하지 않는다.
- 시각 증거가 있으면 사건일 제한과 `available_at <= cutoff`를 모두 적용한다. 결과의 확정 지연·수정 이력도 반영한다.
- 공개시각이 없으면 `verified / assumed / unknown`으로 구별한다. 과거 결과는 명시적 공개 지연 가정을 둔 연구 입력으로만 사용한다. 조교·진료·출전조건의 공개 근거가 없으면 주 arm에서 제외하거나 `ASSUMED_AVAILABILITY` 보조 arm으로 분리한다.
- 날짜만 확인되는 전날 사건은 18시 전에 공개되었다고 단정할 수 없다. 기본적으로 하루 추가 지연해 전전날까지 사용한다. 원천별 공개 지연 근거가 있으면 해당 규칙을 우선한다. 추가 1일·7일 지연 민감도를 같은 개발 경주에서 비교한다. 지연만으로 당시 공개를 입증했다고 쓰지 않는다.
- `history_event_date < target_event_date`는 최소 조건일 뿐 충분조건이 아니다. 같은 날 결과는 모든 말의 해당일 `pre` 값을 생성한 뒤 일괄 업데이트한다.
- 역사상 정확한 공개시각이 없다는 사실 자체는 H0 연구의 blocker가 아니다. 그 한계를 표시하고 prospective 수집에서 해소한다.

금지 입력: 대상 경주의 착순·시간·구간·최종 배당·사후 심판보고서, 대상일 마체중·실제 당일 주로, cutoff 이후 진료·조교, 현재 프로필로 소급한 레이팅·기수·관계자 정보.

원문 `normalized_json`은 필요한 경로만 추출한다. 전체 평탄화/`SELECT *` 기반 feature 생성을 금지한다. **원문에 금지 열이 존재하는 것은 정상**이며, feature matrix나 feature allow-list로 유입되면 실패시킨다. 라벨은 별도 경로로 읽고 추론 함수는 결과 table 없이도 작동해야 한다.

### 4.2 상태 생성과 전처리에서 생기는 추가 누수

- Elo 상대 능력도 당시의 `pre` 값으로 계산한다. 시즌 최종 Elo·전체 기간 상대 승률로 과거 경주 수준을 재평가하지 않는다.
- 훈련행의 상태를 만들 때 그 행 이후 결과로 맞춘 speed par·상태 파라미터를 소급 사용하지 않는다. 상태 파라미터는 선행 기간에서 적합하거나 내부 시간순 예측으로 생성한다. 미래 상태까지 본 smoother는 금지한다.
- 과거 경주 자체를 보정하는 day variant를 결과 이후 계산해 다음 경주에 쓰는 것은 허용하되, 해당 과거 경주의 **예측 전 상태**에는 넣지 않는다. 한 말 자신의 시간으로 주로효과까지 결정하지 않도록 다른 말/경주 기반 추정과 표본 부족 시 수축을 사용한다.
- scaler·encoder·imputer·feature 선택은 estimator fit 구간만으로 적합한다. tune/calibration의 분포를 미리 포함하지 않는다. 기존 `lightgbm_model.py`의 `train_all` encoder 경로를 무검토 복사하지 않는다.
- feature와 라벨 key는 별도로 만든다. 결과 변경으로 적격 여부가 바뀌는 테스트에서는 기존 예측 key를 고정해 feature 불변성을 검사하고, 모집단 변경은 별도 검사한다.
- DB 원천 날짜 `YYYYMMDD`는 입구에서 날짜형으로 변환한다. `YYYY-MM-DD` 문자열과 혼용 비교하지 않는다.

## 5. 말 상태와 경주 조건을 명확히 나눈다

말 상태는 조건별 능력의 저장소이고, 대상 거리·상대 편성은 그 상태를 읽는 조회 조건이다. 전체 상태 table에 열이 있다고 모든 arm에서 쓰지 않는다. registry가 arm별 접근을 제한한다.

```text
race_id, entry_id, horse_id, event_date, cutoff_at, field_snapshot_id,
state_version, source_snapshot_hash, history_policy, fit_fold,
ability_mean_pre, ability_uncertainty_pre,
distance_state_pre, early_speed_pre, cruising_speed_pre, finish_stamina_pre,
recent_form_pre, performance_variability_pre,
days_since_last_start, normal_history_count, usable_time_count,
training_observed, trial_observed, medical_observed,
source_quality, availability_class, regime
```

라벨·auxiliary target은 별도 table로 저장한다. 원시 horse ID·entry ID·파일명·source path·미래를 암시하는 수집 batch는 모델 입력으로 사용하지 않는다. 공식 ID는 이력 연결키다.

- 능력 추정의 불확실성(자료 부족)과 실제 경기 변동성(반복 경기 잔차)을 분리한다. heuristic이면 그렇게 명시하고 확률적 신뢰구간인 것처럼 표현하지 않는다.
- 신마는 과거 제주마 사전분포, 첫 거리·희소 거리·긴 휴양은 수축과 큰 불확실성을 사용한다. 신마용으로 미래 전체 말의 평균을 쓰지 않는다.
- 장기 능력과 최근 상태가 같은 관측을 중복 설명하지 않도록 평균 기준·수축·시간 척도를 정의한다. 성분은 인과적인 타고난 재능의 측정값이 아니다.
- 초/밀리초, m, kg, 조교 분/초를 명시한다. 구간 정의 변경·중복 체크포인트·누적/독립구간·근사 거리를 검증한다. 구간 누락이면 전체 말이나 경주를 버리지 않는다.
- 시간 residual의 기준은 거리·시대·과거 주로별로 과거 자료에서 추정한다. 희소 거리 1300/1400/1610m는 독립 모델보다 수축을 기본으로 둔다.
- 조교·진료는 미관측/관측범위 안 사건 없음/사건 있음/관측범위 불명을 구별한다. DB에 행이 없다는 이유만으로 ‘관측된 0회’라 하지 않는다. API와 Text의 동일 사건은 합산하지 않는다.
- 불확실성 또는 잠재 성능분포를 출력하면 관측 가능한 다음 경주 시간 residual의 예측구간 coverage 등으로 검증한다. 단순 softmax 점수만 학습했으면 실제 물리적 성능분포를 학습했다고 주장하지 않는다.
- 0~100 표시 점수는 잠재 원값과 별도로 단조 변환한다. 모델 학습값으로 수작업 점수를 주입하지 않는다.

## 6. 비교 모델과 실험 예산

모든 주 비교는 동일 cutoff 정책·평가 경주·전체 출발집합·평가기에서 수행한다. feature가 없을 때는 그 말의 행을 삭제하지 않고 결측/수축/fallback을 사용한다.

### 6.1 기준선과 핵심 arm

| Arm | 입력/방법 | 확인할 질문 |
|---|---|---|
| `U0_UNIFORM` | 경주별 1/N | 정보 없는 기준을 이기는가 |
| `RATING_ONLY` | 해당 시점 이용 가능한 공식 레이팅의 단조 점수 + 확률 보정 | 공식 레이팅 이상의 정보가 있는가 |
| `ELO_BASELINE` | 과거 완결 경주로 재계산한 multiplayer Elo | 단순 상대 결과 모형보다 좋은가 |
| `SPEED_ONLY` | 과거 보정 속도 요약 + 같은 확률층 | 복잡한 상태가 단순 속도보다 좋은가 |
| `H0_RESULT` | 동적 결과 능력·불확실성·휴양·출전 수·거리별 과거 결과 | 말 결과 이력의 가치 |
| `H1_TIME_SECTION` | H0 + 보정 완주시간·검증된 초반/순항/후반 구간 | 기록의 증분 가치 |
| `H2_STATE` | H1 + 시점 계약을 통과한 과거 조교·심사·진료·과거 체중 추이 | 상태 원천의 증분 가치 |
| `H3_CONDITION` | H2 + 출전표로 확인한 부담중량·등급/출전조건·연령/성별·게이트 및 필요한 상호작용 | 현재 조건에 적용하는 가치 |

대상 거리와 출발두수는 **H0부터 공통 조회 조건**이다. H0의 거리 적성에 쓴 거리를 H3에서 새 정보처럼 재추가하지 않는다. H3의 현재 중량·게이트·등급 등은 별도 allow-list를 갖는다. 대상일 마체중·당일 주로·배당·기수 ID는 H3에도 넣지 않는다.

- 현재 레이팅의 시점 근거가 없으면 `RATING_ONLY`의 결측 정책을 적용하고 실제 레이팅 사용률을 보고한다. 과거 경주에서 관측한 레이팅만 사용했다면 `LAST_OBSERVED_RATING`으로 이름을 바꾼다. 모든 값이 없으면 미실행 사유를 남기며 이름만 기준선인 균등 모델을 만들지 않는다.
- H1이 실패해도 H0를 제출한다. H2의 한 원천이 실패하면 `H2_PARTIAL`을 제출한다. 원천을 빼면 arm 이름·registry·예측 manifest에도 반영한다.
- H2는 개발 단계에서 조교/심사/진료/체중을 한 원천씩 뺀 비교를 제한된 예산 안에서 수행한다. 늦은 공개·관측 여부만으로 얻은 성능과 사건 내용의 성능을 구별한다.
- 2023년 전후 원천 밀도 차이는 시대별 결측/성능으로 보고한다. 상세 원천이 있는 말만 선택한 결과를 전체 모델 개선으로 제시하지 않는다.

### 6.2 기존 제주 모델의 공정한 비교

기존 V2 수치(2026년 179경주 valid, Top1 32.96% 등)는 출발집합과 시점이 달라 새 V1의 출발 성능으로 사용할 수 없다.

- 가능하면 기존 **방법**을 새 시간분할·동일 정보 계약으로 재학습한 `LEGACY_RETRAINED`를 비교한다.
- 저장된 기존 bundle은 fit/tune/calibration/후보선택에 사용된 마지막 날짜를 확인한다. 2026 결과로 선택된 기존 모델을 2025 경주에 소급 추론한 수치는 정당한 과거 예측이 아니다.
- 비교 가능한 경주 전체만 보조표에 쓰고 coverage를 명시한다. 출발마 일부가 누락된 행 교집합으로 경주를 재정규화하지 않는다.
- 기존 T-30 모델과 새 전날 모델의 차이를 모델 구조의 우월성으로 해석하지 않는다. 재현 불가이면 이유를 남기고 핵심 연구를 계속한다.

### 6.3 학습기·확률 보정

핵심 arm마다 다음 두 종류를 같은 시간 계약으로 비교한다.

1. LightGBM binary objective: soft winner label q, 경주당 총 sample weight가 동일하도록 `1/N`의 출전행 가중치를 기본으로 사용한다. class balancing/승자 oversampling은 기본에서 쓰지 않는다.
2. race-softmax 또는 동등한 group-aware objective: 경주 단위 soft CE를 기본으로 한다. full-rank Plackett–Luce는 DQ/DNF를 최하위 정상 착순으로 넣지 않으며 동착/부분순위 likelihood가 명세되지 않으면 사용하지 않는다.

binary 원시 확률 a는 `p_i=a_i/sum(a)`로 정규화한다. raw margin softmax와 임의로 혼용하지 않는다. 경주 softmax는 logits에서 직접 정규화한다. calibration 후보는 무보정과 단일 temperature를 기본으로 하고, **최종 정규화된 분포**에서 loss와 calibration을 측정한다. clip epsilon·temperature 범위·수치 안정화·동점 허용오차를 protocol에 고정한다.

기존 상태/Kalman 코드는 비교 후보로 재사용하되 사전 고정 상수를 최적화된 제주 파라미터라고 부르지 않는다. 시간/순위 auxiliary head, 상태공간 확장, 앙상블은 H0~H3 결과가 나온 뒤 예산 안의 보조 후보로만 다룬다. 앙상블 가중치는 개발의 시간순 예측으로만 선택한다.

### 6.4 예산과 탐색 순서

학습 전 기본 seed `[17, 43]`, 학습기당 최대 2개 사전 설정, estimator fit 상한 **240회**, calibration fit 상한 **240회**, 상태 파라미터 적합 상한 **120회**를 protocol에 기록한다. 이는 계획상의 상한이며 사용할 의무는 없다. 시간·메모리 한도는 실행 환경을 확인해 pilot 전에 정한다.

순서: 작은 H0 pilot → U0/Elo/레이팅과 H0 → H1/H2/H3 → 이력 정책 → 제한된 원천 제거/지연/전개 후보 → 후보 동결. 4 arm × 2 학습기 × 2 설정 × 2 seed × 4 개발 fold = 128 estimator fit이므로 추가 비교·baseline·최종 refit도 남은 예산에 포함한다.

결정적 U0/Elo 계산은 불필요하게 seed를 반복하지 않는다. 자동 튜닝·실패 재시도·조기종료·상태 적합도 ledger에 실제 횟수와 시간을 남긴다. 예산 부족 시 보조 후보를 줄이고 필수 산출물을 완성한다. 실험 예산 확대나 설계 변경은 2026 결과를 보기 전에만 근거와 새 protocol hash를 남긴다.

## 7. 시간 분할과 이력 가치 실험

### 7.1 날짜를 고정한 순차 검증

- 2002-07-28~2018-08-30: 별도 거리/시대 상태의 초기화 이력 후보.
- 2018-08-31~2024-12-31: 계수 학습 기본 후보.
- 2025-01-01~12-27: 4개의 분기별 개발 평가. Q4는 12-27까지다. 경주일을 나누어 같은 날을 서로 다른 split에 넣지 않는다.
- 2025-12-28: 레이팅 조정 경계. DB에는 12-28~12-31 제주 경주가 **0건**이다. 이후 새 snapshot에서 경주가 생기면 별도 bridge 구간으로 관리하고 개발에 조용히 포함하지 않는다.
- 2026-01-01~09-12: 후보/절차/feature/설정을 고정한 뒤 한 번 실행하는 `frozen historical evaluation`. 데이터 감사뿐 아니라 기존 제주 모델 선택에서 일부 2026 결과를 사용한 이력이 있으므로 독립 미사용 test라고 부르지 않는다.

각 개발 fold의 평가 시작일을 E라 할 때 기본 내부 구간은 다음과 같다.

| 역할 | 날짜 계약 |
|---|---|
| estimator FIT | 정책별 시작일 ~ E의 6개월 전 월 시작일 직전 |
| TUNE / early stopping | E의 6개월 전 월 시작일 ~ 3개월 전 월 시작일 직전 |
| CAL | E의 3개월 전 월 시작일 ~ E 직전 |
| EVAL | E부터 해당 분기 종료일까지 |

예: 2025 Q1은 FIT ~2024-06-30, TUNE 2024-07~09, CAL 2024-10~12, EVAL 2025-01~03이다. Q2 이후 이전 분기의 관측이 새 과거 구간으로 들어오는 것은 허용되지만 이미 기록한 과거 예측은 바꾸지 않는다. 각 경계에서 **라벨도 cutoff 전에 확정된 것만** 사용한다.

전처리는 FIT에서만 적합한다. estimator는 FIT에서 적합하고 TUNE으로 반복 수를 정한다. CAL에서 temperature만 적합한다. EVAL은 모두의 적합에서 제외한다. 기본 V1은 이 절차로 최종 계수 재적합도 고정하며 CAL에 적합한 뒤 CAL을 estimator에 다시 합치지 않는다. 전처리·모델을 refit하는 대안은 새 CAL을 둔 별도 사전 명세가 필요하다.

2025 분기 결과를 합쳐 후보를 고른 결과는 **개발 선택 결과**로 표시한다. 같은 결과로 고른 최저 loss의 CI만으로 우월성을 확정하지 않는다. 선택과 평가를 분리해야 한다는 원칙을 시간순으로 적용한다. [scikit-learn 모델 선택 설명](https://scikit-learn.org/1.5/auto_examples/model_selection/plot_nested_cross_validation_iris.html)

2026 기본 실행은 E=2026-01-01로 동일 FIT/TUNE/CAL 규칙을 적용한 고정 계수·고정 보정 모델이다. 다만 실제 운영을 흉내 내어 과거 결과가 이용 가능해지면 말 상태는 사전 정한 updater로 갱신한다. **가중치 재학습과 상태 갱신은 다르다.** 같은 날 결과는 사용하지 않고 2026 결과로 hyperparameter·calibrator를 다시 맞추지 않는다. 상태까지 2025 말에 멈춘 예측과 혼동하지 않도록 `fixed_parameters, sequential_state_updates`를 기록한다.

### 7.2 서로 겹치지 않는 이력 실험

기존 `LONG_FIT`와 `BURNIN_ONLY_OLD`는 같은 구현이 될 수 있으므로 아래처럼 **상태 이력 시작일 × 계수 학습 시작일**을 명확히 나눈다. 비교는 우선 H0의 고정된 한 학습기/설정과 동일 2025 fold에서 한다.

| 정책 | 상태 이력 시작 | 계수 학습 시작 | 비교 의미 |
|---|---|---|---|
| `A_RECENT_SHORT_STATE` | 2023-01-01 | 2023-01-01 | 최근 자료만 |
| `B_RECENT_LONG_STATE` | 2002-07-28 | 2023-01-01 | B−A: 오래된 상태 이력의 효과 |
| `C_LONG_FIT_LONG_STATE` | 2002-07-28 | 2018-08-31 | C−B: 2018~2022 계수 표본의 효과 |
| `D_LONG_FIT_NO_OLD_BURNIN` | 2018-08-31 | 2018-08-31 | C−D: 2018 이전 상태 초기화의 효과 |

계수 학습의 **종료일은 위 FIT 경계**로 통일한다. 초기 사전분포와 상태 파라미터의 적합자료도 각 정책이 허용하는 과거에 한정하고 암묵적으로 오래된 자료를 공유하지 않는다. 상태 이력이 얼마나 실제로 이어졌는지 개발 출전마 중 장기 이력 보유 말 수·기여 경주 수를 보고한다.

이 네 비교만으로 ‘2000년대 자료를 계수 학습에 넣는 것이 좋다’고 결론 낼 수 없다. 그 질문이 필요하면 시대 비교 가능한 공통 feature에 한해 `E_ALL_ERA_FIT`(상태/계수 모두 2002 시작)을 별도 예산으로 사전 등록한다. 실행하지 않으면 **2000년대 계수 학습 효과는 미검증**이라고 답한다. 400m와 제도 차이는 이 arm에서도 자동으로 현재 target과 합치지 않는다.

## 8. 평가·후보 선택·실패 분석

### 8.1 공통 지표

모든 주 지표는 경주를 같은 가중치로 평균한다. 출전행 가중 평균은 별도 열에 표기한다.

- winner-set NLL, soft CE, q 기준 race Brier, 공식 win 기준 binary NLL/Brier 보조 진단.
- Top1 적중률과 적중 수/전체 경주 수. 예측 확률 동점은 입력 순서와 무관한 동점 집합 내 우승마 비율로 기대 적중률을 계산한다.
- 후보 Top3/Top5에 공식 우승마가 **한 마리 이상** 포함될 기대 비율. K는 `min(K, N)`이고 경계 동점은 균등한 부분집합 선택의 기대값으로 계산한다. 실제 서비스 단일 픽은 고정 key tie-break를 사용하고 별도 실적도 남긴다.
- 고정 확률구간별 reliability, 평균 최고확률/실제 Top1 적중률, 분포별 표본 수. singleton 우승과 동착의 calibration을 분리한다.
- 거리·등급·월·두수·신마/기성마·180일 이상 휴양·원천 관측/가정·regime·DQ/DNF·동착별 손실 및 분모.
- 원천 적격 coverage, eligible key 예측 coverage, 사전 고정 fallback 비율.

예측값의 missing/extra/duplicate, nonfinite, 음수, 확률합 오차를 실패 처리한다. 수치 허용오차 기본 `1e-8`, 로그용 epsilon 기본 `1e-12`를 저장하며 보정 전후 합을 검사한다. 모든 확률 0/모델 로드 실패 등 fallback은 입력 실패 이유와 함께 원장에 기록하고 성능 분모에서 숨기지 않는다.

### 8.2 선택과 통계 판정

개발 단계에서 기준선을 U0가 아닌 **가장 강한 시점 유효 기준선**으로 고정한다. 이후 2026을 보고 상대 기준선을 바꾸지 않는다.

- 동일 경주의 NLL 차이 `Δ = candidate − reference`에 대해 paired race bootstrap와 race-day cluster bootstrap 95% CI를 각각 계산한다. 기본 5,000회, 고정 seed; 선택된 날짜의 모든 경주를 함께 복원추출한다.
- **우월성:** 사전에 정한 최종 1개 후보와 기준선의 Δ에 대해 두 CI 상한이 모두 0 미만이어야 한다. 한 CI라도 0에 걸치면 우월성 미확정이다.
- **비열등성:** CI가 0을 포함한다는 이유만으로 비열등이라 하지 않는다. 계획 기본 허용폭은 NLL `+0.01 nat/경주`, Top1 `−1%p`이며 이는 사실로 관측된 값이 아닌 설계상의 허용폭이다. NLL 차이의 양쪽 CI 상한이 허용폭 미만이고, Top1 차이의 race-day CI 하한이 `−1%p`보다 커야 한다. 작은 표본에서 실패하면 ‘판정 유보’다.
- 확률모델 후보의 채택에는 NLL 개선과 Top1 비열등을 요구한다. Top1 최저 손실 후보와의 trade-off는 함께 보여준다. 단순 연구 보존·prospective 그림자 평가 후보 선정과 운영 승격을 구별한다.
- 2025에서 많은 후보를 비교한 CI는 탐색적이다. 최종 하나를 사전 선택하고 2026은 그 후보와 고정 비교군만 평가한다. 여러 후보의 확정적 우월성을 주장하려면 비교 개수를 명시하고 다중비교 보정도 사전 등록한다.
- 경주일 cluster로도 기간 간 의존이 다 사라지지는 않는다. 분기별 개선 방향과 연속 주 단위 block 민감도를 보조 보고하며 표본이 작은 집단의 순위를 확정하지 않는다.
- 예측이 전부 맞은 작은 집단은 표본 수·선택 규칙·coverage·구간을 함께 표기한다. 독립 Bernoulli 가정의 exact 구간을 쓸 경우 그 가정을 명시하고 경주일 의존성은 별도 평가한다. [SciPy exact 비율 구간](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.binomtest.html)

2026 결과가 기대에 못 미쳐도 실패를 제출한다. 수정된 r3가 같은 2026을 다시 쓰면 재사용 역사 평가라고 명시하고 새로운 독립 검증은 이후 prospective 구간에 맡긴다. 버그 수정도 이전 결과·사유·새 hash를 보존한다.

### 8.3 오류를 다음 실험으로 연결한다

개발 예측의 틀린 경주와 가장 큰 NLL 경주를 추려 사전 정보 부족, 상태 추정 실패, 상대 편성/전개, 원천 지연/결측, DQ/DNF, 확률 과신으로 분류한다. 원인을 결과만 보고 확정하지 않고 ‘검증할 가설’로 저장한다.

각 오류 가설에는 필요한 원천·당시 공개 여부·기대되는 개선 대상·추가할 한 feature 묶음·다음 개발 평가를 기록한다. feature importance/SHAP은 설명 보조이며 원천 제거 실험을 대신하지 않는다. 이미 연 2026 실패 사례를 개발에 쓰면 다음 후보의 역사 test 재사용 이력을 명시한다.

## 9. 최고의 제주마 모델로 가는 후속 단계

V1의 말 중심 범위는 원인별 개선을 측정하기 위한 출발점이다. 아래 후속 단계를 생략한 채 ‘최고 모델 완성’이라고 부르지 않는다. 각 단계는 앞 단계 대비 같은 정보시점·같은 경주에서 증분 성능이 있어야 남긴다.

| 단계 | 추가 검증 | 필요한 계약 / 완료 증거 |
|---|---|---|
| V1 | 말 능력·시간·상태·기본 조건 | 본 문서의 재현 가능한 역사 연구 |
| V1.1 상대 편성·전개 | 상대 대비 능력차, 선행 성향 말 수, 게이트×주행성향, 거리×초반 경쟁 | 상대마도 cutoff 당시의 pre 상태. 전개는 과거에서 예측한 값이며 실제 대상 경주 구간은 금지 |

V1.1의 작은 상대 feature 후보는 핵심 H0~H3가 나온 후 잔여 개발 예산에서 먼저 시도할 수 있다. 사람·마주 정보는 무조건 넣는 것이 아니라 제거 비교에서 성능을 더하는지 결정한다. 신마의 혈통·연령 성장 등은 시점 유효 원천과 표본이 확보되었을 때 별도 후보로 다룬다.

### 실제 사전 예측 원장: 미래 성능을 판정하는 필수 연결점

이번 V1 구현은 **원장 schema·로컬 기록/replay CLI·변경 전후 사례 테스트까지** 만든다. 자동 수집 스케줄·운영 발행·registry 변경은 이 작업에 포함하지 않는다. 후속으로 실제 경주 전 예측을 기록해야 prospective 평가가 시작되며 과거 예측을 나중에 채워 넣지 않는다.

필수 필드:

```text
prediction_id, issued_at, cutoff_at, race_id, entry_id, horse_id,
observed_field_hash, source_snapshot_hash, feature_hash,
model_hash, protocol_hash, prediction_version, supersedes_id,
p_win, uncertainty_summary, fallback_reason,
result_joined_at, result_version, eligibility_reason
```

- 예측 레코드는 append-only로 저장하고 확정 결과는 별도 table에서 나중에 조인한다. 취소·기수변경·업데이트는 새 버전을 남기며 과거 확률을 덮어쓰지 않는다.
- 전날 전체 예정 출발집합과 T-30 실제 관측 집합을 각각 저장한다. 사후 미출주마를 제거한 조건부 재계산 결과와 **경주 전에 발행한 원래 결과**를 모두 보존한다. 출발 전 새 입력에 기반한 재예측과 단순 비례 재정규화도 구별한다.
- 단계별 예정 경주 수·발행 수·미발행 이유·적격 결과 수·무효 경주 수를 함께 센다. 주행중지/실격은 예측 실패를 숨기기 위한 제외 사유가 아니다.
- 고신뢰 경주 선택은 개발에서 정한 threshold 또는 상위 비율로 고정한다. 전체 경주 지표를 유지하며 선택 경주 적중률과 coverage를 같이 공개한다. 10경주 중 1경주를 골라 맞힌 100%를 전체 예측률로 제시하지 않는다.
- 최초 미래 평가 계획 기본값은 **연속 300개 적격 경주와 최소 30개 경주일을 모두 충족하는 시점**이다. 이는 통계적 검정력을 보장하는 마법의 표본 수가 아니다. 시작 전에 개발의 일별 손실 변동으로 최소 검출 개선폭을 산정하고 필요하면 늘린다.
- 평가 중 상태 updater는 고정 규칙으로 작동한다. 모델 교체 후보는 별도 버전으로 병행 기록한다. 중간 현황은 기술 통계로만 보고, 매주 유리한 시점에 검정을 멈추지 않는다. 재학습 일정·분포 변화 경보·성능 판정 시점을 시작 전에 저장한다.

## 10. 구현 단계·검증·완료 조건

### 10.1 단계별 산출물과 통과 기준

| 순서 | 산출물 | 다음 단계로 넘어갈 기준 |
|---|---|---|
| P0 | protocol, source/feature registry, 모집단 key manifest, 제외 원장 | DB hash·경주 완결성·시점·분할·예산 계약 고정 |
| P1 | entry dataset + 날짜순 pre-race state builder | 라벨·같은 날 일괄 갱신·미래변경·키 검사 통과 |
| P2 | U0/Elo/레이팅/속도 기준선과 H0 실제 fit/replay | 전체 적격 key 확률·reload·공통 평가 재현 |
| P3 | H1/H2/H3 및 이력 정책 비교 | 각 원천 증분·결측·공개 지연 진단 제출 |
| P4 | 개발 비교표와 최종 후보 선택 기록 | 선택 규칙·고정 후보·2026 평가 manifest 봉인 |
| P5 | 2026 일회 역사 평가와 한국어 보고서 | 지표·CI·coverage·실패·제약 모두 제출 |
| P6 | prospective 원장 schema·로컬 CLI·재생 사례 | 발행/결과 분리·취소/교체/버전 보존 테스트 |

P0의 전체 원천 전수검증을 이름만 바꾸어 반복하지 않는다. 수량 충돌·key 불일치·부적절한 공개 가정처럼 발견된 문제에 집중한다. 중간 승인을 반복 요청하지 않고 격리된 연구 산출물은 진행하되 원천 손상·정답 없는 평가집합·필수 계약을 충족할 수 없는 문제는 결과를 꾸미지 말고 명확히 보고한다.

### 10.2 필수 회귀 반례

구현을 복제하는 테스트 대신 실제 DB 고정 소표본과 독립 계산 가능한 합성 사례를 사용한다.

1. 신마·첫 거리·장기 휴양·희소 거리·상태 사전분포.
2. 정상/DQ/DNF/미출주/무효·동착 우승·TopK 경계 동착.
3. 미해결 상대 한 마리와 미해결 우승마가 있는 경주 전체 격리. 이번 확인의 8경주를 고정 fixture로 포함한다.
4. 대상 결과 삭제·교환·수정과 미래행 추가에도 고정 key의 pre 상태가 불변. transform 검사와 pipeline 재적합 검사를 구별한다.
5. 같은 날 여러 경주·입력 순서 역전·중복 실행에서도 pre 상태와 최종 예측이 동일.
6. 같은 마명 다른 ID, 한라마 혼입, 임시 ID, API/Text 중복 사건, 날짜 문자열 혼용.
7. 원천 미관측/0회/실제 사건, 지연 공개·사후 정정·전날 18시 이후 자료의 차단.
8. JSON 원문에 결과가 존재해도 허용 열만 추출되고, feature matrix에 결과/최종 배당을 주입하면 실패.
9. 미래 결과로 적합한 speed par·encoder·상태 파라미터·calibrator의 유입을 잡는 반례. 대상 경주 결과 table 없이 추론 가능.
10. 말 순서 변경에 대해 확률도 같은 순서로만 바뀌는지 검사. 상대 제거/출전 취소 시 사전 정의한 방식으로 재계산하고 원 예측 보존.
11. 균등 baseline의 동착 없는 NLL=`log(N)`, 동착 m마리의 set NLL=`log(N/m)` 등 수작업 답이 있는 평가 예제.
12. 모델 reload와 전체 snapshot replay가 원 예측과 고정 tolerance 내 일치.

관련 테스트·Ruff check/format·`git diff --check`를 실행하고 기존 오류와 이번 변경의 오류를 구분한다. 학습/전처리 분리의 기본 원칙은 [scikit-learn 누수 방지 문서](https://scikit-learn.org/1.8/common_pitfalls.html)를 따른다.

반드시 답할 질문:

1. 같은 경주에서 U0·Elo·속도·공식 레이팅보다 나아졌는가? Top1과 확률 품질의 결론은 같은가?
2. 시간/구간, 조교/심사/진료/체중, 현재 조건 중 어느 원천이 실제 증분을 주었는가?
3. 오래된 상태 이력과 오래된 계수 학습 표본의 효과를 구별했는가? 미실행 질문은 무엇인가?
4. 어느 거리·두수·신마·휴양·시대·자료 상태에서 가장 약하며 다음에 검증할 오류 가설은 무엇인가?
5. 2026의 기존 사용 이력과 공개시각 가정이 결론을 얼마나 제한하는가?
6. 미래 전체 경주에서 평가할 후보·예측 원장·평가 기간은 무엇인가?
7. 목표인 전체 경주 Top1 100%에 대해 현재 검증된 위치와 아직 측정하지 못한 부분은 무엇인가?

**완료 판정:** P0~P6 산출물과 실제 U0/Elo/H0 학습·평가를 제출한다. 레이팅·H1~H3는 사용 가능한 계약 통과 원천을 실제 실행하고, 불가한 단계는 구체적인 제외 근거와 앞 단계 결과를 제출한다. ‘H1 실패 시 H0 제출’과 ‘H1 실행 없이는 무조건 미완료’라는 상충 조건을 두지 않는다. 성능 개선은 주장할 때만 증거가 필요하며, 개선이 없다는 정직한 결과도 연구 완료다.

이 문서를 **실행하도록 요청받은 작업**은 계획만 작성하고 끝내지 말고 위 연구 fit·평가·산출물까지 완성한다. 운영 발행·베팅·registry 변경은 후속 범위다.
