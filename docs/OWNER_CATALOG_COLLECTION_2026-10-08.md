- 한 행의 키: `(ingestion_run_id, meet_code, kra_owner_id)` — 같은 마주가 여러 지역에 있어도 각각 보존한다.
- 필드: `owner_id` (기존 owners 공식 번호와 정확히 일치하는 경우에만 연결, 미연결은 null), `kra_owner_id`, `official_name_ko`, `meet_code`, `registration_date`, `total_registered_horses`, `observed_at_ms`, `source_document_id`.
- API309 `owNo` → `kra_owner_id` (6자리 번호 문자열), `owName` → 공식명, `stDate` → 등록일, **`totHorses` → `total_registered_horses`**. `ownerHorses`(현소유두수)와 혼용하지 않는다.
- `meet_code=1` 서울, `3` API 원문 영남 (화면에서 부산으로 표시 가능), `2` 제주. 실제 경주 출전 지역을 마주 등록지역으로 추정하지 않는다.
- UI는 `IngestionRun.data_type == 'owner_catalog_full' AND status == 'completed'` 중 `started_at_ms DESC, id DESC`의 첫 실행 ID 하나를 선택하고 그 실행의 스냅샷만 조회한다. 말별/지역별 최신 행을 섞지 않는다. 전체 3지역 완전성 검증 후 한 트랜잭션으로 저장된 실행만 완료 상태가 된다.
- 같은 기존 마주번호의 다지역 관측은 별개 등록이다. UI가 경마장별 행을 표시한다면 해당 meet 값으로 선택한다. 전체 목록의 단일 마주에 여러 지역이 연결되면 총등록두수를 임의 합산/최댓값 선택하지 않고 지역별 표시 또는 별도 판단이 필요하다.
- 이름 일치만으로 연결하거나 기존 `owners.name_ko`, `owners.kra_owner_id`, 경주 이력을 수정하지 않는다. API에만 있는 번호는 이 테이블에 미연결로 보존하며 기존 owners 기본행을 임의 생성하지 않는다.
- 총취소두수·현소유두수·상금 컬럼과 UI는 추가하지 않는다. API 원문에는 원래 제공된 필드가 보존될 수 있으나 운영 구조화 컬럼은 위 범위만 저장한다.
- 수집 CLI는 기본 dry-run (비밀값·네트워크·DB 쓰기 없음), `--apply`로만 대상 Supabase에 저장한다. 세 지역·모든 페이지·중복키·날짜·비음수 정수·지역코드를 검증한다. 동일 전체 업무 스냅샷 재실행은 중복 생성하지 않으며, 실제 변화 시 새 전체 실행을 추가한다. 로컬 SQLite 쓰기·예약·외부 알림·배포·Git 작업 없음.

## 마주 기간별 전적

- 기수와 동일한 `최근 1개월 · 최근 1년 · 통산` 탭을 사용하며 기본은 통산이다. 등록두수 뒤에 `출전 · 1위 · 2위 · 3위 · 승률 · 복승률 · 입상률`을 표시한다. 기간은 등록두수 자체를 변경하지 않는다.
- 기간은 서울 오늘 날짜부터 한 달/한 해 전 같은 날짜까지 양 끝을 포함한다. 말일·윤일은 유효한 마지막 날짜로 맞춘다. 통산은 수집된 전체 실제 경주 이력 기준이며 공식 생애 누적치와 같다고 가정하지 않는다.
- 출전 당시 `race_entries.owner_id`로 집계한다. 현재 말의 마주가 바뀌어도 과거 성적을 새 마주에게 이전하지 않는다. 예정·미래·취소·출전 제외·빈 결과는 제외하고, 실제 출전 후 중지·실격은 출전에 포함하되 실격을 입상으로 세지 않는다.
- 전체는 모든 경마장(영천 포함), 지역 선택 시 그 경마장에서 시행한 경주만 집계한다. 등록지역 필터는 공식 등록 명단을 기준으로 유지한다.
- 승률=1위/출전, 복승률=(1위+2위)/출전, 입상률=(1위+2위+3위)/출전이며 소수점 한 자리로 표시한다. 집계 출전 0이면 횟수는 0, 비율은 `—`다.
- 추가 정렬 `선택 기간 출전 많은 순`은 서버에서 전체 대상에 적용한 뒤 페이지를 나눈다. 기간·지역·검색·페이지 이동에서 선택 상태를 유지하며 기간 변경은 첫 페이지로 이동한다. 전적 조회는 마주별 개별 쿼리 없이 한 번에 조회한다.
- 관련 목록·상세 페이지 회귀 테스트 36개와 Ruff 통과. 테스트는 기간 경계·지역 분리·제외 결과·실격 처리·비율·0출전·전적 정렬/페이지·기간 상태 유지를 검증한다.
