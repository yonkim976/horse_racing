# 제주 심판리포트·통과순위·주로빠르기 확인 (2026-09-17)

## 결론

1. 심판리포트는 공식적으로 경주일별 문서 안에 경주번호별 내용을 싣는 구조지만, 현재 로컬 자료가 모든 제주마 경주를 덮지는 않는다. 최종 제주 연구 DB의 확정 경주와 대조하면 2025년은 722/722, 2026년 9월 12일까지는 516/549경주에 운영 DB 심판리포트가 있다.
2. 2018~2024년 심판리포트는 공식 API 표본에서 실제 응답을 확인했다. 2017년 이전 자료는 한국마사회 과거 게시판에서 2006-04-01까지 내려받을 수 있다. 초기 파일은 PDF만이 아니라 HWP도 섞여 있다. 2002-01-01~2006-03-31 자료는 이 게시판에서 확인되지 않았다.
3. 공식 경주성적표의 통과순위는 GPS 위치가 아니라 S1F·코너·G1F 등 특정 지점에서의 말 순서다. 기존 원천과 운영 DB에는 상당 부분 들어 있지만 최종 제주 연구 DB에는 순위 열이 없다.
4. 주로빠르기는 `①`~`⑤`의 경주로 기록환경 등급이다. 숫자가 작을수록 가벼워 기록이 빠르게 작성되는 주로다. 말 자체의 속도나 함수율과 같은 값은 아니다.

## 1. 심판리포트 보유와 coverage

현재 운영 DB `race_steward_reports`에는 제주 `meet_code=2` 리포트가 1,238건 있다.

| 연도 | 운영 DB 리포트 | 최종 연구 DB 확정 경주 | 경주키 연결 | coverage |
| --- | ---: | ---: | ---: | ---: |
| 2025 | 722 | 722 | 722 | 100.00% |
| 2026-09-12까지 | 516 | 549 | 516 | 93.99% |

2026년 미연결 33경주는 2026-03-20 8경주, 03-21 6경주, 07-07 4경주, 08-25 8경주, 08-26 7경주다. 앞서 운영 DB에 존재하는 경주만 분모로 사용하면 누락은 18경주이지만, 최종 제주 연구 DB의 확정 경주 모집단을 분모로 하면 33경주다.

보고서가 있다는 것은 사건이 있었다는 뜻이 아니다. 경주별 항목이 존재하면서 특이사항이 없다고 기록될 수도 있다. 반대로 로컬 행이 없다는 이유만으로 해당 경주에 공식 보고서가 없었다고 단정할 수 없다.

## 2. 2018~2024 공식 API 확인

공식 `/API215/JudgeReport`를 `meet=2`, `rc_date=경주일`로 읽기 전용 조회했다.

| 표본 경주일 | 공식 응답 행 |
| --- | ---: |
| 2018-01-12 | 9 |
| 2019-01-11 | 9 |
| 2020-01-03 | 8 |
| 2021-12-25 | 6 |
| 2022-12-24 | 7 |
| 2023-12-30 | 6 |
| 2024-12-28 | 5 |

2015~2017 표본과 2002-07-28 표본은 API에서 0건이었다. 이는 2017년 자료가 없다는 뜻이 아니라 API의 과거 제공 범위가 제한된 결과다. 실제 2017년 리포트는 홈페이지 과거 게시판에 있다.

API `meet=2`에는 당시 제주경마장의 다른 마종 경주가 함께 들어갈 수 있다. 새 제주 연구 DB에 넣을 때는 `(meet=2, 경주일, 경주번호)`가 확정 제주마 `event`와 일치하는 행만 연결하고 나머지는 제외 원장으로 보낸다.

## 3. 2006~2017 홈페이지 첨부자료

현재 심판위원 Report 화면은 2017-10-13 이후 날짜를 선택할 수 있고, `2017년 이전 자료` 버튼은 과거 게시판 `boardNo=77`로 연결된다.

- 게시판 표시 전체: 1,125건
- 가장 오래된 확인 게시물: 2006-04-01 `재결위원리포트`
- 마지막 구형 첨부 표본: 2017-12-30 `심판위원 리포트`
- 인증 없이 첨부파일 직접 다운로드 가능
- 2006-04-01 표본: HWP 5.x, 32,768바이트
- 2017-12-30 표본: PDF 1.4, 3쪽, 76,707바이트

2017-12-30 PDF에는 그날 제주경마장의 제1~6경주가 들어 있다. 한라마 경주와 제주마 경주가 한 문서에 함께 있으므로 경주번호와 경주 등급·마종 표기를 대조해야 한다.

전수 수집 시에는 게시판 목록 → 게시물 ID → 첨부 `fileNo` → 원본 파일 순서로 저장하고, 게시물 메타데이터·파일명·파일 SHA-256·HTTP 응답·수집시각을 남긴다. PDF와 HWP를 각각 파싱하고 원본 파일은 보존한다. 문서 안의 경주번호별 구역을 나눈 뒤 확정 제주마 경주키와 연결한다.

현재 확인된 게시판 시작일이 2006-04-01이므로 2002-07-28~2006-03-31은 별도 공식 보관처를 찾기 전까지 미확보 구간이다. 게시물 1,125건이 모든 경주일을 완전하게 덮는지는 아직 날짜별 전수 coverage를 계산하지 않았다.

## 4. 경주성적표의 통과순위

공식 용어 설명에서 구간별 통과순위는 각 말의 주행을 검토하기 위한 코너·지점별 말 위치다.

| 코드 | 의미 |
| --- | --- |
| `S1F` | 출발 후 최초 약 200m 지점 |
| `1C`~`4C` | 각 코너 통과 지점 |
| `G3F` | 결승선 전 600m 지점 |
| `G1F` | 결승선 전 200m 지점 |
| `FIN` | 최종 착순 |

말별 성적표의 `2 - - 2 2 2 1` 같은 값은 표 머리글의 지점 순서에 따른 해당 말의 순위다. 빈 칸은 그 거리에서 해당 지점을 사용하지 않거나 원천값이 없는 경우다.

경주 전체 표기 `(^5,7),4,(1,3,6)-2`는 말 번호를 앞에서부터 주행 순서대로 나열한 것이다. 괄호는 서로 가까운 마군이며 괄호 안에서는 내측 말부터 표시한다. `^`는 마군의 선두말 표기다. 쉼표·하이픈 등은 말 사이 간격 구분을 나타낸다.

이 표기는 설명을 위해 재구성한 값이 아니라 2015년 이후 `dacom11` 성적표 원문에 실제 문자열로 남아 있다. 현재 보유한 제주 `dacom11` 원문 898개 모두에 경주 전체 `통과순위 S-1F`와 `G-1F` 줄이 있으며, 전체 제주 경주종류를 합쳐 7,283개 경주 구역이다. 예시는 `통과순위 S-1F : (^2,3,8),1,(4,6),(5,7)-10,9`와 같은 형태다. 제주마 연구에 사용할 때는 이 7,283개 전체를 사용하지 않고 확정 제주마 경주키와 일치하는 구역만 선택해야 한다.

원문에는 이 경주 전체 문자열과 별도로 각 출전마 행의 `8- - - 8-8-8` 같은 지점별 숫자 순위열도 있다. 현재 운영 DB의 `race_section_results.position`은 이 말별 숫자 순위를 구조화한 값이다. 이름과 달리 `group_notation_raw`에는 경주 전체 마군 문자열이 아니라 말별 순위열 원문이 반복 저장돼 있다. 따라서 괄호·`^`·간격기호를 분석하려면 `dacom11` 원문에서 경주 전체 줄을 별도로 파싱해 새 테이블에 보존해야 한다.

이 값은 순서형 관측이다. 실제 좌표, 내·외곽 이동거리, 몇 미터 앞섰는지 또는 주행 방해 원인을 직접 알려주지 않는다. 특히 `G1F 통과순위`는 결승 200m 전 위치이며 `G1F 시간`인 마지막 200m 주파시간과 다르다.

분석에는 다음처럼 쓸 수 있다.

- S1F 상위권 비율: 초반 선행 성향
- S1F→3C→4C→G1F 순위 변화: 전개 중 위치 상승·하락
- G1F→FIN 변화: 마지막 200m의 상대적 순위 변화
- 순위/출전두수: 서로 다른 편성 규모를 비교하는 정규화 위치

## 5. 현재 프로젝트의 통과순위 보유 상태

2002~2014 명시적 제주마 공식 결과 원천 24,256행에는 `sjS1fOrd`, `sj_3cOrd`, `sj_4cOrd`, `sjG1fOrd` 등이 있다. 최소 한 지점의 양수 통과순위가 있는 행은 23,721행(97.79%)이다.

이 2002~2014 JSON 원천에서 확인된 것은 말별 숫자 순위 필드다. 2015년 이후 `dacom11`과 같은 경주 전체 괄호·`^`·간격기호 문자열은 해당 JSON 필드에 없다.

| 2002~2014 원천 필드 | 양수 행 |
| --- | ---: |
| 최소 한 지점 | 23,721 |
| S1F | 23,706 |
| 3C | 21,064 |
| 4C | 21,062 |
| G1F | 23,701 |
| G3F | 0 |

운영 DB의 2015~2026 제주 구간은 325,126행이고, 공식 통과순위가 있는 셀은 260,730개다. 구간행이 있는 출전 66,401개 중 66,399개에 최소 한 지점 통과순위가 있다.

그러나 최종 제주 연구 DB `jeju_native_text_phase2.sqlite3`의 `section_checkpoint`에는 `position`, `group_notation_raw`, `gap_to_leader_lengths` 열이 없다. 현재 연구 DB는 시간·거리·근사 여부만 저장한다. 따라서 홈페이지 통과순위까지 최종 연구 DB에 적재 완료됐다고 말하면 안 된다.

추가 적재 시 기존 DB를 덮어쓰지 않고 새 복사본에 다음 열 또는 별도 테이블을 추가한다.

- `official_position INTEGER`
- `position_source_kind TEXT`
- `group_notation_raw TEXT`
- `position_inferred INTEGER DEFAULT 0`
- `source_artifact_id` 또는 원천 응답 SHA-256

공식 순위와 누적시간으로 추정한 순위는 반드시 분리한다. 원천 미제공 순위를 기본값 0으로 만들지 않는다.

## 6. 주로빠르기의 의미

한국마사회 제주 출전표 설명은 주로빠르기를 경주로 상태에 따른 기록 빠르기로 설명한다.

| 값 | 해석 |
| --- | --- |
| `주로①` | 가장 가볍고 기록이 빠르게 작성되는 쪽 |
| `주로②` | 빠른 쪽 |
| `주로③` | 중간 범주 |
| `주로④` | 느린 쪽 |
| `주로⑤` | 가장 무겁고 기록이 느리게 작성되는 쪽 |

이는 말의 능력점수나 해당 말의 구간속도가 아니다. `건조·양호·다습·포화·불량` 같은 상태명이나 함수율과도 별도 값이다. 같은 거리의 기록을 비교할 때 당시 경주로가 기록에 유리했는지 불리했는지를 설명하는 경주 맥락 변수다.

확인한 공식 설명에는 `①`~`⑤`의 세부 산출식이나 초 단위 경계가 공개돼 있지 않다. 함수율만으로 이 값을 역산하거나 1단계 차이를 일정 초 차이로 바꾸면 안 된다. 분석에서는 범주형 또는 순서형 경주환경 값으로 보존하고, 정확거리·경주일·함수율·주로상태와 함께 사용한다.

대상 경주의 주로빠르기는 성적표에 포함되는 사후 정보다. 같은 경주의 사전 예측 입력에는 넣지 않고, 완료된 과거 경주의 이력이나 사후 진단에 사용해야 한다. 출전표에 표시되는 과거 경주의 주로빠르기는 해당 과거 경주의 기록으로 해석한다.

## 7. 후속 적재 권장 순서

1. 2006-04-01~2017-12-30 과거 심판 게시판의 목록·첨부 전수 수집과 해시 원장 생성
2. 2018-01-12~2024-12-31 API 심판리포트 전수 수집과 날짜별 응답 coverage 생성
3. 2025~2026 기존 원천 재사용 및 누락 경주 재조회
4. 문서별 경주 구역을 확정 제주마 경주키에 연결하고 한라마·미확정 경주 격리
5. 2002~2014 공식 결과, 2015~2026 dacom11/API의 통과순위를 새 연구 DB 복사본에 적재
6. 경주성적표 또는 `경마코너별통과순위·주로빠르기` 공식 API에서 주로빠르기 원값 수집
7. 공식값·추정값·결측을 분리한 분석 뷰와 독립 검증 생성

이번 확인은 홈페이지와 API의 읽기 전용 조회 및 로컬 DB 감사다. 운영 DB와 최종 제주 연구 DB는 변경하지 않았다.
