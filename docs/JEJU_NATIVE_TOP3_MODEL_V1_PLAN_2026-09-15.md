## 1. 새 목표: 집합과 순서를 모두 맞힌다

전체 적격 제주마 경주에서 아래 두 목표를 각각 100%에 최대한 가깝게 높인다.

1. **Top3 집합 완전 적중:** 예측한 세 마리가 실제 1·2·3착 세 마리와 모두 일치한다. 순서는 보지 않는다.
2. **Top3 순서 완전 적중:** 예측한 1착·2착·3착이 실제 1착·2착·3착과 모두 일치한다.

예: 실제 결과가 A–B–C일 때 A–C–B는 **집합 성공, 순서 실패**다. A–B–D는 둘 다 실패다. A–B–C는 둘 다 성공이다. ‘후보 3두 안에 우승마 한 마리 포함’은 별도의 보조 지표다.

100%는 장기 목표다. dataset 생성이나 과거 자료의 높은 학습 적중률을 목표 달성으로 표현하지 않는다. 모든 성능표에는 적중 수·전체 경주 수·기간·coverage·95% 구간을 함께 표시한다. 선택한 쉬운 경주에서의 적중률은 전체 경주 실적과 분리한다.

### 두 결과를 연결하는 출력 계약

- 같은 경주에서 세 마리의 순서별 확률 `P(i 1착, j 2착, k 3착)`를 만든다. i/j/k는 서로 다른 출발마다.
- N두 경주의 가능한 순서 수는 `N*(N-1)*(N-2)`이며 전체 합은 1이다. 예를 들어 10두면 720개 순서다.
- 한 세 마리 집합 S의 확률은 S의 가능한 6개 순서 확률을 합한 값이다. 전체 `N choose 3`개 집합 확률합도 1이다.
- **주 출력은 일관된 2단계 결정:** 집합 확률이 가장 높은 S를 선택하고, 그 S 안에서 확률이 가장 높은 순서를 선택한다. 집합용 세 마리와 순서용 세 마리를 다르게 발표하지 않는다.
- 전체 순서 중 최대확률 하나를 직접 고르는 `GLOBAL_ORDER_MAP`은 보조 전략이다. 집합 우선 전략과 어떤 목표에서 유리한지는 2025 개발에서 비교하고 최종 정책을 봉인한다.
- 집합 오류와 집합은 맞지만 순서만 틀린 오류를 따로 센다. 동일 주 출력이라면 `순서 적중률 = 집합 적중률 × 집합 성공 경주 내 순서 적중률`이다.

## 2. 동착·실격·불완전 경주의 정의

### 2.1 동착은 실제 자료의 일부다

공식 정상 착순을 동착 그룹으로 묶는다. 동착 그룹 안에서는 순서가 결정되지 않은 것으로 취급한다.

- `1, 2, 2, 4`: 2착 동착인 두 말의 두 가지 순서를 모두 정답으로 인정한다. 집합 정답은 하나다.
- `1, 2, 3, 3, 5`: 세 번째 자리는 3착 동착 말 중 어느 하나여도 호환된다. 정답 집합과 정답 순서는 각각 두 개다.
- `1, 1, 3`: 동착 우승마의 두 순서를 모두 인정한다.
- 정상 착순의 중간 누락·불명 코드를 정상 순위로 재번호 매기지 않는다. 공식 자료에 필요한 상위 착순을 확인할 수 없으면 이유를 기록하고 경주 단위로 격리한다.

데이터셋은 `accepted_orders`와 중복을 제거한 `accepted_sets`를 별도 table에 저장한다. 주 지표는 예측이 이 호환 집합/순서 중 하나인지 판단하며 **동착 호환 판정**임을 표기한다. 동착 없는 일반 경주와 동착 경주의 실적도 각각 보고한다.

3착 경계 동착으로 공식 3착 이내 말이 네 마리 이상이면 **정확히 세 마리를 출력해 그 모두를 포함하는 일은 불가능**하다. 이때 가능한 세 자리의 호환 정답과 ‘공식 3착 이내 전원 포함’ 목표를 혼동하지 않는다. 데이터에 `official_top3_count`와 경계 동착 flag를 보존하고 후자는 별도 지표로 보고한다.

- 91 실격/92 주행중지는 실제 출발마로 유지한다. 이 말은 우승/정상 Top3 정답이 아니며 정상 시간·순위 능력 업데이트는 mask한다. 제일 느린 완주시간이나 가짜 4착으로 대체하지 않는다.
- 93/94/95 미출주는 실제 출발 조건부 집합에서 제외한다. 98/99·미확정·취소·착순 불명은 경주 정답 계약에 따라 제외한다.

최종 수량은 builder가 착순 일관성 검사까지 적용해 저장한 report가 기준이다. 추가 제외가 있으면 실제 경주 key와 사유를 공개한다. 원천 전체 대비 적격 비율과 적격 경주 전체에 대한 예측 비율을 별도로 계산한다.

## 3. dataset 구조와 정보 시점

### 3.1 분리된 데이터층

| 산출물 | 용도 | 포함하면 안 되는 것 |
|---|---|---|
| `entries.parquet` | 출전키·말 ID·경주일·거리·두수·cutoff·split 등 메타 | 대상 결과를 학습 feature처럼 사용 |
| `labels.parquet` | 공식 착순·정상/DQ/DNF·win/top3·target mask | 추론 입력으로 자동 조인 |
| `races.parquet` | 경주별 정답/동착/적격/분할 요약 | label 성격의 열을 feature로 사용 |
| `accepted_orders.parquet` | 경주별 호환 정답 순서 | 사후 순서를 예측 입력으로 사용 |
| `accepted_sets.parquet` | 경주별 호환 정답 집합 | 동착으로 중복된 집합을 중복 가중 |
| `history_results.parquet` | 말 상태를 순방향 생성하는 과거 관측 원천 | target 날짜 이후의 관측 사용 |
| `horse_states.parquet` | 결과와 분리된 출전 전 H0/H1 및 보조 상태 | 대상 결과·배당·동착 결과·DQ 여부 |
| `exclusions.parquet` | 경주/행별 제외 사유와 원천 근거 | 실패 경주를 이유 없이 삭제 |
| `protocol.json`, `feature_registry.json`, `manifest.json` | 시점/목표/feature 사용/파일 hash/재현 계약 | feature 자동 전체 선택 |

하위 모듈의 실제 열 이름과 형식은 생성 시 저장되는 schema를 따른다. 모든 table은 `race_id/entry_id/horse_id` 중 명시된 키로 조인한다. labels가 별도라는 이유만으로 `races`의 정답 요약을 모델 feature로 허용하지 않는다. 학습기는 오직 registry에 등록된 feature 열을 사용한다.

원천의 허용 열만 읽는다. `source_row.normalized_json`을 전체 평탄화하지 않는다. 출처를 위한 source row ID/hash는 메타이며 모델 feature가 아니다. 원 DB·기존 Parquet·운영 모델을 수정하지 않고 새로운 버전 디렉터리에 저장한다.

### 3.2 전날 18시 기준의 역사 가정

- cutoff는 경주 전날 18:00 Asia/Seoul이다.
- 기본 과거 feature는 날짜만 확인되는 자료의 늦은 공개를 보수적으로 다루어 **대상일의 전전날까지** 사용한다. 같은 날과 전날 사건을 소급 사용하지 않는다.
- 사건일·공개일·현재 snapshot 수집일은 다르다. 이 DB로 정확한 당시 공개시각이나 전날 전체 출전집합을 복원했다고 주장하지 않는다.
- H0/H1 역사 결과 사용도 공개 지연을 가정한 연구다. 조교/진료 등 실제 공개시각이 없는 H2 원천은 `ASSUMED_AVAILABILITY` 보조 arm으로 분리한다. 가용시각을 입증하지 못한 사실을 0회/건강함으로 바꾸지 않는다.
- cutoff 이전에 확정된 공식 결과만 사용해야 하는 prospective 구현에서는 `available_at`와 정정 version으로 대체한다.
- 400m 역사 기록은 별도 거리 상태로만 유지하고 일반 능력·속도 척도에 무분별하게 합치지 않는다.
- 모든 말의 같은 날짜 pre 상태는 같은 정보 snapshot에서 생성한다. 행 순서를 바꾸어도 결과가 바뀌지 않는다.
- 대상 결과 삭제/변경·미래행 추가에도 고정된 target key의 pre feature는 변하지 않아야 한다.

### 3.3 현재 만들 상태와 그 의미

- **H0 결과 상태:** 과거 상대를 고려한 Elo 요약, 출전/완주 수, 최근 결과, 거리 경험, 휴양 기간, 관측 부족을 나타내는 불확실성 대용 지표.
- **H1 기록 상태:** 해당 시점 과거 자료만으로 만든 거리·시대별 시간 기준, 과거 보정 잔차·검증된 구간. 원시 시간을 거리 간 직접 비교하지 않는다.
- 초반 S1F는 DB에서 일반 거리는 200m, 1110m·1610m 경주는 210m로 저장돼 있다. 정확 계측 위치와 비근사 표시를 확인하고 두 길이의 과거 평균을 별도 feature로 보존한다. 후반 G1F 200m·G3F 600m도 독립적인 closing 시간만 사용한다.
- **H2 보조 상태:** 공개시각 가정을 표시한 과거 조교·출발조교·심사·진료·체중. API/Text에서 같은 사건을 두 번 세지 않는다. 행 없음은 사건 미관측일 수 있다.
- **H3 현재 조건:** 거리·두수는 H0부터 공통 조회 조건이다. 중량·등급·게이트·연령/성별 등은 시점 유효 출전표 계약을 완성한 뒤 추가한다. 첫 생성본에서 제공하지 않는 feature는 registry/보고서에 명시한다.

현재 상태 생성의 고정 Elo 계수·수축·평균/분산은 재현 가능한 **기준 feature**이며 최적 학습된 잠재 능력이나 검증된 확률분포가 아니다. 모델 학습 시 scaler·encoder·imputer·calibrator는 각 fold의 허용 과거 구간으로만 적합한다. 전체 dataset을 한 번 fit한 전처리를 fold에 공유하지 않는다.

## 4. 상위 3두와 순서를 직접 학습하는 모델 계획

기존 우승확률을 큰 순서대로 세 개 뽑는 모델은 기준선으로 남긴다. 새 목표를 위해 **집합 확률과 조건부 순서 확률**을 직접 평가한다.

| 단계 | 비교 모델 | 검증할 질문 |
|---|---|---|
| B0 | 모든 서로 다른 ordered triple에 균등확률 | 정보 없는 정확한 출발점 |
| B1 | Elo/과거 보정 속도/시점 유효 공식 레이팅의 Plackett–Luce | 단순 능력 점수의 Top3·순서 성능 |
| M0 | LightGBM 순위 score + Top3 Plackett–Luce 보정 | 기존 tabular 구조로 목표를 얼마나 달성하는가 |
| M1 | Top3 순서 likelihood를 직접 최적화하는 경주 단위 모델 | 우승만 맞추는 학습보다 세 자리 예측이 좋아지는가 |
| M2 | 앞서 선택한 말을 조건으로 2·3착을 예측하는 조건부 모델 | 단일 능력 score의 고정 상대비 가정을 완화하면 좋아지는가 |
| M3 | 집합 선택 loss + 집합 내 순서 loss의 분해/공동학습 | 3/4위 경계와 1/2/3위 순서 오류를 함께 줄이는가 |

M0/M1을 먼저 완성하고 M2/M3는 개발 결과와 예산에 따라 확장한다. LambdaRank의 relevance나 binary Top3 loss만으로 정확순서 학습을 완료했다고 하지 않는다. DQ/DNF를 가짜 정상 착순으로 학습하지 않도록 목적함수별 마스크를 명시한다.

각 모델은 H0 → H1 → H2 보조 → H3 조건의 정보 묶음을 따로 비교한다. 다음 후속 신호의 우선순위를 상위 3두·순서 오류에서 정한다.

1. 상대 대비 능력차, 선행 성향 말 수, 게이트×전개, 거리×초반 경쟁.
2. 기수 → 말×기수 → 조교사/마방. 현재 상대와 기수도 cutoff 당시 정보만 사용.
3. 실제 관측 T-30 체중·주로·교체/취소·장구.
4. 공동 전개 변동을 가진 성능 시뮬레이션, 사건 위험, 앙상블.

기수·조교사 효과를 독립 인과효과로 단정하지 않는다. 상위 3두가 맞았는데 순서가 틀리는 원인과, 실제 3착마 대신 4착마를 고르는 원인을 별도 제거 실험으로 확인한다.

## 5. 학습·개발·역사 평가 분리

기본 기간은 그대로 유지한다.

| 역할 | 기간 |
|---|---|
| 상태 초기화 역사 | 2002-07-28~2018-08-30 |
| 계수 학습 후보 | 2018-08-31~2024-12-31 |
| 개발 선택 | 2025-01-01~12-27, 분기별 walk-forward |
| 레이팅 조정 경계 | 2025-12-28; 현재 DB의 12-28~12-31 경주 0개 |
| 동결 역사 평가 | 2026-01-01~09-12 |
| 진정한 미래 검증 | 실제 경주 전에 남긴 이후 prediction ledger |

개발 평가 시작 E 기준 FIT는 E−6개월 월초 직전까지, TUNE은 그다음 3개월, CAL은 E 직전 3개월, EVAL은 해당 분기다. 2025 Q1의 예: FIT ~2024-06-30, TUNE 2024-07~09, CAL 2024-10~12, EVAL 2025-01~03. 같은 경주일을 여러 split에 나누지 않는다.

2026은 protocol·feature·선택 정책·hyperparameter를 고정한 후보와 사전 기준선만 한 번 평가한다. 이미 기존 모델 개발과 데이터 감사에 쓰인 결과가 있어 독립 미사용 test라고 부르지 않는다. 계수와 calibration은 고정하고 말 상태만 과거에 이용 가능해진 결과로 순차 업데이트한다. 이번 dataset 생성은 2026 정답을 저장·검증하지만 예측 성능을 계산하거나 모델을 선택하지 않는다.

오래된 자료의 가치는 다음 네 정책으로 따로 비교한다.

- A: 상태 시작 2023 / 계수 시작 2023.
- B: 상태 시작 2002 / 계수 시작 2023.
- C: 상태 시작 2002 / 계수 시작 2018-08-31.
- D: 상태 시작 2018-08-31 / 계수 시작 2018-08-31.

B−A는 장기 상태 이력, C−B는 2018~2022 계수 표본, C−D는 2018 이전 초기화의 기여다. 생성한 장기 상태 table은 B/C용 기본 자료이며 A/D는 builder를 해당 history policy로 다시 실행해야 한다. 이 비교 없이 모든 정책을 시험했다고 하지 않는다.

기본 seed는 `[17,43]`, estimator 240회·calibration 240회·상태 파라미터 적합 120회 상한을 유지한다. 이번 dataset 단계의 모델 fit 수는 0이다. 하위 에이전트는 `gpt-5.6-luna` / `high`로 지시하고 결과를 주 담당자가 검토한다.

## 6. 평가 지표와 후보 판정

### 6.1 새 주 지표

| 지표 | 정의 | 의미 |
|---|---|---|
| `top3_set_exact_accuracy` | 예측 세 마리 집합이 accepted_sets 중 하나인 비율 | 실제 상위 세 자리의 말 선택 완전 적중 |
| `top3_order_exact_accuracy` | 예측 세 자리 순서가 accepted_orders 중 하나인 비율 | 말 선택과 순서 동시 완전 적중 |
| `order_accuracy_given_set_hit` | 집합 성공 중 순서 성공 비율 | 순서 결정 단계의 약점 |
| `top3_set_nll` | 정답 호환 집합들의 총 확률에 −log | 집합 확률 품질 |
| `top3_order_nll` | 정답 호환 순서들의 총 확률에 −log | 순서 확률 품질 |

모든 지표는 경주를 같은 가중치로 평균한다. 동착 정답을 여러 개 저장했더라도 한 경주를 여러 번 세지 않는다. 정답 집합 확률은 그 집합의 **모든** 순서 확률을 합하고, 순서 loss는 공식 순서와 호환되는 순서만 합한다. 둘을 혼용하면 집합과 순서의 학습이 구별되지 않는다.

보조 지표는 실제 상위 3두 중 맞힌 말 수(0/1/2/3), 1착·2착·3착 각각의 적중률, 우승마 후보3 포함률, Top1, 예측 집합/순서 확률 calibration이다. 3착 경계 동착에서 단순 교집합 개수는 의미가 달라지므로 호환 집합 기준 또는 일반 경주 전용으로 표시한다.

N두·동착 없는 B0 균등 기준의 집합 적중 기대값은 `1 / C(N,3)`, 순서 적중 기대값은 `1 / [N(N−1)(N−2)]`다. 예를 들어 10두는 각각 1/120과 1/720이다. 이는 실제 학습 모델 성능이 아닌 수학적 sanity check다. 동착이면 호환 정답 개수만큼 확률을 합한다.

확률이 같은 후보를 행 순서로 고르지 않는다. 결정 정책의 동점은 고정된 경주/말 key로 처리하고, 균등 baseline 등 동점이 많은 비교에서는 모든 최대확률 후보에 대한 기대 적중률도 병기한다.

### 6.2 개선을 주장할 조건

- 2025에서 **집합 적중률 최대 후보**와 **순서 적중률 최대 후보**를 모두 보고한다. 주 최종 후보는 집합 비열등 조건 아래 순서 적중률이 높은 후보를 선택하며, 확률 품질도 악화하지 않아야 한다.
- 순서·집합의 차이에 paired race bootstrap와 race-day cluster bootstrap 95% CI를 계산한다. 기본 5,000회·고정 seed이며 같은 날짜 경주 전체를 묶는다.
- 계획 기본 허용폭: 집합/순서 적중률 각각 −1%p, 집합/순서 NLL 각각 +0.01 nat/경주. 이는 사전 선택한 연구 설계값이며 성능을 보장하지 않는다.
- 최종 순서 개선 주장에는 순서 적중률 차이의 두 CI 하한이 모두 0보다 크고, 집합 적중률 차이의 두 CI 하한이 −1%p보다 커야 한다. 확률 NLL 차이의 두 CI 상한도 +0.01보다 작아야 한다.
- ‘두 목표 모두 향상’은 집합·순서 양쪽에 개선 증거가 있을 때만 사용한다. 표본이 적어 구간이 넓으면 판정 유보다. 차이가 유의하지 않다는 이유만으로 비열등이라 하지 않는다.
- 개발에서 여러 후보를 고른 뒤 가장 유리한 CI만 보고하지 않는다. 2026의 사전 고정 후보 1개 검증과 이후 미래 기록으로 확인한다.

거리·월·두수·신마·휴양·regime·원천 관측/가정·DQ/DNF·동착별 분모와 실패를 보고한다. 실격/주행중지는 틀린 예측을 삭제할 이유가 아니다.

## 7. 검증과 완료 산출물

이번 dataset 단계의 필수 검증:

1. DB SHA-256 대조와 읽기 전용 추출. 기대 경주/출발 key와 실제 key 일치.
2. 미해결 출발마 포함 8경주 전체 격리, 미출주 제외, DQ/DNF 유지 및 auxiliary mask.
3. 정상 완주 3두·착순 일관성, accepted_orders/sets의 동착·경계 동착·키 유일성.
4. 예측용 상태와 대상 결과 분리, 미래/대상 결과 변경 반례, 같은 날/전날 제외, 행 순서 불변.
5. 상태 table과 entries의 key coverage 100%, 비유한 수치/중복 검사, source 사건 중복과 결측 의미 구별.
6. artifact 파일 hash·schema·기간/거리/split/동착/원천 coverage와 생성 커맨드.
7. 관련 pytest·Ruff·변경 파일 검사. 별도 하위 모델의 SQL 집계와 라벨 구현 대조.

현재 완료물은 새 계획, builder/state 코드와 테스트, 실제 Parquet 묶음, protocol/feature registry/manifest, 한국어 생성 보고서다. 이것이 생성되면 dataset 단계가 완료되며 모델 학습 완료나 100%에 가까운 성능 달성으로 표현하지 않는다.

최종 dataset에는 `reproduce/` 디렉터리로 생성 당시 코드·계획·의존성 계약 사본을 함께 저장한다. manifest의 git commit만으로는 untracked 연구 코드를 재현할 수 없으므로 실제 파일과 hash를 모두 보존한다.

## 8. 실제 사전 예측 원장

다음 모델 구현 단계에서는 경주 전 append-only prediction ledger를 연결한다. 각 예측에 cutoff/발행시각·전체 출전집합 hash·입력/model/protocol hash·선택된 세 마리·선택 순서·집합 확률·순서 확률·변경 전 버전을 저장한다. 결과는 나중에 별도 table로 조인한다.

취소·기수변경 시 새 버전으로 재예측하고 최초 발표를 덮어쓰지 않는다. 원래 발표 집합과 사후 실제 출발 조건부 재평가를 구분한다. 전날 모델과 T-30 모델은 별도 성능으로 기록한다.

최초 미래 평가는 기본 **연속 300개 적격 경주와 최소 30개 경주일**을 모두 충족할 때다. Top3 순서 적중은 단승보다 희소할 수 있으므로 시작 전에 개발 손실과 일별 변동으로 검출 가능한 개선폭을 산정하고 필요 표본을 늘린다. 유리한 중간 시점에서 평가를 멈추거나 틀린 경주를 빼지 않는다.

결국 개선 과정은 **세 마리를 놓친 오류를 줄이고, 맞힌 세 마리의 순서 오류를 줄이는 두 축**으로 관리한다. 이 두 축을 전체 경주의 사전 기록으로 검증하며 100%에 접근한다.
