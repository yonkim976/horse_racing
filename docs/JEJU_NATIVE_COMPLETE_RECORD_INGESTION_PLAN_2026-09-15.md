# 제주마 전 기록 연구 적재 실행안 (2026-09-15)

## 목표와 완료 정의

“전부 적재”는 **공식 공개 원천에서 확인 가능한 제주마 관련 자료를 원천의 지원 기간 안에서 빠짐없이 수집하고, 경주·말·사건 단위로 연결 상태와 미연결 사유를 함께 보존한 별도 연구 DB**를 뜻한다. 원천에 존재하지 않거나 접근 권한이 없는 기간, 공식 마종·말 ID가 확인되지 않는 행은 `완료`로 포장하지 않고 격리 원장과 coverage 분모에 남긴다. 기존 운영 DB·원문·데이터셋·모델·registry는 수정하지 않는다. 과거 경주 전 게시 시각과 예측 성능은 이 적재의 검증 목표가 아니다.

적재 모집단은 둘로 나눈다. **경주 기준**은 2002-07-28~2026-09-12에 공식 결과에서 `제`로 확인된 제주마 경주다. **말 생애 기준**은 공식 마종/등록 근거가 확인된 제주마 전체로 확장한다. 현재 경주에서 확인된 **3,996두**만으로는 아직 출전하지 않았거나 한 번도 출전하지 않은 제주마를 포괄할 수 없다. 현재 말 프로필의 소속·마주·통산정보를 과거 시점 값으로 복제하지 않는다.

## 적재 순서

1. **공식 분모 확정.** 제주 시행일·경주번호의 공식 전수 목록과 경주결과·출전표를 독립 원천으로 대조한다. `제`가 명시된 경주와 미확정 마종을 분리하고, 한/래는 새 제주마 원장에 넣지 않는다. 기존 정상 결과 **9,288경주·90,892출전행**과 `제` 표시지만 양수 정상 결과가 없는 **135경주·1,316행**을 별도 상태로 유지한다. 2019년 말 ID 충돌 4행과 비개인 조교사번호 25행은 기존 29행 원장을 승계한다. **완료 기준:** 원천별 공식 경주/출전 키 분모, 공통/한쪽 전용 키, 취소·무효·미출주 상태가 경주·행별로 설명돼야 한다.
2. **말 모집단 확장.** 경주 출전 말 ID 외에 현역·비현역 등록말의 공식 마종 근거를 수집한다. `hrNo`는 문자열로 보존한다. 동일 마명·개명은 ID와 등록 근거로만 합친다. 최초 출전 이전 사건은 같은 공식 말 ID라면 말의 이력으로 보존하되, 당시 사람 소속은 별도 증거가 없으면 비워 둔다. **완료 기준:** 등록 제주마 분모, 경주 출전마/미출전마, 마종 미확정 말 수를 서로 분리해 보고한다.
3. **이미 검증된 원천부터 별도 연구 DB에 적재.** 공식 경주 결과·ID 연결, 일별 조교 **884,383행**, 출발조교 **184,351행**, 말 ID 확인 진료 **11,653행**, 실측 체중 **90,713행**을 파일 SHA-256을 확인한 뒤 원천행 단위로 append-only 적재한다. 기존 결과의 2002~2014년 원문과 2015년 이후 DB는 출처를 분리한다. 출발조교의 완전 동일 payload **3,153행** 및 진료의 초과 **21행**은 원천 반복으로 보존하고, 독립 사건 수에는 자동 합산하지 않는다. **완료 기준:** 파일별 입력행 수=적재행 수, 원천행 해시·경로·행번호 재현, 재실행 후 신규/변경 0, 말 ID/날짜/경마장 검증 통과.
4. **체중·당일 자료 공백 해소.** 정상 결과 **90,892출전 키 중 체중 미연결 630키**를 원장으로 재조회·원문 대조한다. 특히 **2026-07-07 네 경주·40행**은 DB에 양수 결과와 체중이 있으나 보존 체중 API 부분집합과 `dacom71` Text에 없다. 2019년 말 ID 충돌 4행은 별도 공식 출전표·체중 원천으로 대조하되 이름만으로 선택하지 않는다. `dacom71`은 확인 경주 6,731개 중 138개의 파일 구간이 없고, 존재하는 경주의 65,665출주번호는 공식 결과와 일치하지만 4행 마명이 다르다. **완료 기준:** 체중·장구·진료·폐출혈·기수변경·취소·주로상태의 경주키와 출전키 coverage를 연도별로 공개하고, 미연결은 0 또는 근거 있는 상태 코드로 남긴다.
5. **Text 9종을 유형/연도별로 파싱·연결.** 파일 해시 검증은 끝났지만 `dacom71`의 진료/장구 내용과 다른 8종의 말별 행은 아직 파싱·공식 ID 연결이 아니다. 출전표·체중표·출전마 진료/장구는 `(경마장, 경주일, 경주번호, 출주번호)`로 공식 결과에 대조하고 마명을 추가 확인한다. 말 진료·조교·주행/출발심사처럼 경주키가 없는 Text는 공식 말 ID가 직접 없으면 동명이마·개명 후보를 격리한다. **완료 기준:** 파일 수가 아니라 파싱 성공 행, 공식 ID 연결 행, 다중 후보·불일치·미파싱 행을 각 원천/연도별로 보고한다.
6. **나머지 공식 원천을 원천별로 수집·대조.** 구간, 출전표, 등급변동/레이팅 당시 snapshot, 주행·출발심사, 심판보고서, 배당, 출전취소, 장구·폐출혈, 혈통·등록 이력을 독립 provenance로 담는다. 수영·언덕조교와 예방접종·장제·약물·ECG 등은 현재 접근 승인/제공 범위가 확인되지 않아 `미수집·접근확인 필요`로 분리한다. [공식 일별훈련 API](https://www.data.go.kr/data/15058782/openapi.do), [진료 API](https://www.data.go.kr/data/15057799/openapi.do), [장구·폐출혈 API](https://www.data.go.kr/data/15058040/openapi.do). **완료 기준:** 원천별 지원 기간·요청 건수·`totalCount`·반환/보존/연결행 수·제외 사유를 연도별 manifest로 고정한다.

## 별도 연구 DB의 최소 계약

원천과 해석을 분리한다. `source_request`에는 API/파일 경로, 비밀키를 제거한 요청, 응답 SHA-256, 수집 시각, `totalCount`, 파일 SHA-256을 둔다. `source_row`에는 **제주마로 확인된 행만** 원문 JSON/Text 내용 또는 기존 원문 위치·행번호, 행 SHA-256, 마종 확인 상태를 둔다. 혼합 응답의 한/래 본문을 새 연구 DB에 복사하지 않는다. `race_entry_link`에는 경주일·경주번호·출주번호·공식 `hrNo/trNo/owNo` 문자열과 각 필드의 원천 근거를 둔다. `horse_event`에는 공식 말 ID, 사건일, 사건 유형, 원천행 참조를 두되 **조교사/마주 ID는 사건일 소속 근거가 있을 때만** 둔다. `resolution_issue`는 충돌·중복·추가·누락·마종 불명·사람 귀속 불명의 행별 근거를 보존한다. `coverage`는 원천/연도/마종/상태별 분모와 분자를 저장한다.

`event_date`, `source_retrieved_at`, `source_published_at`은 서로 다른 필드다. 과거 게시 시각을 모르면 NULL로 유지한다. 동일한 원문을 다시 적재해도 `source_row` 해시/위치 기준으로 중복 생성하지 않아야 하지만, 원문 자체의 반복 행은 별도 원천행으로 보존한다. 정규화 뷰는 `verified`, `provisional`, `quarantined`를 명시해 소비자가 상태를 선택할 수 있게 한다.

## 첫 실행 묶음과 승인 기준

가장 먼저 **기존 보존 자료만**으로 별도 연구 SQLite를 만들 수 있다. 1차 결과물은 (a) 위 4개 ID 기반 원천의 원문행 적재, (b) 확인된 경주결과와 체중의 엄격한 키 연결, (c) 29 ID 미해결·630 체중 미연결·중복 사건·Text 공백 원장, (d) 연도별 coverage, (e) 파일/행 해시 및 재실행 검증이다. 이 단계는 자료를 합친 연구 저장소를 만드는 것이지 전수 완료 선언이 아니다.

그 뒤 공식 경주/등록말 분모와 옛 Text 행별 연결, 미접근 API의 이용 가능 여부를 순서대로 해결한다. 모든 원천이 100%라고 쓰기보다 **원천별 `확인됨 / 미연결 / 원천에 없음 / 접근 불가 / 마종 불명`**을 수치로 발표한다. [현재 ID 미해결 29행](JEJU_RACE_TIME_ID_UNRESOLVED_29_2026-09-14.md), [다른 원천 검증과 공백](JEJU_OTHER_SOURCE_VERIFICATION_2026-09-15.md), [원천 수집 범위](JEJU_NATIVE_SOURCE_COLLECTION_AVAILABILITY_2026-09-14.md)를 첫 기준선으로 사용한다.
