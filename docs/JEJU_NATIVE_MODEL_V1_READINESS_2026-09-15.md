모델의 기본 결과 모집단은 `confirmed_native_normal_race`이고, 이름만으로 ID를 채우지 않는다. 공식 ID가 완결된 실제 출발 확인 집합은 정상 착순 1~89, 실격 91, 주행중지 92다. 93·94·95는 사후 미출주이므로 실제 출발 조건부 연구에서는 제외한다. 99 경주취소, 98 및 의미가 확정되지 않은 상태, 양수 결과가 없는 135경주는 학습·평가하지 않는다.

연구 DB의 `record_status`만으로 라벨을 만들면 안 된다. 코드 91 중 162행은 양수 완주시간 때문에 `normal_completed`로 저장돼 있지만 공식 의미는 실격이다. 새 builder는 **착순 코드＋근거 상태를 함께 해석**해야 한다. 실격·주행중지는 win/topK=0으로 사용할 수 있으나 정상 순위와 완주시간 target은 mask한다. 기존 E1 계약의 코드 의미를 제주에도 적용하고 실제 제주 원천 표본으로 다시 대조한다. 동착 우승 경주의 winner NLL은 동착 우승마들의 확률합에 적용하며, soft-label을 쓰면 우승자 수로 나눈다.

과거의 정확한 T−30 출전집합은 보존되지 않았다. 따라서 이 첫 역사 연구의 정확한 이름은 **사후 확인 실제 출발마 조건부 모델**이다. 실제 예측 때는 그 시점에 관측된 출전표 전체에 확률을 내고, 이후 실제 사전 예측 원장에서 차이를 측정한다. 이 한계는 역사 모델 개발을 막는 조건으로 삼지 않는다.

## 3. ID와 자료 밀도

경주 전체 92,208행에는 말 ID와 마주 ID가 모두 있고 조교사 ID가 57행 비어 있다. 정상 경주 중 공식 연결 미해결 29행은 분석 대상에서 제외한다. 최신 표준 `entry` 테이블에는 기수 ID·게이트·부담중량·성별·연령이 독립 열로 모두 올라와 있지 않다. 일부는 `source_row.normalized_json` 또는 Text `entry_card.parsed_json`에 있으며, 최근 출전표 Text의 구조화 행은 54,219개다. 그러므로 1차 모델은 말 중심으로 만들고 기수 확장은 출전표 정규화 계약을 별도로 완성한 뒤 진행한다.

`source_row.normalized_json`에는 과거 결과 원천 전체가 들어 있어 착순·완주시간·구간뿐 아니라 확정 단승/연승 배당도 함께 존재한다. JSON을 자동 평탄화해 모두 feature로 쓰면 대상 경주의 정답이 섞인다. 새 builder는 **허용 열 목록 방식**으로 필요한 열만 읽고, 대상 경주의 `ord`, `rcTime`, 구간, `winOdds`, `plcOdds`, 당일 결과 주로값을 feature 계약 단계에서 거부한다.

현행에 가까운 2023-01-01 이후 실제 출발 확인 25,548행을 대상으로 대상 경주보다 **엄격히 이전 날짜**만 사용해 coverage를 계산했다.

| 과거 정보 | 연결 행 | coverage |
|---|---:|---:|
| 직전 28일 일별 조교 | 25,548 | 100.00% |
| 직전 28일 출발조교 | 17,197 | 67.31% |
| 직전 90일 진료 사건 | 6,777 | 26.53% |
| 이전 유효 경주구간 1회 이상 | 24,480 | 95.82% |
| 이전 공식 연결 주행심사 1회 이상 | 25,539 | 99.96% |

| 대상 경주의 구간 자체가 usable | 25,518 | 99.88% |

진료 coverage 26.53%는 누락률이 아니라 해당 기간 내 진료행 존재율이다. 진료가 없다고 건강하다고 라벨링하지 않는다. 조교가 전 행에 연결된다는 것은 직전 28일 내 최소 한 행이 있다는 뜻이며, 공식 역사에서 모든 훈련 시행을 완전히 포착했다는 뜻은 아니다. 같은 출발조교/진료 payload의 반복은 distinct 분석 뷰를 사용한다.

## 5. 기존 제주 데이터셋을 그대로 쓰면 안 되는 이유

기존 `jeju_native_racefit_v5_history`는 2016-01-08~2026-09-05의 62,301행·6,281경주, `jeju_native_racefit_v5_recent`는 2025-01-03~2026-09-05의 11,637행·1,203경주다. 키 중복·비유한 float는 없었고, 각 데이터셋의 1착 동착도 정상 보존됐다.

그러나 두 파일은 다음 이유로 **새 연구 DB의 정확성을 대표하는 최종 학습 입력이 아니다.**

1. 최신 2002~2026 제주 연구 DB에서 재생성한 파일이 아니다.
2. 미출주뿐 아니라 실격·주행중지를 모두 제거한 정상완주 조건부 계약이다.
3. `pace_fade_avg5`는 두 파일에서 전 행 null이다.
4. 기존 recent는 232개 feature를 포함해 말 능력·기수·조교사·당일 체중 효과가 한꺼번에 섞인다.
5. 반복 사용한 2026-03~05 개발 검증에서 후보를 고른 과거가 있어 새 독립 기준선이 아니다.

기존 제주 V2는 비교용 baseline으로 재현하되, 새 V1 학습 입력은 연구 DB에서 새 버전과 hash로 만든다.

## 6. 권장하는 제주마 첫 모델

첫 목표는 **기수·조교사·마주·배당을 제외하고 말의 경주 전 성능분포만으로 우승확률을 만드는 것**이다. 한 번에 모든 자료를 넣지 않는다.

### 6.1 모델 입력 계층

| Arm | 입력 | 검증 질문 |
|---|---|---|
| `U0_UNIFORM` | 경주당 `1/N` | 모델이 아무 정보 없는 기준보다 나은가 |
| `H0_RESULT` | 과거 상대 착순, 경주 수준, 출전 수, 휴양, 거리 경험 | 결과 이력만으로 재현 가능한 능력 신호가 있는가 |
| `H1_TIME_SECTION` | H0 + 보정 완주시간·검증된 인접 구간 | 시간·구간이 결과 이력에 추가 정보를 주는가 |
| `H2_STATE` | H1 + 과거 조교·출발조교·주행심사·진료 상태 | 최근 상태 자료가 증분 정보를 주는가 |
| `H3_CONDITION` | H2 + 이번 경주의 거리·등급·부담중량 | 능력을 오늘 조건에 적용하면 더 좋아지는가 |

공식 레이팅은 말의 잠재 능력 정답으로 넣지 않고 `RATING_ONLY` 비교 기준을 따로 둔다. 대상 경주의 최종배당, 결과, 구간, 당일 이후 조교·진료, 대상 경주의 심판보고서는 금지한다. 당일 마체중과 당일 주로는 첫 day-before 능력 모델에서 제외하고, 이후 T−30 정보 모델에서 별도 추가한다. 과거 완료 경주의 마체중·주로는 그 다음 경주 이전에 이미 알려진 이력으로 사용할 수 있다.

### 6.2 능력 상태

각 출전 직전에 다음을 저장한다.

```text
horse_id, cutoff_date, ability_mean, ability_uncertainty,
distance_suitability, recent_form, performance_variability,
normal_history_count, section_history_count, source_quality
```

기존 multiplayer Elo와 보정 속도지수를 baseline으로 재계산한다. 새 후보는 지속 능력, 거리 적합성, 최근 상태와 불확실성을 분리한다. 실격·주행중지는 최종 우승 확률에서 패배이지만 정상 순위/시간 능력 업데이트에는 사용하지 않는다. 첫 출전·장기 휴양·처음 거리에서는 마종 평균으로 수축하고 불확실성을 높인다.

### 6.3 시간 분할

1. **이력 burn-in:** 2002-07-28부터. 과거 경주로 능력 상태를 순차 초기화한다.
2. **계수 학습 후보:** 2018-08-31~2024-12-31. 시대 feature 또는 최근 가중치를 사용한다.
3. **개발 선택:** 2025년을 월/분기 단위 walk-forward로 사용한다.
4. **동결 역사 평가:** 2026-01-01~09-12를 한 번 평가한다. 2026년 집계와 일부 결과는 데이터 감사에서 이미 열렸으므로 이를 완전히 보지 않은 prospective test라고 부르지 않는다.
5. **최종 판정:** 이후 실제 출전표로 사전에 남기는 제주 경주 예측 원장에서 확인한다.

추가 통제 실험으로 `2023~2024만 학습`, `2018~2024 학습`, `오래된 경주는 burn-in에만 사용`을 같은 2025 개발 경주에서 비교한다. 오래된 자료가 도움이 되는지는 이 비교로 결정한다.

### 6.4 평가 계약

- 주 지표: 경주별 winner-set NLL
- 보조: Top1, 우승마 Top3/Top5 포함률, Brier, 확률 calibration
- 분해: 연도·월, 거리, 등급, 신마/기성마, 출전두수, 2026 rating rebase
- 불확실성: 같은 경주의 예측을 짝지은 bootstrap과 경주일 cluster bootstrap
- 모든 arm은 같은 경주·같은 출전집합·같은 calibration 구간을 사용
- 후보가 실패하면 해당 feature 계층만 버리고 앞 단계 모델을 유지

## 7. 구현 순서

1. 연구 DB의 `event/entry/source_row/derived_segment`에서 새 불변 entry-level dataset builder를 만든다.
2. 제주 특수착순 adapter와 동착 loss를 먼저 고정한다.
3. 미래 결과를 바꿔도 과거 feature가 변하지 않는 테스트, 같은 날 결과 일괄 갱신 테스트, 마명 조인 금지 테스트를 둔다.
4. `U0`, 기존 Elo, `H0`를 먼저 실행한다. 여기서 정합성과 개선이 확인된 뒤 H1/H2/H3를 하나씩 붙인다.
5. 기존 제주 V2를 동일 평가 키로 재추론해 기준선으로만 비교한다.
6. 기수·말×기수·조교사·마주 확장은 말 중심 모델의 능력값을 기준으로 별도 arm에서 진행한다.

현재 가장 빠르고 올바른 다음 작업은 추가 수집이 아니라 **최신 연구 DB에서 말 중심 V1 dataset builder와 라벨 계약을 만드는 것**이다. 데이터 자체는 이를 시작할 만큼 충분하다. 기존 Parquet을 그대로 재학습하는 것은 이번에 정리한 장기 자료와 상태 분리를 활용하지 못한다.
