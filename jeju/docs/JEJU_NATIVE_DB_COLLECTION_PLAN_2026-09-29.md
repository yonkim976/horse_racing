## 목표와 진행 순서

먼저 제주마 경주와 주행심사 원천을 수집하고, 경주·심사·말·사람의 공식 ID를 연결한다. 기본 원천의 보유 범위와 출처별 누락을 고정한 뒤 정제한다. 기본 결과층을 확인한 다음 상세 이력 자료를 별도 단계로 보완한다.

## 수집원칙: API 우선, RPT/TXT 보완

모든 수집 항목은 **해당 필드를 제공하는 KRA 공식 API 응답을 1차 원천**으로 삼는다. API 원문 응답 바이트를 먼저 보존하고, 날짜·말 ID·출전/심사 번호·필드 정의·건수를 확인한 뒤 정규화한다. 경주 결과·주행심사 외의 구간, 통과, 심판, 진료, 조교, 체중, 장구 자료도 API가 제공하는 필드는 각 API를 기본 수집원으로 둔다.

RPT/TXT 파일은 아래 경우에만 별도 보완 자료로 쓴다.

1. API 서비스가 해당 기간·필드를 제공하지 않는 것을 명세 또는 실제 응답으로 확인한 경우
2. API 누락·결측·오류를 검증하거나 원인 설명이 필요한 경우
3. API 데이터로 제공되지 않는 추가 상세문구가 필요한 경우

보완 RPT/TXT는 API 원문을 대체하거나 덮어쓰지 않는다. 별도 보조 출처로 저장하고 파일·행·필드 단위 출처와 SHA-256을 붙인다. API와 내용이 다르면 API 값을 그대로 보존하고 불일치로 격리한다. 기존 Text 기반 연구 스냅샷을 API 수집 DB로 복사하지 않는다.

모든 API 응답은 원문 바이트, 요청 파라미터(서비스 키 제외), 조회·수집시각, 응답 크기·SHA-256, 건수·기간, 파서 버전을 기록한다. 한 API의 오류는 해당 시도 manifest에 HTTP 상태 또는 DNS/전송 오류를 남긴다. RPT/TXT가 있다는 이유로 API 요청 실패를 성공 또는 완결로 바꾸지 않는다.

1. **기본 원천 고정:** 경주결과 API 응답은 2002~2026, 주행심사 API 응답은 2000~2026 범위에서 수집해 원문/응답 단위로 보관했다. API가 반환한 경마장·마종 전체 원행을 먼저 기록하고 제주마 판정은 별도 근거수준으로 관리한다. 출처 URL, 수집시각, 요청범위, 응답 해시와 연도별 coverage가 새 근거 DB에 있다. RPT/TXT는 API 검증 뒤 필요한 보완분만 별도 수집한다.
2. **기본 경주·심사·관계자 연결:** 경주 거리·등급·부담중량·주로상태·기수와 말, 조교사, 마주, 기수를 출전행에 연결한다. 심사는 날짜·심사번호·거리·결과·말·기수를 연결한다.
3. **기본 데이터 정리:** 원천 중복·누락·충돌·미해결 신원·마종을 점검하고, 승인된 제주마 행만 정규화 원장에 포함한다. 원천 행은 수정하지 않는다.
4. **상세 데이터 보완:** 경주 구간기록, 통과착순, 통과조, 심판 리포트, 진료, 일별 조교, 출발조교를 각각의 원천·가용기간·키 기준으로 추가한다.
5. **학습표 구성:** 전체 보관 이력과 모델 정답 구간을 분리한다. 계획된 정답 학습 시작은 2017년이며, 2017년 이전 결과는 예측시점 이전 말 이력으로만 쓴다. 수집·적재 단계에서 학습행을 미리 자르지 않는다.

## 범위와 필수 필드

### A. 제주마 경주

포함 모집단은 제주경마장에서 시행됐다는 사실만으로 정하지 않는다. 원천 스키마가 품종으로 정의한 공식 마종 필드 또는 기록 시점에 유효한 공식 말 ID별 제주마 확인 근거가 있는 경주·출전행만 제주마 원장에 넣는다. `meet=제주`는 경마장이고, `rank`의 `제` 접두는 현재 확보된 API4_3 스키마로 의미를 확정하지 못했으므로 단독 품종 근거로 쓰지 않는다. 한라마·더러브렛·마종 미확인 행은 혼합 원천에 남아 있어도 제주마 정규 원장에서 제외하거나 격리한다.

경주키는 `경주일+경주장+경주번호`, 출전키는 여기에 공식 말 ID와 출주번호를 더해 관리한다. 최소 수집 필드는 다음과 같다.

- 경주: 날짜, 경마장, 경주번호, 거리, 등급/경주조건, 경주명, 주로상태·함수율, 날씨, 경주 상태, 원천 식별자
- 출전·결과: 출주번호, 말 ID·마명, 착순·착차·주파기록·결과상태, 부담중량, 게이트, 장구, 체중, 출전/취소 상태
- 사람 관계: 해당 경주의 기수·조교사·마주 공식 ID와 표기명, 출전행에서의 역할
- 근거: 원천 마종표기, ID 출처, 판정상태, 원문행 해시/행 번호, 미해결 사유

기수·조교사·마주 ID는 문자열로 보관해 선행 0을 보존한다. 이름만으로 ID를 확정하지 않는다. 현재 프로필이나 현재 소속을 과거 경주에 소급 적용하지 않으며, 해당 경주 당시의 사람-말 관계와 현재 프로필을 분리한다.

### B. 제주마 주행심사

주행심사 모집단은 제주경마장의 `meet=2` 심사 전체가 아니라 제주마로 확인된 말의 결과만이다. 원문 `제` 표기, 심사 결과표의 공식 말 ID, 기록 시점의 공식 말 품종 근거를 사용한다. 한라마 등 비제주마 행과 품종·ID 충돌 행은 제외 또는 격리한다.

- 심사: 일자, 심사번호, 심사종류/회차, 거리, 편성두수, 합격두수·합격여부, 결과/기록
- 출전행: 출주번호, 말 ID·마명·마종 근거, 기수 ID/이름, 주파기록·통과기록, 결과상태
- 근거: 원문 파일·행, 공식 상세표 키, ID 연결근거, 출처 해시, 미해결 사유

심사번호는 경주번호와 구별하며, 날짜·번호 조합을 사용한다. 주행심사와 출발심사는 별도 이벤트 종류로 저장한다.

## 데이터 흐름과 저장 원칙

- **원천 보관층:** 원문/API 응답 또는 기존 응답 파일을 바이트 단위로 보존하고 manifest에 크기·SHA-256·수집시각·조회기간·파서 버전을 남긴다. 이미 보관된 원천은 복제 수집보다 무결성 확인 후 참조한다.
- **연결 후보층:** 원천의 값을 그대로 두고 공식 ID 후보, 마종 근거, 자연키, 연결 방법을 추가한다. 공식 ID 불일치·동명이마·개명 가능성은 미해결 원장에 둔다.
- **정규화 원장:** 판정이 끝난 제주마 경주/심사 행만 넣는다. 마종이 불명확한 행을 제주마로 추측해 채우지 않는다.
- **출처별 coverage:** 자료별 최초/최종 관측일, 연도·월별 경주/출전행 수, 결측 및 공식 키 미연결 수를 기록한다. ‘자료 없음’과 ‘미수집’을 구분한다.
- **반복 실행:** 기존 운영 SQLite, Supabase, 모델·등록부는 변경하지 않는다. 새 버전의 연구 산출물만 만들고, 같은 자연키의 재수집은 원천 해시와 함께 중복·개정 이력을 보존한다.

새 DB `jeju/data/jeju_native_core.sqlite3`는 구축 완료됐다. 이는 API 원문, 정규화된 관측, 연결 후보, 보완 출처와 충돌을 담는 **API-first 근거 원장**이며, 제주마 확정 행만 모은 최종 DB는 아니다. API4_3 결과 행에 말별 품종 필드가 없고 과거 유효시점도 증명되지 않아 결과행에 `native_confirmed`를 부여하지 않았다. 스키마는 `jeju/data/schema/jeju_native_core.sql`, 로더는 `jeju/scripts/build_native_core_from_api_raw.py`, 검증 결과는 `jeju/data/jeju_native_core.build_manifest.json`이다. 기존 운영 DB `data/horse_racing.sqlite3`와 연구 스냅샷 `data/research/jeju_native_text_phase2_db_20260915/jeju_native_text_phase2.sqlite3`는 읽기 전용으로 확인했고 신규 원장 입력으로 복사하지 않았다.

## 상세 자료 수집 순서

기본 경주·심사·말·사람 연결을 동결한 뒤 아래 자료를 한 종류씩 추가한다. 어느 자료도 2002년부터 모두 존재한다고 가정하지 않는다.

1. 구간기록: 말별 시간, 누적/구간 정의, 계측지점·거리, 출처·수정 상태
2. 통과착순·통과조: 말별 지점 착순과 경주 단위 통과군을 별도 구조로 보관
3. 심판 리포트: 사건일, 게시일/수집시각, 말 ID·경주키, 조치와 원문근거
4. 진료기록: 진료일, 진단 원문/코드, 말 ID, 공개/수집시각, 미확정 사건
5. 일별 조교: 훈련일, 말 ID, 훈련 종류·시간·횟수와 자료 시작 전 상태
6. 출발조교: 심사/훈련일, 말 ID, 결과·기록과 조교 종류

상세 자료는 자체 이벤트 날짜와 공개·수집시각을 모두 남긴다. 예측 기준시점 이후에 발생/게시된 사건은 과거 경주의 피처로 사용하지 않는다. 수영·언덕주로 등 현재 시작일이 확인되지 않은 자료는 별도의 원천 조사 대상으로 표시한다.

## 완료 기준

### 기본 수집·연결 단계

- 2002~2026 API4_3 결과 191,786행과 2000~2026 API20_1 주행심사 34,377행을 연도 coverage와 함께 원문 보존했다.
- 원문 artifact 80개의 SHA-256, SQLite integrity, FK 검증이 모두 통과했다. 건수·날짜 범위·해시는 DB build manifest에 있다.
- API 관측, 후보, 보완, 충돌을 분리했다. 과거 품종 유효성 근거가 없는 결과는 제주마로 확정하지 않으며, 최종 확정 전환은 후속 작업이다.
- 경주·출전·심사 자연키 중복, ID 형식 및 말/사람 연결률을 계산하고 미해결 원장을 보존한다.
- 연도별 공식 원천 건수와 정규화 원장 건수가 대조되며 차이마다 사유가 있다.

### 학습용 구성 전 단계

- 성적표/주행심사 결과, 통과/구간, 이벤트 자료를 구분하고 정답 라벨과 피처를 분리한다.
- 2017년 이후 전체 대상 경주를 학습·시간순 평가 후보로 두고, 2017년 이전 이력은 각 대상 시점 이전 기록만 연결한다.
- 이력 미관측을 0회/정상/건강으로 치환하지 않고 coverage와 left truncation을 표시한다.
- 학습·평가 및 모델 비교는 수집/정제 완료와 시점 계약 고정 후에만 시작한다.

## 최신 확인된 출발점과 우선 공백

API-first 원장 전체 결과와 provenance는 [2026-09-29 API 우선 재수집 보고서](../research/20260929_core_collection_inventory/API_FIRST_RERUN_20260929.md)를 기준으로 본다.

- **경주결과:** 공공데이터포털 15058305, 한국마사회 경주기록 정보, `API4_3/raceResult_3`에서 제주 경마장 전체 API 행 191,786개를 2002-01-12~2026-09-19 범위로 보존했다. 이 응답에는 말별 품종 필드가 없다.
- **주행심사:** 공공데이터포털 15056974, 한국마사회 주행심사 상세결과, `API20_1/ridingTestResult_1`에서 전체 마종 34,377행을 2000-01-05~2026-09-16 범위로 보존했다. 직접 `majong=제주`는 15,738행·1,967심사이며 첫 관측은 2002-06-12다. 2000·2001년에는 제주 라벨이 없다. 2003-01-10은 당시 모든 마종을 포함한 첫 심사일이고, 제주 라벨의 2003년 첫 날짜는 2003-02-21이다.
- 기존 phase2 주행심사 스냅샷은 2003-07-11~2026-09-09, 15,688행이다. API에는 2003년 제주 11행이 추가로 보이며, 그중 9행은 phase2의 시작일 이전, 2행은 2003-09-05 1차 심사 출주 1·2번으로 phase2 날짜 범위 안의 별도 누락이다. 새 DB는 RPT phase2를 API 사실로 복사하지 않았다.
- **새 저장소:** `jeju/data/jeju_native_core.sqlite3`는 원문 API 행·정규화 관측·후보·보완 facts·충돌을 연결하는 API-first 근거 원장이다. 확정 제주마 전용 행만 담은 최종 원장은 아니다. 과거 품종 유효시점이 입증되지 않은 결과를 `native_confirmed`로 표기하지 않았다. 기존 운영 DB와 phase2 DB는 읽기 전용 참조로 유지한다.

### 경주 결과 품종 후보

- 원문 API `rank`의 `제` 접두 후보는 92,414행·9,445경주·4,006개 말 ID다. 말별 마종은 API4_3에서 오지 않으므로 `breed_label_raw`를 NULL로 보존하고, `rank`는 `rank_class_raw`에 둔다.
- 이 후보 4,006개 ID는 같은 공식 ID의 API20_1 `majong=제주` 심사 관측이 있고, 92,414 결과행 전체에 대해 심사 관측일이 경주일 이전 또는 당일이다. 이 사실은 교차 후보 근거일 뿐 과거 경주 당시의 품종 유효성을 단독으로 증명하지 않는다.
- `rank`가 `제` 접두가 아니어도 동일 ID의 제주 `API20_1` 관측이 해당 경주일 이전/당일인 추가 후보 281행·197개 말 ID가 있다. 2002~2012년 68개 경주에 걸쳐 있고, 그 68경주의 API4_3 전체 출전행은 609개다. 추가 281행이 전 출전행인 경주는 24개뿐이므로 나머지는 혼합/부분 후보 경주다. 전체 `jeju_race_population_candidates` 뷰는 92,695행·9,513경주·4,006개 ID지만, 9,513을 제주마 전용 경주 확정 수로 해석하지 않는다.
- 2023년 이후 시행이 제주마 전용이라는 제도·편성 근거는 경주 모집단 후보에 별도 표시할 수 있으나 API4_3 말별 품종 필드가 아니다. 과거 말의 품종을 소급하거나 rank를 품종으로 확정하지 않는다.
- API20_1 동일 ID 후보 중 비제주 마종 라벨과의 교차 또는 같은 ID 내 다중 API20 라벨은 현재 원장 기준 0건이다. RPT와의 별도 충돌 사례는 아래에 기록한다.

### 최신 데이터 대조와 보완

- 2026-09-17~19 경주 후보 206행은 API4_3에서 206/206 날짜·경주·출주번호·공식 말 ID·착순이 일치했다. 기록은 204/206 일치하며 두 차이는 9/19 4R 비주행 말 `3103453`, `3103835`의 API `rcTime=0`/후보 NULL이다.

### 현재 말 프로필 API의 한계

공공데이터포털 15057985 **한국마사회 마필종합 상세정보**(`API42_1/totalHorseInfo_1`)는 현재 `breed`를 조회할 수 있다. 무필터 호출은 실제 100개 결과만 반환하므로, 고정한 대상 말 ID를 `hr_no`로 개별 조회했다.

- **2026-10-01 수집 완료:** 경주결과 후보 4,006두와 API20 제주 심사 보조 후보 611두, 합계 4,617두의 프로필을 확보했다. 9월 30일 성공 2,900두를 보존하고 10월 1일 미완료 1,717두를 추가 조회했으며, 전체 `breed=제주마`, 남은 ID 0개다.
- 독립 검증에서 응답 원문 4,618개의 SHA·바이트 수, 성공 응답 4,617개의 공식 말 ID·마종·API 성공 상태를 대조했다. API42/API20 마종 충돌 0건, 이전 성공 ID의 오늘 재조회 0건이다. 원문 수에는 과거 실패 응답 1개가 포함된다.
- 이 API에 품종 유효기간/기준일이 없으므로 프로필 관측일을 그대로 보존한다. 원문 파일과 전체 item JSON을 연결해 `jeju_native_core.sqlite3`의 `horse_profile_observations`에 적재했으며, `breed_evidence`에는 경주일이 없는 조회시점 근거 4,617개를 추가했다. 과거 경주일로 소급하거나 `native_confirmed`로 자동 승격하지 않았다. 기존 API20 근거 집계는 evidence_kind를 제한해 조회시점 프로필과 혼합하지 않는다.
