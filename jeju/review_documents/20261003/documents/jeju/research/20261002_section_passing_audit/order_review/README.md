# API4 통과착순 불일치 원문 재검토

2026-10-02 `root_audit/api4_group_order_disagreements.csv`의 27경주·31지점·105 관측을 읽기 전용으로 재검토했다. 전체 현행 API4 경주 출전표 296행을 포함해 원문 말별 순위·구간시간, 경주별 API303 통과조, API6 통과순위 문자열과 원본 페이지 위치를 연결했다. 기존 CSV와 데이터베이스를 수정하지 않았다.

## 결과

- API4 원행 payload 해시 296건, API303 DB payload와 원본 페이지 대조, 대상 API6/API303 페이지 해시·크기·행 수 검증이 통과했다.
- 지정한 API6/API303 지점 필드끼리 문자열이 같은 항목은 31건 중 22건, 다른 항목은 9건이다. 9개 차이는 모두 2002년이다. 9건 중 8건에서 API6 값이 같은 경주의 **다른 API303 `corner_N` 열**에도 원문 그대로 나타나며, 2002-10-26 4R 3C는 `corner_2`와 `corner_8` 두 열에 모두 있다. 이는 2002년 지점 대응·열 배치가 당시 경주별로 달랐을 가능성을 강하게 제기하지만, 어느 칸이 공식 3C/G1F/S1F인지를 이 사실만으로 확정하지는 않는다. 2002-12-14 3R 4C 값은 지정 API6 칸이나 API303의 다른 열과 같지 않고, API303 `corner_4`와 `corner_8`이 서로 같은 문자열이다.
- 같은 경주·지점의 API4 말별 순위와 API4 원시 구간시간 순위를 짝별로 비교하면, 둘 다 구별되는 짝 1,202개 중 1,039개(86.4%)가 같은 방향이고 163개가 반대다. 사후 구간 뷰는 대조 완료 필드에는 웹 검토값을, 나머지 양수 미대조 필드에는 API 원값(`api_positive_unreviewed`)을 제공한다. 이 뷰에서 비동점 짝 1,027개 중 898개(87.4%)가 같은 방향이다. 이는 API4 순위와 구간시간이 대체로 함께 움직인다는 보조 관찰이다. 같은 API4 레코드 안의 두 필드라 독립 검증은 아니며, API4 오류가 없음을 증명하지 않는다.
- 105개 불일치 말/지점 관측 중 원시 API4 구간시간으로 계산한 순위 구간이 파서상 API303 순위 구간과 겹치는 경우는 15건이다. 이미 적재된 공식 홈페이지 시간 검토값을 사용하면 21건이다. 이 비교는 통과조 문법·지점 연결을 확인하는 참고치이며 순위의 정답 판정은 아니다.

## 원인 가설과 현재 증거

1. **지점 필드 대응 오류 또는 연도별 열 배치 차이 — 우선 대조 가설.** API6 지정 순위 문자열이 API303의 다른 열과 정확히 일치하는 2002년 사례가 7건이다. 2002년 API303/API6 차이를 지점별로 바로 비교해 API4 값까지 틀렸다고 결론내리면, 비교 지점이 어긋난 상태일 수 있다.
2. **API303 표기 문법을 넓게 단순화했을 가능성.** 기존 파서는 괄호를 한 무리로 보고 모든 숫자를 구성원으로 세며 `^`를 제거한다. 쉼표·하이픈·`=`·`≡`는 모두 다음 무리 경계로 처리한다. 이 의미가 틀리면 만들어진 순위 범위가 잘못된다. 특히 서로 다른 기호가 공식적으로 같은 착순을 뜻하는지, 별도 레일·기준을 표시하는지 확인 전에는 범위 비교를 확정할 수 없다.
3. **API4 개별 순위 또는 시간 원문 이상.** API4 order와 API4 rawtime가 대체로 같은 방향인 것은 이 가설을 낮추는 정황일 뿐이다. 두 필드는 원천 응답을 공유하고 한 필드가 함께 잘못됐을 수 있다. 시간 이상 사례는 순위와 원시시간을 분리해서 봐야 한다.
4. **경주별 출전표/마번 파싱 또는 연결 차이.** 이번 산출물은 전체 현재 경주 결과표의 말 ID·마번과 각 원문 항목 위치를 함께 제시한다. 그러나 해당 경주의 출전 취소·주행 제외 여부나 괄호·기호의 공식 의미까지 로컬 원문만으로 새로 확정한 것은 아니다.

### 검토 시간 이상과 겹치는 키

- 2025-10-17 7R S1F 8번은 API4 원문 77.8초가 공식 홈페이지 검토값 17.8초로 정정돼 있다. 원시시간 순위는 10위였으나 검토값 순위 구간은 API303의 파서상 2~4위와 겹친다. 같은 지점의 불일치 6건 모두 검토값 순위 구간이 API303 범위와 겹친다. 이 결과는 API4 원순위가 맞다는 증거도, API303 그룹이 맞다는 증거도 아니다.
- 2026-03-06 8R G1F 6번은 원시 76초가 16.0초로 정정돼 있다. 검토값 순위 구간 5~6위는 그룹 범위 4~7위와 겹치지만 API4 순위 1위는 여전히 그룹 범위 밖이다.
- 2026-01-17 5R G1F 8번은 API·홈페이지 모두 77.2초이며 미해결로 검토 뷰가 NULL이다. 이를 17.2초로 바꾸거나 순위 추정에 대입하지 않았다. API4 순위 1위·원시시간 순위 10위·파서상 그룹 5위가 서로 다르므로 공식 근거 없이 어느 값을 선택하지 않는다.

## 원문 대조 때 볼 점

- 먼저 같은 날짜·경주·지점의 **API4 개별 순위 필드, API4 구간시간 필드, API303 각 `corner_N`, API6 각 `passrank*`**를 함께 확인한다. 지정 필드끼리 불일치하는 2002년 9개 지점은 동일 문자열이 발견된 다른 API303 열도 같이 비교한다. 그 동일성은 열 대응의 단서이지 공식 지점 정의가 아니다.
- API4의 `sj*Ord` 값과 완료순위(`finish_position`)는 다른 측정이다. 완료순위를 지점 순위 대용으로 쓰지 않는다. API6 `passtime*`는 경주 단위 값이므로 말별 API4 시간과 직접 비교하지 않는다.
- `API4 rawtime` 비교에는 2025-10-17 S1F, 2026-01-17 G1F, 2026-03-06 G1F의 기존 검토 상태를 포함했다. status가 `website_corrected`면 검토값을 참고하고, `unresolved_official_website_anomaly`는 순위 계산에서 빠진다. 다른 양수 원시시간은 `api_positive_unreviewed`로, 홈페이지 확인 완료를 뜻하지 않는다.
- 괄호 안 말 순서를 개별 순위로 해석하지 않는다. `^`, `=`, `≡`, 쉼표, 하이픈은 공식 설명 확인 전 문법을 확장하거나 바꾸지 말고 원문 그대로 보존한다.
- 사용자 지정 교정이나 미해결 시간 처리 결과를 순위 원문 검증으로 오인하지 않는다. 사후 구간·통과순위·통과조는 해당 경주의 사전 입력에 연결하지 않는다.
