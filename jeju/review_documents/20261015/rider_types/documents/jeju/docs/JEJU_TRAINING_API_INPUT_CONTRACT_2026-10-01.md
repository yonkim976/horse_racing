## 홈페이지 기준 출발조교 적재

기존 API22에 기록된 2007-10-17부터 2026-09-27까지 2,529개 날짜의 공식 홈페이지 표를 전부 조회했다. 마명 링크에 포함된 공식 `hrNo`를 API42 제주마 프로필 ID와 직접 연결하며, 이름 문자열로 ID를 추정하지 않는다. 홈페이지 전체 295,470행 중 보유 제주마 4,476두의 190,842행이 연결되고, 현재 경주 상한 2026-09-19까지는 190,790행이다. 이후 52행도 원문과 최신 조회에 보관한다.

출발조교 정규 조회는 `starting_training_website_rows_latest`, 분석용 조회는 `starting_training_website_rows_analysis_2026`이다. 분석 뷰의 `current_horse_name`은 최신 API42 마명이며 `current_horse_age_2026`은 2026년 고정 기준 나이다. 원문 이름은 `horse_name_raw`, 조교장소는 `location_raw`로 보존한다. `stable_horse_number_raw`는 화면 조번이며 조교사 ID가 아니다.

2024-01-17은 API와 홈페이지의 총 139행이 같아도 말별 48개 ID의 행 수가 다르다. API 과다 24두·27행과 홈페이지 전용 24두·27행이 상쇄된다. 별마로·서부검객·아연로의 API 4행은 홈페이지 400M·800M 두 행을 기준으로 저장하고, 그날 전체를 홈페이지 ID 기준으로 적재한다. API 원문은 삭제하거나 대표행으로 덮어쓰지 않는다. 홈페이지 행과 API item의 일대일 사건 대응도 추정하지 않는다.

홈페이지의 각 원문 행은 `artifact ID + source_row_no`로 보존하고, 같은 내용이나 같은 말·날짜를 이유로 합치지 않는다. 날짜별 최신 성공 조회를 선택하고 실패·빈 응답으로 이전 자료를 대체하지 않는다. 홈페이지 행 수를 실제 시행 횟수로 단정하지 않으며 당시 공개시점이 미확정인 상태도 유지한다. 조교 원행을 경주 출전행에 직접 다대다 연결하거나 기존 모델에 자동 반영하지 않는다.

## API18 기준 일별조교 적재 완료

대상 DB는 `data/jeju_native_core.sqlite3`다. API18 제주 경주장 전체 원문 1,444,319행 중 API42 제주마로 확인된 보유 ID 4,545두의 **908,316행**을 적재했다. 원문 337페이지(263개 자료 페이지·74개 정상 빈 응답)는 `daily_training_api_artifacts`, 제주마 연결 원행은 `daily_training_api_rows`에 보관한다. 검증 명단 밖 536,003행의 원문은 페이지 아카이브로 유지하고 페이지별 제외 수를 기록하며, 그중 형식 오류 ID `018570 ` 3행은 확인 전 연결하지 않는다. 명단 밖의 말을 전부 한라마로 확정한 것은 아니다.

정규 분석 조회는 `daily_training_api_rows_analysis_2026`이다. 현재 경주 상한 2026-09-19까지 **907,389행**을 제공하며 이후 927행도 원문 테이블에 보존한다. 표시명 `current_horse_name`은 말 ID에 연결된 최신 API42 이름, 나이 `current_horse_age_2026`은 2026 − 최신 출생연도다. 당시 조교 원문 마명은 `hrName_raw`와 뷰의 `horse_name_raw`로 유지한다. 보유 4,617두 중 기록이 없는 72두는 0회로 채우지 않는다.

제주마 행 **890,288행**의 시작·종료 시각은 유효한 같은 날짜이고 차이가 양수 원문 `trTerm`과 일치한다. `start_time_local`·`end_time_local`, `duration_seconds` 및 `duration_minutes=duration_seconds/60.0`으로 조회한다. 시각은 제주 현지시각으로 보관하고 한국 시간(Asia/Seoul)으로 해석하며 UTC로 변환하지 않는다. 원문에는 별도 시간대 메타데이터가 없다. 시간 미제공 18,028행은 원문 `trTerm=0`을 보존하고 정규 기간을 NULL, `duration_status='raw_zero_unavailable'`로 둔다. 이 0은 실제 0초 훈련이 아니다. `run1_count`·`run2_count`도 NULL과 `all_zero_unavailable` 상태이며 실횟수 0으로 사용하지 않는다.

원문 15개 API 필드는 각각 `<원래 API 필드명>_raw` TEXT로 보존하고 `raw_row_json`에서 원래 JSON 형식과 키의 부재 여부를 추적한다. `trName_raw`는 조교사명, `prNo_raw`는 기승자 사번(선행 0 유지), `partNo_raw`는 소속조 안의 말 번호다. 시각 차이로 원문 기간을 덮어쓰지 않는다. 일별조교에 수영조교나 출발조교 시행시각을 생성하지 않으며 화면의 `경주일` 행도 실제 조교행으로 만들지 않는다.

모든 저장 원문·시간 상태·ID와 최신 이름·2026년 나이를 독립 검증했다. 재적재는 추가 artifact 0개·행 0개와 DB 해시 동일로 통과했고, 기존 경주·심사·프로필·출발조교 테이블과 스키마 정의를 유지했다. 전체 기간 홈페이지 재수집은 수행하지 않았으며 기존 9개 날짜 화면 대조와 API18 원문이 근거다. 구현과 적용 원장, 백업·무결성 검증은 [일별조교 보고서](</Users/kimyongjin/Desktop/horse_racing/jeju/research/20261001_daily_training_api_load/README.md>)를 따른다. 적재 완료를 과거 공개시각 확인이나 모델 피처 채택으로 해석하지 않는다.

## 원천과 실제 기록 범위

| 항목 | 일별조교 | 출발조교 |
|---|---|---|
| 공식 API | API18_1 dailyTraining_1 | API22_1 startingTranning_1 |
| 요청 경로 | `/API18_1/dailyTraining_1` | `/API22_1/startingTranning_1` |
| 보유 수집 방식 | `meet=2`, 2002-01부터 2026-09까지 297개월 | `meet=2`, 2002년부터 2026년까지 25개 연도 |
| 유효 기간 필터 | `tr_month=YYYYMM`, 필요시 `tr_date=YYYYMMDD` | `tr_year=YYYY` |
| 실제 첫 관측일 | 2007-10-01 | 2007-10-17 |
| 실제 마지막 관측일 | 2026-09-28 | 2026-09-27 |
| 원문 행 수 | 1,444,319 | 295,471 |
| 원문 페이지 수 | 337 | 311 |
| API42에서 제주마로 확인된 보유 ID 연결 행 | 908,316 | 190,842 |
| 연결 말 수 | 4,545 | 4,476 |
| 현재 보유 상한 2026-09-19 뒤 원문 행 | 1,039 | 80 |

이 표는 중복 제거 전, 상한 날짜로 자르기 전의 집계다. `meet=2`는 제주 경주장 필터이며 제주마 품종 필터가 아니다. 원문에는 보유 제주마 모집단 외의 말도 포함된다. 최종 입력은 API42 품종이 `제주마`로 확인된 공식 말 ID와 연결하고, 목적에 맞는 날짜 범위를 적용한 후 별도 집계해야 한다.

보유 대상 4,617두의 API42 마종 수집과 확인은 완료됐다. 조교 연결 대상은 경주 연결 4,006두와 주행심사 보조 611두다. 이 명단 밖의 조교 원문 말은 이번 작업으로 마종을 확인한 것이 아니며, 이름 유사도나 ID 접두로 제주마를 추정하지 않는다.

조회 기간과 실제 관측 기간을 구분한다. 일별조교 2002-01부터 2007-09까지 69개월은 정상 0행 응답이며, 출발조교 2002년부터 2006년까지는 정상 0행 응답이다. 이는 보유 API 응답에서 자료를 얻지 못했다는 뜻이며 해당 말이 조교하지 않았다는 근거가 아니다. 공식 최초 제공일도 이 관측 시작일로 단정하지 않는다.

## 원문 필드와 입력 제한

### 시간 필드와 다른 API의 관계

공식 출력 명세를 확인한 결과는 다음과 같다.

| API | 제주 조회 | 시간 필드 |
|---|---|---|
| [한국마사회 일별훈련 상세정보 API18](https://www.data.go.kr/data/15058782/openapi.do) | `meet=2` | `stTime` 조교시작시간, `spTime` 조교종료시간은 `YYYYMMDDHH24MISS`; `trTerm`은 초 |
| [한국마사회 출발훈련 정보 API22](https://www.data.go.kr/data/15059043/openapi.do) | `meet=2` | 훈련일 `trDate`만 있고 시행·등록·수정 시각 필드는 없음 |
| [한국마사회 홈페이지자료실 경마기록실 제주출발조교현황 API330](https://www.data.go.kr/data/15140266/openapi.do) | 제주 전용 | 훈련일 `trngDt`만 있고 시행·등록·수정 시각 필드는 없음 |

입장·퇴장 표시와 대응하는 일별조교 시각은 보유 API18 원문에 이미 있다. 다른 API에서 새로 구해야 하는 공백으로 취급하지 않는다. 출발조교의 각 시행 시각을 API18 시작·종료 시각으로 대체하지 않는다. 수집 원장의 조회 시각은 우리 수집기가 요청·응답을 관측한 시간이며 마사회의 사건 등록·게시 시각이 아니다.

API330은 홈페이지 자료실의 제주 출발조교를 제공하는 별도 API이며, 명세의 item은 `trngDt`, `beloNo`, `beloTrngNo`, `hrnm`, `ridrNm`, `remkTxt`다. 말 ID와 시행 시각이 없어 기존 API22에 없는 시간·ID를 보충하지 않는다. 현재 API330은 명세만 확인했으며 실제 원문을 수집하거나 DB에 적재하지 않았다. 두 출처 사이의 내용 일치와 각 출처 안의 반복행을 구분한다. 향후 API330은 별도 대조 출처로 보관하고, API22와 단순 합산해 조교 건수를 늘리거나 마명만으로 사건을 자동 연결하지 않는다.

### 일별조교

실제 원문에서 확인한 필드는 `hrNo`, `hrName`, `meet`, `trDate`, `trTerm`, `stTime`, `spTime`, `run1Cnt`, `run2Cnt`, `prGubun`, `prNo`, `part`, `partNo`, `trName`, `chulGubun`이다. 모든 시기의 모든 행에 모든 필드가 있는 것은 아니다. 전체 항목별 존재·공백·0값 집계는 [감사 요약](</Users/kimyongjin/Desktop/horse_racing/jeju/research/20261001_training_audit/audit_summary.json>)의 `field_presence_counts`와 `field_states`를 따른다.

- `run1Cnt`, `run2Cnt`는 **1,444,319행 전체에서 모두 0**이다. 실제 횟수가 0이라는 피처로 사용하지 않는다. 이 보유 제주 원문에서는 횟수 정보를 제공하지 않는 상태로 표시하고 모델의 횟수·강도·총주행량 입력에서 제외한다.
- `trTerm`은 0이 아닌 값 1,364,791행, 0값 79,528행이다. 처음으로 0이 아닌 값이 나타나는 날짜는 2008-11-10이며, 마지막 0값은 2009-04-24다. 초기 조교시간 0값을 휴식, 미조교, 0초 훈련으로 해석하지 않는다. 시간의 미제공 또는 특수값으로 보존하고, 별도의 값 유효성 상태를 둔다. 원인 자체는 미확정이다.
- `trTerm`의 단위는 공식 [일별훈련 API 설명](https://www.data.go.kr/data/15058782/openapi.do)에서 초로 확인했다. 화면의 백두명성 9개 날짜는 `trTerm / 60`과 분 표시가 일치하며, `stTime`·`spTime`의 날짜와 시각도 일치한다. 원문 단위는 초로 보존하고 분으로 보여줄 때만 명시적으로 환산한다. 이번 적재 전수 감사에서 전체 원문의 양수 1,364,791행은 유효한 같은 날짜의 시작·종료 시각과 일치했고, 제주마 연결행 중 890,288행이 이에 해당했다. 제주마 시간 미제공 18,028행은 원문과 결측 상태를 보존하며, 시각 차이로 원문 시간값을 대체하지 않는다.
- `prGubun`·`prNo`는 기승자 구분·사번, `trName`은 조교사명으로 구분한다. 백두명성 원문 `prNo='003086'`은 보유 경주결과에서 이동준에 연결되며 화면의 기승자명과 일치한다. 같은 행의 `trName='문성호'`를 기승자로 표시하면 안 된다. `part`·`partNo`는 소속조·조번으로 보존한다. 현재 API42 관계자로 과거 조교의 관계자를 대체하지 않고, 다른 코드의 의미도 임의 추정하지 않는다.
- `chulGubun`은 해당 API 응답의 출전예정 구분이다. 재조회 결과가 당시 공개 정보와 같다는 근거가 확보되기 전에는 역사적 예측 입력으로 사용하지 않는다.

경주 연결 말 중 일별조교 원문이 없는 57두는 모두 마지막 보유 경주가 2007-10-01 이전이다. 이것은 실제 기록 범위 대조 결과이며 결측을 0으로 채울 근거가 아니다. 명단과 경주 기간은 [원장](</Users/kimyongjin/Desktop/horse_racing/jeju/research/20261001_training_audit/missing_daily_race_horses.jsonl>)에 보존한다.

### 출발조교

실제 원문 필드는 `hrNo`, `hrName`, `meet`, `trDate`, `part`, `partNo`, `prName`, `remark`다. `remark`에는 `양호`, `출발자세불량`, `진입불량` 등의 값과 `-`가 있다.

- 출발조교와 경주·주행심사는 별도 자료 종류로 유지한다. 출발조교의 평가를 경주 착순, 심사 합격 또는 일별조교 강도로 바꾸지 않는다.
- `remark='-'`와 값 부재를 `양호`로 바꾸지 않는다. 약어를 임의로 확장하거나 심각도 점수로 변환하지 않는다.
- `prName`은 원문 기승자명으로 보존한다. 이름만으로 기수·조교사 ID를 연결하지 않는다.
- 조·순번 등 필드가 다른 같은 말·같은 날 기록은 원문에서 서로 다른 레코드다. 실제 서로 다른 훈련인지, 정정·재노출인지 이 API만으로 확정하지 않는다.

## 중복 판정과 보존

**완전 동일 판정은 하나의 API item에 있는 모든 키, JSON 값의 형식과 값을 비교한다.** JSON 객체의 키 순서는 무시한다. 이름 공백 제거, 숫자 형식 변환, 비고 제거, 말 ID와 날짜만의 비교는 완전 동일 판정에 사용하지 않는다. 원문 바이트 해시와 레코드 내용 해시를 구분한다.

일별조교에는 같은 원문 `hrNo`와 `trDate` 조합의 반복이 없고, 따라서 완전 동일한 반복 행도 없다. 출발조교에서는 완전 동일한 추가 반복 4,205행이 확인됐다. 같은 말과 같은 날의 추가 반복은 7,297행으로, 4,205행과 같은 수치가 아니다. 내용이 다른 레코드를 가진 말과 날짜 조합은 3,092개다.

현재 원문은 모두 유지한다. 향후 정규화 시 적용할 기준은 다음과 같다.

1. 내용이 완전히 같더라도 서로 다른 원문 item 위치는 각각 보존한다. 정규화에서 item 내용 해시를 유일키로 사용하지 않는다. 한 응답 페이지를 재적재하는 문제는 `원문 artifact ID + item 순번`으로 막고, 같은 페이지 안의 서로 다른 item이나 다른 페이지의 같은 내용은 자동으로 합치지 않는다. 특정 사건의 오류 중복임을 별도 확인하기 전 대표 한 행만 남기는 정제는 하지 않는다.
2. 동일 말·날짜지만 필드가 다른 기록은 유지하며, 정정 여부나 이벤트 식별자 확인 없이 하나로 합치지 않는다.
3. 출발조교의 이벤트 식별 근거가 검증되기 전에는 원문 행 수나 서로 다른 내용의 수를 실제 훈련 횟수로 입력하지 않는다.
4. 중복 해시에는 반드시 API 종류를 포함하거나 API 종류별로 별도 처리한다. 일별조교와 출발조교를 서로 중복 제거하지 않는다.
5. 이번 감사의 중복 원장은 위치를 확인하기 위한 산출물이며 모델 입력이나 중복 제거 완료 원장이 아니다.

일별조교 화면의 2026-09-18 `경주일` 행은 보유 API18에 해당 조교행이 없다. 화면 표시를 실제 조교행 또는 0분 조교로 생성하지 않는다. API18 응답에는 별도 수영조교 필드도 없으므로 화면의 `-`를 API 기반 수영조교 0회·미시행으로 채우지 않는다.

그룹·연도·페이지별 결과와 대표 사례는 [조교 원문 감사 보고서](</Users/kimyongjin/Desktop/horse_racing/jeju/research/20261001_training_audit/README.md>), 모든 동일 그룹과 출현 위치는 [완전 동일 중복 원장](</Users/kimyongjin/Desktop/horse_racing/jeju/research/20261001_training_audit/starting_exact_duplicate_groups.jsonl>), 내용이 다른 말·날짜 그룹은 [별도 원장](</Users/kimyongjin/Desktop/horse_racing/jeju/research/20261001_training_audit/starting_same_horse_day_different_records.jsonl>)을 따른다.

## 말 ID와 날짜 연결

- 공식 말 ID를 문자열로 연결하고 원문 `hrNo`도 별도로 보존한다. 마명은 연결키가 아니다. 분석 표시명은 최신 API42 이름을 사용하되 조교 원문 이름은 유지한다.
- 공백이 붙거나 형식이 맞지 않는 원문 ID는 별도 목록에 보존하고 확인 전 연결에서 제외한다. 임의로 공백 제거, 선행 0 제거 또는 숫자 변환한 ID를 공식 ID로 간주하지 않는다. [ID 형식 점검 원장](</Users/kimyongjin/Desktop/horse_racing/jeju/research/20261001_training_audit/invalid_raw_training_ids.jsonl>)을 따른다.
- 조교행이 없는 말의 경주행을 제거하지 않는다. 경주 모집단을 기준으로 왼쪽 연결하고 관측 여부와 자료 가용 범위를 함께 남긴다.
- 조교 내역을 경주행에 그대로 다대다 연결해 출전행을 증식시키지 않는다. 모델 입력 전에는 경주별 예측시점을 기준으로 말별 집계한 후 출전키당 한 행으로 연결하고, 전후 출전행 수와 키 중복을 검증한다.
- 현재 경주 수집 상한은 2026-09-19다. 이후 조교 원문은 보관하되 해당 상한의 경주 데이터에 포함하지 않는다. 향후 상한 변경은 별도 버전으로 명시한다.
- 실제 예측시점보다 뒤의 조교는 제외한다. `trDate`는 사건 날짜이며 공개 시각을 증명하지 않는다. 당일 기록은 예측시점 이전에 공개됐다는 근거 없이는 사용하지 않고, 날짜뿐인 자료는 최소한 `trDate < race_date` 조건을 적용하며 공개 시점 미확정 상태도 기록한다. 이 날짜 조건만으로 과거 가용성이 입증됐다고 하지 않는다.

## 새 모델 입력 전 확인 항목

입력 버전에는 원문 해시·필터·대상 ID 명단·날짜 상한·공개시점 정책·필드 단위·0값과 공백 처리·중복 그룹과 대표행 출처·집계 창·연결 전후 건수를 기록한다. 확인되지 않은 시간 단위, 횟수 0값, 이벤트 식별자, 공개시점은 별도 상태로 남긴다. 해당 검증이 필요한 피처는 검증 완료 전 입력에서 제외한다.

이 문서는 새 조교 피처를 채택하거나 기존 모델의 입력을 변경한 기록이 아니다. 기존 모델 재현은 저장된 원래 입력 계약을 따른다. 새 조교 입력은 이 문서와 감사 결과에 따른 별도 버전으로 검증한 뒤 사용한다.

이전 원문 감사 JSON의 DB 미적재 표시는 당시 스냅샷이다. 출발조교 홈페이지와 일별조교 API18 자료는 각각 전용 테이블에 저장하므로 `api_records.record_type`만으로 현재 적재 상태를 판단하지 않는다. 최신 상태는 홈페이지 기준 출발조교 및 API18 일별조교 적재 보고서와 각 적용 원장, 전용 테이블·뷰를 조회한다.
