# 제주 일별조교 기승자 종류 감사

2026-10-15 기준 `daily_training_api_rows` 908,316행의 기승자 종류 집계와 보유 공식 홈페이지 32페이지의 독립 검토다. 산출물은 이 `audit/` 폴더에만 작성했다. 조회는 SQLite `mode=ro`와 `PRAGMA query_only=ON`으로 실행했으며 DB 본체와 WAL의 SHA-256은 조회 전후 같았다. 네트워크 요청은 하지 않았다.

## 파일

- `rider_type_audit.json`: 재현 집계, 적용 범위, 미분류 이유, 홈페이지 대조 결과.
- `audit_training_rider_types.py`: 오프라인 재현 코드. 기존 공식 HTML만 파싱한다.

재현:

```sh
python3 jeju/research/20261015_training_rider_types/audit/audit_training_rider_types.py \
  --output-name rider_type_audit_recheck.json
```

코드는 지정한 파일이 이미 있으면 중단한다. 재실행할 때는 아직 없는 새 JSON 파일명을 지정한다.

## 판정 기준

API18 `prGubun_raw`의 명시된 다섯 값은 원문 그대로 종류로 사용했다. `-`는 현재 DB에 이미 저장된 동일 조교행 홈페이지 관측만으로 보완했다. 다른 날짜의 직원 이름·사번 명부·현재 관계자를 과거 `-`의 종류 증거로 소급 적용하지 않았다.

보유 KRA HTML 32페이지의 공식 범례는 모두 `[기승자범례] 이름:기수명, 조:조교사, 관:주로조교, 생:교육생, 이름(트):기수트랙라이더`다. 따라서 이름만 표시된 행은 범례가 명시한 기수로, `관`은 주로조교로 분류한다. `관`을 관리사 등 직원 직책과 동일시하지 않는다. `조`, `생`, `(트)`는 각각 조교사, 교육생, 기수트랙라이더를 뜻한다. 웹페이지의 `외`는 의미가 확정되지 않아 미분류다.

같은 사건의 명시 API 종류와 홈페이지 종류가 충돌하면 해당 행은 `미분류`로 두고 `api_website_type_conflict` 상태를 기록한다. API 종류가 `-`이고 동일 사건 홈페이지 종류 근거가 없거나 `외`만 있으면 미분류다. 32페이지 파싱에서 추가로 발견한 행은 감사에만 썼으며 웹 관측 테이블이나 전체 종류 집계에 추가하지 않았다.

종류 후보는 `기수`, `조교사`, `조교보`, `조교승인`, `기수후보생`, `주로조교`, `교육생`, `기수트랙라이더`, `미분류`다. 이름 노출 정책은 **최종 종류가 `기수`일 때만 사람 이름을 제공**하는 것이다. 다른 확정 종류는 종류만 제공하고, 미분류 행은 추정 이름이나 추정 종류를 제공하지 않는다. 원문/API·홈페이지 근거 테이블은 감사를 위해 보존한다.

## 32페이지 독립 검토

감사 스크립트는 기존 수집기와 별도로 표준 라이브러리 `HTMLParser`로 32개 원문 HTML을 파싱하고, 각 파일의 SHA-256 및 페이지 말 ID를 수집 manifest와 대조했다. 공식 범례는 32페이지 모두 동일했다.

- 각 페이지의 2026-04-15~2026-09-28 훈련행을 말 ID·날짜·시작분·종료분·API 초 단위 기간으로 DB 원행과 대조했다.
- 유일한 동일 사건 일치 1,691건 중 API `기수`는 311건이었다. 이 311건은 모두 홈페이지에서 범례에 맞는 표식 없는 기수 이름으로 표시됐다.
- API `기수` 후보 317건 가운데 나머지 6건은 유일한 동일 사건 행으로 확인되지 않아 종류 충돌이나 누락으로 단정하지 않았다.
- 유일 일치 사건에서 명시 API 종류와 홈페이지 종류가 충돌한 행은 0건이다. API `기수`에 대한 `(트)` 표기도 발견되지 않았다.
- 홈페이지 행 중 API와 정확히 일치하지 않은 170행은 이 감사의 종류 집계에 추가하지 않았다.

이 검토는 최근 6개월 홈페이지 자료만 다룬다. 과거 전체 `-` 기록의 종류를 증명하지 않으며 사건 날짜가 최초 공개 시각이라는 뜻도 아니다.

## 재현 및 통합 참고

JSON에는 네 집계 범위의 종류 수와 상태별 수, 홈페이지 관측 표식별 수, 32페이지 해시, 독립 정확일치 및 충돌 검토가 들어 있다. 실행 시 코드가 원문 종류 값이 예상한 6개(`-`와 명시 API 5종)인지 확인하고, 행 수가 908,316 및 분석 뷰 상한이 907,389인지 독립 집계한다. 결과 파일을 쓰기 전에 DB·WAL 지문이 바뀌었으면 중단한다. 기존 감사 산출물은 덮어쓰지 않는다.

기존 `daily_training_riders` 뷰의 `rider_name`은 사번 참조 이름을 여러 API 종류에서 제공한다. 새 종류 조회에서는 위 이름 정책을 적용해 종류가 기수인 경우에만 이름을 내보내고, 나머지는 종류로 표현해야 한다. 이 감사는 스키마·DB·기존 조회를 수정하지 않았다.
