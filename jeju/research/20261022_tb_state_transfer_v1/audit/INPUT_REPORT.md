## Timing and source limitations

The snapshot has no `result_status` field; normal complete ranks were therefore established from `started`, `valid_time`, positive finite finish time, and the exact 1..N roster. No missing/failed runner was assigned a last-place result. The source provides event dates but no publication timestamps, and the final race roster is retrospective. Thus `T−2` is an event-date cutoff, not proof that all information was publicly available at that time. The complete-normal-history filter also conditions the state on a selected past-race cohort and does not model non-finish risk.

The prior per-race source-row digest serializer had not been recorded, so those old row-level hash values are not described as verified. The ledger retains the same race keys, dates, distances, counts, DB-roster flags, eligibility flags, and reason codes; only its `source_rows_sha256` values were regenerated using the documented canonical JSONL scheme in `SOURCE_AUDIT.md`. The previous CSV was compared cell-for-cell to the temporary zstd Parquet version before removal. The current ledger is Parquet, SHA256 `0aeef4ba4e5c072d19993d4286023c68ee06fabaaf6b29fa651ffad95ee1b3ef` (354,756 B). The old CSV SHA and serializer correction are retained in `source_manifest.json`. The DB file itself was not copied or hashed by this worker; the supervisor owns the independent DB reference and roster/hash review.
