# 사전 구매 QPL 기대값 감사 계획

## 고정된 입력과 시점

- 예측 입력은 `jeju/research/20261012_pair_jockey_id_v1/outputs/evaluation_pair_predictions.parquet`의 SHA-256 `0d41ee66149edfae79f2b422ba588c422686a328aad0122071183ee9db6768d6`으로 고정한다.
- `selected_jockey_id_candidate == 1`인 선택 쌍만 쓴다. 확률은 선택한 두 말이 함께 Top3에 들 확률인 `jockey_id_candidate_calibrated_probability`이며, QPL 사건과 뜻이 맞는다. 저장된 확률은 QNL의 정확 Top2 확률이 아니므로 QNL 기대값은 계산하지 않는다.
- 주 평가 cohort는 기존 QPL 비교와 같은 2025-01-01~2026-09-19 제주 1,142경주(2025년 654, 2026년 488)다. 전체 고정 예측 중 다른 연도·경주는 배당 원천 인벤토리에만 적고, 새 학습·재예측으로 보충하지 않는다.
- 구매 가능 시점은 해당 경주의 저장된 `scheduled_at_ms` 5분 전으로 고정한다. cutoff는 `scheduled_at_ms - 300000`이며 예정시각 누락 경주는 eligible로 추정하지 않는다.
- 스냅샷 선택은 사전 cutoff만 사용한다. `actual_start_at_ms`는 사전 quote 선택에 쓰지 않고, 가능한 경우 시점 오류를 사후 감사하는 용도로만 본다. 실제 시작 시각이 없으면 공식 결과 상태와 원천 수집 시각/endpoint 성격을 별도로 확인한다.
- 원문 API301 자료는 `odds_snapshots`만으로 판정하지 않고 일자·meet·경주·승식·선택 조합이 맞는 원응답까지 확인한다. 원문 요청·응답이 cutoff보다 앞선 정확한 QPL 행은 **사전 원천 후보**로 분류한다. 로컬 시계, 공개 표시·구매 가능성, 값의 의미가 별도 입증되지 않으면 확정 사전 시세로 단정하지 않는다. `observed_at_ms`를 시장 관측시각이라고 간주하지 않는다.
- 9999.9는 프로젝트의 가격 처리에서 제외되는 특이값으로 별도 표시한다. 공식 API 설명에서 이 숫자의 의미를 확정하지 못했으므로 placeholder나 구매불가라고 단정하지 않고, 의미가 확인될 때까지 EV 입력에서 제외한다.
- 적격 quote가 있을 경우에만 `EV = p_top3_pair × pre_purchase_QPL_odds - 1`을 계산하고 `EV >= 0, 0.05, 0.10, 0.20` 기준을 고정 적용한다. 각 기준은 경주당 10,000원 등액으로 계산하며, 정산 환급은 공식 최종배당으로 평가한다. 하나의 사전 EV quote와 사후 정산 환급은 서로 다른 열·개념으로 둔다.

## 보고 제한

- 사후 최종배당을 사전 quote처럼 사용하거나 그 값으로 EV를 계산하는 oracle 표를 만들지 않는다. 원문에서 cutoff 전에 요청·수신된 값은 별도 evidence로 보존하되, 확인된 public/bettable quote와 분리한다.
- 선택된 말쌍의 사전 quote가 없으면 해당 경기의 값은 결측이며 0배당으로 채우지 않는다. 적격 경주가 0이면 EV 경계별 선별·환급·ROI·신뢰구간을 만들지 않고, coverage와 원천 한계를 보고한다.
- 저장 예측 파일의 공개시각이 확인되지 않으면 예측과 quote의 실제 동시 가용성을 증명하지 못한다고 표시한다.
- 기존 269일 단위 추출물이 있고 충분한 적격 경주가 있을 때만 재사용해 경기일 단위 불확실성을 요약한다. 표본이 작으면 기술통계만 낸다.

## 안전 범위

- 공유 SQLite는 `mode=ro`, `PRAGMA query_only=ON`으로 조회한다. DB 쓰기, 네트워크, live probe 실행, 모델 fit/재예측을 하지 않는다.
- 산출물은 이 연구 디렉터리에만 만든다. 기존 연구, 운영 모델·등록부 및 공유 DB를 바꾸지 않는다.
