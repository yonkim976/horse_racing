# 사전 구매 QPL 배당 시점 감사

## 결론

고정 예측 1,142경주의 현재 `odds_snapshots`에는 T-5분 전에 기록된 선택쌍 QPL 행이 없다. 하지만 이것만으로 과거 사전 배당이 전혀 없었다고 결론 내릴 수는 없다. 이 테이블은 정산 작업에서 같은 승식·조합의 배당과 `observed_at_ms`를 갱신할 수 있어, 날짜별 원응답도 별도로 검사했다.

모든 대상 날짜의 API301 원문 페이지 889개를 로컬 source registry와 대조해 SHA-256을 확인했다. 그 중 2026-09-05 네 경주에서 선택쌍과 정확히 일치하는 QPL 값이 고정 cutoff보다 먼저 요청되고 수신된 기록이 네 건 있다. 값은 두 건이 1.0, 두 건이 9999.9다. 따라서 **사전 원천 후보는 4건**이며 **검증된 공개·구매 가능 quote는 0건**이다. 요청·수신 시각은 로컬 수집기 시각이고, 독립적인 시계 검증이나 당시 화면의 공개·체결 가능성 증거가 없다.

두 1.0 값에만 `p × 표시배당 − 1` 조건부 proxy를 계산했다. 선택쌍 확률이 모두 1보다 작아 두 proxy는 음수이며 EV 0, 0.05, 0.10, 0.20 기준을 통과하지 않는다. 9999.9는 이 프로젝트에서 EV 계산에서 제외하는 특이값으로 표시했지만 공식 의미나 구매 가능 여부를 확인하지 못했으므로 placeholder·무효배당이라고 단정하지 않았다. 이 네 건은 하루의 네 경주뿐이고 후속 API301 응답에서 모두 값이 바뀌어, 수익·ROI·신뢰구간이나 대표성 있는 백테스트를 만들지 않았다.

## 고정 기준과 해석

- 예측은 `20261012_pair_jockey_id_v1/outputs/evaluation_pair_predictions.parquet`의 SHA-256 `0d41ee66149edfae79f2b422ba588c422686a328aad0122071183ee9db6768d6`로 고정했다. `selected_jockey_id_candidate == 1`과 저장된 `jockey_id_candidate_calibrated_probability`를 사용했다. 이 확률은 선택쌍 공동 Top3 사건(QPL)에 맞고 QNL 확률로 쓰지 않았다.
- cutoff는 저장된 `scheduled_at_ms - 300000`(예정 출발 5분 전)이다. 실제 출발 시각은 cutoff를 고르는 데 사용하지 않았다. 대상 1,142경주 모두 DB의 `actual_start_at_ms`가 비어 있다.
- 원문 후보에는 날짜·meet·경주번호·QPL 승식·선택쌍이 모두 맞고, 요청과 수신이 cutoff보다 앞서며, 원문 payload hash가 registry와 일치해야 했다.
- 공식 [API301 설명](https://www.data.go.kr/data/15058559/openapi.do)은 확정 배당률 통합 API로 설명한다. 원응답이 cutoff 전에 저장된 사실은 보존했지만, 그것만으로 해당 값이 당시 이용자에게 표시되었거나 살 수 있었음을 증명하지 않는다. pari-mutuel 배당은 이후 바뀔 수 있으므로 조건부 proxy는 최종 배당이 사전 표시와 같다는 가정 아래의 산술값일 뿐 확정 EV가 아니다.
- 저장 예측 파일의 경기별 공표 시각도 확인하지 못했다. quote와 예측이 실제로 동시에 이용 가능했다는 점은 검증되지 않았다.

## 원문 및 현재 DB의 시점 차이

공유 DB의 제주 QPL 전체에는 예정 T-5분보다 앞선 `observed_at_ms` 행 7개가 있었지만, 모두 2026-09-05 7R에 속했고 고정 예측 cohort에는 없다. 일곱 선택쌍 모두 취소된 말 7번을 포함한다. 해당 경주의 실제 출발 시각도 DB에 없다. 예외 목록에는 배당 값은 복사하지 않았다.

저장 코드 `src/horse_racing/services/race_day.py`의 `_upsert_final_odds`는 기존 조합의 `odds`와 `observed_at_ms`를 갱신하며, `scripts/backfill_dividends_verified.py`도 기존 행을 조정한다. 따라서 현재 테이블의 시간은 각 가격의 최초 관측시각을 보장하지 않는다. 원응답 페이지가 필요한 이유다.

네 원문 후보 각각에 대해 cutoff 이후 동일 선택쌍 응답이 두 건씩 있었고, 이후 값은 사전 후보와 달랐다. CSV에는 이후 값 자체를 넣지 않고 개수·변경 여부만 기록했다. 별도 2026-10-09 API301 probe는 모델 cohort 밖이며 prestart-positive 행이 없어, 9월 5일 원응답 후보를 부정하거나 API301의 일반 동작을 대표하지 않는다.

## 산출물

- `PLAN.md`: cutoff·EV 기준·범위와 누출 방지 계획
- `analyze.py`: 읽기 전용 SQLite 및 원문 page 감사 재현 코드
- `REPORT.json`: 수량 집계, 판정, 제한사항
- `SOURCE_HASHES.json`: 고정 예측·추출·원문 manifest 및 source DB hash
- `SOURCE_PAGE_INDEX.json`, `api301_day_run_index.csv`: 민감한 URL·전체 요청 파라미터 없이 남긴 원문 provenance
- `selected_pair_time_audit.csv`: 고정 cohort 1,142경주의 시각·coverage 집계
- `RAW_PRESTART_API301_CANDIDATES.csv`: 원문에서 확인한 네 사전 후보와 조건부 proxy, 이후 변경 여부
- `selected_pair_required_odds.csv`: 저장 확률만으로 계산한 EV 경계별 필요 표시배당. 실제 배당·EV·환급·수익이 아닌 이론값이며 quote 열은 비워 두었다.

재현은 저장소 루트에서 `.venv/bin/python -B jeju/research/20261013_prepurchase_ev_audit_v1/analyze.py`를 실행한다. 코드는 SQLite를 `mode=ro`와 `query_only=ON`으로 열며 네트워크, DB 쓰기, live probe, 모델 fit·재예측을 하지 않는다.

## 다음 비교에 필요한 조건

현재 말 평가와 선택쌍은 유지하고, 사전에 저장된 확률과 복연 표시배당을 같은 시각으로 연결하는 선별 연구가 다음 단계다. 저장 시각·경주·승식·마번·취소 여부·원본 해시를 함께 보존하고, 오래된 배당을 그대로 최신 시세로 간주하지 않도록 관측 경과시간도 기록해야 한다. 이번 네 후보는 예정 출발 약 27~177분 전의 값이어서 T-5분의 최신 배당으로 확인된 것도 아니다.

복연의 손익분기 표시배당은 `1/p`, 표시배당 기준 +10% 조건부 proxy 경계는 `1.10/p`다. 예를 들어 두 말 동시 Top3 확률이 40%라면 각각 2.50배·2.75배다. 이는 연구용 산술 경계이며 채택된 구매 규칙이나 수익 예측이 아니다. 실제 기대수익은 적중 시 최종 환급배당의 조건부 기대값에 달려 있고, 사전 표시배당과 최종 배당은 달라질 수 있다.

충분한 시점 자료가 생기면 같은 고정 선택쌍에 대해 전 경주 구매·확률만 선별·확률과 사전배당을 함께 선별하는 방식을 비교한다. 선별에는 사전 정보만 쓰고 확정배당은 사후 환급 계산에만 쓴다. 기준을 고르는 기간과 새 평가 기간을 분리하고 경주 수·적중률·ROI·날짜 단위 불확실성을 함께 확인한다. 복승은 별도의 두 말 정확 Top2 확률이 먼저 필요하다. 이번 작업에서는 수집기 실행·자동화·모델 변경을 하지 않았다.
