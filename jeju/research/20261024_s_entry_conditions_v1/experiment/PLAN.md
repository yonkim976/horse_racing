# S 출전조건 3변수 단일 비교

## 범위와 상태

비교는 봉인된 `20261022_tb_state_transfer_v1` S40 기준선과 그 40개 입력에 정확히 세 수치 입력을 더한 E43 후보 한 쌍이다. E43 입력은 현재 선언 부담중량(kg), 현재 선언 부담중량에서 동일 말의 T−2일 이전 마지막 유효 실제 부담중량을 뺀 값(kg), 출주번호 비율 `(declared_horse_number−1)/(max_declared_horse_number−1)`이다. 출주번호 비율은 확인된 선언번호 명단의 정규화 위치이며 물리적 게이트로 해석하지 않는다. 변수 외의 목표, 모델군, 전처리, 연도 분할, seed, 평가 규칙은 S40 계약과 같다.

현재 단계는 설계·코드·합성검사 준비다. 원천 감사에서 과거 일자부 공식 H3 출전선언을 확인했다. 선언 자료의 값·날짜가 있다는 사실과 그 자료가 과거 예측 시각 전에 실제 게시됐다는 사실은 구분한다. H3 원본에는 최초 공개시각/수정 이력이 없어 `publication_time_status`는 감사 계약의 정확한 값으로 보존하고 `pre_race_availability_verified=false`를 기록한다. 날짜 기반 가정은 별도 메타데이터로만 남긴다. 이 연구 결과는 공개시각 확인 전에는 실전 당시 사전 가용성이나 운영 적용 가능성을 주장하지 않는다. 기준선과 후보의 대상 키는 S40 그대로 두고 감사된 3변수 thin parquet만 읽는다. 원천 계약 및 실행 승인 전에는 후보 학습, 확률·성능 계산을 하지 않는다.

## 입력과 고정 비교

- 기준선 S40의 저장 모델·연도별 raw OOS 점수·PL 온도를 읽기 전용으로 재사용한다. 저장된 S 점수를 기존 연도별 온도로 다시 연결해 경주별 7승식 지표·주변확률·선택을 재계산하고, 기존 S의 동일 산출물과 행별 비교한다. 기준선을 다시 학습하거나 다시 보정하지 않는다. 위치와 SHA는 preflight에서 기존 S의 `fit_run_receipt.json` 및 manifest를 통해 핀한다.
- F1_STYLE6 30개와 TB 상태 10개는 기존 S40 입력 원본에서 동일한 키로 읽고 복사하지 않는다. 감사된 신규 세 입력은 출전키당 한 행으로 연결하고, 공식 말 ID·출전키의 1:1 여부 및 누락 원인을 검증한다. 감사 열·출처·공개시각·계보는 검사와 보고에만 쓰며 모델 입력에 넣지 않는다. `event_number`는 H3 경주키 대조용이고, `horse_number`는 S40의 결과 기반 target key다. 출주번호 피처 분자는 H3 `declared_horse_number`, 분모는 S40 target roster와 같은 명단임이 원문으로 확인된 최대 선언번호 `max_declared_horse_number`다. H3에서 개별 부담중량/행이 빠진 경우 확인 가능한 H3 행만으로 분모를 축소하지 않는다. 원 선언표 전체 최댓값은 별도 계보로 기록해 S40 target roster 최대와 대조한다.
- 현재값은 H3 공식 선언 부담중량이고, 이전값은 동일 공식 말 ID의 기록 경주일 `<= T−2` 중 가장 최근의 유효 실제 부담중량이다. 현재 선언값과 이전 실제값의 출처 역할을 섞지 않는다. 결측은 그대로 결측으로 두고 0kg으로 채우지 않는다. 취소 번호를 압축하지 않는다. 유효 행·동일 날짜 복수 이력은 원천 계약의 고정 규칙만 사용한다. 선언 번호 누락 또는 `max_declared_horse_number<=1`이면 비율을 결측으로 두되 S40 행은 유지한다.
- 연구 모집단은 기존 2017년 이후 정상 완주 5,206경주·52,155두, 평가 모집단은 2024년부터 2026-09-19까지 1,779경주·17,412두·269일이다. 결측 피처를 이유로 행이나 경주를 제거하지 않는다. 평가 명단은 기존 S와 동일한 결과 기반 정상완주 명단이며 당시 개시 명단이 확인되지 않은 한계를 유지한다.

## 학습·보정·확률

- 평가 연도 `Y=2024, 2025, 2026`마다 초기 학습은 2017..`Y−3`, 조기종료는 `Y−2`, 선택 반복 수로 2017..`Y−2` 재학습, 보정은 `Y−1`, 평가는 `Y`다. 같은 경주의 행은 항상 같은 구간에 둔다. 범주 어휘는 S40과 동일하게 초기 학습 구간에서만 정한다. 세 추가 입력은 수치형으로 유지하고 결측값도 LightGBM의 기존 결측 처리에 맡긴다.
- E43은 S와 같은 binary Top3 LightGBM, 출전마별 `1/field_n` 가중치, seed 20261008, learning rate 0.04, 15 leaves, `min_data_in_leaf=100`, `lambda_l2=5`, deterministic/column-wise, 4 threads, 최대 800회와 early stopping 25회를 사용한다. 후보는 세 vintage의 초기학습+재학습으로 총 6회 학습하고 최종 모델 3개를 저장한다. S40은 추가 fit·온도 최적화 0회다.
- 각 E43 vintage의 양의 scalar temperature는 같은 vintage의 직전 해 raw OOS 점수에서 full-field sequential Plackett–Luce ordered Top3 joint NLL을 최소화하여 `[0.35, 4]`에서 한 번 정한다. S40의 검증된 기존 연도별 온도를 그대로 쓴다. 최종 공동분포와 7승식 확률은 경주별 스트리밍으로 계산하고 전체 ordered triple 확률은 저장하지 않는다.

## 분모·평가와 결과 전 판정

두 arm은 기존 S40의 동일 경주·표·숫자 선택 규칙을 사용한다. WIN, QNL, EXA, QPL, TLA, TRI는 각 1,779경주다. 일반 규칙상 개시두수 5~7두는 PLC 정산 깊이가 불명확할 수 있다. 이 고정 평가 코호트에서는 저장된 S40 격리 원장의 실제 7두 경주 36개(개시두수 미확인)를 같은 키로 제외해 PLC 분모를 1,743으로 둔다. 7승식 정의와 법정 최소 출전두수는 기존 봉인 승식 계약을 그대로 쓴다. 코드는 S40 격리 경주 key set의 정확한 일치를 검사한다.

모든 승식의 경주별 NLL 및 Brier와 전체·연도별 평균을 보고한다. TRI NLL은 ordered Top3 공동사건 NLL이며 유일한 주 손실 비교다. 동일 2,000회·269일 paired date bootstrap을 재사용한다. 유일한 주 비교 E−S는 TRI NLL의 95% bootstrap 상한 `<0`, TRI Brier 차이 `<=0`, WIN NLL 차이 `<=0`, WIN Brier 차이 `<=0`를 모두 만족할 때 연구 후속 후보 기준을 통과한다. WIN 조건은 점추정 보호이며 통계적 비열등성 주장이 아니다. 전체 및 연도별 7승식 proper loss와 기존 고정 확률 구간 신뢰도표를 함께 보존한다.

보조 결과는 두 arm의 동일 최대확률 1장, WIN 축의 Top3 적중, 복승(QNL)·복연승(QPL) 상위 3장 적중 및 정확 합집합 확률·적중 수, 날짜 bootstrap 차이 구간이다. 보조 선택 결과로 주 gate나 분모를 바꾸지 않는다. 저장 원장은 기존 S schema의 `race_pool_metrics`, `selected_ticket_ledger`, `evaluation_runner_marginals`, `win_axis_ledger`, `pair_selection_diagnostics`, `reliability_bins`, `pool_summary`, `pool_year_summary`, `comparison_bootstrap_draws`와 호환되게 한다. 모델 metadata는 연도별 feature/parameters/category vocabulary/temperature를, 점수 ledger는 calibration/evaluation 역할을 기록한다. 시장 가격·비용 자료가 없으므로 수익성·시장 우위는 평가하지 않는다. 본 평가는 반복 사용된 개발기간이므로 독립 검증 또는 운영 승격을 주장하지 않는다.

## 코드·저장·승인

실험 코드는 이 `experiment/` 아래에만 쓴다. source audit와 code review가 통과하고 감독관이 코드·입력 해시를 결합한 1회 실행 승인을 남기기 전에는 `--run`이 거부되어야 한다. 합성검사는 실제 출전 자료·결과를 읽지 않고, 세 변수 수·kg 단위·T−2 이전 값 선택·결측 보존·번호 비율 산식·키 1:1 및 경로 격리를 검사한다. preflight는 파일 해시·키·분할·분모·환경·저장량을 확인하되 후보 모델 적합, 후보 Q 계산, 결과 metric 계산은 하지 않는다.

신규 연구 전체 저장 상한은 40,000,000 bytes다. 원천·DB·기준선·더러브렛 데이터/모델 사본을 만들지 않는다. audit/ 소유자가 만든 신규 세 변수의 얇은 입력과 계보, E 모델·calibration/evaluation raw 점수, E 지표·선택 원장·bootstrap·보고서만 보관한다. 모델·점수 산출은 `-B`로 실행해 기존 파일을 건드리는 바이트코드 캐시를 만들지 않는다. 완료 후 메인 감독관이 독립 검산하고 판정한다.
