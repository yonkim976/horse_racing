# 백두명성 조교 화면과 보유 API 대조

확인일: 2026-10-01. 대상 말: 백두명성, 공식 말 ID 3107491.

사용자가 제공한 일별조교 화면과 출발조교 화면을 보유 API18·API22 원문과 대조했다. 그림 파일은 변경 없이 보존했고 바이트 수·SHA-256·원래 경로를 [crosscheck.json](crosscheck.json)에 기록했다. API를 새로 호출하지 않았고 DB는 읽기 전용으로 조회했다. 화면은 사용자 제공 근거이며 해당 홈페이지를 별도로 재조회한 것은 아니다.

공식 [일별훈련 API 설명](https://www.data.go.kr/data/15058782/openapi.do)은 훈련시간을 초로 정의한다. 예를 들어 9월 16일 원문은 `stTime=20260916060900`, `spTime=20260916063000`, `trTerm=1260`이며 표시 시간은 `1260 / 60 = 21분`이다. 이 9개 행에서 시각 형식과 시간 관계가 확인된 것이며 전체 과거 기간의 모든 값 정합성을 새로 확정한 것은 아니다.

API에는 기승자명 대신 `prGubun=기수`, `prNo='003086'`이 있다. 같은 ID의 보유 경주결과 855행에서 이름은 이동준 하나로 일치해 화면 기승자명과 연결된다. `trName='문성호'`는 조교사명이다. 조교사명을 기승자명으로 사용하지 않는다.

화면의 9월 18일 `경주일` 행은 보유 API18의 백두명성 조교 기록에 없다. 이 표시를 조교행으로 만들거나 조교시간 0으로 입력하지 않는다. 별도 수영조교 필드도 이번 API18 응답에는 없으므로 화면의 `-`를 수영 미시행으로 확정하지 않는다. API의 `run1Cnt`·`run2Cnt`는 수영조교 항목이 아니다.

9월 16일 같은 내용의 두 행은 홈페이지 화면에도 두 행으로 존재한다. 사용자는 같은 날 두 번 시행한 것으로 볼 수 있다고 확인 방향을 제시했다. 따라서 내용이 같다는 이유로 오류 중복으로 판단하거나 두 행을 한 행으로 합치지 않는다. 8월 26일은 평가가 다른 두 행을 모두 보존한다. 날짜·내용 차이 또는 화면 순번만으로 실제 시행 순서·회차·재시행 사유를 확정하지 않는다.

## 처리 기준 변경

전체 전수 감사에서 확인한 동일 내용 4,205그룹은 관측 사실로 유지한다. 그 수치를 실제 오류 중복 4,205건이나 삭제 대상 4,205행으로 사용하지 않는다. 모든 말의 같은 내용 두 행을 실제 두 번 시행한 것으로 확정한 것도 아니다.

- 서로 다른 item 위치는 모두 보존하고 내용 해시를 정규화 행의 유일키로 사용하지 않는다.
- 같은 응답 페이지의 재적재 방지는 원문 artifact ID와 item 순번으로 처리한다.
- 다른 페이지의 같은 내용도 원문 위치가 다르면 유지한다. 특정 사건의 오류 중복임을 별도 확인하기 전에는 합치지 않는다.
- 날짜 상한 내 보유 제주마 출발조교는 내용 반복을 포함한 **190,790행**을 보존한다. 내용 유일화 가정의 187,491행은 입력 모집단 수로 사용하지 않는다.
- 원문 기록 건수와 실제 시행 횟수는 별도 변수로 구분한다. 실제 횟수 피처는 이벤트 정의와 확인 근거를 확보한 뒤 사용한다.

이 기준을 [조교 API 입력 문서](../../docs/JEJU_TRAINING_API_INPUT_CONTRACT_2026-10-01.md), [작업 지침](../../AGENTS.md), [전수 감사 보고서](../20261001_training_audit/README.md), [수집 계획](../../docs/JEJU_NATIVE_DB_COLLECTION_PLAN_2026-09-29.md)에 반영했다. 원문과 DB는 변경하지 않았다. 기존 `documentation_verification.json`은 이 화면 대조 전 문서 버전의 검증 기록이며, 현재 문서의 해시와 링크는 이 폴더의 `documentation_verification.json`을 따른다.
