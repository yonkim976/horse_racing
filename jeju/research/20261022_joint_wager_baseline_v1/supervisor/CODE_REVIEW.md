# 실행 전 감독 코드 검토

검토 대상: experiment/baseline.py. 검토자는 구현 모듈을 사용하지 않고 별도 source verifier와 확률 계산을 작성했다.

초안에서 아래 오류를 발견해 적합 승인 전에 수정 요청했다. 이 시점에 적합·평가 결과는 생성되지 않았다.

1. race_id는 `YYYY-MM-DD_2_R` 형식인데 정수로 변환하고 있었다. 모든 원장에 원 문자열을 보존해야 한다.
2. calibration score 제공자의 fold는 모든 라벨 연도 c에서 c+1인데, 2024/2025만 c로 검사하는 조건 오류가 있었다.
3. 감사용 2024/2025 calibration 파일을 조회하면서 expected-count 사전에 해당 연도가 없었다. 감사와 실제 온도 보정(2019–2023)을 분리해야 한다.
4. 메타의 refit 날짜를 읽는 것 외에 실행 경로가 T−2 경계를 직접 검사하도록 보강해야 한다. 감독관 독립 원천 검증은 이미 통과했다.
5. 승인 파일이 계획·코드 외에 preflight·입력 manifest·공식 계약의 해시를 고정하도록 보강해야 한다.
6. 미확정 연승 36경주뿐 아니라 전체 평가경주의 발매 시작 두수 미관측, 하한 추론, 공식 발매/정산 전수 미감사 상태를 원장에 남겨야 한다.

확률 계산 구조는 전 출전집합의 순차 조건부 추출로 전체 ordered Top3를 구성하고, 사건별로 합산한다. 같은 말 중복 순열을 만들지 않으며 전체 순열은 저장하지 않는다. categorical와 다중당첨 binary 손실이 구분되고 Brier는 clip하지 않는다. 날짜 bootstrap은 고정 일정에서 날짜 전체 경주를 같은 횟수로 재표집한다. 이 수식·손실·불확실성 정의는 사전 설계와 일치한다.

수정 후 synthetic·source preflight와 최종 해시를 다시 검토해 별도 BASELINE_EXECUTION_APPROVAL.json에 승인 여부를 기록한다. 그 파일 전에는 fit/evaluate가 허용되지 않는다. 실행 후의 계산 일치는 RESULT_REVIEW.json과 독립 검산 코드로 확인한다.

최종 검토: 위 여섯 항목은 적합 전에 모두 수정되었다. 두 팔의 원점수 제공자·스키마·경계는 감독관의 별도 source verifier와 일치했다. 12,453행(1,779×7)의 전체 경주/승식 계약 원장에 opening count 미관측과 공식 상태 미감사를 표시했고, 연승 36행만 사건 범위 unknown으로 구분했다. 합성·구조 사전 검사 통과 및 코드/계획/입력 계약 SHA를 확인한 뒤 **단일 온도 적합 1회와 고정 평가 실행만 승인**했다. 실제 승인 해시는 BASELINE_EXECUTION_APPROVAL.json을 따른다.

실행 복구 기록: 최초 승인 시도는 온도 적합 후 첫 경주의 연승 선택 원장을 JSON으로 변환하다 NumPy 정수 직렬화 오류로 종료되었다. 전체 평가/성과 보고서가 만들어지기 전이며 결과 기반 변경은 없었다. 감독관은 티켓 번호를 Python int로 직렬화하는 최소 수정을 검토하고, 별도의 8두 합성 경주에서 7승식 결과·선택·주변확률 전체의 JSON 직렬화가 통과함을 확인했다. 최초 승인은 BASELINE_EXECUTION_APPROVAL_ATTEMPT1.json에 보존했다. 소실된 스칼라를 복구하기 위한 **동일 결정적 온도 적합의 두 번째 실행 및 성공 평가 1회**만 승인했다. 비교조건/목적함수/범위/분할/게이트는 변경하지 않았다. 따라서 실제 최적화 호출은 2회이며, 후보는 여전히 하나다.
