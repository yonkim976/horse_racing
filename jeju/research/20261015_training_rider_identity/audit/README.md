# 제주 일별조교 기승자 사번 대조 감사

기준 DB: `jeju/data/jeju_native_core.sqlite3`  
감사일: 2026-10-15

API18 `daily_training_api_rows`의 `prGubun_raw`·`prNo_raw`를 보유 경주결과와 주행심사의 공식 `jockey_id`·`jockey_name`, `trainer_id`·`trainer_name`에 **원문 문자열 그대로** 대조했다. `trName_raw`는 별도 담당 조교사명 필드로 유지했다. 출발조교 홈페이지의 같은 말·같은 날 `rider_raw`는 여러 관측 이름의 집합을 비교하는 보조자료로만 사용했다.

## 확인 결과

전체 908,316행 중 `prNo_raw`가 ID 문자열인 행은 816,151행이고, 나머지 92,165행은 원문 `-`다. NULL, 빈 문자열, 공백 문자열, `0`은 없었다. 선행 0을 보존했으며 공백 제거·숫자 변환·접두 추정은 하지 않았다.

경주결과의 유효 ID는 기수 73개·조교사 35개, 주행심사는 기수 76개·조교사 36개였다. 두 출처 합집합은 각각 76개와 36개이며 **두 역할 간 유효 ID 교집합은 0개**다. 경주결과와 주행심사 양쪽에 존재하는 ID는 기수 73개·조교사 35개다. 이 공통 ID는 출처 간 원문 이름 집합과 공백 제거 이름 집합이 모두 일치했다. 따라서 이 DB 범위에서는 `기수`는 `jockey_id`, `조교사`는 `trainer_id`와 범주별로 직접 대조할 수 있다.

역할을 자동 확정할 수 없는 220개 범주×ID 그룹은 `unresolved_employee_ids.csv`에 상세히 남겼다. 여기에는 `-` 구분의 공식 이름 후보 64개(기수 43·조교사 21, 역할 미상), `-` 구분에서 공식 ID를 못 찾은 93개, `조교승인` 41개, `조교보` 21개, 후보생 1개가 포함된다. 후보생은 후보 이름 근거이며, 나머지는 미연결 또는 역할 검토 대상이다.

ID별 공식 원문 이름, 이름 variant, 공백 정규화 진단은 별도 산출물에 보존했다. 공백 정규화는 충돌 확인에만 썼다. 기수와 조교사 모두 ID 하나에 복수 이름 0건, 공백 제거 후 복수 이름 0건, 다른 ID 사이의 동일 정규화 이름 0건이었다. API18 `조교사` 26개 ID 중 23개의 `trName_raw`에는 해당 ID의 공식 조교사명과 일치하는 원문 값이 있었다. 이 검사는 담당 조교사 필드만 점검하며 기승자 ID-이름 연결에 쓰지 않았다.

주행심사 `trainer_id='-'` 6행도 확인했다. 원문 `prNo_raw='-'`를 ID로 다루면 이런 센티널끼리 잘못 연결될 수 있으므로 `-`, `–`, `—`, `−`, `－`, 빈 값, 공백 값, `0`은 ID 비교에서 제외했다. 이 DB 스냅샷에는 API307 명부가 정규화 테이블이나 `api_records` 항목으로 저장되어 있지 않다. 최신 표시명은 별도의 공식 명부 근거로 갱신하더라도 이 감사의 원문 ID·역사 이름 근거를 보존해야 한다.

### 출발조교 홈페이지 보조 대조

`starting_training_website_rows_latest`의 190,842행을 말 ID·훈련일별로 묶었다. 같은 말·날짜에 여러 행이 있으면 전체 행 수와 모든 고유 `rider_raw` 원문값을 집합으로 비교했다.

| 범주 | 동일 말·날짜 홈페이지 행 있음 | 후보명이 유일한 사용 가능 이름 | 후보명이 다중 이름 집합에 포함 | 이름 불일치 | 사용 가능 이름 없음 | 홈페이지 행 없음 |
|---|---:|---:|---:|---:|---:|---:|
| `기수` | 74,232 | 63,797 | 267 | 10,140 | 28 | 241,367 |
| `조교사` | 24,213 | 19,217 | 595 | 4,392 | 9 | 87,435 |

`기수후보생`의 1행은 같은 말·날짜 홈페이지 기록이 없었다. 98,445개의 보조 비교 상세 행을 작성했으며 공백 제거만으로 새로 일치한 사례는 없었다. 같은 말·날짜 홈페이지 그룹 중 5,835개에는 여러 행, 2,351개에는 서로 다른 원문 이름이 있었다. 따라서 홈페이지 대조는 이름을 대체하거나 사번을 역추정하는 근거가 아니다.

## 안전한 연결 규칙

1. 원문 `prGubun_raw='기수'`이고 원문 `prNo_raw`가 센티널이 아니며, 그 문자열이 공식 `jockey_id`와 정확히 일치하고, ID별 원문 이름과 공백 제거 이름이 각각 하나일 때 이름을 연결한다.
2. 원문 `prGubun_raw='조교사'`는 같은 조건으로 `prNo_raw == trainer_id`일 때 해당 기승자 인물을 trainer ID/name으로 연결한다. `trName_raw`를 대입하지 않는다.
3. `기수후보생`은 공식 기수 ID와 일치하더라도 원문 구분을 보존하고 별도 후보 근거로 남긴다.
4. `prGubun_raw='-'`는 역할 미상이다. 공식 ID 일치와 단일 이름은 이름 후보로만 기록하며 역할을 소급하거나 자동으로 확정하지 않는다.
5. `조교승인`, `조교보`는 이 DB에서 공식 기수/조교사 ID로 직접 확인되지 않은 ID이므로 이름 기반 추정이나 숫자 접두 변환을 하지 않는다.
6. `prNo_raw`가 NULL·빈 값·공백·대시 센티널·`0`이면 매핑하지 않는다. 홈페이지 이름에서 사번을 추정하지 않는다.

## 산출물

- `audit_training_rider_identity.py`: SQLite `mode=ro` 및 `PRAGMA query_only=ON`을 사용하는 재현 코드. 결과 파일이 이미 있으면 덮어쓰지 않는다.
- `results/summary.json`: DB 해시·읽기 전용 확인, 범주별 사번 상태, 공식 ID 대조, 이름 variant·충돌, 홈페이지 보조 대조 요약.
- `results/safe_rider_mappings.json`: 범주별 안전 매핑 78개(기수 52·조교사 26), 후보생 별도 후보, 미연결·역할 검토 목록.
- `results/category_summary.csv`: `prGubun_raw`별 원행 수·사번 상태·대조 상태.
- `results/employee_id_evidence.csv`: 303개 범주×원문 `prNo_raw` 그룹의 행 수, 날짜, 공식 ID/이름 후보, 매핑 상태, `trName_raw` 별도 점검.
- `results/unresolved_employee_ids.csv`: 자동 이름 연결 대상이 아닌 220개 ID 그룹과 검토 근거.
- `results/official_identity_crosswalk.csv`: 역할별 공식 ID, 출처별 원문 이름·행 수·기간, 이름 variant와 출처 간 비교.
- `results/normalized_name_collisions.csv`: 공백 제거 비교에서 발견된 이름 충돌. 현재 데이터 행은 없다.
- `results/website_crosscheck_by_employee.csv`: 기수·후보생·조교사 범주의 ID별 같은 말·날짜 홈페이지 이름 집합 비교 집계.
- `results/website_crosscheck_details.csv`: 홈페이지 관측이 있는 개별 API18 행과 홈페이지 원문 이름 집합.
- `results_superseded_before_trainer_role_correction_20261015/`: 최초 초안 산출물 보존본. `조교사` 범주를 안전 매핑에 포함하기 전 결과이므로 사용하지 않는다. 최신 결과는 `results/`다.
