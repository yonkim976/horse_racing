# 착순 단계별 temperature — 결과 전 감독관 설계 고정

2026-10-22. 새 후보의 적합이나 평가 확률 계산 전에 고정했다. 결과를 본 뒤 범위·후보·주 지표·게이트·분모를 변경하지 않는다. 2024–2026 자료의 선행 결과를 보고 세운 후속 가설이므로, 이번 설계 고정은 새 독립 평가기간을 만들지 않는다.

질문은 ‘F1_STYLE6의 같은 말 점수에 세 착순 단계마다 다른 보정 강도를 주면 공통 temperature의 단승/후속 착순 간 손실 교환을 줄일 수 있는가’다. 선행 저장 지표를 체인룰로 분해하면 공통 T의 조건부 단계 NLL 차이는 첫 단계 +0.00347724, 두 번째 −0.00533414, 세 번째 −0.01641021이었다. 마지막 둘은 정확 2·3착 주변확률의 손실과 구분한다. 근거는 `PRIOR_ERROR_DECOMPOSITION.json`이다.

## 후보·참조

- 새 후보는 하나다. `Q(i,j,k)=softmax(s/T1)[i] × softmax(s_except_i/T2)[j] × softmax(s_except_i_j/T3)[k]`. 세 단계 모두 전체 남은 출전집합을 분모로 사용한다. 정해진 3두 집합 내부의 순서 모형이 아니다.
- 말 평가·원점수·feature table·기존 모델·두수·라벨·T−2 경계·공개시각 미확정 상태는 선행 연구와 동일하다. 새 피처, 결측 대체, 말 평가 재학습, 배당 입력, 파라미터 탐색 후보는 추가하지 않는다.
- 주 참조 COMMON은 기존 적합값 `T=1.1837152381349905`를 세 단계에 사용하는 PL이다. 이 T는 다시 맞추지 않는다.
- WIN 보호용 참조 RAW는 세 단계 모두 `T=1`이다. native F1_STYLE6 집합분포나 운영 HY_R_FORM과의 직접 비교가 아니다.

## 적합·평가

2019–2023 OOS 원점수 2,492경주만 세 보정값 적합에 사용한다. 같은 해에 맞춘 기존 tau를 원점수에 적용하지 않는다. 각 stage의 실제 관측 경로 조건부 NLL을 경주 균등 최소화한다. 정답 prefix는 보정 목적함수의 관측 경로에만 사용하며, 예측 Q는 모든 가상 prefix를 순회한다. 평가 정답을 예측 risk set 구성에 쓰면 안 된다.

각 T는 [0.35, 4.0], `scipy.optimize.minimize_scalar(method='bounded', options={'xatol':1e-12})` 한 번과 두 끝점 목적값 비교로 정한다. 세 파라미터, 추가 규제 없음, hyperparameter 선택 없음이다. 목적값이 완전히 같으면 T가 작은 점을 택한다. 최적화 실패·비유한 값·평탄/식별 불능은 중단해 원인을 검토하며 결과를 보고 bounds를 넓히지 않는다. 경계 최적은 도달 사실을 기록하고 역온도 gradient 방향으로 확인한다. 역온도에 대한 stage 목적함수의 분리·볼록성과 보정 표본에서 common-T보다 NLL이 나쁘지 않아야 한다는 성질도 점검한다.

평가는 기존 2024-01-05–2026-09-19의 1,779경주, 17,412출전, 269일이다. 연승은 개시두수 분기 미확정 36경주를 같은 이유로 분리해 1,743경주로 한다. 동착·취소·미완주·실제 pool offering 미감사 등 공식 계약의 한계를 그대로 승계한다. 기존 원장과 비교해 분모가 달라지면 조용히 제외하지 않고 중단한다.

## 결과와 무관하게 고정한 통과 기준

다음 네 조건을 모두 만족해야 이번 연구 후보 게이트를 통과한다.

1. TRI categorical NLL `후보−COMMON`의 날짜 paired bootstrap 95% 구간 상한 < 0.
2. TRI sum-Brier `후보−COMMON`의 경주 균등 점차이 ≤ 0.
3. WIN categorical NLL `후보−RAW`의 경주 균등 점차이 ≤ 0.
4. WIN sum-Brier `후보−RAW`의 경주 균등 점차이 ≤ 0.

날짜 재표집은 이전과 같은 고정 2,000×269 schedule을 경로·해시로 참조한다. 각 재표집 날짜의 전체 경주를 함께 포함하고 경주 균등 평균한다. 세 T는 bootstrap 내에서 고정하므로 fit 불확실성은 포함하지 않는다. WIN과 Brier의 점추정 보호 조건을 통계적 비열등성으로 표현하지 않는다. 다른 승식·기간·선택 적중률이 이 게이트를 뒤집지 않는다.

모든 7승식의 NLL·Brier·고정 reliability bins와 연도별 결과를 공개한다. 5개 단일 당첨 승식은 categorical NLL/sum-Brier, PLC/QPL은 ticket binary 손실의 경주 내 평균 후 경주 균등 평균이다. ε=1e−15는 로그에만 사용한다. Reliability는 선행 16개 구간과 ticket-event 가중을 그대로 사용한다. 원확률을 상위 후보만으로 재정규화하지 않는다.

## 선택 진단과 저장

선행 수치 동점 문제를 반복하지 않도록 이 연구의 모든 arm에 동일한 선택 규칙을 사전 고정한다. 승식별 `p >= max(p)−1e−12`인 티켓 중 마번 사전순으로 하나를 선택한다. tolerance는 선택 진단에만 적용하고 Q·손실·구간 집계에는 적용하지 않는다. 확률이 다르면 ordered MAP의 raw-score 순서 보존을 가정하지 않는다. 이번 선택 비교는 같은 새 규칙으로 COMMON·RAW도 계산한다. 예전 선택 적중 수와 직접 섞지 않는다.

기존 baseline 지표·모델·입력·규칙 원장은 경로와 해시로 참조한다. 신규 저장은 후보 확률·손실·원장·요약과 동일 선택 규칙용 소형 참조 원장에 한정한다. 전체 경주의 모든 순열, DB·원천·feature 사본, 새 환경은 만들지 않는다. 신규 목표 20,000,000 bytes, 앞선 연구와의 합산 상한 300,000,000 bytes다.

`audit/`와 `design_review/` 검토, 구조 preflight, 감독관 코드 검토를 마친 뒤 현재 파일 해시에 맞는 `RANK_STAGE_EXECUTION_APPROVAL.json`이 있어야 실행한다. 승인 전 실제 후보 fitting·평가 확률 계산은 하지 않는다. 감독관은 실험 구현을 가져오지 않은 별도 수식으로 최적값 미분, Q와 사건 확률, 저장 지표와 bootstrap을 검산한다. 운영 등록부·더러브렛·DB·기존 연구는 변경하지 않는다.
